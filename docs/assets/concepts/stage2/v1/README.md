> **이전안 보존용입니다.** 최신 공간 방향은 [v2](../v2/README.md)입니다. 05 전동 체결기와 07 고정 작업 발판은 수동 몽키스패너·이동식 사다리 방향으로 대체되었습니다. 아래 제작 메모와 프롬프트는 v1 당시 기록이며 그대로 최종 에셋을 제작하지 않습니다. 크레인에는 승강기와 연결 통로의 추가 설계가 필요합니다.

## 먼저 보기

![폐허 지구 발사장](scene/stage2-launch-site.png)

기존 토끼 우주복 캐릭터, Stage1 로켓 에셋 프리뷰와 격납고 컨셉아트를 참고했다. 아이보리와 둥근 모서리, 작은 청록색 표시등을 유지하면서 지구 장비에는 바랜 주황색·청록색·회녹색을 사용한다. 폐허는 배경에 두고 작업물과 동료가 식별되도록 밝기를 확보한다.

이 그림은 분위기와 협동 장면을 전달하는 컨셉아트이지 배치도나 기계 설계도가 아니다. 크레인 끝부분이 프레임에 걸리고 분사 효과가 로켓 쪽에 닿아 보이는 등 연출상의 오차가 있다. 실제 제독 대상은 기획대로 팀원이다. 아래 별도 크레인도 v1 외형 후보이며 최종 설계가 아니다.

`tripo-inputs`에는 배경이 단순하고 물체가 하나씩 보이는 PNG 7장이 있다. `assembly-reference`는 조립 구조를 검토하는 시안이다. 둘 모두 완성된 3D 에셋은 아니며 Tripo의 복원 품질을 보장하지 않는다.

## Tripo에서 사용하는 순서

1. 만들려는 물체의 PNG 한 장을 선택한다. 전체 발사장 이미지를 개별 에셋 생성에 넣지 않는다.
2. 이미지 기반 3D 생성 입력에 해당 PNG를 넣는다. 캐릭터·배경·설명 문구가 없는 개별 시안을 사용한다.
3. 텍스트 보조 입력이 가능한 화면이라면 [프롬프트 모음](PROMPTS.md)의 해당 물체 설명을 사용한다. 기능이 없다면 이미지 입력만 사용한다.
4. 먼저 한 개만 생성해 뒷면, 구멍, 접합면, 실루엣을 확인한다. 여러 장의 서로 다른 물체를 한 모델의 다각도 이미지로 넣지 않는다.
5. 만족한 모델을 보유한 환경에서 지원하는 형식으로 내보낸다. Unity 반입용은 FBX와 텍스처를 함께 보관하고, 가능하면 원본 GLB도 별도로 보존한다.
6. 생성 모델에 스케일·피벗·재질·Collider·상호작용을 설정한 뒤 게임에 넣는다. 이미지 생성만으로 이 과정이 완료되지는 않는다.

현재 작업에서는 Tripo에 로그인·업로드·생성·변환 요청을 보내지 않았으며 Tripo 크레딧을 사용하지 않았다. 이미지 제작은 내장 이미지 생성 도구로 수행했고 별도 API 키를 사용하는 CLI는 쓰지 않았다.

## 제작 예산 제안

아래는 프로젝트용 초기 목표일 뿐, Tripo 옵션의 제공 여부나 결과를 보장하는 수치가 아니다. 실제 생성 화면의 옵션과 비용을 확인하고 선택한다. 모든 에셋을 8K 텍스처로 만들 필요는 없다.

| 종류 | 초기 삼각형 목표 | 텍스처 시작안 |
| --- | --- | --- |
| 손 도구 | 각각 3,000~5,000 | 1K~2K, 1인칭 확대에서 확인 |
| 로켓 파츠 | 각각 5,000~10,000 | 2K |
| 환경 탱크 | 3,000~5,000 | 1K~2K |
| 작업 발판 | 5,000~8,000 | 2K 또는 공용 재질 |
| 크레인 | 단일 예산 미확정 | 부품 분리 후 전체 화면 비용 측정 |

폴리곤 수를 줄여도 큰 텍스처, 재질 수, Collider 비용은 별개다. 이것은 디자인 초안용 예산이며 최종 목표는 실제 화면 크기와 성능으로 조정한다.

## 가동부와 모듈 제작 메모

### 로켓

- 3분할은 이번 아트 초안의 구성이다. 기획상 파츠 개수를 확정하는 변경은 아니다.
- 서로 다른 생성 결과의 접합면이 자동으로 같은 지름이 되지 않는다. Blender 등에서 지름·중심축·평면·스케일을 맞춘다.
- 하단 시안은 핀보다 착륙 지지대에 가까운 형태다. 지지대 유지 여부와 발사대 고정을 확인한다.
- 상단 인양 고리를 제외한 각 파츠의 최종 인양 고리는 별도 설계가 필요하다.
- 큰 볼트, 브래킷, 인양 고리처럼 단순하고 규격이 중요한 소품은 기존 부품 재사용이나 간단한 모델링을 우선 고려한다. 이번 묶음에는 별도 이미지가 없다.

### 크레인

![크레인 조립 참고](assembly-reference/08-crane-assembly.png)

한 장을 통째로 생성하면 정적인 조형물로 검토할 수는 있지만, 회전·반경·높이 조작이 바로 구현되지는 않는다. 다음 구조로 나눠 제작한다.

```text
고정 기둥·기초
└─ 회전부 (기둥 중심 수직축)
   ├─ 조종석·붐·카운터웨이트
   └─ 트롤리 (붐을 따라 직선 이동)
      └─ 와이어·훅 (높낮이 조절)
```

- 가느다란 와이어와 긴 레일은 통째로 생성하기보다 별도 구조로 만드는 방향을 권장한다.
- 팔 끝의 작은 고리처럼 생성 그림이 추가한 장식은 기획상 두 번째 인양 지점이 아니다. 실제 훅은 트롤리 아래 하나를 기본으로 한다.
- 시안의 밀폐 창은 외관 후보다. 동료가 조종사를 제독할 수 있는 열린 측면 또는 승하차 구조를 별도로 정해야 한다.
- 조종석 내부, 출입 동선, 사각지대와 실제 작업 반경은 아직 검증하지 않았다.

### 작업 발판

![작업 발판](tripo-inputs/07-service-platform.png)

- 타워 전체가 아니라 1층 외관 후보다. 같은 메시를 그대로 위에 얹으면 난간·기둥·사다리가 간섭할 수 있다.
- 기둥, 바닥, 난간, 사다리를 분리하고 상층·최상층 변형을 만든다.
- 사다리 도착 지점과 로켓 쪽 작업 면을 열고, 실제 캐릭터로 통과·등반·체결 거리를 검증한다.
- 바닥과 난간 Collider는 생성 메시 전체를 그대로 쓰기보다 플레이에 맞춰 단순하게 설계한다.

## 시안 검토 결과와 남은 일

- 전체 1장 + 개별 물체 8장 생성 및 파일 보관.
- 개별 시안은 한 물체, 단일 시점, 단순 배경, 글자 없음으로 육안 확인.
- 로켓 3종과 도구는 아이보리·주황·청록 계열을 공유한다.
- 표준 삼면도/다각도 세트는 아직 없다. 서로 다른 시점을 추가할 경우 형태 일관성을 먼저 확인해야 한다.
- 뒷면 형상, 내부 구조, 실제 치수, 삼각형 수, UV, 리깅·가동부, Collider는 이미지에서 검증할 수 없다.
- 전체 맵 배치, 크레인 도달 범위와 사다리 동선은 플레이용 블록아웃으로 검증할 것.
- 최초 이미지 제작 당시 Unity 씬·코드·기존 에셋은 변경하지 않았다. 2026-09-17 문서·이미지 정리는 [S15P21B202-578](https://ssafy.atlassian.net/browse/S15P21B202-578)에서 관리한다.
