## 근거와 변경

### 용접 안내의 CPU 부하

`WeldingJointGuide.Show`가 한 번에 모든 콜라이더 쌍을 조사하고, 각 축 양면의 최대 49×49 표본마다 레이캐스트와 용접 접촉 조회를 수행했다. 움직임 감지는 0.1초 제한까지 우회했다. 동일한 면이 여러 상대 파츠 때문에 중복 투영됐다.

- 계산을 여러 호출로 나누고 호출당 작업 2,048개 / 약 2ms의 협력적 예산을 둔다. 32개 단위 시계 검사이므로 단일 물리 조회, 초기 수집, 최종 메시 업로드까지 2ms 이하라고 보장하는 하드 제한은 아니다.
- 표시용 격자를 2.5cm/최대 48셀에서 7.5cm/최대 16셀로 줄였다. 실제 `WeldBead` 접촉·성장 판정 정밀도는 변경하지 않았다.
- 상대 파츠들의 후보 범위를 합쳐 원본 콜라이더의 면을 한 번만 투영한다. 실제 접촉 질의로 빈 부분을 거른다.
- 파츠 이동·비활성화·파괴 시 오래된 표시를 즉시 숨기고 계산을 취소한다. 도구를 내려놓거나 씬에서 제거할 때도 취소한다.
- 표시 생성이 비동기적인 만큼 첫 추천이 몇 프레임 늦게 나타날 수 있다. 계속 움직이는 접합부는 안정될 때까지 추천이 나타나지 않을 수 있다. 조준 및 실제 용접은 이 표시를 기다리지 않는다.

### 비드 상태를 두 번 적용하는 경로

기존 `WorldSync`는 용접 행동 RPC를 클라이언트에서 다시 판정한 후 사슬 스냅샷도 적용했다. 클라이언트의 보간된 콜라이더는 서버의 물리 위치와 다르므로 같은 노즐 좌표가 다른 비드를 고를 수 있었다. `RestoreChains`는 값이 같아도 기존 비드를 모두 파괴하고 다시 만들었다.

- 용접 복제는 기존의 신뢰성 있는 사슬 스냅샷으로 통일했다. 서버의 작업 판정과 로컬 빔·불꽃 표시 경로는 유지한다.
- 같은 사슬의 끝 크기와 개수만 갱신한다. 뒷 사슬 추가·제거에서도 앞 사슬을 보존한다. 완전히 같은 keepalive는 비드 오브젝트를 다시 만들지 않는다.
- 형상/순서가 바뀌어 대응할 수 없는 사슬은 기존 전체 복원 경로를 사용한다. 늦참, 질량 계산, 발사대 접합 해제, 절단에 의한 감소를 유지한다.
- 주기적 전체 상태 전송은 유지하므로 늦참·재접속을 행동 RPC 이력에 의존시키지 않는다. 이번 수정은 신규 전체 델타 전송 프로토콜을 도입하지 않는다.

### 이동 보정과 입력 전송

서버가 같은 입력 순번을 여러 물리 틱 유지하면서 현재 위치를 echo로 보냈다. 클라이언트의 기록은 입력을 보낼 때의 위치 하나이므로, 같은 순번이어도 echo 타이머에 따라 비교 시점이 달라졌다. 또한 이미 적용한 이전 보정량이 과거 위치 기록에 반영되지 않아 지연된 echo에서 다시 갚을 수 있었다.

- 서버는 새로운 입력을 처음 소비하는 경계의 위치를 한 번 저장하고 그 위치를 echo한다. 클라이언트의 송신 자세와 대응하는 근사 경계이며, 결정론적 rollback/replay 구현으로 바꾼 것은 아니다.
- 과거 위치 조회에 기록 이후 실제 적용한 보정량을 더해 중복 보정을 방지한다.
- 보정 시 골반만 옮겨 관절을 늘리는 대신 래그돌 전체를 같은 거리로 옮긴다. 서버의 상호작용 권한은 바꾸지 않는다.
- 입력 기록을 유한 링 버퍼로 유지하고 순번 wrap, 순간이동 및 탑승 전환 시 기록 초기화를 처리한다.
- 연속 마우스/조준 변화는 20Hz로 전송한다. 이동 방향·모든 버튼의 누름/해제는 즉시 보내며 신뢰 채널과 기존 일회성 입력 큐는 유지한다. 누락됐던 `StuckEscapeHeld` 변화도 즉시 전송한다.
- 원격 플레이어의 기존 Mirror NetworkTransform 보간과 WorldSync의 공유 물체 추종 방식은 유지한다.

## 아직 필요한 실제 다인 확인

후속으로 화면 조작 없이 로컬 4인 실행 파일을 계측했다. [실제 멀티 FPS 측정 기록](2026-09-23-728-multiplayer-fps.md)에서 60 FPS 미달을 확인했다. 아래 항목 중 지속 용접/절단, 별도 PC 및 지연·손실 조건은 여전히 확인이 필요하다.

화면 직접 조작 제한을 지켰다. 따라서 사용자가 신고한 실매치 프리징이 완전히 없어졌거나 모든 오류가 없다고 보장하지 않는다.

1. 같은 수정 빌드의 호스트·참가자 2인 이상으로 Stage1 입장. 참가자가 30초 전진·정지·방향 전환·점프하고, 파츠 밀기/식생 감속/탑승·하차/리스폰 전후 되감김을 확인한다.
2. 호스트에서 핵심 파츠를 발사대에 조립하고 참가자가 용접 건을 든 채 4m 안으로 진입한다. Profiler의 main-thread 최대 프레임 시간과 프레임 분포를 수정 전과 같은 위치에서 비교한다. 추천의 첫 표시 지연도 확인한다.
3. 양쪽에서 용접 성장·연속 그리기·절단·발사대 접합 해제를 반복하고 비드 수/모양/진행이 되돌아오지 않는지 비교한다. 작업 도중 늦참 및 호스트 이전에서도 현재 상태가 복원되는지 확인한다.
4. 50/100/200ms 지연과 패킷 손실 조건에서 같은 절차를 반복한다. 입력/권위 판정은 여전히 신뢰 채널이므로 심한 손실에서 재전송 대기는 남는다.
5. 고정쇠 게이지와 구조 게이지는 서버 상태를 유지한다. 진행 중단/재개 및 여러 사람이 이어받는 동작을 확인한다. 이번 변경에서 임의로 진행을 완료시키는 로컬 예측을 추가하지 않았다.

롤백은 위 5개 런타임 파일과 관련 테스트/문서를 되돌리는 범위다. 네트워크 RPC 경로가 바뀌므로 호스트·참가자는 동일 버전으로 검증한다.
