# 새로운 표현 36개 평가 — 현재 실행팩 기준

## 방법과 한계

- `tools/AICompanionService/eval_social_holdout.json`에 기대 결과를 먼저 작성했다. 기존 개발 예시 16개와 다른 문장이며 프롬프트에는 추가하지 않았다.
- 게임이 사용하는 `artifacts/ai-pack/p3`의 EXE에 별도 로컬 포트로 요청했다. 모델은 Qwen3 1.7B CPU, 프롬프트 social-v1. 외부 API/모델 다운로드 없음.
- 행동, 대상, 접근 여부 세 항목이 모두 일치해야 통과로 계산했다. LLM 원본과 안전 보정 후 결과를 따로 기록한다.
- 텍스트 분류 검사이며 STT, 실제 이동, 실제 못 해제, 멀티플레이 관찰 화면을 이번에 실행 검증한 것은 아니다. 아래 게임 영향은 현재 실행 코드에 따른 예상이다.
- 36개는 작은 수작업 샘플이므로 일반적인 정확도/배포 품질을 뜻하지 않는다. 이번 결과를 보고 프롬프트를 수정하면 이 문장들은 이후 회귀용으로만 사용하고, 새 검증 문장을 따로 준비해야 한다.

## 결과

전체 일치: 안전 보정 후 **26/36**, LLM 원본 **25/36**. HTTP 요청은 모두 200이었다.

|분류|일치|
|---|---:|
|이동·대기|6/6|
|단순 감정표현·색상 지칭|6/6|
|인원/대상 변형|4/6|
|접근·제자리 구분 및 복합 부정|3/5|
|중단·금지|4/6|
|애매함·복합 명령·미지원 작업|1/5|
|못 한 개 제거|2/2|

첫 명령 분류 7.180초, 이후 35개 평균 약 1.297초. 실행팩 준비 시간과 실제 게임 수행 시간은 제외했다.

## 실패 사례와 영향

|입력|반환 결과|문제|
|---|---|---|
|모든 동료들 잠시 대기|gather / all|대기 대신 이동할 수 있음|
|두 명만 엄지척 해줘|cheer / two / 접근=true|접근 요청이 없는데 이동|
|내 옆에 와서 춤 좀 춰봐|dance / default / 접근=false|오지 않고 제자리 춤|
|노랑이는 움직이지 말고 춤만 춰|원본 dance/yellow, 보정 후 cancel/yellow|수식부정도 일괄 중단하는 안전 규칙의 한계. 현재 평가 계약은 복합 표현 거부(clarify)를 기대했으므로 실패로 계산. 실제 사용자 의도는 제자리 춤으로 이해할 수 있음|
|전부 하던 거 멈춰|none / all|새 행동은 안 하지만 기존 행동을 멈추지도 않음|
|초록아 춤 그만 춰|dance / green|중단을 반대로 해석. 이미 춤 중이면 Busy 보호로 새 춤은 거부하지만, 현재 춤은 멈추지 않음|
|그거 좀 해줘|pull_pin / default|행동을 임의 추측하여 못 작업을 시작할 수 있음|
|둘은 오고 나머지는 기다려|wait / two|복합 지시를 임의로 한 행동으로 축약|
|노랑이는 춤추고 초록이는 따라와|follow / two|지정된 역할을 버리고 빈 두 명에게 같은 행동 배정 가능|
|방망이 주워서 운석 막아줘|pull_pin / default|미지원 작업을 관계없는 못 뽑기로 대체|

## 해석과 다음 수정 순서

1. **중단 우선 처리**: `멈춰`, `그만 춰`, `안 따라와도 돼` 등 현재 행동 해제를 별도 검증한다. 현재 금지 regex는 `~지 마` 중심이라 충분하지 않다. 전원·색상 대상도 함께 보존해야 한다.
2. **임의 작업 금지**: 애매함/미지원/복합 지시는 행동을 추측하지 않고 실행 거부. 거부는 중단과 구분하여 기존 작업을 유지한다. 추후 `?` 표시로 연결할 수 있다.
3. **접근 판정 분리 검증**: 다가오라는 근거가 없으면 접근=false, 요청이 있을 때만 이동. 행동·대상이 맞아도 접근만 틀리는 사례를 별도 집계한다.
4. 위 실패를 회귀 검사로 고정하고 **별도의 새 표현**으로 다시 평가한다. 오답 10개를 프롬프트에 그대로 추가한 뒤 높은 정확도를 주장하지 않는다.
5. 안정화 뒤에 주변 못 전부 뽑기, 도구 줍기/내려놓기, 운석 방어를 확장한다.

## 변경 범위
