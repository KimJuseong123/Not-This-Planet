# S15P21B202-261 방망이 스윙을 우타자 야구 스윙으로

## 앞선 판단을 뒤집었다

S15P21B202-243 의 기록에 이렇게 적어 두었다.

> 야구처럼 수평으로 돌리지 않는 이유는 목표가 **떨어지는** 운석이라서입니다. 위에서 오는
> 것을 맞이하는 궤적이어야 하고, §18.2 의 "약간의 위쪽 각도를 더해" 반사하는 것과도
> 맞습니다.

인게임에서 보고 우타자 스윙으로 정했다(2026-09-02). 기획 §18 은 궤적 모양을 정하지 않으므로
**손맛 결정**이고, 그 결정은 화면을 본 쪽이 한다.

## 바꾼 것은 순수 함수 하나다

243 에서 동작과 판정을 일부러 분리해 둔 것이 여기서 값을 했다.

```
Swing()  →  판정 먼저 (FindTarget · FindPlayer · FindProp)
         →  그 뒤에 동작 시작
```

기획 §18.1 이 "완벽한 프레임, 등급과 치명타 판정은 없다" 고 정하므로 동작 위상이 판정에
섞이면 타이밍 게임이 된다. 그래서 이 이슈는 `SwingAim` 만 바꿨다 — 판정·사거리·대기
시간·반사 방향을 하나도 건드리지 않았다.

**`MeteorBatTests` 17개가 그대로 통과하는 것이 그 증거다.**

## 궤적

```
0.00   오른쪽 뒤 위      yaw +110  ·  pitch +45
0.45   정면, 거의 수평    yaw    0  ·  pitch  +5   ← 맞는 순간
1.00   왼쪽 앞, 살짝 아래  yaw  -70  ·  pitch -15
```

**좌우 성분이 아예 없었다.** 예전에는 pitch 하나로만(위 55 → 아래 −35) 움직였다.

### 대칭이 아니다

시작이 오른쪽 110도, 끝이 왼쪽 70도다. 같은 폭으로 흔들면 "부채질" 로 보인다 — 야구
스윙은 뒤에서 시작해 앞을 지나 앞쪽으로 끝난다.

110도로 90도를 넘긴 것도 그 때문이다. 뒤까지 가지 않으면 "들었다 내린다" 가 된다.

### 가속이 앞뒤로 다르다

```csharp
if (t <= contact)      // 맞는 순간까지 가속 — t²
else                   // 팔로스루는 감속 — 1-(1-u)²
```

한 곡선으로 처리하면 **맞는 순간이 뒤로 밀린다.** yaw 를 110 → −70 으로 t² 로 보간하면
정면(yaw 0)이 진행도 0.78 에 오고, "늦게 휘두르는" 것으로 보인다. 맞는 순간을 상수
(`BatSwingContactAt` 0.45)로 못박고 앞뒤를 따로 보간했다.

## 스윙이 카메라 주위로 돈다

243 에서 알게 된 것이 이 이슈를 작게 만들었다. `PlayerRig` 가 **방향 하나로** 도구의
위치와 회전을 둘 다 정한다.

```csharp
Vector3 holdPoint = cameraOrigin + direction * Tuning.ToolHoldDistance;
Quaternion targetRotation = Quaternion.LookRotation(direction, up);
```

방향에 yaw 를 넣으면 방망이가 **화면을 가로질러 쓸고 간다** — 1인칭에서 야구 스윙이
보이는 모습이 정확히 그것이다. 팔도 같은 방향을 따라가므로 팔을 따로 움직이는 코드가
필요 없었다.

## 검증에서 걸린 것 — 내 측정이 틀렸다

궤적은 맞는데 검증 둘이 실패했다.

```
TheSweepIsNotSymmetric   기대 > 0.908, 실제 0.664
TheSweepNeverReverses    진행도 0.05 에서 0.665 → 0.676 (커졌다)
```

**원시 내적으로 좌우를 재면 안 된다.** 두 가지가 섞인다.

| 문제 | 무엇 |
| --- | --- |
| pitch 와 섞인다 | 45도 들린 방향은 수평 성분이 `cos(45)=0.71` 로 줄어든다. pitch 가 평평해지는 것만으로 "오른쪽으로 되돌아간 것" 처럼 보였다 |
| 90도에서 꺾인다 | `sin(110)=0.94`, `sin(90)=1.0` — yaw 가 110→90 으로 **줄어드는 동안 성분은 커진다** |

`Mathf.Atan2(x, z)` 로 **각도를 직접 재면** 둘 다 사라진다. 구현이 아니라 검증을 고쳤다.

## 예전 검증 하나는 성립할 수 없었다

`TheArcKeepsTheAimedHeading` 이 "진행도 내내 겨눈 쪽을 벗어나지 않는다" 를 단언했다.
좌우 성분이 없던 궤적이라 성립했고, 야구 스윙에서는 성립할 수 없다.

지우지 않고 **뜻을 바꿨다** — `TheArcRotatesWithTheAim` 이 "조준을 돌리면 스윙 전체가
같은 회전으로 따라오는지" 를 본다. 원래 검증이 지키려던 것("옆으로 휘면 무엇을 쳤는지
알 수 없다")은 `ItPassesTheFrontAtContact` 가 대신 지킨다 — **맞는 순간이 정면**이다.
