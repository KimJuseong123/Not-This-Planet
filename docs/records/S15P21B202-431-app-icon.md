# S15P21B202-431 — 앱 아이콘을 게임 아이콘으로

> 2026-09-11 · 김주성(물리·퍼즐·캐릭터·상호작용·QA) · 브랜치 `S15P21B202-431-art`

---

## 1. 무엇이 문제였나

빌드한 실행 파일과 작업 표시줄에 **유니티 기본 아이콘**이 나왔다. 잘못 지정된 것이
아니라 **한 번도 지정한 적이 없었다.**

```yaml
# ProjectSettings.asset:299 (이전)
m_BuildTargetIcons: []
m_BuildTargetPlatformIcons: []
```

제품명은 이미 `Not This Planet` 으로 들어가 있어(`companyName` · `productName`)
**아이콘만 어긋난 상태**였다. 빌드를 받은 사람에게는 유니티 프로젝트로 보인다.

---

## 2. 원본을 먼저 다듬어야 했다

받은 이미지가 앱 아이콘으로 쓸 수 있는 모양이 아니었다.

| 항목 | 받은 것 | 필요한 것 |
| --- | --- | --- |
| 크기 | **161 x 147** | 정사각형 |
| 해상도 | 161px | 1024px (윈도우가 1024 슬롯까지 요구한다) |
| 알파 | 있음 ✅ | 있음 |

**정사각형이 아니면 유니티가 늘린다** — 세로로 찌그러진 아이콘이 된다.

`scratchpad/icon_prep.py` 로 다듬었다. 한 일은 둘뿐이다.

1. 알파 경계(`getbbox`)로 실제 그림 범위를 찾아 잘라낸다 — 원본 여백이 좌우·상하
   비대칭이라 그냥 캔버스 가운데에 놓으면 그림이 치우친다
2. 비율을 유지한 채 1024 x 1024 가운데에 놓는다 (여백 4%)

```
원본     : 161 x 147
내용 범위: (8, 8, 150, 135)  (142 x 127)
결과     : 1024 x 1024 · RGBA
내용 크기: 942 x 842 (여백 4%)
```

**그림 자체는 건드리지 않았다.** 색·모양·획 두께를 손대는 것은 디자인 변경이고 이
이슈의 범위가 아니다.

> **원본이 161px 라 1024 는 업스케일이다.** 256px 아이콘은 원본보다 큰 크기로 늘린
> 결과라 완전히 선명하지는 않다. 작은 크기(16~48px)에서는 오히려 문제가 없다 —
> §4 에서 실제로 확인했다. 더 선명하게 하려면 고해상도 원본이 필요하다.

---

## 3. 왜 도구를 만들었나

`ProjectSettings.asset` 을 손으로 고칠 수도 있었다. 그러지 않은 이유는 그 파일의
아이콘 항목이 **텍스처 GUID 를 크기별 슬롯에 적는 구조**라서다.

```yaml
- m_BuildTarget: Standalone
  m_Icons:
  - serializedVersion: 2
    m_Icon: {fileID: 2800000, guid: 3677aa6c6c10e5c4f952134193c25290, type: 3}
    m_Width: 1024
```

GUID 한 글자만 틀려도 조용히 빈 슬롯이 되고, **그 결과는 빌드해 보기 전에는 보이지
않는다.** `AppIconSetup` 을 거치면 유니티가 슬롯을 채우므로 그 실수가 없고, 아이콘을
바꿀 때 같은 방법을 다시 쓸 수 있다.

```
Unity.exe -batchmode -quit -projectPath METAGAME \
  -executeMethod Metagame.EditorTools.AppIconSetup.Apply
```

`Tools/Space/앱 아이콘 지정` 메뉴로도 부를 수 있다.

### 3-1. `IconKind` 와 `PlatformIconKind` 는 다른 타입이다

처음에는 `PlayerSettings.GetSupportedIconKinds(target)` 를 돌려 종류마다 채우려
했는데 컴파일이 안 됐다.

```
error CS0030: Cannot convert type 'UnityEditor.PlatformIconKind' to 'UnityEditor.IconKind'
```

여러 종류(Settings · Notification · Store 등)는 **모바일 쪽 개념**이고 그것은
`SetPlatformIcons` 가 다룬다. 데스크톱은 `IconKind.Any` 하나면 된다.

## 4. 확인 — 설정이 아니라 exe 를 봤다

**설정이 채워졌다는 것과 exe 에 구워졌다는 것은 다르다.** 유니티는 빌드 끝에 아이콘을
exe 에 굽는 별도 단계를 거치고, 그 단계가 조용히 실패하면 설정은 채워져 있는데
실행 파일은 유니티 기본 아이콘이다.

그래서 빌드한 뒤 **exe 의 리소스 섹션을 직접 열어** 확인했다
(`scratchpad/exe_icon.py` — PE 헤더 → `.rsrc` → `RT_ICON`).

```
exe: NotThisPlanet.exe · 652 KB
RT_ICON 9개 · RT_GROUP_ICON 1개
   256 x 256  DIB   264.0 KB
   192 x 192  DIB   148.5 KB
   128 x 128  DIB    66.0 KB
    96 x 96   DIB    37.2 KB
    64 x 64   DIB    16.5 KB
    48 x 48   DIB     9.4 KB
    32 x 32   DIB     4.2 KB
    24 x 24   DIB     2.4 KB
    16 x 16   DIB     1.1 KB
```

**개수만 세면 유니티 기본이 9개 들어간 경우와 구분되지 않는다.** DIB 를 ICO 로 감싸
PNG 로 바꿔 눈으로 확인했고, 게임 아이콘이 맞았다.

### 4-1. 16px 에서도 알아볼 수 있다

지라 본문에 "작은 크기에서 안테나와 고리가 뭉개질 수 있다 — 획을 굵힌 판이 따로
필요한지는 실제로 줄여 보고 판단한다" 고 적어 두었다.

16 / 24 / 32 / 48px 로 줄여 8배 확대해 보니 **행성 · 고리 · 안테나가 모두 구분된다.**
별도 이미지는 **필요 없다.**

흰 테두리가 얇아 아주 밝은 배경에서는 윤곽이 약간 묻힐 수 있다. 지금 형태를 유지한
채 고치려면 테두리를 한 단계 진하게 해야 하는데, 그것은 디자인 변경이라 하지 않았다.

## 5. 무엇이 커밋에 들어갔나

| 파일 | |
| --- | --- |
| `Assets/_Project/UI/AppIcon.png` (+`.meta`) | 1024 x 1024 RGBA |
| `Assets/_Project/Scripts/Editor/AppIconSetup.cs` (+`.meta`) | 설정 도구 |
| `ProjectSettings/ProjectSettings.asset` | 아이콘 슬롯 9칸 |

`ProjectSettings.asset` 의 diff 는 **아이콘 항목뿐**이다(54줄 추가).

**유니티가 배치 실행 중에 건드린 것은 전부 되돌렸다** — 프리팹 14개, `PC_RPAsset`,
`.fbx.meta` 3개, `GraphicsSettings`, `QualitySettings`. 내 변경이 아니고, 프리팹은
`repo-hygiene` 의 씬/프리팹 검사에도 걸린다.

## 6. 정정 — 지라 본문의 실행 파일 이름이 틀렸다

내가 쓴 지라 본문의 확인 절차에 `Build/Windows/SpaceFlop.exe` 라고 적혀 있다.
**실제 이름은 `NotThisPlanet.exe` 다.** `productName` 이 `Not This Planet` 이고
유니티가 그것으로 파일명을 만든다.

예전 세션의 빌드 경로 기억을 확인 없이 옮긴 것이다(!339 AI 리뷰가 짚었다).
MR 본문에는 바르게 적혀 있다. **지라 본문의 그 줄은 정정이 필요하다.**

## 7. 남은 것

- **더 선명한 원본이 있으면 교체할 가치가 있다.** 지금 1024 는 161px 를 늘린 것이라
  256px 아이콘이 완전히 선명하지는 않다. 교체는 `AppIcon.png` 를 덮어쓰고
  `AppIconSetup.Apply` 를 다시 부르면 끝난다.
- **다른 플랫폼이 생기면 각자 칸을 채워야 한다.** 지금 빌드 대상은
  `StandaloneWindows64` 하나다. `SetAll(NamedBuildTarget.Unknown, …)` 이 기본값을
  채워 두므로 새 플랫폼도 빈 아이콘으로 나가지는 않지만, 그 플랫폼이 요구하는
  크기·모양(둥근 모서리, 안전 영역)은 다를 수 있다.
- **로비 화면·런처의 아이콘은 별개다.** 이 이슈는 실행 파일과 창 아이콘만 다룬다.
