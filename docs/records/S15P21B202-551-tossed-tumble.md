# S15P21B202-551 — 던져진 몸이 실제로 구르게 한다

> `-550` 위에 쌓는다. 그쪽이 몸을 늘어뜨리는 것까지 했고, 여기서 실제로 넘어가게 한다.

## 한 줄

**범인은 균형 조인트의 감쇠 바닥 한 줄이었다.** 강체의 각저항이 아니었다.

## 무엇이 회전을 먹고 있었나

`-550` 이후 던져진 몸은 `Ragdolled = true` · `uprightBlend = 0` 인데도 각속도를 주면
0.15초 만에 멈췄다. 지렛대를 하나씩 떼어 쟀다(각속도 12 rad/s · 1.2초 · 골반 기울기).

| 무엇을 껐나 | 최대 기울기 | 남은 각속도 |
| --- | --- | --- |
| 지금 그대로 | 8.5도 | 0.00 |
| `Rigidbody.angularDamping = 0` | **8.7도** | 0.00 |
| **균형 조인트 드라이브 끔** | **179.6도** | 2.32 |
| 둘 다 | 179.2도 | 2.88 |

**강체의 각저항(0.70)은 범인이 아니다**(8.5 → 8.7). 범인은 `Balance()` 한 줄이다.

```csharp
float k = (Grounded ? 1f : 0.26f) * uprightBlend;     // 조종을 잃으면 0
JointTools.SetDrive(Doll.Balance,
                    Tuning.UprightSpring * k,                  // 스프링은 0 이 된다
                    Tuning.UprightDamp * Mathf.Max(k, 0.25f),  // ← 감쇠에 0.25 바닥
                    Tuning.UprightMaxTorque);
```

`uprightBlend` 을 0 으로 만들어도 **감쇠는 190 × 0.25 = 47.5 로 남는다.** 균형 조인트는
`connectedBody = null` 이라 **세계**를 기준으로 붙잡으므로, 이 감쇠가 세계에 대한 회전을
통째로 먹는다 — 스프링이 0 이라 "세우지는" 않으면서 "구르지도 못하게" 했다.

## 고친 것

```csharp
float DampFloor(float k) => BodyOutOfControl ? k : Mathf.Max(k, 0.25f);
```

**조종을 잃었을 때만 걷는다.** 기절과 던져짐이 함께 해당된다(`-550` 이 이미 한 조건으로
묶었다).

그리고 `LaunchTossed` 가 회전을 준다.

```csharp
public static Vector3 TossSpin(Vector3 velocity, float charge01, Vector3 fallbackRight)
```

**앞구르기다.** 날아가는 방향을 축으로 삼으면 꼬치처럼 제자리에서 돌고, 위를 축으로
삼으면 팽이가 된다. 넘어가 보이려면 **가는 방향과 위 둘 다에 수직인 축**이어야 한다 —
`Vector3.Cross(Vector3.up, forward)`.

빠르기는 던진 세기를 따른다. 위로만 던져 앞 성분이 없으면 몸의 오른쪽으로 축을 잡고,
그것마저 없으면 **회전을 주지 않는다** — 아무 축이나 고르면 던질 때마다 다르게 돈다.

### 얼마나 돌려야 하나 (실측)

| 준 각속도 | 최대 기울기 | 완전히 뒤집힌 횟수 |
| --- | --- | --- |
| 4 rad/s | 62.3도 | 0 |
| 8 rad/s | 123.9도 | 1 |
| **12 rad/s** | **179.6도** | 1 |
| 20 rad/s | 179.7도 | 1 |

12 이상은 더 안 는다. `Tuning.TossSpinSpeed = 12f` 로 정하고 근거를 주석에 적었다.

## 검증

`TossedTumbleTests` 13개 + `-550` 의 `TossedBodyTests` 9개가 그대로 돈다.

- 축이 옆으로 누웠는가(위 성분 0 · 날아가는 방향과 겹치지 않음)
- 세게 던질수록 빨리 도는가 · 꽉 채우면 정해 둔 빠르기가 나오는가
- 위로만 던져도 도는가 · **축이 없으면 아무 축이나 고르지 않는가**
- **실제로 넘어가는가**(90도 초과) · 약하게 던지면 덜 넘어가는가
- **기절한 몸도 이제 굴러다니는가** — 이 변경이 기절에도 간다는 사실을 못박는다
- 그냥 뛴 몸은 여전히 똑바로 착지하는가 · 휘청임이 여전히 멈추는가
- **넘어간 몸도 착지 판정을 받고 일어나는가** · 조종이 돌아오는가
- **머리가 실제로 도는가**(카메라가 읽는 값이다) · **날아가는 시간이 1인칭 창 안인가**

### 대조 2가 왜 안 잡혔나 — 재서 확인했다

감쇠 바닥을 **통째로** 걷어도 검증이 전부 통과했다. 테스트를 급히 늘리는 대신 **바닥이
조종 살아 있는 몸에 무슨 일을 하는지 쟀다**(각속도 6 rad/s 를 주고 3초).

| 상황 | 바닥 있음 | 바닥 없음 |
| --- | --- | --- |
| 휘청임 | 0.7 0.9 1.0 0.9 0.8 | 0.7 0.9 1.0 0.9 0.8 |
| 공중 | 1.7 1.3 0.7 0.8 0.8 | 1.7 1.3 0.8 0.9 0.9 |
| 그냥 서 있기 | 0.6 0.7 0.7 0.7 0.7 | 0.6 0.7 0.7 0.7 0.7 |

**아무 차이가 없다.** 이유는 수에 있다 — 조종이 살아 있으면 `uprightBlend = 1` 이므로
`k` 가 지상 **1.0**, 공중 **0.26** 이다. 둘 다 0.25 보다 커서 **바닥이 애초에 안 걸린다.**

즉 이 바닥은 사실상 **늘어진 몸에만** 걸리는 장치였다. 그럼에도 조건부로 남긴 이유는
`Ragdolled` 가 기절·던져짐이 아닌 경우에도 켜지기 때문이다 — `UpdateSpeed` 가 "머리가
골반보다 낮으면" 참으로 만든다. 그냥 넘어진 사람은 `uprightBlend → 0.18` 이라 바닥이
걸리고, 이 변경은 **그쪽을 건드리지 않는다.** 바꾸는 범위를 최소로 두는 쪽을 골랐다.

> **대조가 안 잡혔다고 테스트를 억지로 만들지 않았다.** 차이가 없는 것을 있다고 재는
> 테스트는 다음 사람을 속인다. 왜 차이가 없는지를 재서 적어 두는 것이 맞다.

## 화면도 같이 뒤집힌다 — 따로 고칠 것이 없었다

사용자가 원한 것은 **"날아가거나 정신없이 뒤집힐 때 시점도 그 캐릭터의 눈의 위치와
방향에 맞게 바뀌는 것"** 이었다. 새로 만들 일이 있는 줄 알고 들여다봤는데 **배선은 원래
있었다.**

`OrbitCamera` 는 `DownedFalling` 동안 머리 본을 그대로 쓴다.

```csharp
if (DownedFalling && downedEyes != null)
{
    transform.position = downedEyes.position;
    transform.rotation = downedEyes.rotation;   // 회전까지 그대로
    ...
}
```

**따라갈 회전이 없었을 뿐이다.** 이 티켓 전에는 머리가 2.8도밖에 안 기울었다.
고친 뒤 실측:

| 잰 것 | 값 |
| --- | --- |
| 머리 기울기 (0.2초마다) | 37 68 100 130 158 **175** 149 124 101 78 |
| 머리 최대 | **179.9도** |
| 화면이 90도 넘게 뒤집혀 있는 시간 | **1.36초** |
| 던져짐이 끝나는 시각 | **3.37초** |
| 카메라가 머리를 따라가는 창 | **5초** |

전 구간이 창 안에 들어온다. 그래서 새 티켓을 만들지 않고 **관계를 테스트로 잠갔다** —
`TheHeadTurnsOverSoTheViewTurnsWithIt` 과 `TheFlightEndsWhileTheViewIsStillOnTheHead`.

> **여유가 1.6초뿐이다.** 던지는 세기를 올리거나 `DownedFirstPersonSeconds` 를 줄이면
> 날아가는 도중에 화면이 3인칭으로 튄다. 두 번째 검증이 그 자리를 지킨다.

참가자 화면은 자기 몸의 머리가 서버처럼 도는지에 달려 있다 — 2프로세스로 봐야 한다.

## 남은 것

1. **이 브랜치는 `-550` 위에 쌓여 있다.** `-550` 이 머지된 뒤 develop 으로 리베이스한다.
2. **기절 연출이 바뀐다** — 사용자에게 확인받았다(2026-09-15): "기절도 구르는 거 맞아".
   기획 §26-13 "운석에 굴러다녀야 한다" 와 같은 방향이다.
3. **참가자 화면에 회전이 보이는지**는 EditMode 로 확정할 수 없다. `-550` 에 남긴
   2프로세스 확인과 같은 자리에서 함께 본다.
4. 회전 축은 **날아가는 방향 기준**(앞구르기)이다. 사용자가 말한 "시점에 맞춰" 는
   축이 아니라 **화면이 눈을 따라가는 것**이었고, 그쪽은 위에 적은 대로 이미 된다.
