# S15P21B202-249 기절한 동료를 끌고 옮긴다

[문서 안내](../README.md) → [작업 기록](README.md) → 도구·캐릭터

기절한 동료를 잡아 운반하는 동작을 다룬 기록입니다. 구조와 운반의 상호작용, 물리 처리, 검증 결과와 후속 작업을 보관합니다.

본문의 “현재”, 검증 수치, 미완료 항목은 **기록 당시 기준**입니다. 후속 변경은 관련 이슈와 [주제별 색인](README.md)을 함께 확인합니다.

<a id="왜-지금인가"></a>

## 운반 기능이 필요한 배경

S15P21B202-247 이 운석 직접 충돌을 **한 번에** 기절로 만들고, 248 이 **자력 기상을
막았다.** 그래서 지금부터 기절한 동료가 실제로 바닥에 남는다.

§20.3 은 "주변을 확인하지 않고 구조하면 두 플레이어가 함께 다시 맞을 수 있다" 고 경고하는데
**옮길 수단이 없으면 그 경고를 피할 방법이 없었다.**

<a id="막고-있던-것--두-겹의-마스크"></a>

## 잡기 대상과 충돌 마스크의 제한

기절한 인형에 `Grabbable`이 없는 것은 예상한 문제였다. **추가로 확인된 제한은 마스크였다.**

```csharp
// RagdollBuilder.cs:34 — FindCrosshairGrabbable 이 쓰는 마스크
public static int WorldMask =>
    ~((1 << GameLayers.Player) | (1 << GameLayers.PlayerDowned)
      | (1 << GameLayers.Interactable) | (1 << GameLayers.BeamQuery));
```

기절한 플레이어와 Interactable을 **둘 다** 뺀다. 그리고 질의가
`QueryTriggerInteraction.Ignore` 라 트리거도 안 걸린다. 즉 `Grabbable`을 어디에 붙여도
콜라이더로는 찾을 수 없다.

### 마스크를 열면 고정못이 파츠의 잡기 지점이 된다

Interactable 레이어를 마스크에 넣고 트리거를 켜는 것이 가장 쉬운 길이었다. 그 레이어에
무엇이 있는지 세어 보고 **접었다.**

```
구조 지점   골반의 자식 — DownedRescue (§20.3)
Hatch       발사대(pad)의 자식
Clamp_N     파츠의 자식 · 트리거
```

`FindCrosshairGrabbable`은 `collider.GetComponentInParent<Grabbable>()`로 후보를
정한다. **고정못은 파츠의 자식**이므로 마스크를 열면 고정못 트리거를 조준했을 때 파츠의
`Grabbable`이 잡히게 된다 — 놓인 파츠를 고정못으로 집을 수 있게 되는 셈이다.

### 그래서 물리 질의를 안 쓴다

`PlayerRig.All`을 훑는다. `MeteorBat`이 때릴 동료를 그렇게 찾는 것과 **같은 방식**이고
(S15P21B202-233), 마스크·콜라이더·충돌 매트릭스를 하나도 건드리지 않는다.

운반 지점에는 **콜라이더가 없다.** 물리 질의로 찾지 않으므로 필요가 없고, 골반의 자식에
콜라이더를 두면 복합 콜라이더가 되어 골반의 관성과 무게중심이 흔들린다 —
S15P21B202-226 에서 비드로 같은 것을 겪었다.

몸의 레이어는 건드리지 않는다. §20.3 이 "몸의 레이어를 바꾸면 충돌 매트릭스가 함께
흔들린다" 며 피한 것이고, `RefreshRescueTarget`이 그 선례다. 운반도 자식 하나만 둔다.

<a id="349kg-이-도구로-오인된다"></a>

## 캐릭터 질량과 잡기 방식 판정

인형 총 질량을 실측했다 — **34.9kg** (골반 8 + 가슴 10 + 머리 5 + 팔 3.9 + 다리 8).
검증이 이 값을 확인한다.

```csharp
// Hand.GripTo
if (targetBody != null && !targetBody.isKinematic && targetBody.mass < Tuning.FixedGripMass)
    return CarryTo(target, targetBody);   // 키네마틱 — 몸 앞에 고정
```

`Tuning.FixedGripMass`는 40kg 이고 **잡히는 골반은 8kg** 이다. 그대로 두면 사람이
도구처럼 몸 앞에 뻣뻣하게 붙는다. §20.4 는 "**물리 오브젝트처럼** 끌고 옮길 수 있다" 고
정한다.

`Grabbable.PhysicsGrip`을 하나 두고 그 경로를 건너뛴다. 기본값이 거짓이라 도구와 소품
운반은 그대로다 — 검증이 그것도 잠근다.

<a id="일으키면-손이-놓인다"></a>

## 소생 시 잡기 해제

`CarryTarget.gameObject.SetActive(false)` 만으로는 **이미 만들어진 `FixedJoint`가
사라지지 않는다.** 구조받은 사람을 계속 들고 있게 된다.

`Revive` 경로에서 그 대상을 잡고 있는 손을 찾아 놓게 한다. §20.4 의 마지막 줄이
"안전한 곳으로 옮긴 뒤 `E`로 구조한다" 이므로 이 순서가 실제로 자주 일어난다.

<a id="저중력장은-떼어냈다"></a>

## 저중력장 운반의 별도 구현 범위

§20.4 는 "저중력장으로 띄워 옮길 수도 있다" 고 하지만 지금 저중력장은 플레이어를
아예 제외하고, **그 주석이 이미 별 이슈로 미뤄 뒀다.**

```csharp
/// 플레이어도 지금은 빼 둔다. 부유는 강제 견인이 아니라 직접 조작이라
/// 별도 이슈에서 다룬다.
public const int FieldMask = GameLayers.PartMask | GameLayers.PropMask;
```

플레이어를 저중력장에 넣는 것은 서 있는 사람의 조작감(§14.1)까지 건드린다. 손으로 끌고
옮기는 것만 했다.

전체 522개 중 509 통과. 실패 13개는 develop에 이미 있던 것이다(S15P21B202-232 건).
509 + 13 = 522, 496 + 13 = 509 — **늘어난 실패가 없다.**

## 산출물과 후속 확인

- **저중력장 부유** — 위 이유로 별 이슈다
- 기절한 사람을 **던지는** 것 — §20.4 에 없다
- 운반 중 카메라·자세 연출 — [Art] 몫이고 재생 경로가 없다
- 소리 — `AudioSource` 사용처가 0곳이다([Sound])
- **잡는 지점이 골반 하나다.** §20.4 는 "양손으로 잡아" 라고 하는데 지금은 한 손으로도
  잡힌다. 두 손을 강제하면 한 손에 도구를 든 상태로 옮길 수 없게 되므로, 강제할지는
  플레이테스트로 볼 항목으로 남긴다.

## 인게임 확인은 못 했다

빌드가 develop에서 멈춘다(지형 자산 체크아웃 손상 + 로비 씬 Volume Profile 누락).

EditMode로 확인한 항목은 **운반 지점 수명 · 조인트 경로 · 놓기 · 마스크 불변**이다.
`DownedCarryReach` 2.5m · `DownedCarryAngle` 35도로 쓰러진 사람을 서서 겨눌 수 있는지,
34.9kg 을 절반 속도로 끄는 감각이 맞는지는 인게임에서 봐야 한다.
