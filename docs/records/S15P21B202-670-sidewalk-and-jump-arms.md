# S15P21B202-670 · 옆걸음과 점프 팔

## 1. 점프에서 팔이 파닥거린다 — 원인은 둘이었다

실제 물리로 점프시켜 프레임마다 팔 각도 변화를 쟀다.

| 구간 | 세로 속도 | 팔 각도 변화 |
|---|---|---|
| 뜨는 직후 | 6.0 → 4.5 | **16.9 → 29.4 → 32.3 → 25.9 → 14.7 → 5.1도** |
| 올라가는 중 | 4.5 → 0.1 | 2.4도/프레임 |
| 내려오는 중 | −0.1 → −3.5 | 0.30도/프레임 |
| **−3.5 아래** | −3.9 → −5.2 | **0.00도 — 아홉 프레임 얼어붙음** |
| 착지 | −5.4 → −5.8 | 2.7 → 4.6 → 4.1도 |

**첫 가설이 틀렸다.** "골반 차분이 노이즈라 클립 시간이 흔들린다" 를 의심했는데
세로 속도는 매 프레임 −0.203 으로 **떨림이 전혀 없었다.** 측정이 기각했다.

### 원인 A — 켜지는 0.15초에 팔이 32도/프레임 움직인다

`AirBlendTime` 으로 자세 전체가 한꺼번에 들어오는데, 팔은 그 클립에서 각도
범위가 가장 큰 뼈라 가장 크게 휘둘린다. 50fps 면 초당 1600도다.

**S15P21B202-628 은 클립 안의 각속도만 봤고 켜고 끄는 구간은 안 봤다.** 그때
놓친 자리다. 628 에서 점프 끊김을 "큰 동작에 자기 타이밍 창을 주어" 푼 것과
같은 방법으로, 몸은 0.15초 그대로 두고 **팔만 0.40초**로 늘렸다.

측정: **21.13 → 12.05도/프레임** (43% 감소).

### 원인 B — 자세가 얼어붙는다

`AirSpeedSpan` 이 3.4 인데 점프는 −5.8m/s 까지 떨어진다. 넘으면 `Clamp` 가
−1 에 붙여 **자세가 통째로 멈춘다**. 얼어 있다가 착지에서 튀는 것이 나머지 절반이다.

`tanh` 로 눕혀서 재맵했다 — 어디서도 멈추지 않는다. 대신 ±3.4 에서의 자세가
조금 덜 벌어진다(1.00 → 0.76). **그 값은 눈으로 보고 정해야 한다.**

### 확정한 것 하나 더

최고점 뒤꿈치 동작의 효과는 지난번 비교가 **순서에 오염**됐었다(첫 스윕이 가중치
0 에서 올라오는 중). 데우고 다시 재니 **뒤꿈치 있음 4.35도 vs 없음 1.38도** —
3.2배다. 블렌드인보다는 작지만 기여한다.

## 2. 옆걸음

**뒷걸음은 안 넣었다.** 지금 그대로 둔다.

### 정정 — 뒤로 걷기는 문워크가 아니었다

지라를 쓸 때 "뒤로 가면 앞으로 걷는 클립이 그대로 재생된다" 고 적었는데,
실제로는 `direction = -1` 로 **역재생**하고 있었다. 문워크는 아니다.

### 지금 옆으로 가면 애니메이션이 통째로 꺼졌다

```csharp
state.Speed > 0.15f && Mathf.Abs(state.Direction.x) <= Mathf.Abs(state.Direction.y) + 0.1f
```

이 항이 거짓이라 가중치가 0.12초에 걸쳐 0 으로 떨어졌다. **그 0 이 날것 래그돌**
이라 다리가 멈추고 그대로 미끄러졌다. 항을 걷어냈다.

### 접지 위상을 앞걸음에 맞췄다

네 방향이 `_phase` 하나를 공유하므로 같은 위상에서 같은 발이 땅에 닿아야 한다.
기존 `Rabbit_Walk` 를 에디터에서 재서 얻은 값이다.

```
왼 허벅지 앞끝  위상 0.717
오른 허벅지 앞끝 위상 0.183   (정확히 반 주기 차이)
길이 1.167초 · 30fps
```

옆걸음도 같은 길이·같은 위상으로 구웠다.

### 좌우 두 벌인 이유

거울로 뒤집어 쓰면 **접지 위상까지 뒤집힌다**(0.183 → 0.817). 그러면 앞걸음과
섞을 때 발이 미끄러진다. 두 벌이면 가는 쪽 발이 제 위상을 지킨다 — 오른쪽은
오른발이 0.183, 왼쪽은 왼발이 0.717 에 딛는다.

### 굽기가 한 번 거부했다

왼쪽 클립에서 `L_Hand` 가 정지해 거부됐다(18개 중 1개). 팔을 고정값으로 뒀던
탓이다. 걸음에 맞춰 흔들도록 고쳤다 — **보기에도 팔만 굳어 보이던 것이 같이
고쳐졌다.** 굽기의 "안 움직이는 뼈" 가드가 또 값을 했다(616·628 에 이어 세 번째).

### 고르지 않고 섞는다

```csharp
float sideward = Clamp01(|Direction.x| - |Direction.y| * 0.35f);
_sideBlend = MoveTowards(_sideBlend, sideward, dt / 0.14f);
```

문턱으로 갈아끼우면 대각선(W+D)에서 딱딱 튄다 — 628 에서 점프를 둘로 나눴다가
"너무 둘로 나누니까 끊겨" 를 들은 것과 같은 실수다.

## 검증

| 무엇을 지키나 |
|---|
| 옆으로·대각선으로 가도 **애니메이션이 안 꺼진다** |
| 멈춰 있을 때는 여전히 안 켜진다 |
| 옆 자세가 앞 자세와 **다르다** (클립이 실제로 섞인다) |
| **좌우가 다른 클립**을 쓴다 |
| 앞→옆 · 대각선 · 옆→점프 전환에서 프레임당 각도가 문턱 아래다 |
| 팔이 몸보다 **늦게** 섞인다 |
| **아무리 빨리 떨어져도 자세가 안 얼어붙는다** |

`SideWalkTests` 10건 신규. 로코모션 관련 5개 스위트 **87건 전부 통과.**

### 기존 검사 둘을 고쳤다 — 둘 다 옛 전제를 잠그고 있었다

* `RabbitLocomotionTests.SidewaysMovementKeepsExistingSideStep` — "옆으로 가면
  가중치가 0" 을 단언했다. 이 이슈가 **일부러 바꾼 바로 그 동작**이라 반대로
  고쳐 적었다(이름도 바꿨다)
* `JumpAirTests.TheSameFallSpeedGivesTheSamePoseWhetherYouJumpedOrNot` — 30프레임
  창에서 봤는데, 팔을 0.40초로 늦추면서 뛴 쪽이 아직 못 따라잡는다. **60프레임으로
  늘렸다.** 이 검사가 지키는 것은 "같은 속도면 같은 자세로 모인다" 이지 "몇 프레임
  만에" 가 아니다

## 남은 것

* **눈으로 봐야 하는 것 둘** — `tanh` 로 바꾸면서 ±3.4 에서의 공중 자세가 덜
  벌어진다(1.00 → 0.76). 그리고 팔 블렌드 0.40초가 굼떠 보이는지
* 옆걸음 클립은 **시안 A(게걸음)** 그대로다. 실제 화면에서 보고 폭·속도를 조정할 수 있다
* 제자리 돌기·몸-카메라 사각은 손대지 않았다 — 조준·상호작용·멀티에 닿고
  기존 자기검사가 몸과 카메라의 각도를 32도로 잠근다
