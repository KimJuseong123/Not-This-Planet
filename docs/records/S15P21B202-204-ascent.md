# 발사 성공 상승과 임시 1장 완료 처리 (S15P21B202-204)

## 결론부터

성공 경로가 **깨져 있었다.** `LaunchTest.Tick` 의 첫 줄이 이랬다.

```csharp
if (State != LaunchState.Ramping || deltaTime <= 0f) return;
```

`Succeed()` 가 `State` 를 `Success` 로 바꾸는 순간 추력이 끊긴다. 우주선은
`LaunchLiftOffHeight`(1.5m) 만 뜨고 발사대로 다시 떨어졌다. 없는 기능이 아니라
**잘못 동작하는 상태**였다 — 용접까지 제대로 한 플레이어가 보는 것이 그것이었다.

기획 §22.5 는 "성공 후 약 8~10초 동안 우주선이 상승한다" 다.

## 상태를 하나 늘렸다

`Ramping → Ascending → Success` 로 바꿨다. 이제 **하중 시험 통과는 끝이 아니라
상승 시작**이다. `Success` 는 상승까지 끝난 1장 완료를 뜻한다.

`Succeed()` 를 `PassLoadTest()` 로 고쳐 이름이 실제로 하는 일과 맞게 했다.

상승을 다른 컴포넌트로 떼지 않았다. **추력을 주는 곳이 하나여야 한다** — 두 곳에서
같은 강체를 밀면 어느 쪽이 얼마를 주는지 알 수 없게 된다.

## 추력을 그냥 유지하면 안 된다

추력이 탑 무게의 `LaunchThrustRatio`(3.2배)다. 그대로 두면 순가속이 중력의 2.2배로
계속 붙어 9초에 60m/s 를 넘고 500m 이상 올라간다. 카메라가 따라갈 수 없고 지형이
순식간에 사라진다. 기획 §22.5 는 **상승 중에 카메라를 돌려 볼 수 있어야** 한다고
하므로 볼 수 있는 속도로 묶어야 한다.

```csharp
var weight = _towerMass * -UnityEngine.Physics.gravity.y;
var overspeed = _engine.linearVelocity.y - PhysicsScale.AscentMaxSpeed;
var extra = -overspeed * PhysicsScale.AscentSpeedDamp;
var thrust = Mathf.Max(0f, weight + _towerMass * extra);
```

상한을 넘으면 여유가 음수가 되어 무게 상쇄분에서 깎인다 — 그래서 속도가 상한
근처에 머문다. **상한에서 추력을 딱 끊지 않는다.** 끊으면 중력이 즉시 이겨 상승이
멈칫한다.

| 상수 | 값 | 이유 |
| --- | --- | --- |
| `AscentSeconds` | 9초 | 기획 "약 8~10초" 의 가운데 |
| `AscentMaxSpeed` | 12 m/s | 9초 × 12 ≈ 108m — 절벽과 배경 행성이 보이는 높이 |
| `AscentSpeedDamp` | 2 | 상한 근처에서 부드럽게 줄인다 |

### 엔진 질량이 아니라 탑 전체 질량

처음에 `_engine.mass` 로 무게를 상쇄했다. **틀렸다** — 엔진만 상쇄하면 위 세 파츠의
무게가 그대로 남아 우주선이 떨어진다. `Begin` 이 이미 총질량을 재고 있었으므로
`_towerMass` 로 보관해 쓴다.

## 완료는 상태와 이벤트만

```csharp
void Finish()
{
    State = LaunchState.Success;
    Completed?.Invoke(this);
}
```

대기권 컷신과 2장 로딩은 [Level]·[Network] 의 몫이다. 여기서 씬을 로드하면 그쪽
작업이 이 파일을 건드려야 하므로 **이벤트로 붙을 자리만** 만들었다.

**스테이지를 초기화하지 않는다.** 기획 §22.5 가 "별도의 장 사이 로비와 다시 준비하는
절차는 없다 … 참가자, 연결과 호스트 상태를 유지한 채 다음 장을 로딩한다" 고 정한다.

## 궤도 카메라 — 만들지 않았다

기획 §22.5 의 "상승 중에도 궤도 카메라를 자유롭게 회전하고 확대" 는 이미 된다.
플레이어가 S15P21B202-201 에서 모듈에 조인트로 붙어 있고 카메라는 플레이어를
따라가며, `SetVehicleView` 는 운반 장치 전용이라 켜지지 않는다.
`Ascent_CarriesThePlayerAlong` 이 플레이어가 20m 이상 함께 올라가는 것을 확인한다.

## 195 의 검증 두 개를 고쳤다

`WeldedTower_PassesTheLoadTest` 와 `SuccessfulLaunch_SealsJointsAgainstFurtherBreaking`
가 "하중 시험 통과 = `Success`" 를 전제했다. 통과가 이제 `Ascending` 이므로 기대값을
바꿨다. 값만 바꾼 것이 아니라 **판정이 끝나는 지점이 어디인지**를 주석으로 남겼다 —
그 뒤 9초 상승은 §22.5 의 연출이고 그 규칙이 볼 것이 아니다.

`SuccessfulLaunch_SealsJointsAgainstFurtherBreaking` 의 문서에는 이미 §22.3 "성공 상태
이후 상승 연출 중에는 접합부가 파손되지 않는다" 가 적혀 있었다. 195 가 상승을
예상하고 있었던 것이다.

## 이 이슈가 하지 않는 것

- 대기권 컷신과 2장 로딩 (§22.5, [Level]·[Network] — `Completed` 에 붙인다)
- 상승 화염·연기·사운드 ([Art]·[Sound])
- 완료 화면 UI ([UI] — `Ascent01` 을 쓰면 된다)
- 탑승 궤도 카메라 연출 (§22.2)
