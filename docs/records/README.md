# 작업 기록 (records)

코드로 남지 않는 작업의 결과를 한 장으로 남기는 곳입니다. 회의 결정, 실측·조사 결과, 사고 대응, 외부 도구(Figma·Notion 등) 작업 요약이 여기 옵니다.

## 파일 이름 규칙

```
<이슈키>-<slug>.md      예) S15P21B202-34-e2e-test.md
```

- **이슈키가 앞에 옵니다** — 어느 이슈에서 나온 기록인지 파일 목록만 보고 알 수 있어야 합니다.
- `slug` 는 영문 소문자와 하이픈. 짧게(2~4 단어).
- 한 이슈에서 기록이 여럿이면 slug 로 구분합니다: `-34-e2e-test.md`, `-34-e2e-followup.md`.

## 무엇을 적나

[templates/work-record.md](../templates/work-record.md) 틀을 씁니다. 핵심은 세 가지입니다.

1. **무엇을 했는지** — 다음 사람이 같은 일을 반복하지 않을 만큼
2. **무엇을 정했는지** — 결정과 그 이유. 나중에 "왜 이렇게 했지?" 의 답이 여기 있어야 합니다
3. **실측값** — 추측과 구분되게. 언제·어디서 측정했는지 함께

## 여기에 넣지 않는 것

- 팀 전체가 지키는 **규칙**은 `docs/*.md` 로 (여기는 "그때 그 일" 의 기록입니다)
- 코드 변경 설명은 MR 본문과 커밋 메시지로 (중복하지 않습니다)
- 테스트하며 만든 임시 파일 — 검증이 끝나면 지웁니다
