# 상호작용 동기화 규칙 (S15P21B202-149)

혼자 할 때 되던 것이 넷이 되면 안 되는 이유와, 새 기능을 만들 때 지킬 것.

## 왜 매번 문제가 되나

혼자 할 때는 **세계가 하나**다. 내가 부품을 밀면 그게 곧 정답이라 "누가 정하나" 라는
질문 자체가 없다.

넷이 되면 **세계가 다섯 개**다(서버 1 + 화면 4). 그러면 모든 기능이 이 질문을 받는다.

> 이 기능의 결과는 **누가 정하고**, 나머지는 그걸 **어떻게 아나**?

혼자용으로 짠 코드는 이 질문에 답한 적이 없다. "내 입력 읽고 → 세계를 바로 바꾼다" 로
되어 있어서, 넷이 되면 각자 다른 답을 내고 어긋난다. 2026-09-03 에 나온 문제들
(고정쇠·용접·탑승)은 새 버그가 아니라 **같은 누락이 파일마다 다른 얼굴로 나온 것**이다.

## 두 종류로 갈린다

| 종류 | 예 | 비용 |
| --- | --- | --- |
| **위치만 있는 것** | 부품, 운반체, 운석, 새 소품 | **공짜.** `WorldSync` 가 알아서 실어 나른다 |
| **상태가 있는 것** | 잡고 있음, 고정쇠 진행도, 용접 정도, 탑승 중 | **매번 작업** |

"상태" 는 좌표를 봐도 알 수 없는 것이다. 용접이 70% 됐다는 사실은 위치에 안 적혀 있다.

**소품을 추가하는 것은 이미 공짜다.** 값이 드는 것은 새 **메커니즘**을 추가할 때뿐이다.

## 새 기능을 만들 때 지킬 것

### 1. 카메라를 직접 보지 않는다

카메라는 각자 PC 에만 있다. 서버에 선 남의 몸에는 없다.

```csharp
// 하지 말 것 — 서버에서 조용히 다른 답이 나온다
if (Cam != null) { ... } else { /* 월드 축이나 머리로 대충 */ }

// 할 것 — 조준 창구로 묻는다
Vector3 origin  = AimOrigin;        // 카메라가 있으면 카메라, 없으면 클라이언트가 보낸 시작점
Vector3 forward = AimForward;
Vector3 move    = RelativeMove(input.Move);
```

이 규칙을 어긴 자리에서 나온 실제 증상:

| 어긴 곳 | 증상 |
| --- | --- |
| 서버가 카메라 없이 월드 +Z 를 앞으로 삼음 | 어느 키를 눌러도 +Z 로만 걸었다 |
| 탑승 후보를 `if (Cam != null)` 안에서만 찾음 | **참가자만 탈것에 못 탔다** |
| 고정쇠 끄는 방향이 월드 축으로 떨어짐 | 어디를 보든 같은 방향으로 끌렸다 |
| 도구 조준이 도구 자신의 forward 로 떨어짐 | 래그돌 손과 함께 흔들려 겨냥이 안 됐다 |

### 2. 판정은 서버, 화면은 따라만 간다

```
클라이언트: 요청(입력)만 보낸다
서버:       판정하고 결과를 만든다
클라이언트: 그 결과를 받아 그린다 — 스스로 같은 계산을 하지 않는다
```

같은 계산을 양쪽에서 하면 **겹치거나 어긋난다.** 실제로 참가자 화면이 스스로 용접해서
서버가 보낸 것과 겹쳐 두 배로 자랄 뻔했다. `WorldEvents.RemoteDecides` 가 참이면
그 화면은 그림이므로 세계를 바꾸지 않는다.

### 3. 상태냐 행동이냐를 고른다

| 보내는 것 | 언제 | 예 |
| --- | --- | --- |
| **상태** | 값이 적고 단순할 때 | 고정쇠 진행도(0~1) + 해제 여부 |
| **행동** | 상태가 크고 복잡할 때 | 용접 — (노즐 위치, 이번 스텝의 양) 만 보내고 각자 같은 동작을 재생 |

행동을 보내는 쪽이 되려면 **양쪽 세계가 이미 같아야** 한다. 부품 위치가 이미 맞춰져
있으니 같은 자리에서 같은 양만큼 자라면 같은 모양이 나온다.

### 4. 게임플레이는 Mirror 를 참조하지 않는다

`Metagame.Gameplay` 에 Mirror 를 들이지 않는다. 이 경계 덕분에 전용 서버에서 호스트
모드로 옮길 때 **물리 코드를 한 줄도 고치지 않았다**(-263).

네트워크가 알아야 하는 사건은 `Gameplay/WorldEvents.cs` 에 내놓고, 실어 나르는 일은
`Network/WorldSync.cs` 가 맡는다.

### 5. 기능이 섰다는 줄을 하나 남긴다

"에러 없이 기능만 없는" 증상은 로그가 비어 있는 것 자체가 유일한 단서다.
실제로 `WorldSync` 가 콜백을 못 받아 통째로 안 돌던 것을, 로그가 한 줄도 없다는
사실로 찾았다.

## 새 상호작용 만들 때 체크리스트

- [ ] 카메라(`Cam`)를 직접 보지 않는다 — `AimOrigin`·`AimForward`·`RelativeMove` 로 묻는다
- [ ] 결과를 정하는 곳이 서버 하나인가
- [ ] 그 결과가 다른 화면에 전달되는가 (상태 또는 행동)
- [ ] 클라이언트가 같은 계산을 또 하지 않는가 (`WorldEvents.RemoteDecides`)
- [ ] 양쪽이 같은 순서로 같은 것을 가리키는가 (위치가 아니라 계층 경로로 줄 세운다)
- [ ] 기능이 섰다는 로그가 한 줄 있는가

## 런타임에 NetworkIdentity 를 붙일 때

꺼진 채로 조립하고 마지막에 켠다.

```csharp
var go = new GameObject("...");
go.SetActive(false);                  // Awake 를 미룬다
go.AddComponent<NetworkIdentity>();
var sync = go.AddComponent<WorldSync>();
go.SetActive(true);                   // 여기서 한꺼번에 Awake
```

켜진 오브젝트에 붙이면 `NetworkIdentity` 가 **자기 밑의 NetworkBehaviour 목록이 빈 채로
굳어**, 뒤에 붙인 것은 `OnStartServer`·`OnStartClient` 를 영영 못 받는다.
2026-09-03 에 월드 동기화가 통째로 빠져 있던 원인이 이것이었다.
