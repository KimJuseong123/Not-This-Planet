# 661: 첫 고정못 공세와 독립 운석 낙하

## 작업 기준

- 브랜치: `S15P21B202-661-puzzle`, 기준 `7b69e1996f2a1c57c77fdaf7fa1e856749d9b388`.
- 워크트리: `.local-worktrees/661-puzzle`. 원격 브랜치를 fetch하여 같은 커밋임을 확인했다.
- Unity 6000.5.4f1 / Mirror. 화면 조작 없이 별도 프로젝트의 배치 테스트를 사용했다.

## 동작

- `Stage1Sequence.Tick`이 권위 있는 솔로/서버의 현재 씬 고정못을 확인한다. 처음 `IsReleased`가 되는 프레임에 공세 연출을 시작한다. 당기기 시작/부분 진행에는 발동하지 않는다.
- 주차대의 기존 `Stage1AssaultTrigger`는 씬 참조 보존용으로만 남는다. 충돌로 공세를 시작하지 않는다.
- 입장 연출 중 이미 해제된 고정못은 탐색 단계로 넘어갈 때 처리한다. 후속 해제는 공세를 반복하지 않는다. 개발용 컷신 재생 API는 유지한다.
- 기존 연출의 5초 경고/8초 종료 시점을 유지한다. 첫 해제 때 연출이 시작되고 5초 시점부터 강화된 스케줄을 사용한다.
- `Stage1Sequence.Configure`가 Stage1에만 독립 스케줄을 켠다. 스포너 오브젝트를 8개 복제하지 않고 하나의 관리자가 8개의 타이머를 관리하므로 기존 운석/흔적/네트워크 목록 소유권이 유지된다.
- 탐색에서는 타이머 1개, 공세에서는 8개가 동작한다. 모든 타이머는 최초 및 매 낙하 후 각각 1~5초를 새로 고른다. 솔로/2인/4인 모두 공세는 8개이다.
- 탐색 낙하는 기존 맵 생성 사각형 내 무작위 지점이다. 공세는 기존 플레이어 주변 비율(씬 기본 30%)로 플레이어를 선택하고, 나머지는 맵 무작위 지점이다. 기존 작업장/발사대 가중 낙하는 이 모드에서 맵 무작위에 합쳐진다.
- 플레이어 목표는 생성 시점의 수평 위치를 중심으로 반경 내 면적 균등 분포로 고르고 기존 지형 투영을 사용한다. 기본 반경은 5m이며 `MeteorSpawner`의 `_assaultPlayerTargetRadius`로 변경한다. 움직이는 플레이어를 추적하거나 정확한 위치에 강제 명중시키지 않는다.
- 쓰러진 플레이어를 제외하며 여러 명일 때 직전 대상과 다른 사람을 우선한다. 솔로/유효 대상 1명일 때도 계속 반경 내에서 선택한다.
- 동시에 살아 있는 운석은 최대 16개다(`_maxIndependentLiveMeteors`, 1~16). 기본 1194-byte 전송 크기에서 낙하 자세 16개는 기존 패킷 상한 안에 들어간다. 상한에 걸린 낙하는 건너뛰고 밀린 생성 요청을 쌓지 않는다.
- 발사 중 일시정지 및 입장 중 보류는 시계도 멈춘다. 기존 낙하/예고/흔적 수명 처리는 계속 기존 경로를 따른다. 시험장/고정 프리셋은 기존 묶음 스케줄을 유지한다.
- `MeteorClockBridge`가 서버/솔로만 Tick하고 클라이언트는 `WorldSync`의 예고/운석과 `Stage1SequenceSync`의 단계를 받는다. 클라이언트가 고정못 복제 상태를 받았다고 자체 공세를 시작하지 않는다.

## 검증

- Unity 6000.5.4f1에서 실제 런타임/네트워크/에디터/테스트 어셈블리를 컴파일했다. 마지막 컴파일에 C# 오류가 없다.
- 변경 전: 267개 중 261 통과, 6 실패. 변경 후 최종: 운석·고정못·컷신·신규 독립 스케줄·네트워크 직렬화/수신·WorldSync 테스트 총 298개 중 293 통과, 5 실패. 새 실패는 없다.
- 신규 `IndependentMeteorTests` 12개 모두 통과: 8개 시계의 1~5초 범위/비동기 분포/재추첨, 시드 재현/긴 프레임 폭주 방지, 1·2·4인 생성/예고/16개 상한, 일시정지, 맵 무작위/솔로 반경, 멀티 대상 교대/반경, 입장 중 해제, 옛 구역 트리거 비활성화, 권위/비권위 해제 및 중복 전환 방지.
- 남은 5개는 동일 기준 코드에서도 실패했다. `MeteorWavePresetTests.HeavyZone_StaysHalfOfWhateverRadiusIsInUse`는 None 기대에 Shockwave, `PartClampTests.Pull_TakesThePlannedTime`은 4.5초 기대에 약 1.124초, `Stage1CutsceneTests.SerializedAssaultMultiplierControlsInterval` 3개는 옛 30초 기대에 현재 10초를 받는다. 이 변경과 무관한 판정/이전 기획 기대값이므로 수정하지 않았다.
- 최초 추가 실패 1개는 축소 검증 프로젝트에 컷신 씬이 없던 환경 차이였다. 원래 씬과 렌더 설정/프로필/머티리얼을 보충한 뒤 `BothAuthoredScenesAreEnabledInBuild`도 통과했다. 빌드 가드나 실패 테스트를 비활성화하지 않았다.
- 화면 없는 실제 별도 프로세스의 솔로·호스트·원격 클라이언트·늦참자 모두 통과했다. 원격 클라이언트의 인증된 해제 요청으로 서버에서 공세가 시작되고, 클라이언트는 권위 운석을 자체 생성하지 않으면서 예고/운석 그림/해제된 고정못/전투 단계를 받았다. 최종 실행은 호스트 15:24:41, 클라이언트 15:24:43, 전투 단계 통과 후 늦참자 15:24:53(KST) 순서였다.
- 별도 작은 물리 씬을 사용하는 Windows Development 플레이어 빌드가 성공했다. 실제 Stage1 전체 배포 빌드를 의미하지 않는다.
- 원본 develop의 수정 중 에셋은 건드리지 않았으며 661의 씬/프리팹/프로젝트 설정 변경도 없다.

### 실행 증거 위치

원본 저장소 루트의 `.local-validation/661-meteors/`에 다음을 보존했다.

- `baseline.xml`, `baseline-run.log`: 변경 전 비교.
- `verified.xml`, `verified.log`: 최종 298개 테스트.
- `build-peer.log`: 최종 네트워크 검증용 플레이어 빌드.
- `harness/`: 별도 검증용 씬 빌더/런타임/인증된 테스트 Command 소스.
- `run-peers.ps1`: 화면 없이 솔로·호스트·클라이언트·늦참자를 실행하고 소유 프로세스를 정리하는 스크립트.
- `network-smoke.json`, `solo-verified.log`, `host-verified.log`, `client-verified.log`, `late-verified.log`: 최종 실제 프로세스 통신 결과.

멀티 하네스는 게임의 `WorldSyncInstaller`, `WorldSync`, `Stage1SequenceSync`, `MeteorClockBridge`를 그대로 사용한다. 원격 입력은 인증된 테스트 Command로 서버의 실제 `PartClamp.Pull`을 완료시킨다. 실제 손 조작/로비/완전한 Stage1 맵을 자동화한 검증과 구분한다.

## 남는 플레이 확인

- 실제 Stage1_Astra에서 솔로, 호스트, 원격 클라이언트 각각 첫 고정못을 뽑아 컷신/입력 복구를 확인한다.
- 네트워크 지연·손실 조건, 실제 4인 장시간 부하, GPU/물리 프로파일링, 조작감 및 시각 품질은 별도 확인 대상이다.
- 타이머의 평균 생성 시도는 공세에서 초당 약 2.67개이며 상한에 따라 실제 생성은 줄어든다. 측정 없이 성능 개선을 주장하지 않는다.
