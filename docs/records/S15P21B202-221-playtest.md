# 1장 플레이테스트 체크리스트 (S15P21B202-221)

[문서 안내](../README.md) → [작업 기록](README.md) → 검증·리뷰

1장 플레이테스트에 앞서 씬과 기획값을 검사하는 도구를 만들었습니다. 당시 지면 문제로 사람이 플레이할 수 없었던 원인, 항목별 판정과 점검 출력을 보관합니다.

본문의 “현재”, 검증 수치, 미완료 항목은 **기록 당시 기준**입니다. 후속 변경은 관련 이슈와 [주제별 색인](README.md)을 함께 확인합니다.

<a id="결론부터"></a>

## 변경 배경과 결과

**사람이 플레이하는 검증은 시작할 수 없었다.** 밟을 지면이 없다.

그 사실을 눈으로 찾지 않도록 QA 점검 도구를 만들었다. 지금 돌린 결과가 이 문서
아래에 그대로 붙어 있다 — 실패 4개가 전부 지면 하나에서 나온다.

## 왜 점검 도구부터 만들었나

기획 §26 의 14개 항목은 사람이 플레이해야 판정할 수 있다. 그런데 **플레이를
시작조차 못 하는 상태가 눈에 띄지 않게 만들어진다.** 2026-08-31 에 두 번 겪었다.

| 무엇 | 어떻게 숨었나 |
| --- | --- |
| `TD_Stage1_Arena.asset` 손상 → 지면 콜라이더 0개 | 빌드는 `Succeeded`, 실행해도 예외 없음. 화면을 봐야 알았다 |
| `MeteorSpawner._meteorPrefab`이 배치 도구를 돌릴 때마다 풀림 | 폴백 회색 구체로 조용히 대체됨(S15P21B202-200 에서 발견) |

둘 다 오류도 경고도 내지 않는다. 사람이 매번 같은 것을 눈으로 확인하는 대신,
**기계가 볼 수 있는 것**을 한곳에 모았다. 사람의 판정을 대신하지 않는다 —
사람이 판정을 시작할 수 있는지만 본다.

```
Unity.exe -batchmode -quit -projectPath METAGAME \
  -executeMethod Metagame.EditorTools.Stage1QaAudit.Run
```

실패가 있으면 종료 코드 1 이다. 메뉴에도 있다 — `Tools/둥실둥실 우주 대탈출/1장 QA 점검`.

## 기획 수치 대조 결과

플레이하지 않고도 볼 수 있는 부분이다. 12개 모두 기획값과 일치한다 — 아래 보고서
`기획 수치` 절에 값이 있다. 이 항목들이 어긋나면 플레이테스트에서 "느낌이 이상하다"
로 나오기 전에 여기서 잡힌다.

## 막고 있는 것 — 설정 변경이 필요하다

새로 클론해도 재현된다.

```
git cat-file -s <blob>  → 40772
stat -c%s <파일>        → 40773
```

`.gitattributes:4`의 `*.asset text`가 **바이너리** TerrainData를 텍스트로 다뤄,
체크아웃할 때 LF 하나가 CRLF로 바뀌며 1바이트 늘고 헤더가 깨진다. Unity가 못 읽어
`Terrain.terrainData == null`이 되고, `Stage1TerrainBuilder`가 옛 평면을 꺼 두었으므로
**밟을 콜라이더가 0개**가 된다.

고치는 방법:

```
METAGAME/Assets/_Project/Terrain/**/*.asset -text
```

`.gitattributes`는 모든 팀원의 체크아웃에 영향을 주므로 이 이슈에서 건드리지
않았다([Infra]/[Level]). 고친 뒤 이 점검을 다시 돌리면 실패 4개가 사라지는지로
검증할 수 있다.
