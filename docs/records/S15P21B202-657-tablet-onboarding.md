# S15P21B202-657 · 태블릿 안내가 진행도를 가리지 않게

처음 하는 사람에게 아무 말 없이 시켜 보니 여섯 가지를 못 했다.
**그중 다섯 가지의 원인이 하나였다.**

## 원인 — 안내가 막다른 길이었다

태블릿을 열면 안내 4쪽이 **덮개처럼** 얹히고, 그동안 진행도와 조작 안내는
아예 안 그려졌다.

```csharp
// Stage1TabletScreen.Refresh
if (RefreshGuidePage()) return;   // ← 안내가 켜져 있으면 나머지를 통째로 건너뛴다
```

빠져나오려면 확인 키(E)를 눌러야 했는데, 그 키는 **안내 화면 구석에만** 적혀
있었다. 그래서 진행도도 조작 안내도 못 봤다 — 조작 안내에는 버리기·엎드리기·
저중력장이 다 들어 있다.

| 관측 | 원인 |
|---|---|
| Tab 을 절대 안 눌러봄 | 신호는 계속 떠 있었다. **뜻을 몰랐다** — "TAB" 글자뿐, 동사가 없었다 |
| 버리는 법 모름 | 조작 안내 안에만 있고, HUD 키캡은 "던지기" 라고만 썼다 |
| 진척도 보는 법 모름 | 위의 관문 |
| 엎드리기 모름 | **조작 안내에 Z 가 없었다.** 616 에서 기능만 넣고 안내를 안 고쳤다 |
| 저중력장 모름 | F 가 어디에도 없었다 |
| *(읽다 발견)* 구조 키 오표기 | 태블릿은 `E … 동료 구조`, 실제는 **G**. HUD 는 G 로 맞게 썼다 |

## 고친 것

### A. 안내를 같은 쪽 줄에 합쳤다

**안내를 없앤 것이 아니다.** 처음 여는 사람이 보는 첫 화면은 그대로 안내 1쪽이다.
달라진 것은 거기서 **빠져나올 수 있다**는 것뿐이다.

* 마지막 안내에서 한 번 더 넘기면 진행도로 나간다 (`TabletGuideState.Move` 가
  나갔는지를 돌려준다)
* 진행도에서 앞으로 더 가면 안내로 되돌아온다 — **다시 보려고 판을 새로 시작하지
  않아도 된다**
* 두 번째부터는 진행도부터 열린다 (이미 있던 `Guide.Completed` 를 그대로 쓴다)
* 확인 키는 남겼지만 **관문이 아니라 지름길**이다. 문구에서 "확인" 을 뺐다

쪽 표시는 `●●●● | ● | ●●●` 로 세 덩어리를 끊는다. 여덟 개가 나란히 있으면
어디쯤인지 안 읽힌다.

### B. 안내를 한 곳으로 모으고 채웠다

**같은 목록이 세 군데 있었다.** 그래서 화면마다 다른 키를 가르쳤다.

| 어디 | 무엇에 쓰였나 |
|---|---|
| `Stage1TabletScreen` 배열 셋 | 태블릿 카드 |
| `Stage1TabletScreen.HelpText(page)` | **아무 데도 안 쓰였다** — `body` 라벨이 늘 꺼져 있다 |
| `Stage1ExplorationHud` 배열 셋 | IMGUI 카드 + **폰트 글자 수집** |

셋째가 함정이다. 안내에 새 글자를 넣고 글자 수집 목록에 안 넣으면 **네모로
깨진다.** 전부 `TabletHelpContent` 한 곳으로 모으고, 쓰이지 않던 사본은 지웠다.

**키 이름은 `Controls` 에서 읽는다.** 손으로 적으면 키를 바꾼 사람에게 안내가
거짓말을 한다 — 이 이슈가 고치는 것이 정확히 그것이다. 다만 `ToString()` 을
그대로 쓰면 `LeftShift` · `Escape` 가 되어 지금보다 읽기 나빠지므로
`Name(KeyCode)` 로 짧게 줄인다.

채운 것: **Z 엎드리기**(왜 쓰는지까지 — 폭풍을 피한다) · **F 저중력장** ·
**G 구조**(E 에서 분리) · **Q 짧게 = 버리기**("내려놓기" 로는 못 알아봤다).

카드가 9개였는데 G 를 더하면 10줄이 된다. **넘친 줄은 조용히 안 그려진다** —
12로 올리고 검사를 걸었다.

### C. 화면에서 바로 보이는 두 글자

* 왼쪽 신호: `TAB` → **`[Tab] 태블릿 열기`**. 동사가 있어야 명령으로 읽힌다
* 왼쪽 아래 키캡: `던지기` → **`버리기 · 길게 던지기`**
* 태블릿 키캡을 상시 표시로 바꿨다 (안내를 끝내면 사라지고 있었다)

## 검증

| 무엇을 지키나 |
|---|
| **확인 키 없이** 방향키만으로 진행도에 닿는다 |
| 조작 안내 세 쪽 전부에 넘겨서 닿는다 |
| 진행도에서 앞으로 가면 안내로 돌아온다 |
| 두 번째로 열면 진행도부터 뜬다 |
| **플레이어가 쓸 키 13개가 전부 안내에 있다** — 기능만 넣고 안내를 빠뜨리면 걸린다 |
| 구조가 제 키(G)로 적히고, 줍기 줄이 구조를 떠안지 않는다 |
| 엎드리기에 **쓰는 이유**(폭풍)가 적혀 있다 |
| 버리기가 "버리기" 라고 적혀 있다 |
| 키 이름이 `LeftShift` 가 아니라 `Shift` 다 |
| 한 쪽이 카드 수를 안 넘는다 |
| 안내의 모든 글자가 폰트 수집 목록에 있다 |
| 쪽 표시가 여덟 개 · 구분선 둘 · 현재 하나다 |

**기존 검사 하나를 고쳤다.** `TabletGuideTests.NavigationClampsAndDoesNotWrap`
이 "마지막 쪽에서 더 넘겨도 안 나간다" 를 잠그고 있었다 — 이 이슈가 일부러 바꾼
바로 그 동작이라, 뒤로 클램프는 남기고 앞으로는 나가는 것으로 고쳐 적었다.

## 남은 것

* **상황별 안내 한 줄**(운석이 떨어질 때 "몽둥이를 집으세요") — 새 표시 계층이라 별도
* **상황별로 해당 안내 쪽 열기** — 위와 짝이다
* **저중력장·엎드리기 안내 그림** — 아트
* **파츠가 너무 잘 밀리는 것** — 물리. 자유 파츠는 질량이 500 → 100kg 으로
  **의도적으로** 낮다(`FreePartMassScale`). 밀린 것이 자유 파츠였는지 놓인
  파츠였는지부터 재야 한다
* 미니맵 — 넣지 않기로 했다
