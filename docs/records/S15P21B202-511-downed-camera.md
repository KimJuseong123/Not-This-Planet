# S15P21B202-511 — 죽었을 때 3인칭이 참가자에게만 안 된다

> 2026-09-14 · 김주성(물리·퍼즐·캐릭터·상호작용·QA) · 브랜치 `S15P21B202-511-character`
>
> 기획 §10.1 1인칭 시점 · §10.3 기절 카메라 · `docs/parts.md`

---

## 1. 무엇이 문제였나

> "죽었을 때 3인칭으로 안보이는 문제. 호스트만 되고 다른 플레이어는 안된다"

---

## 2. 실측

프로브를 임시로 만들어 두 경로를 같은 방법으로 쟀다(조사용이라 커밋하지 않았다).

```
호스트(GoDown)          — DownedView False → True   Downed=True
호스트(Revive)          — DownedView=False          Downed=False
참가자(SetRemoteDowned) — DownedView False → False  Downed=True
참가자 상세             — Downed=True 구조지점=True 잡을지점=True DownedView=False FirstPerson=True
직접 호출               — SetDownedView(true) → DownedView=True
```

**셋째·넷째 줄이 결정적이다.** 참가자 쪽에서

- `Downed` 플래그는 **선다**
- 구조 지점·잡을 지점도 **켜진다**
- **카메라만 안 바뀐다**

그리고 다섯째 줄 — `SetDownedView` 를 직접 부르면 **바로 된다.** 카메라 쪽에 다른 조건은
없다. **"부르는 곳이 없다" 가 답이다.**

### 2-1. `-505` 와 뿌리가 다르다

| | 무엇이 빠졌나 | 실측에서 |
| --- | --- | --- |
| `-448` · `-505` | **전송 자체** | 플래그가 **거짓** |
| **이번** | **받은 뒤의 처리** | 플래그가 **참인데** 결과만 없다 |

같은 "호스트만 된다" 인데 고칠 자리가 다르다. **먼저 플래그가 참인지 보면 갈린다.**

---

## 3. 왜 이렇게 되는가 — 이미 적혀 있었다

`NetPlayer.ApplyDowned` 의 주석(S15P21B202-378)이 이 문제를 **명시적으로** 적어 두었다.

> 넉백·장비 해제·레이어·카메라는 여기서 하지 않는다. 그것들은 서버 권위이고
> `SetRemoteDowned` 도 손대지 않는다. **참가자 본인의 기절 카메라 전환은 이 이슈
> 범위가 아니다** — 원래도 없었고 따로 봐야 한다.

| 경로 | 무엇을 하나 |
| --- | --- |
| `GoDown()` | 넉백 · 장비 해제 · 레이어 · 지점 · 표시 · **카메라** |
| `SetRemoteDowned()` | 지점 · 표시 (**카메라 없음**) |
| 참가자의 자기 몸 | `ApplyDowned` → `SetRemoteDowned` (`isServer` 가 아니면) |

### 3-1. 넷을 한 묶음으로 다룬 것이 문제다

`-378` 은 **"넉백·장비 해제·레이어·카메라"** 를 한 줄에 묶어 "서버 권위" 로 다뤘다.

**셋은 맞고 하나는 틀리다.**

| | 서버 권위인가 | 왜 |
| --- | --- | --- |
| 넉백 | ✅ | 물리다. 두 곳에서 밀면 갈라진다 |
| 장비 해제 | ✅ | 세계의 상태다. 남도 본다 |
| 레이어 | ✅ | 충돌 판정이 달라진다 |
| **카메라** | ❌ | **각자 화면의 일이다. 남이 볼 일도, 서버가 알 일도 없다** |

카메라는 `-505` 의 빔이나 `-448` 의 게이지와 **같은 부류**다 — 그 기계에서 그 사람에게만
보이는 것. 서버 권위와 섞을 이유가 없었는데 같은 문장에 들어 있어서 함께 빠졌다.

## 4. 고친 것

**전환 규칙을 한 곳으로 모으고 세 경로가 모두 그것을 부른다.**

```csharp
void RefreshDownedCamera()
{
    if (Cam == null) return;        // 남의 몸에는 카메라가 없다

    Cam.SetDownedView(Downed, Downed ? Doll?.Head?.transform : null);
}
```

예전에는 `GoDown` 과 `Revive` 안에 `Cam.SetDownedView(...)` 가 **각각 인라인**으로 있었고
`SetRemoteDowned` 에는 아무것도 없었다. **흩어져 있었기 때문에 세 번째 경로를 만들 때
조용히 빠졌다.**

`RefreshDollVisibility()` 가 이미 그 세 경로에서 불리고 있다 — **새 구조가 아니라 옆에
같은 모양을 하나 더 둔 것**이다.

### 4-1. 남의 몸은 저절로 걸러진다

`PlayerRig.Cam` 은 `SpaceBootstrap` 이 **로컬 플레이어 하나에만** 붙인다
(`SpaceBootstrap.cs:261`) — 원격 몸의 `Cam` 은 `null` 이다. 그래서 "내 것일 때만" 같은
조건을 따로 두지 않았다.

**그 전제가 깨지면 조용히 틀리는 것이 아니라 터진다** —
`ABodyWithNoCameraDoesNotThrow` 가 그 자리를 잠근다.

### 4-2. 켜는 것과 끄는 것 둘 다다

`Revive` 도 참가자에서 돌지 않는다. **한쪽만 고치면 참가자는 살아나도 3인칭에 갇힌다** —
§10.3 "구조되면 1인칭으로 돌아온다" 가 깨진다.

### 4-3. 고르지 않은 안

| 안 | 판단 |
| --- | --- |
| `SetRemoteDowned` 에만 `Cam.SetDownedView` 를 추가 | **기각.** 전환 규칙이 세 곳(인라인 둘 + 여기)이 된다. 흩어져 있던 것이 이 결함의 원인인데 더 흩는 것이다 |
| 카메라 상태를 전송 | **기각.** 카메라는 각자 화면의 일이다. 보낼 이유가 없고 `-505` 와 성격이 다르다 |
| `NetPlayer` 에서 카메라를 만진다 | **기각.** 네트워크 계층이 표현을 직접 만지면 의존 방향이 뒤집힌다 — `SetRemoteDowned` 주석이 레이어에 대해 같은 말을 한다 |

## 5. 파트를 `[Character]` 로 정했다 — `[Network]` 이 아닌 이유

담당자가 물었다: **"이거도 네트워크인거 아니야? 호스트는 원하는 대로 되잖아."**

**증상만 보면 맞는 말이다.** 그런데 리포지토리에 거의 같은 이슈가 있고 거기서는
`[Character]` 로 갔다.

> **`-305`** — "운반체에 탑승한 사람의 몸이 **남의 화면에서** 보이는 것을 고친다" →
> 브랜치 `S15P21B202-305-character`

멀티 화면 결함이고, 호스트/참가자가 갈리고, **`NetPlayer.cs` 를 37줄 만졌는데도**
Character 였다. 그 37줄이 SyncVar 훅과 `ApplyRiding` → `SetRemoteRiding` 배선 —
**받은 값을 표현에 적용하는 일**이고 이번 건과 같은 모양이다.

| | `-505` (UFO 빔) | 이번 (기절 카메라) |
| --- | --- | --- |
| 값이 내려오나 | **안 내려옴** | **잘 내려옴** |
| 할 일 | `WorldSync` 에 `FieldState` **신설** | 이미 오는 값으로 **카메라를 바꾼다** |
| `Runtime/Network/` 변경 | 있음 | **0개** |

`docs/parts.md` 가 `[Network]` 를 "세션, **동기화**, 매치메이킹" 으로 정의하는데
**동기화 자체는 잘 돌고 있다.**

> **반대 논리도 적어 둔다.** `SetRemoteDowned` 는 동기화 프로토콜의 "받는 쪽" 이고,
> 그것이 `GoDown` 의 불완전한 거울이라는 것이 근본 원인이다. "그 둘을 짝으로 유지하는
> 것은 동기화 담당의 일" 로 보면 `[Network]` 도 말이 된다. **팀이 "참가자 화면 결함은
> Network 버킷" 으로 운영한다면 그 규칙이 맞다** — 제목과 브랜치만 바꾸면 된다.

## 7. 남은 것

- **2인 이상 실제 멀티 확인이 아직이다.** EditMode 는 `SetRemoteDowned` 를 직접 불러
  참가자 상태를 **재현**한 것이고 두 프로세스를 띄운 것이 아니다. 봐야 하는 것:
  1. 참가자가 죽으면 **자기 화면이 3인칭으로 바뀐다**
  2. 구조되면 **1인칭으로 돌아온다**
  3. **기절 5초 뒤 물러나는 연출**(`-259` · `DownedFirstPersonSeconds`)이 참가자
     화면에서도 도는가 — `OrbitCamera` 가 자기 `downedSeconds` 로 세므로 `downedView`
     가 켜지면 따라올 것으로 보이지만 재야 한다
  4. 호스트 쪽에 회귀가 없다
- **`GoDown` 의 나머지 셋(넉백·장비·레이어)은 건드리지 않았다.** `-378` 의 판단이 맞다.
- **파트 태그는 담당자 판단이 남아 있다**(§5).
