# S15P21B202-250 파츠를 손으로 민다

## 무엇을

파츠에 닿은 상태로 파츠 쪽으로 걸어가면 밀린다(기획 §13). 별도 버튼이 없다.

## 접촉은 이미 물리적으로 실재했다

충돌 매트릭스를 읽었다. Player(6) ↔ Part(9) = **1** — 실제로 부딪힌다.

§13.1 의 "파츠에 닿은 상태" 를 위해 새 트리거를 만들 필요가 없었다.
S15P21B202-249 에서 겪은 마스크 문제가 여기서는 없다.

이동 입력도 이미 있었다 — 다만 `MovementDirectionLocal` 은 **실제 속도를 우선하는 로컬
좌표**라 쓸 수 없었다. 500kg 짜리 파츠에 막혀 제자리걸음일 때도 "파츠 쪽으로 밀고 있다"
는 것을 알아야 한다. `PlayerRig.MoveWish`(월드 수평 의도)를 공개했다.

## 가장 미묘한 부분 — 운석과의 간섭

§13.2 는 1명이 밀 때 **0.4m/s** 를 요구한다. `PhysicsScale.PartMass` 가 500kg 이므로
힘을 그때그때 주는 것으로는 표를 맞출 수 없다 — **속도를 몰아야** 한다.

그런데 §13.2 의 마지막 줄이 "운석 충격은 플레이어의 밀기보다 **훨씬 강한 힘**을
적용한다" 다. 운석은 `AddExplosionForce` 로 충격량을 넣는데(S15P21B202-247), 밀기가 매 틱
속도를 목표값으로 덮으면 **그 충격량이 사라진다.**

```csharp
var along = Vector3.Dot(horizontal, PushDirection);
if (along >= top) return;   // 이미 더 빠르다 — 건드리지 않는다

var add = Mathf.Min(PhysicsScale.PartPushAccel * deltaTime, top - along);
_body.linearVelocity = velocity + PushDirection * add;
```

**목표보다 느릴 때만 가속한다.** 그리고 미는 방향 성분만 더한다 — 수직 속도와 직각
성분을 건드리지 않으므로 떨어지는 파츠를 밀어도 위로 뜨지 않는다.

### 감쇠에도 같은 함정이 있었다

§13.2 "아무도 밀지 않으면 약 1초 동안 관성이 줄어든 뒤 정지" 를 **무조건** 걸면 운석에
날아간 파츠도 1초 만에 멈춘다.

```csharp
if (horizontal.magnitude > _lastTopSpeed * PhysicsScale.PartPushForeignSpeedFactor)
{
    _pushedRecently = false;
    return;
}
```

§13.2 가 말하는 관성은 **밀어서 생긴 것**이다. 마지막으로 민 목표 속도의 1.5배를 넘으면
밀린 것이 아니라 맞은 것으로 본다.

검증 두 개가 이것을 잠근다 — 미는 중에 운석에 맞은 경우와, 감쇠 중에 운석에 맞은 경우.

## 표를 식으로 바꾸지 않았다

```
1명 0.4  ·  2명 0.8  ·  3명 1.2  ·  4명 1.5   (m/s)
```

**선형이 아니다** — 1·2·3명은 0.4씩 오르는데 4명은 0.3만 오른다. 식으로 바꾸면 기획이
정한 값이 아니라 내가 정한 값이 된다. `MeteorWaveTable` 이 §17.4 를 표로 둔 것과 같은
방식이다(S15P21B202-234).

표를 넘는 인원은 마지막 값으로 묶는다. 인원을 제한하려는 것이 아니라 **표에 없는 값을
만들어내지 않기** 위한 것이다.

## 시작과 종료 (§13.1)

| 조건 | 값 | 이유 |
| --- | --- | --- |
| 시작 | 파츠 쪽 이동 **0.2초** | §13.1 "스쳐 지나가는 접촉으로 발동하지 않도록" |
| 종료 | 입력 멈춤·접촉 끊김 뒤 **0.5초** | 0이면 걸음이 한 틱 끊길 때마다 파츠가 덜컥거린다 |
| 방향 | 이동 입력과 파츠 방향의 내적 ≥ 0.5 (60도) | §13.1 "당기기는 제공하지 않으며" |
| 접촉 | 콜라이더 최근점까지 **0.6m** | 아래 |

**접촉 콜백을 쓰지 않는다.** 인형은 뼈가 열두 개라 어느 뼈가 닿았는지에 따라 판정이
흔들리고, 밀기는 **몸으로 미는 것**이지 손가락이 스치는 것이 아니다. 골반에서
콜라이더의 가장 가까운 점까지의 거리로 잰다.

## 어느 상태를 미나

| 상태 | 밀리나 | 근거 |
| --- | --- | --- |
| `Locked` | 아니오 | 고정쇠로 박혀 있다. "운석에 맞아도 움직이지 않는다" |
| `Free` | **예** | 풀렸고 아직 안 들렸다 |
| `Carried` | 아니오 | 견인 빔이 잡고 있다 |
| `Placed` | **예** | §13 이 노리는 상태다 |
| `Welded` | **아니오 — 보류** | 아래 |

`Welded` 를 미는 것은 **탑 전체를 미는 것**이다. `ShipAssembly:57` 에 이미
"누가 탑을 밀어 구역을 벗어나거나 기울면 탑승이 다시 막혀야 한다" 는 주석이 있어
**누군가 밀리는 것을 전제해 두었다.** §22.1 이 "완성된 탑이 중앙 발사 구역 안에 있다" 를
탑승 조건으로 두므로 의미도 있다.

다만 수백 kg × 4를 0.4m/s 로 미는 것이 맞는지는 기획 판단이라 이 이슈에서 제외했다.
검증 하나가 그 결정을 명시적으로 잠근다 — 나중에 열 때 그 검증을 고치게 된다.

## 남긴 것

- **`Welded`(탑 전체) 밀기** — 위 이유로 기획 판단 대기다
- **밀기 자세**(§13.1 "양손을 대고 몸을 기울여") — 넣지 않았다. `ToolBase.CarryAim`
  (S15P21B202-243)과 같은 방식으로 만들 수 있지만, 자세는 보이는 것이고 밀기가
  실제로 동작하는지를 먼저 인게임에서 봐야 한다
- 파츠를 **들어 올리는** 것 — §13 은 "민다" 뿐이다
- 소리 — `AudioSource` 사용처가 0곳이다([Sound])

## 인게임 확인은 못 했다

빌드가 develop 에서 멈춘다(지형 자산 체크아웃 손상 + 로비 씬 Volume Profile 누락).

`PartPushContactDistance` 0.6m 로 실제 파츠 옆에 서서 밀 수 있는지, 500kg 이 0.4m/s 로
움직이는 것이 "민다" 로 느껴지는지는 인게임에서 봐야 한다.
