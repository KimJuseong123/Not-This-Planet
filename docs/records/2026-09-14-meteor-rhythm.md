# 운석 방망이 타이밍 가이드

- 방망이를 실제로 들고 있는 로컬 플레이어가 낙하지점의 타격 보조 반경 안에 들어오면 기존 GameHud에 준비 안내와 타이밍 바가 표시된다. 무장 해제, 기절, 탑승, 메뉴/태블릿 표시, 엔딩 중에는 숨긴다.
- 낙하 예고 중에는 준비 안내만 표시한다. 운석 생성 후에는 중력·속도·지면 높이로 남은 시간을 예측하여 바를 움직인다. 겹치는 운석은 가장 먼저 떨어질 것을 선택한다.
- 기존 좌클릭 입력과 서버 판정을 사용한다. 기존 타격 창 안의 입력은 GOOD, 창의 60% 시점을 기준으로 오차 20% 이내는 GREAT, 8% 이내는 PERFECT다. 발사 속도는 기존 대비 1 / 1.35 / 1.8배이며 결과 문구와 짧은 회전 흔들림을 표시한다. 조준·이동 방향은 흔들지 않는다.
- 헛스윙은 기존 재사용 대기를 유지하고 운석은 계속 떨어진다. 방망이 소지 여부로 피격을 면제하지 않는다. 직접 충돌은 기존 GoDown(기절), 주변 충격파는 기존 거리별 넘어짐 처리를 유지한다. 실패 즉시 강제 기절시키지는 않는다.
- 이미 쳐낸 운석과 착지한 소품은 가이드/운석 타격 대상에서 제외한다. 일반 소품 밀기와 동료 타격은 기존 경로를 유지한다.
- WorldSync 도구 스냅샷은 결과 번호·등급·재사용 대기를 전달한다. 낙하 스냅샷은 지면 높이·무해 여부·타격 창·보조 반경을 추가로 전달한다. 클라이언트 가이드는 판정 없는 ghost 목록을 사용하며, 실제 타격은 서버가 처리한다. 서버와 클라이언트 모두 같은 버전이 필요하다.
- TryPredictImpact는 읽기 전용으로 바꾸어 HUD 조회가 비활성 네트워크 운석을 Meteor.All에 등록하거나 직접 충돌 이력을 초기화하지 않도록 했다.

## 설정

씬·프리팹·입력 설정 작업은 필요 없다. 기존 MeteorTuning의 BatSwingWindowSeconds / BatAssistRadius를 사용한다. 등급 기준과 속도 배율은 MeteorBat에서 조정한다.

## 검증

Unity 6000.5.4f1 격리 검증 프로젝트에서 전체 스크립트 컴파일 및 Mirror 후처리가 완료됐다. 운석·네트워크 EditMode 153개와 카메라 회귀 44개, 총 197개가 통과했다. 결과는 tmp/meteor-rhythm/final-results.xml 및 camera-results.xml에 기록했다. 화면 구성, 실제 타격감, 네트워크 지연이 있는 2인 플레이는 직접 플레이로 추가 확인해야 한다. 클라이언트가 별도의 성공 결과를 예측하거나 지연 보상 판정을 수행하지는 않는다.
