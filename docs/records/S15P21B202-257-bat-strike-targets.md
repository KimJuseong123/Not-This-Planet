# S15P21B202-257 방망이 타격 대상을 금지 목록 방식으로 바꾼다

## 기획이 금지한 것은 한 줄뿐이다

§18.3 전문이다.

> - 방망이로 다른 플레이어를 직접 때릴 수 있다.
> - 약하게 스치면 휘청이고 정면으로 맞으면 넘어지지만 기절하지는 않는다.
> - **장비를 떨어뜨리게 하거나 파츠와 용접부에 피해를 주지는 않는다.**

마지막 줄이 금지의 전부이고 두 가지를 말한다.

1. **맞은 플레이어가 장비를 놓지 않는다** — 플레이어 타격의 부작용에 대한 규정
2. **파츠와 용접부에 직접 피해를 주지 않는다**

## 그 문장을 과하게 읽었다

S15P21B202-245 에 이렇게 적어 두었다.

```csharp
/// <summary>기획 §18.3 "장비를 떨어뜨리게 … 하지는 않는다" 를 넓게 읽었다.</summary>
[Test] public void ADroppedTool_IsNotPushed()
```

**"바닥에 굴러다니는 용접기를 못 때린다" 로 읽은 것이 틀렸다.** 원문은 §18.3 의 문맥
그대로 "다른 플레이어를 때렸을 때 그 사람이 들고 있는 장비를 놓게 하지 않는다" 다.
내려놓은 도구를 밀치는 것과는 아무 관계가 없다.

## 그래서 접근이 뒤집혀 있었다

245 는 **허용 목록** 방식이었다.

```
GameLayers.PropMask 로 찾고
  ToolBase 를 빼고            ← 근거 없음 (위 과잉 해석)
  SpaceshipPart 를 빼고        ← §18.3 맞음
  TransportVehicle 을 뺀다     ← §14.5 맞음
```

결과는 인게임에서 **아무것도 안 맞는 것**이었다(2026-09-02 확인). 씬의 Prop 레이어
Rigidbody 는 용접기 · 방망이 자신 · 견인 운반체뿐이고 셋 다 제외 대상이었다.

## 금지 목록 방식으로 바꿨다

빼는 이유가 둘뿐이다.

```csharp
bool CanPush(Rigidbody body)
{
    // 밀릴 수 없는 것은 물리적으로 대상이 아니다.
    if (body == null || body.isKinematic) return false;

    // 들고 있는 이 방망이. 자기를 때리는 것은 어느 경로로도 일어나면 안 된다.
    if (body == Body) return false;

    // §18.3 "파츠와 용접부에 피해를 주지는 않는다". 비드는 파츠의 자식이므로
    // 부모에서 함께 걸린다(S15P21B202-226).
    if (body.GetComponentInParent<Parts.SpaceshipPart>() != null) return false;

    // §14.5 "마지막 우주선 파츠이기도 하다". 사람이 타고 있을 수도 있다.
    if (body.GetComponentInParent<Parts.TransportVehicle>() != null) return false;

    return true;
}
```

`ToolBase` 제외를 지우고 **자기 자신만** 막았다. 휴대 중에는 충돌이 꺼져 있어
(S15P21B202-237) 어차피 검색에 걸리지 않지만, 규칙으로도 막아 두는 편이 맞다.

## 레이어도 넓혔다

`GameLayers.PropMask` 하나만 보던 것을 `BatStrikeMask` 로 바꿨다.

```csharp
public const int BatStrikeMask =
    ~((1 << Player) | (1 << PlayerDowned) | (1 << Meteor)
      | (1 << Part) | (1 << PartCarried)
      | (1 << Interactable) | (1 << BeamQuery));
```

| 빼는 것 | 이유 |
| --- | --- |
| Player · PlayerDowned | 동료 타격은 별 경로다(§18.3) — `FindPlayer` |
| Meteor | 운석 반사도 별 경로다(§18.1) — `FindTarget` |
| Part · PartCarried | §18.3. 비드는 파츠와 같은 레이어(`go.layer = gameObject.layer`)라 함께 빠진다 |
| Interactable · BeamQuery | 물리 충돌이 없는 질의 전용 레이어다 |

남는 것(지면 · 자연물 포함)은 `CanPush` 가 Rigidbody 로 다시 거른다 — **조준한 쪽에
움직일 것이 없으면 헛스윙**이 되는 것이 맞다. 검증이 그것도 잠근다.

`SurfaceMask`(S15P21B202-254)와 같은 방식이다. 레이어 하나로 가르는 것이 아니라
"빼는 것을 적는다".

## 이제 때려지는 것

| 무엇 | 근거 |
| --- | --- |
| 떨어지는 운석 | §18.1 — 주 용도 |
| 다른 플레이어 | §18.3 "직접 때릴 수 있다" |
| **내려놓은 용접기·방망이** | 금지 근거가 없었다 — 과잉 해석을 되돌렸다 |
| 해제된 고정못 | 뽑아 던져 둔 못이다 |
| **Prop 레이어 밖의 움직이는 물체** | 예전에는 찾지 못했다 |

**씬에 새 자산을 놓지 않았다.** 규칙을 고치는 것만으로 이미 씬에 있는 용접기 · 방망이 ·
해제된 고정못이 대상이 된다. 화물 상자 추가는 별 이슈로 남긴다.

## 플레이어 타격을 처음으로 잠갔다

§18.3 은 플레이어 타격을 허용하고 S15P21B202-233 에서 구현했는데 **인게임에서 확인된 적이
없다** — 솔로 플레이에서는 확인할 수 없다. `FindPlayer` 가 `PlayerRig.All` 을 훑고 자기
자신을 뺀다.

그리고 §18.3 의 첫 번째 금지가 위험한 자리에 있다. S15P21B202-247 이
`PlayerRig.DropEquipment()` 를 공개했고 그것이 `KnockDown` **바로 옆**이다 — 나중에 딸려
들어가기 쉽다. 검증으로 막았다.

## 검증 14개 추가 (기존 1개 뒤집음)

| 묶음 | 무엇 |
| --- | --- |
| 뒤집은 것 | **내려놓은 도구가 밀린다** (245 의 `ADroppedTool_IsNotPushed` → `_IsPushed`) |
| 새로 때려지는 것 | 내려놓은 다른 방망이 · **Prop 레이어 밖 물체** |
| 안 때려지는 것 | **자기 자신** · Rigidbody 없는 자연물은 **헛스윙** |
| 마스크 | 파츠·플레이어·운석·질의 레이어 제외 · Prop·Default 포함 |
| **플레이어 허용**(§18.3) | 정면이면 넘어짐 · 뒤쪽 안 됨 · 사거리 밖 안 됨 |
| **플레이어 금지**(§18.3) | **기절하지 않음** · **장비를 놓지 않음** · 열 번 맞아도 기절 안 함 · 자기 자신 안 맞음 |
| 우선순위 | 운석 > 동료 > 소품 |

전체 588개 중 575 통과. 실패 13개는 develop 에 이미 있던 것이다(S15P21B202-232 건).
574 + 14 = 588 — **늘어난 실패가 없다.**

## 배운 것

**기획 문장을 넓게 읽으면 기능이 죽는다.** 245 에서 "넓게 읽었다" 고 주석까지 달아
놓았는데, 그 넓힘의 결과가 "씬에서 아무것도 안 맞음" 이었다. 근거가 애매할 때는 **좁게
읽고 금지를 명시하는 편**이 안전하다 — 금지 목록은 나중에 늘릴 수 있고, 허용 목록은
줄어든 것을 눈치채기 어렵다.
