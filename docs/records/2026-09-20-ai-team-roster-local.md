## 구현 범위

Mirror 게임 세션에서 사람 1/2/3/4명에 AI 3/2/1/0명을 채운다.
서버 소유의 기존 `PF_NetPlayer`를 사용하고 이름/자리/AI 구분을 SyncVar로 전달한다.
몸과 자세, 색, 이름표는 기존 플레이어 경로를 재사용한다. 이번 AI는 **대기만** 한다.

- 사람은 몸 생성 전부터 자리를 예약한다. 접속하면 해당 자리 AI를 제거한다.
- 사람이 나가면 5초 후 AI로 채운다. 사람이 전부 나가면 AI도 정리한다.
- 복귀 자리는 보존하되, 실제 빈자리는 새 사람이 재사용할 수 있다. 5번째 동시 사람은 거절한다.
- 컷신/호스트 이전 중에는 생성하지 않는다. 사람 주변의 정적 바닥/여유 공간을 확인해 생성한다.
- 안전한 자리가 없으면 재시도하며 경고한다. 벽/낭떠러지에 강제 배치하지 않는다.
- 대기 AI가 인간 전원 기절 복구를 막지 않는다.

## 범위 밖

음성/LLM/추종/도구/모델 다운로드, 같은 몸·장비를 유지하는 조종자 교체,
AI 위치·행동의 호스트 이전 보존, 엔딩 출연 명단 확장, 백엔드 방 정책 변경은 포함하지 않는다.
씬/프리팹/기존 물리 코드는 수정하지 않았다.
네트워크를 시작하지 않은 에디터 솔로 실행에는 AI가 생기지 않는다.

추가 사람은 서버 actor로 모사한다. 실제 두 프로세스 검사를 대체하지 않는다.
초기 SyncVar 직렬화와 호스트 재시작도 검사한다.
최종 배치 검사: **22개 통과, 실패 0개** (2026-09-20).

MCP 테스트 상태는 도메인 재로드 이후 실행 중으로 남는 문제가 있어 Unity 기본 배치 결과로 확인했다.
실제 다중 클라이언트의 수신·시각 검사, Windows 빌드 검증은 추가 필요하다.
2026-09-21 사용자와 친구의 빌드 2인 테스트에서 참가, 퇴장 후 AI 대체, 재접속 성공을 확인했다고 보고받았다.
이는 사용자 수동 검증 기록이며, 에이전트가 두 클라이언트 화면/빌드 로그를 직접 검사한 결과는 아니다.
호스트 이전, 서로 다른 네트워크 지연 조건, 장시간 반복 접속은 아직 검증하지 않았다.

## MCP / 실행

사용자 요청으로 Package Manager에서 Coplay MCP for Unity v10.0.0을 설치했다.
manifest/lock 변경은 개발 도구 설정이므로 나중에 게임 기능 MR과 별도로 검토한다.
기존 Codex의 `unityMCP` 주소 `http://127.0.0.1:8080/mcp`를 재사용한다.
임시 설치 스크립트는 제거했다. 유료 API/AI 모델은 사용·다운로드하지 않았다.

Unity 6000.5.4f1로 이 저장소의 `METAGAME`을 연다.
기존 Lobby에서 방을 만들고 호스트로 게임을 시작하면 컷신 후 빈자리 AI가 생성된다.
Stage1에서 Play만 누르는 오프라인 실행과는 구분한다.

## 다음 단계 — 방장 기준 AI 사용 정책

- 방장의 사용 선택과 실행 준비 상태를 분리한다. 모델 파일 유무만으로 준비 완료로 판단하지 않는다.
- 방장이 사용을 켰고 런타임 준비가 완료됐을 때만 빈자리를 AI로 채운다.
- 미설치/준비 중/실패 상태에서는 사람들만 플레이할 수 있어야 한다.
- 참가자는 모델 설치 없이 방장의 AI를 본다. 참가자에게 모델이 있어도 자동으로 실행 책임을 넘기지 않는다.
- 방장 이전 시 새 방장의 준비 상태를 재평가한다. 설정과 실제 활성 상태를 혼동하지 않는다.
- 현재는 행동 런타임이 없으므로 가짜 Ready 상태를 배포 경로에 넣지 않는다.
- 검사용 대기 AI 생성 모드가 필요하면 일반 AI 사용과 명확히 구분하고, 배포 기본값으로 켜지 않는다.
- 이후 모델 준비/다운로드, 이동/작업 행동 구현을 이 정책에 연결한다. 이번 체크포인트에는 해당 구현이 없다.
