# 609 캐릭터 치장템

작업 브랜치: `S15P21B202-609-art`, 기준 `88f8c334`.
작업 위치: `.local-worktrees/609-art`. Unity 6000.5.4f1 / URP.

## 구성

기존 단순 도형 장식 4종을 Blender 모델로 교체하고 8종을 추가한다.
토끼 우주복의 밝은 바탕, 보라색 포인트에 어울리는 탐사 장비와 작은 기념 배지로 구성했다.
얼굴을 덮는 마스크나 큰 모자 대신 귀 주변의 작은 장식을 선택했다.
의상·망토·배낭은 현재 목도리·등 장비 및 래그돌 변형과의 간섭 검증이 더 필요해 이번 범위에 넣지 않았다.

| 번호 | 머리 장식 | 가슴 장식 |
| --- | --- | --- |
| 0 | 없음 | 없음 |
| 1 | 탐사 안테나 | 탐사 배지 |
| 2 | 통신 헤드셋 | 쌍별 배지 |
| 3 | 탐조등 | 토성 배지 |
| 4 | 별 더듬이 | 로켓 배지 |
| 5 | 새싹 | 구조대 배지 |
| 6 | 궤도 핀 | 비행기록 배지 |

5색 × 머리 7개 × 가슴 7개 = 245개 조합. 장식은 능력치나 조명 기능을 추가하지 않는다.

## 파일과 재생성

- FBX 12개와 각 `.fbm/Palette.png`: `METAGAME/Assets/_Project/Models/Characters/Cosmetics609/`.
- Unity 재질과 메타도 같은 모델 폴더. Resources 프리팹: `Assets/_Project/Prefabs/Resources/Cosmetics609/`.
- Blender 원본 및 실제 모델 렌더: `docs/assets/concepts/cosmetics609/`. AI 컨셉아트가 아니라 실제 모델의 렌더다.
- 제작 소스: `tools/art/build_609_cosmetics.py`. Blender MCP의 Python 실행으로 제작했다.
- Unity 메뉴 `Metagame > Art > Rebuild 609 Cosmetics` 또는 `Metagame.EditorTools.Cosmetics609Builder.Build`로 프리팹과 재질을 재생성한다.
- 모든 장식은 하나의 메시와 하나의 팔레트 텍스처 재질. 삼각형 수는 `catalog.json`에 기록한다.

## 런타임 연결과 호환성

`CustomizationData`의 이름 배열을 확장하여 기존 스크롤 선택 화면에 자동 표시한다.
`PlayerAppearance`는 선택된 Resources 프리팹을 머리 또는 가슴의 `Prim.DecoRoot` 아래에 생성한다.
부모 스케일 보정, 레이어 전파, 숨김 및 그림자 전용 상태 재적용을 유지한다. 콜라이더·강체는 추가하지 않는다.
재질은 기존 `CharacterSuitTint` 셰이더를 사용하며 캐릭터의 안개 제외 정책을 따른다.

기존 `appearance.v2`의 색상·머리·배지 하위 비트를 유지하고 사용하지 않던 비트 7/8에 새 번호의 상위 비트를 넣는다.
기존 45개 조합의 정수 값은 바뀌지 않으며 v1 색상 마이그레이션도 유지한다.
신규 장식 동기화에는 같은 버전의 클라이언트/서버가 필요하다. 구버전과의 혼합 실행은 지원하지 않는다.

## 검증

Blender 렌더로 팔레트 UV와 실제 토끼 모델 장착 위치를 확인했다.
Unity의 실제 토끼 모델 장착 렌더도 확인했다: `docs/assets/concepts/cosmetics609/unity-lineup.png`.
격리된 배치 에디터에서 `Metagame.EditorTools.Cosmetics609Builder.CaptureLineup`으로 다시 렌더할 수 있다.
Unity 6000.5.4f1 배치 임포트·컴파일 및 12개 Resources 프리팹 생성 성공.
`CustomizationTests`, `Cosmetics609Tests`, `CustomizerRuntimeTests`: 총 18개 통과, 실패 0개.
245개 조합 왕복 인코딩, 기존 45개 정수 호환, v1 마이그레이션, 모델의 실제 로딩·텍스처·미터 단위 크기·앞 방향,
추가 콜라이더/강체 없음, 기본 도형 및 실제 토끼 모델에서 모든 장식의 숨김 유지, 기존 미리보기 생성과 취소 흐름을 확인했다.
모델은 개당 180~1,212 삼각형이며 12개 합계 8,092 삼각형이다.
에셋 및 폴더의 `.meta` 누락 없음. 결과: `.local-validation/cosmetics609-tests.xml`.
첫 배치 실행은 라이선스 IPC 접근 때문에 중단됐고 권한을 갖춘 별도 배치 실행으로 검증을 완료했다.
실제 두 클라이언트 간 표시, 플레이어 빌드 및 모든 래그돌 자세의 시각 검사는 별도 범위다.

## 추가: 아우라 치장

- 독립된 아우라 슬롯: 없음 / 황금 별가루 / 푸른 궤도 / 보랏빛 반딧불.
- 별가루는 몸 주변에서 천천히 상승하는 별빛, 궤도는 상하 두 고리의 반대 방향 회전, 반딧불은 노이즈로 떠다니는 보라색 광점이다.
- Particle System 프리팹은 같은 `Resources/Cosmetics609/Aura01~03.prefab`, 재질은 `Assets/_Project/VFX/Cosmetics609`에 있다. FBX 메시가 필요 없는 네이티브 Unity 효과다.
- `Shaders/Resources/CharacterAura.shader`가 텍스처 없이 별 모양과 부드러운 빛 번짐을 만든다. HDR 강도 2~2.5로 기존 Bloom에 반응하며, Bloom이 없는 화면에서도 파티클 자체의 빛 번짐이 보인다. 공용 Volume/Bloom 설정은 변경하지 않는다.
- 캐릭터당 최대 64개 파티클, 로컬 시뮬레이션, 실시간 조명·충돌·트레일 없음. 가슴 기준 장착으로 캐릭터와 함께 이동하며 월드에 잔상이 남지 않는다.
- `Doll.SetVisible`은 파티클을 그림자 전용 렌더에서 제외한다. 1인칭과 탑승 숨김 상태에서 아우라가 보이지 않고, 다시 보일 때 그림자를 만들지 않는다.
- 선택값만 기존 정수 SyncVar로 전달하며 개별 파티클은 클라이언트에서 시뮬레이션한다. 비트 9/10을 사용하므로 기존 저장값은 자동으로 아우라 없음이다. 전체 조합은 980개.
- 재생성 메뉴: `Metagame > Art > Rebuild 609 Auras`. 배치 메서드: `Metagame.EditorTools.CosmeticAuraBuilder.Build`.
- 실제 Unity 미리보기: `docs/assets/concepts/cosmetics609/unity-auras.png`. 배치 메서드: `Metagame.EditorTools.Cosmetics609Builder.CaptureAurasAndExit` (`-quit` 없이 실행).
- 아우라 추가 후 검증: Unity 6000.5.4f1 컴파일 및 42개 테스트 통과, 실패 0개. `CustomizationTests`, `Cosmetics609Tests`, `CosmeticAuraTests`, `CustomizerRuntimeTests`, `DollVisibilityTests`, `FirstPersonVisibilityTests`, `RemoteRidingVisibilityTests`를 실행했다.
- 980개 조합 인코딩, 저장/재로드, 기존 저장값의 아우라 없음, 파티클 수 제한, 실제 Play Mode 자동 재생, 숨김 상태에서 선택 변경, 그림자 유지 상태에서 파티클 숨김, 재표시·해제·물리 불변성을 확인했다. 결과: `.local-validation/aura609-tests.xml`.

- 렌더 후 즉시 종료할 때 Unity 에셋 작업자 종료 충돌이 발생했다. 미리보기 도구가 비동기 작업 정리 시간을 확보한 뒤 종료하도록 조정했으며 최종 실행은 셰이더 오류·assertion·종료 충돌 없이 완료됐다 (`aura609-render-settled.log`).

## 후속: 안개 제외 테스트 회귀

`d9cf538f`에서 `PlayerFogExemptionTests.TheCustomizerTrinketsAreExemptToo` 실패를 재현했다.
테스트가 삭제된 프리미티브 생성 함수 `Piece(...)`의 소스 서명을 찾았기 때문이다.
프리팹 재질은 이미 `_FogStrength = 0`, `_AtmosphereFogExemptMask = 64`로 설정되어 있었다.
테스트를 실제 `PlayerAppearance.Apply` 장착 경로로 변경하여 모든 헬멧·배지의 각 재질 슬롯에서
두 안개 제외 속성과 값을 확인한다. 장식 미생성도 실패시켜 빈 검사가 통과하지 않게 했다.
런타임 코드와 기체 물리는 변경하지 않는다.
