## 2. 측정 방법

같은 녹음, 같은 지표(`stt_metrics.py`)로 모든 엔진을 비교했습니다.

- **CER** — 문자 오류율. 짧은 명령에서는 분모가 작아 환각 한 번에 값이 크게 튄다.
- **키워드 보존율** — 행동을 가르는 단어(못/몽둥이/따라/멈춰 등)가 살아남은 비율. 짧은 명령에서 CER보다 신뢰할 수 있다.
- **부정 뒤집힘** — `뽑아줘` ↔ `뽑지 마`. 가장 치명적인 오류.
- **최종 행동 정확도** — STT 결과를 LLM에 넣어 나온 행동이 맞는지. 실제 사용자 체감값.

책임 분리는 같은 발화를 두 번 분류해서 가릅니다.
정답 대본으로 분류한 결과와 STT 결과로 분류한 결과를 겹치면,
틀린 원인이 STT인지 LLM인지 나뉩니다.

## 5. 적용한 변경

### app.py — STT 모델 교체

```python
ASR_MODEL = os.environ.get("COMPANION_ASR_MODEL", "whisper-small-ko-zeroth")
```

하드코딩을 제거했습니다. `/api/status`가 실제 사용 모델을 보고합니다(이전에는 항상 `whisper-base`로 보고).

### companion_v4.py — 음성인식 오타 보정 프롬프트

발음이 비슷한 말로 보정하도록 지시하되, **금지 표현은 보정 대상에서 제외**했습니다.

| 세트 | 이전 | 이후 |
|---|---|---|
| 또박또박 10개 | 5/10 | **7/10** |
| 평소 발화 35개 | 16/35 | 14/35 |
| 42문장 회귀 | 42/42 | **42/42** |

평소 발화에서 줄어든 2개는 `none` → `clarify`입니다.
`CompanionPolicy.TryParse`가 둘 다 `false`를 반환하므로 **게임 동작은 동일**합니다.

### 실패했다가 고친 것

처음 넣은 프롬프트에 `"지원하지 않는 일이면 none을 유지한다"`를 포함했더니
부정문(`따라오지 마`, `몽둥이 줍지 마`)이 `cancel` 대신 `none`이 되어 **42/42 → 40/42로 깨졌습니다.**
금지 표현을 보정 대상에서 명시적으로 제외해 복구했습니다. 기존 회귀 세트가 이를 잡았습니다.

## 6. 추가한 도구

| 파일 | 역할 |
|---|---|
| `stt_metrics.py` | 공통 지표. 표준 라이브러리만 사용하며 두 venv에서 모두 import된다 |
| `eval_stt.py` | Whisper 계열(CTranslate2) 평가. `--model`, `--compute`, preset A/B |
| `eval_transcribe_cpp.py` | GGUF 음성 모델 평가 (nemotron/Parakeet, Qwen3-ASR). CPU/GPU 선택 |
| `eval_vosk.py` | Vosk 자유전사 / 문법제약 비교 |
| `eval_wav2vec2_onnx.py` | wav2vec2 CTC(ONNX) 평가. 새 패키지 불필요 |
| `eval_llm.py` | LLM 분류 정확도, 혼동행렬, STT/LLM 책임 분리 |
| `eval_llm_prompt.py` | 잡음 입력용 프롬프트 변형 비교 |
| `eval_stt_script.json` | 낭독 대본 35문장 (12개 행동 + 부정문 7개) |
| `eval_stt_register.py` | 녹음을 평가 케이스로 등록. `align`은 녹음 누락 시에도 안전 |
| `watch_captures.py` | 녹음 중 도착 여부 실시간 확인. `--ids`로 일부만 진행 |

음성 보관은 **기본 꺼짐**입니다. `fixtures/captures/ENABLED` 파일이 있을 때만 동작하며
서버 재시작 없이 켜고 끌 수 있습니다. 개인 발화이므로 `fixtures/`와 `results/`는 Git 제외입니다.

`vosk`와 `transcribe-cpp`는 서버의 고정된 `.venv`를 보호하기 위해 `.venv-eval`에만 설치했습니다.

## 7. 주의할 점

- **`initial_prompt`를 쓰지 않습니다.** 음성이 불명확하면 Whisper가 프롬프트를 그대로 출력합니다
  (실측 4건: `그 못은 뽑지 마` → `우주선 정비 협동 게임의 한국어 음성 명령.`).
  키워드 보존율도 함께 오염되므로 프롬프트 없는 preset이 올바른 기준선입니다.
- 짧은 명령에서 CER은 분모가 작아 크게 튑니다. 키워드 보존율과 최종 행동 정확도를 함께 봅니다.
- Vosk 문법제약은 모델 사전에 없는 단어(`고정못`, `뽑아줘`)를 조용히 무시합니다. 실행 시 경고를 확인합니다.
- 닫힌집합 매칭 수치는 사용자가 미리 정한 문장 중 하나를 말한다고 가정한 값이라 실사용보다 낙관적입니다.
  독립 문장은행 없이 측정하면 정보 누출이 생깁니다.
- 이 PC에는 GPU(RTX 4070 Laptop)가 있습니다. CPU 전용은 하드웨어 제약이 아니라 현재 설정입니다.

## 9. 후보 매칭 — 효과 없음으로 확인, 폐기

STT 결과와 발음이 가까운 등록 명령을 LLM에 함께 주는 방식입니다.
행동 선택은 LLM이 하고 매칭기는 후보만 좁히므로 설계 경계는 지켜집니다.

**정직하게 측정하기 위해** 평가 대본 35문장과 문구가 겹치지 않는 문장은행을 새로 썼습니다
(`eval_command_bank.json`, 52표현 / 12행동, 겹침 0개 확인).

| 세트 | 후보 없이 | 후보 제시 | 변화 |
|---|---|---|---|
| 또박또박 10개 | 7/10 | 7/10 | 얻음 0, 잃음 0 |
| 평소 발화 35개 | 14/35 | 14/35 | 얻음 0, 잃음 0 |

이유는 두 가지입니다.

- **맞히는 것은 후보가 불필요합니다.** 발음 보정 프롬프트가 이미 같은 일을 합니다
  (`몽동이 주어져` → 후보 없이도 `pickup_bat`).
- **틀리는 것은 후보도 못 찾습니다.** `멈춰`는 은행의 `스톱`/`하지 마`/`취소해`와 발음이 닮지 않았습니다.
  평소 발화 35개 중 **17개가 문턱 미달**로 후보를 받지 못했습니다.

### 이전 측정이 왜 좋아 보였는가

작업 중간에 "닫힌집합 매칭 28/35"라는 수치가 나왔지만, 그때는 **사용자가 읽은 바로 그 35문장**을
후보로 썼습니다. 시험 문장이 곧 후보인 정보 누출이었고, 독립 은행으로 바꾸자 효과가 0이 됐습니다.
**평가 세트와 후보 세트를 분리하지 않으면 이 방식은 항상 좋아 보입니다.**

표현을 나열해 덮는 방식은 사람마다 말이 달라 원리적으로 완결되지 않습니다.
`eval_command_bank.json`과 `eval_candidates.py`는 남겨 둡니다. STT 품질이 오르면 같은 도구로 재측정하면 됩니다.
