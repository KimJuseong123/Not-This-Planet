# S15P21B202-666: 컷씬 만장일치 스킵

- 기준: `80b4b210`, `S15P21B202-666-qa-esc` 전용 워크트리.
- Unity 6000.5.4f1, 기존 Mirror·IMGUI 사용. 씬/프리팹/패키지 변경 및 Inspector 연결 불필요.
- 화면 직접 조작 없이 코드 수정 및 Unity 배치모드 검증.

## 동작 계약

오른쪽 아래 `SKIP (0/4)` 버튼에 현재 연결된 인증 참가자의 투표 수를 표시한다.
각 참가자는 구간마다 한 번만 투표하며 서버만 만장일치를 판정한다. 솔로는 한 번에 진행한다.
중복 요청, 이전 구간의 늦은 요청, 인증되지 않았거나 준비되지 않은 연결의 요청은 반영하지 않는다.
이탈한 사람의 표와 인원은 제거하고 새 참가자는 새 표가 필요하다. 0명은 만장일치가 아니다.
호스트 이전 중 버튼을 숨기며 새 서버는 투표를 새로 시작한다.

| 구간 | 스킵 후 도착점 |
| --- | --- |
| Stage1 입장 | 탐색 (공세 자동 시작 없음) |
| Stage1 공세 | 전투 (운석 공세 활성화 포함) |
| 인사/탑승 | 발사 |
| 발사 | 단체 사진 |
| 단체 사진 | **1장 완료 / 플레이 타임** |
| **1장 완료 / 플레이 타임** | **스킵 불가: 버튼 없음, 기존 3초 표시 유지** |
| 우주 표류 | 운석 충돌 |
| 운석 충돌 | 비상 하강 |
| 비상 하강 | 기존 Stage2 전환 경로 |

클리어 시간은 `DemoEndingSnapshot.PlayTimeSeconds`를 그대로 보존한다.
엔딩 스킵은 서버의 공통 재생 시작 시점만 변경하며, 준비/실패 화면과 씬 로딩은 건너뛰지 않는다.
투표는 구간마다 초기화되므로 앞 구간의 동의로 다음 구간이나 클리어 시간 화면을 넘기지 않는다.

## 기존 기능 영향 검토

- 공세를 5초 경고 이전에 스킵해도 `BeginAssault`를 실행해 난이도/운석 상태를 보존한다.
- 가산 씬 로딩 중 스킵되면 완료 후 오래된 컷씬 카메라를 켜지 않고 해당 씬을 언로드한다.
- 스킵 버튼은 컷씬 레터박스보다 앞에 그리며, 준비/실패 화면은 더 앞에 둔다.
- 컷씬에서 커서를 풀고 종료 시 기존 잠금 상태를 복원한다. Esc/설정이 열려 있으면 스킵 입력을 막고 메뉴를 닫지 않는다.
- 신뢰성 있는 기존 Mirror 메시지를 사용한다. 상태가 바뀌었을 때 전달하고, 늦은 씬 로딩/재접속은 상태 조회로 복구한다.
- 엔딩 전환에서 플레이어 객체가 사라져도 연결 기준 투표가 유지된다.
- Stage2 전환 및 로비 복귀 시 기존 `EndingSceneFlow` 수명에 따라 메시지 핸들러와 UI를 정리한다.

## 검증

- Unity 6000.5.4f1 `-batchmode -nographics`: 최종 코드 컴파일 및 Mirror Weaver 완료, 컴파일 오류 없음.
- `CutsceneSkipTests`, `Stage1CutsceneTests`, `DemoEndingTests`, `EndingGreetingTests` 중 Heavy 제외: **50개 중 47개 통과, 기존 실패 3개**.
- 새 `CutsceneSkipTests` **8개 모두 통과**: 1/4인 엔딩 경계와 클리어 시간 보호, 투표 규칙, 입장/공세 권한과 부작용, Mirror 메시지 직렬화, 솔로 실제 컴포넌트 수명/커서 복원, Mirror 서버 가상 연결 4개의 실제 패킷 처리.
- 서버 패킷 테스트는 3/4에서 재생 유지, 4/4에서 전환, 중복 표와 이전 구간 요청 거부, 준비되지 않은 연결 요청 거부, 미투표자 이탈 시 남은 전원 동의 처리를 검증했다. 실제 외부 네트워크 4인 실행은 아니다.
- 기존 실패는 `SerializedAssaultMultiplierControlsInterval`의 매개변수 3개이다. 테스트는 공세 이전 간격 30초를 기대하지만 현재 `MeteorIntensity.Drizzle`은 10초다. 2026-09-18 이후 `MeteorSpawner.IntervalAt`은 기존 배율도 더 이상 사용하지 않는다.
- 변경한 소스 전부를 임시 보관하고 **수정 전 HEAD 소스로 같은 3개를 재실행해 동일 실패를 확인**한 뒤 기능 소스를 복원했다. 이번 스킵 변경으로 발생한 회귀가 아니며 기존 난이도나 테스트 기대값은 수정하지 않았다.
- 새 스크립트 3개의 `.meta` 짝과 GUID 중복 없음 확인, 코드 diff 공백 검사 통과. 씬/프리팹/프로젝트 설정 변경 없음.
- 로컬 증거: `tmp/666-validation/final.xml`, `final.log`, `baseline.xml`, `baseline.log` (Git 제외).
- 실제 네트워크 다인 플레이, 렌더링된 버튼 배치, 카메라/씬 전환 시각 결과는 미검증이다. 아래 절차로 이어서 확인할 수 있다.

실제 다인 실행에서 추가로 확인할 항목:

1. 호스트+클라이언트 3명: `(0/4)` → `(1/4)` → `(3/4)`에서 재생 유지, 네 번째 표에 전원 전환.
2. 클라이언트의 연속 클릭과 구간 경계 클릭이 중복 표나 다음 컷씬 투표로 남지 않는지 확인.
3. 미투표자 이탈/중간 합류 시 분모와 만장일치 판정 확인.
4. 엔딩 각 구간 스킵 후 전원 동일 구간 표시, 클리어 시간 화면에는 버튼이 없고 기록 값 유지.
5. 가산 씬 로딩 중 입장 스킵, 공세 즉시 스킵, Esc 메뉴 열기/닫기 후 카메라·조작 복귀 확인.
6. 전용 서버와 호스트 이전 후 새 투표, 엔딩 완료 후 Stage2에서 버튼·핸들러 잔류 없음 확인.
