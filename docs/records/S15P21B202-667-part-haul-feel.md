# S15P21B202-667 · 1인 운반이 실제로 되게

> 관측: "손으로 잡고 밀면 잘 안 밀리고, 안 잡은 채로 모듈 윗부분에 몸통박치기를
> 하면 모듈이 굴러가면서 밀린다."

## 재 보니 두 가지가 섞여 있었다

측정 하네스로 3초씩 밀어 보고 잰 값이다.

| 무엇 | 이동 | 회전 |
|---|---|---|
| 자유 파츠 · 손으로 잡고 밀기 | 1.623m | — |
| 자유 파츠 · 손으로 잡고 당기기 | 1.623m | — |
| 자유 파츠 · 몸으로 옆면 밀기 | 1.623m | — |
| 자유 파츠 · 몸으로 **윗면** 밀기 | 1.623m | **82.8도** |
| **놓인** 파츠 · 손으로 잡기 | 불가 | — |
| **놓인** 파츠 · 몸으로 밀기 | 0.000m | 0.0도 |

**미는 속도는 손이든 몸이든 같다.** 표의 상한(1인 0.6m/s, 기획 §13.2)이 지배하기
때문이다. 다른 것은 **회전**이었다 — 윗부분을 밀면 굴러가고, 그래서 더 잘
밀리는 것처럼 보였다.

그리고 **놓인 파츠는 원래 안 밀린다.** `PartPush` 가 `PartState.Free` 로 한정한다.
그러니 사용자가 민 "모듈" 은 자유 파츠였다.

## "잘 안 밀린다" 의 원인은 밀기가 아니라 걷기였다

파츠는 1명일 때 **0.6m/s** 로 제한된다. 그런데 미는 사람은 걸어서 **2.9m/s**,
뛰면 4.6m/s 로 간다. 그리고 `Hand.BraceTo` 는 **조인트를 만들지 않는다** — 손으로
잡아도 붙잡아 주지 않는다.

**그래서 잡고 걸으면 그냥 파츠를 두고 앞서 간다.** 몸으로 밀 때는 몸이 파츠에
붙어 있어 접촉이 유지되므로 계속 밀렸다. 그것이 "손으로 잡으면 안 밀리는데
몸통박치기는 된다" 의 정체다.

플레이어 속도 상한에는 **동료를 끌 때 · 엎드릴 때 · 풀숲**만 있고 **미는 중이
없었다.**

처음에는 고정 배율(걷기의 0.25배 = 0.73m/s)로 눌렀는데, **AI 리뷰가 4인 밀기에서
전원이 뒤처진다고 지적했다** — 파츠는 1.5m/s 인데 사람이 0.73이면 접촉이 끊겨
협동 밀기가 오히려 깨진다. 맞는 지적이라 **파츠가 낼 수 있는 속도를 따라가게**
고쳤다.

```
상한 = PartPushTable.SpeedFor(미는 인원) × 1.15
      1인 0.69 · 2인 0.92 · 3인 1.38 · 4인 1.73 m/s
```

1.15배의 여유는 접촉을 유지하며 밀 수 있게 하는 몫이다. 참가자 화면에는 인원수가
안 오므로 1인 값을 바닥으로 쓴다.

## 굴러가는 것은 원인에서 막았다

`PartPush.Drive` 는 **질량중심에 힘을 넣어 토크를 안 만든다** — 주석에 "미는 것이
파츠를 넘어뜨리는 것이 되면 §13 이 아니라 §22.4 의 붕괴가 된다" 고 적혀 있다.
그런데 **미는 사람의 몸 콜라이더가 그것을 우회한다.**

각속도 감쇠를 먼저 시도했는데 82.8 → 74.3도로 거의 안 줄었다. 접촉이 매 스텝
토크를 다시 넣어 균형을 이루고, 넘어지기 시작하면 중력이 마무리하는데 그때는
이미 미는 사람이 아니라 감쇠가 안 돈다.

**그래서 원인에서 막았다.** 골반이 파츠 질량중심보다 **위**면 몸으로 미는 것으로
치지 않는다. 정상적으로 서서 미는 데에는 영향이 없다 — 골반은 지면에서 0.30m
(`Tuning.RideHeight`)라 파츠 질량중심보다 늘 아래다. 막히는 것은 **올라타서
윗부분을 밀 때**뿐이다. 그 하네스로 다시 재니 1.52m / 73.8도 → **0.000m / 0.0도**.

## 두 번 틀렸다 — 둘 다 "숫자가 똑같다" 로 드러났다

1. 감쇠를 **조기 `return` 아래**에 뒀다. 상한에 닿는 순간부터 매 스텝 그냥
   빠져나가 감쇠가 한 번도 안 돌았다 — 값이 74.3 → 74.3 으로 **소수점까지 같아서**
   드러났다
2. 내 하네스가 키네매틱 인형을 파츠에 **겹쳐** 놓았다. 밀어내는 힘이 생겨
   **밀기가 아닌 것을 재고 있었다** — 서서 미는데도 20도 기울었다. 기존
   `PartPushTests` 하네스는 표면에서 틈을 둔다

두 번째 때문에 충돌로 회전을 재는 검사는 버리고, **규칙 자체**(질량중심 위는
밀기로 안 친다)를 재는 검사로 바꿨다.

## 3. 고정못을 잡은 채 몸을 비비면 아주 쉽게 밀렸다

> "고정못을 붙잡고 있는 상태(마우스 꾹)일 때 모듈에 몸을 비비면 모듈이 엄청 쉽게
> 밀린다. 들고 있는 고정못이 위치를 강하게 잡고 있어서 그런 게 아닌지"

**그 짐작이 맞다.** 코드가 이렇게 되어 있다.

```csharp
// PlayerRig.TryAttachClampHand
var body = target.PartBody;                               // ← 파츠의 강체
left.Hand.GripToFixedAtPoint(target.GripTarget, body, leftPoint);
```

손이 **파츠 강체에 FixedJoint** 로 묶이고, 박혀 있는 파츠는 `Locked` 라
kinematic 이다. **그래서 잡은 사람은 밀리지 않는 벽이 된다.**

그 자체는 의도된 것이다 — 기획 §12.1 의 "발을 구르며 낑낑대는" 그림이고 코드
주석에도 *"고정못이 몸을 붙들고 있으므로 아무리 밀어도 거의 제자리다"* 라고
적혀 있다.

**문제는 그 벽이 다른 파츠에 닿을 때다.** 힘이 한쪽으로만 간다 — 파츠는 밀리는데
사람은 안 밀린다. 무한 질량으로 미는 셈이다.

그리고 하나가 더 겹쳐 있었다. 고정못을 잡으면 `hand.Held` 는 **고정못의** 잡이라
`IsHoldingPart` 가 거짓이고, 그래서 `bodyPushing` 경로로 빠진다 — **`PartPush` 의
설계된 힘까지 추가로 받는다.** 충돌과 밀기가 겹친다.

둘 다 막았다.

* 고정못을 잡고 있으면 **몸으로 미는 것으로 안 친다** (`bodyPushing` 에서 제외)
* 고정못을 잡고 있는 동안 **몸 콜라이더가 자유 파츠와 안 부딪힌다.** 놓으면 되돌린다
  (이미 있던 "들고 있는 물건과 자기 몸" 무시 패턴을 그대로 따랐다)

밀 수 있는 파츠(`Free`)와만 무시한다 — 박힌·놓인 파츠까지 통과시키면 조립된
우주선 안으로 걸어 들어가게 된다.

**이건 EditMode 하네스로 재현하지 못했다.** 세 번 시도했고 세 번 다 숫자가
소수점까지 같아 계측이 조건을 못 만들었다는 것만 확인했다. 그래서 고친 뒤의
검증은 충돌 결과가 아니라 **규칙**(고정못을 잡으면 미는 사람으로 안 센다)을 잰다.
실제 감각은 인게임에서 봐야 한다.

## 건드리지 않은 것

기획이 못 박은 값이라 그대로 뒀고, 검증이 이것을 잠근다.

* **자유 파츠 100kg** (`FreePartMassScale`) — §13.2.1 의 솔로 운반 근거
* **1명부터 밀린다** — 같은 조항이 3인 규칙을 폐기했다
* **인원별 속도표** 0.6 / 0.8 / 1.2 / 1.5 — §13.2
* **운석 충격이 파츠를 미는 힘** — §13.2 가 플레이어보다 훨씬 강해야 한다고 정했다

## 검증

| 무엇을 지키나 |
|---|
| 미는 사람이 **1~4인 모든 인원수에서** 파츠보다 조금 빠르다 |
| **뛰면서 밀어도** 상한을 못 넘는다 |
| 인원수를 모르면 1인 값을 바닥으로 쓴다 |
| 느려지는 것은 **미는 동안에만** 걸린다 |
| 질량중심 **위**를 미는 것은 밀기로 안 친다 |
| 서서(골반 0.30m) 미는 것은 **그대로 된다** |
| **고정못을 잡고 있으면** 몸을 비벼도 미는 사람으로 안 센다 |
| 고정못을 **놓으면** 다시 밀 수 있다 |

`PartHaulFeelTests` 8건 신규. 관련 스위트 합쳐 141건 중 실패 10건은 **전부
develop 에서도 실패하던 것**이고(따로 기준선을 돌려 확인) 새로 깨진 것은 없다.

## 남은 것

* **손으로 잡았을 때 붙잡아 주지 않는 것** — `Hand.BraceTo` 는 조인트를 안 만든다.
  이번에는 걷기를 늦춰 따라붙게 했지만, 조인트로 실제로 매달리게 하는 편이
  "끙끙 끌린다" 에 더 가깝다. 다만 조인트는 끼임·튕김을 만들 수 있어 별도로 재야 한다
* **실제 화면에서의 감각** — 상한이 답답한지 적당한지는 사람이 봐야 한다

## AI 리뷰가 잡은 것 셋 — 전부 맞았다

1. **무시 쌍이 해제되지 않았다.** 고정못을 잡은 채 그 파츠가 `Free → Placed` 로
   넘어가면(남이 조립하면) 무시가 남아 **조립된 우주선 안으로 걸어 들어갈 수
   있었다** — 이 함수가 막겠다고 **내가 주석에 써 놓은 바로 그것**이다. 매 틱
   등록된 쌍 중 더 이상 밀 수 없게 된 것을 즉시 되돌리게 고쳤다
2. **매 틱 `GetComponentsInChildren`** 으로 배열을 새로 할당하고 중첩 루프를
   돌았다. 잡기 시작한 프레임에 한 번만 짓고, 해제만 매 틱 보게 고쳤다
3. **4인 밀기에서 전원이 뒤처진다** — 위의 속도 상한 수정

셋 다 내가 못 본 것이고, 1번은 **내 주석이 사실과 달랐다.**
