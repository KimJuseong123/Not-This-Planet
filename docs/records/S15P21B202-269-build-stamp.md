# 빌드 식별 — 배포 파일 이름과 실행 로그 (S15P21B202-269)

[문서 안내](../README.md) → [작업 기록](README.md) → 서버·배포

배포 파일명과 실행 로그로 테스트 빌드를 식별하는 규칙입니다. 날짜·시각·이슈번호를 포함한 파일명, 실행 시 표시와 로그 위치를 안내합니다.

본문의 “현재”, 검증 수치, 미완료 항목은 **기록 당시 기준**입니다. 후속 변경은 관련 이슈와 [주제별 색인](README.md)을 함께 확인합니다.

테스트 빌드를 나눠 줄 때 "이게 어느 빌드냐" 를 확정하는 방법. 두 방법을 사용한다 —
**파일 이름**(받기 전에 보이는 것)과 **실행 로그**(압축을 푼 뒤에도 남는 것).

## 1. 배포 파일 이름

```
metagame-<YYYYMMDD>-<HHMM>-<이슈번호>.zip

예) metagame-20260902-1513-264.zip
```

| 자리 | 왜 넣나 |
| --- | --- |
| `YYYYMMDD-HHMM` | **시각까지 넣는 것이 핵심이다.** 2026-09-02 에 14:01 빌드와 15:13 빌드를 두고 "새 거 받은 거 맞냐" 로 시간을 버렸다. 하루에 여러 번 빌드하는 지금 날짜만으로는 구분이 안 된다. |
| 이름순 = 시간순 | 탐색기에서 정렬하면 최신이 맨 아래다. 받는 사람이 고민할 것이 없다. |
| `<이슈번호>` | 무엇이 들어간 빌드인지 한눈에 보인다. "264 들어간 거 맞지?" 로 물어볼 수 있다. |

**한글은 쓰지 않는다.** 압축 프로그램에 따라 이름이 깨지고, EC2로 올릴 때 `scp` 인용이 성가시다.

## 2. 실행 로그의 빌드 표시

파일 이름은 압축을 푸는 순간 사라진다. 팀원이 폴더만 남기면 그 안의 exe가 언제
빌드된 것인지 알 방법이 없다 — 위의 혼란이 정확히 그것이었다. 그래서 값을 산출물
안에 박고, 게임이 켜질 때 로그에 찍는다.

`Player.log` 앞부분에 이렇게 나온다:

```
[빌드] 2026-09-02 15:13 · eab8595 · S15P21B202-264
```

| 항목 | 뜻 |
| --- | --- |
| `2026-09-02 15:13` | 빌드한 시각 |
| `eab8595` | 그때의 커밋. 이 해시로 소스를 정확히 되살릴 수 있다 |
| `S15P21B202-264` | 브랜치에서 뽑은 이슈키 |
| `· +커밋안한변경` | **붙어 있으면 해시를 믿으면 안 된다.** 커밋하지 않은 코드가 섞인 빌드다 |

마지막 항목이 있는 이유: 실제로 커밋 전 코드를 빌드해 나눠 준 적이 있다. 그때
해시만 찍혀 있었다면 "이 해시로 재현된다" 는 거짓말이 됐을 것이다.

에디터에서 돌리면 `[빌드] 에디터에서 실행`으로 나온다.

## 3. 어떻게 동작하나

| 어디 | 무엇을 |
| --- | --- |
| `Scripts/Editor/BuildStamp.cs` | 빌드 시작할 때 값을 만들어 StreamingAssets에 실어 보낸다 |
| `Scripts/Runtime/Core/BuildInfo.cs` | 씬이 뜨기 전에 그 값을 읽어 로그에 찍는다 |

설계에서 지킨 것 세 가지다.

- **저장소가 더러워지지 않는다.** 값을 `Assets/` 아래에 쓰면 빌드할 때마다 git에
  변경이 생겨 팀원과 충돌한다. 그래서 임시 폴더에 써서 빌드에만 실어 보낸다
  (`BuildPlayerProcessor.AddAdditionalPathToStreamingAssets`).
- **CLI 든 에디터 Build 버튼이든 똑같이 걸린다.** 팀원은 에디터에서 빌드하므로
  한쪽에만 걸리면 의미가 없다. `BuildPlayerProcessor`는 둘 다 지나간다.
- **실패해도 빌드를 막지 않는다.** git이 PATH에 없거나 저장소가 아니어도
  경고만 남기고 진행한다. 표시 하나 때문에 빌드가 깨지면 손해다.

## 4. 로그 파일 위치

팀원에게 받을 때 알려 줄 경로:

```
%USERPROFILE%\AppData\LocalLow\<회사명>\둥실둥실 우주 대탈출\Player.log
```

실행할 때 `-logFile <경로>`를 붙이면 원하는 곳에 남길 수도 있다.
