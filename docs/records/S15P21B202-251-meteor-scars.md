# S15P21B202-251 착탄한 운석을 흔적으로 남긴다

[문서 안내](../README.md) → [작업 기록](README.md) → 운석·환경

운석 착탄 뒤 남는 지면 흔적을 구현한 기록입니다. 흔적 생성·표현 규칙과 검증 범위, 지면 표시의 후속 확인 사항을 정리합니다.

본문의 “현재”, 검증 수치, 미완료 항목은 **기록 당시 기준**입니다. 후속 변경은 관련 이슈와 [주제별 색인](README.md)을 함께 확인합니다.

<a id="지금까지는-정반대였다"></a>

## 착탄 흔적의 기존 수명과 기획의 차이

```csharp
public const float MeteorDespawnSeconds = 6f;   // 착탄 6초 뒤 Destroy
```

§19 는 "박힌 운석과 분화구는 발사 실패 후에도 유지되며 **스테이지 동안 사라지지
않는다**" 고 정한다. 상수와 검증이 그 반대를 잠그고 있었다.

`MeteorTests.Meteor_ExpiresAfterDespawnDelay`가 **"착탄한 운석이 남아 쌓이면 안 된다"**
를 단언했다 — S15P21B202-247 의 `SpawnedMeteor_CarriesDamageSource`와 같은 종류다.
`Meteor_StaysForeverOnceItSettles`로 뒤집었다.

`MeteorDespawnSeconds`를 지웠다. 착탄한 운석에는 수명 상한(`MeteorMaxLifeSeconds`)도
걸리지 않는다 — `Settled`에서 먼저 돌아나간다. 상한은 **착탄하지 못한** 운석(플레이
공간 밖으로 떨어지거나 콜백을 놓친 것)에만 남는다.

<a id="한-줄은-이미-되어-있었다"></a>

## 충돌 순간의 피해 판정 재사용

§19 "충돌 **순간에만** 넉백과 기절 판정이 있다" 는 S15P21B202-247 에서 처리했다.
`DamageSource`를 운석에서 떼고 `ApplyImpact`가 `HasImpacted`로 한 번만 돌게 했다.
이 이슈에서 다시 하지 않고 회귀 방어선만 남겼다.

<a id="끌-빛도-파티클도-없었다"></a>

## 기존 프리팹의 물리·시각 효과 구성

§19 는 "충돌 후 **고비용 물리, 빛과 파티클**을 끄고" 라고 하는데, 프리팹을 열어 보면
`Light`도 `ParticleSystem`도 없다.

```
PF_Stage1_Meteor   layer Meteor · Rigidbody(60kg) · SphereCollider(r 0.45) · Meteor
 └─ Visual         PF_Stage1_MeteorMain — 겉보기 지름 0.9m
```

파티클은 즉발 헬퍼 `Puff` 하나뿐이라 끌 것이 없다. **실제로 끌 수 있는 것은 물리뿐**이고,
그것을 껐다 — 키네마틱으로 바꾸고 속도를 지운다.

"붉은 빛, 연기와 불꽃이 약해진다" 는 **색으로 대신했다.** `MeteorScarLook`이 5초에
걸쳐 달아오른 색에서 그을린 색으로 옮긴다 — `MeteorWarningLook`(S15P21B202-241)과 같은
방식이고, [Art] 가 실제 연출을 주면 이 값을 버린다.

sqrt로 감쇠한다. 등속으로 두면 5초 내내 붉어 보여서 "약해진다" 가 읽히지 않는다.

## 콜라이더는 남긴다

§19 이 "접촉 피해가 없는 **낮은 정적 장애물**" 이라고 정한다. 걸려서 넘어갈 수 있어야
하므로 콜라이더를 끄지 않는다. 피해는 이미 한 번만 도니(247) 추가 처리가 없다.

박히는 깊이는 반지름의 0.6배다 — "절반 이상 지면에 박힌 모습"(§19)이면서 위쪽이 남아
장애물이 된다. 검증이 "묻힌 비율 > 절반" 과 "위쪽이 0보다 크다" 를 함께 본다.

<a id="남기기로-하는-순간-누출이-됐다"></a>

## 운석 수명 변경에 따른 정리 누락

```csharp
public void ResetRun()
{
    ...
    _pending.Clear();
    _live.Clear();      // 목록만 비운다 — 파괴하지 않는다
}
```

지금까지는 운석이 6초 뒤 스스로 사라졌으니 문제가 없었다. **남기기 시작하면 씬에 영영
쌓인다.** `DestroyAll(_live)` + `ClearScars()`로 바꿨다.

<a id="나이는-스포너가-센다"></a>

## 스포너에서 흔적 경과 시간 관리

운석 쪽에서 세면 200개가 매 스텝 틱을 받아야 하고, §19 이 "고비용 물리를 끄고" 라고
정한 것과 어긋난다. `MeteorSpawner.Scar`가 나이를 갖고, **식은 뒤에는 세지도 않는다.**

```csharp
if (scar.Cooled) continue;
scar.Age += deltaTime;
```

150~200개가 쌓여도 5초가 지난 것들은 비용이 0이다. 검증이 "식은 흔적은 나이가 더 이상
늘지 않는다" 를 잠근다.

## 상한과 로그

§19 가 "정상 20분 플레이에서 약 150~200개의 흔적이 누적되는 상황을 **성능 기준으로
삼는다**" 고 명시했다. `MeteorScarLimit = 200`으로 그 상한을 그대로 쓰고, 넘으면
**가장 오래된 것부터** 지운다.

**로그를 남기고 `ScarsTrimmed`로 센다.** 조용히 잘라내면 "다 남았다" 로 보인다.

<a id="초기화-경로가-아예-없었다"></a>

## 스테이지 재시작 시 흔적 초기화

§19 는 "전원 기절로 스테이지를 완전히 재시작할 때만 초기화한다" 고 정한다. 그런데
`MeteorSpawner.ResetRun`을 부르는 런타임 경로가 **없었다** —
`Stage1Exploration.ResetRun`은 파츠 발견만 되돌린다.

§20.5 자리인 `GameSession.TickAllDowned`는 이렇다.

```csharp
if (!LocalPlayer.Downed) { allDownedSeconds = 0f; return; }
...
Falls++;
Respawn();
```

**"모든 플레이어" 가 아니라 로컬 플레이어만 본다.** 그리고 `Respawn()`은 스폰 복귀이지
§20.5 가 말하는 "파츠, 고정못, 용접, 장비, 운석 흔적과 난이도 시간을 모두 초기화" 가
아니다.

그것을 제대로 만드는 것은 멀티 판정이 걸려 [Network] 몫이다. 이 이슈에서는
`ClearScars()`를 만들어 두고 `ResetRun`에 연결했다 — §20.5 가 완성되면 같은 함수를
부른다.

## 발사 실패 뒤에는 유지된다

§22.4 "발사 실패는 스테이지 초기화가 아니다" 이고 §19 도 같은 말을 한다. `SetPaused`가
예고만 끊고 흔적은 건드리지 않는 것이 이미 맞았다 — 회귀 테스트로 확인하도록 했다.

## 산출물과 후속 확인

- **§20.5 의 "전원" 판정** — `TickAllDowned`가 로컬 플레이어만 보는 것은 멀티 문제라
  [Network] 몫이다. `ClearScars()`를 만들어 두었다
- **실제 분화구 메시 · 붉은 빛 · 연기 · 불꽃** — 자산이 없다. 그레이박스 원판과 색
  감쇠로 두고 [Art] 자리를 남겼다
- **프레임 시간 측정** — EditMode로 잴 수 없다. 잠근 것은 "박힌 운석이 물리 비용을
  갖지 않는다" 와 "식은 흔적이 매 프레임 비용을 갖지 않는다" 와 개수 상한이다.
  150~200개의 실제 비용은 [Art] 자산이 들어온 뒤 인게임에서 재야 한다
- **공유 메시·재질 전환**(§19) — 프리팹 자식이 이미 아트 프리팹을 공유하므로 추가 작업이
  없다고 판단했다. 실측이 필요하면 [Art] 와 함께 본다
- 소리 — `AudioSource` 사용처가 0곳이다([Sound])

## 인게임 확인은 못 했다

빌드가 develop에서 멈춘다(지형 자산 체크아웃 손상 + 로비 씬 Volume Profile 누락).

박히는 깊이 0.6이 "박혔다" 로 보이는지, 200개가 깔린 화면이 지저분하지 않은지,
낮은 장애물로서 걸려 넘어지는 것이 답답하지 않은지는 인게임에서 봐야 한다.
