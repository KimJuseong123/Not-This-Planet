# 견인 우주선 조종석·착륙·반중력장 수정

기준: `docs/planning/chapter-1-detailed-design.md`, 2026-09-10 사용자 요청.
기획 §14.2의 하차 후 무인 호버보다 이번 요청의 하차 후 착륙을 우선한다.

## 코드에서 확인한 원인과 변경

- 탑승 카메라도 일반 1인칭의 골반 위치와 시선 방향 전방 오프셋을 사용했다.
  마우스 yaw에 따라 카메라 위치가 이동하고 물리 조인트의 오차도 전달된다.
  조종석 원점을 눈 위치로 사용하고 조종석을 Visual의 크기·회전 계층에서 분리했다.
- 조종대·계기화면에 `CockpitNoFog` 전용 런타임 재질을 적용했다.
  일반 fog를 합성하지 않으며, 행성과 같은 stencil bit 64로 전체 화면 대기 효과에서 제외한다.
- 장이 켜진 상태의 하차는 무인 호버로 분기했다. 이제 즉시 플레이어를 내려놓고
  장을 끈 뒤 빈 기체가 중력·속도 제한·실제 표면 접촉으로 착륙한다.
- 플레이어 부유는 입력이 없으면 세로 목표 속도가 0이었다. 장 진입 시 약 1.5m를
  자동 부양하되 기체 아래 1.2m까지로 제한한다. Space/Ctrl을 누르면 수동 조작으로
  전환하고 입력을 놓으면 멈춘다. 수직 속도는 2→3m/s, 반응 시간은 0.5→0.25초다.
- 기존 클릭/F 토글에 3중 반투명 청록 원뿔 빔을 연결했다. 실제 장의 깊이·반경을
  사용하며 중심광, 위로 흐르는 빛줄기, 가장자리·하단·표면 접촉 페이드,
  켜짐/꺼짐 전환을 적용했다. 효과는 충돌체가 없으며 메시·재질은 생성 후 재사용한다.

## 검증 결과와 제한

- Unity 6000.5.4f1 / URP 17.5.0, 수정 전 Git 작업 트리 변경 없음.
- Unity의 기존 참조와 Roslyn 컴파일러로 Gameplay 및 Editor 테스트 어셈블리 컴파일:
  각각 오류 0. 출력은 무시되는 `METAGAME/Temp/CraftValidation`에 저장했다.
- 카메라 회전 시 눈 위치, 무입력 부양, 하차 후 착륙·장 해제·재탑승 회귀 테스트 추가/수정.
- 화면 조작, 실행 중인 Editor의 플레이 모드 전환은 하지 않았다. Unity MCP가 없어
  물리 테스트 실행, 셰이더 GPU 컴파일 및 실제 외관, 멀티플레이 동작은 미검증이다.
- 새 컴포넌트와 재질은 코드에서 연결하므로 별도 Inspector 연결은 필요 없다.

## Editor에서 확인할 재현 절차

1. 탑승 후 마우스를 좌우·위아래로 움직이고 비행한다. 눈이 조종석 원점에 고정되며
   조종대가 시선 회전만으로 멀어지거나 가까워지지 않는지 확인한다.
2. 짙은 안개에서 조종대와 계기화면의 색이 유지되는지 확인한다.
3. 상승 후 장을 켠 상태/끈 상태 각각 하차한다. 즉시 조작이 플레이어로 돌아오고
   빈 기체가 지면 또는 구조물 윗면에 내려앉는지 확인한다. 착륙 후 재탑승도 확인한다.
4. 기체 아래로 다른 플레이어가 걸어 들어간다. 점프 없이 발이 들리고, Space/Ctrl로
   오르내리며, 장을 끄거나 밖으로 나오면 중력이 복구되는지 확인한다.
5. 클릭을 누르고 있어도 한 번만 전환되는지, 연속 클릭 때 빔이 부드럽게 켜지고 꺼지는지,
   지면·파츠와 만나는 경계가 부드럽고 투명한지 확인한다.
