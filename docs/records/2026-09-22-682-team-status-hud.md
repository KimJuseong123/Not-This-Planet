# 682 팀 생존 상태 HUD

## 범위

- 브랜치: `S15P21B202-682-ui-ui`, 기준 `ff436b84`.
- 작업 위치: `.local-worktrees/682-ui`. 화면 직접 조작 없이 파일 편집과 숨김 Unity 배치 검사만 사용.
- 왼쪽 위에 자신을 포함한 현재 참가자를 팀 슬롯 순으로 가로 배치한다. 원형 초상화와 닉네임, 플레이어별 이름표/핑 색상을 사용하고 옆에 초록/빨강 심장을 표시한다.
- 게임의 사망 표현은 구조 가능한 `downed` 상태다. `downed` 또는 체력 0이면 빨강, 구조 후 살아 있으면 초록이다. 기존 체력·구조·리셋 판정은 변경하지 않는다.

## 구성과 기존 기능 영향

- `GameHud.TeamStatus`를 기존 HUD에 연결한다. 씬/프리팹/패키지/설정 연결 작업은 없다. `UiScale`을 사용하며 긴 닉네임은 해당 카드 영역으로 제한하고 리치 텍스트를 해석하지 않는다. 닉네임 글리프는 `Update`에서 기존 한글 폰트를 미리 준비한다.
- `TeamStatusRoster`는 `NetPlayer.AllClientPlayers`의 이름, 팀 색, 외형, `downed`, `health`를 읽는다. 원격 몸의 체력이 항상 갱신된다고 가정하지 않는다. 몸이 생성되기 전이나 탑승으로 숨겨진 상태에서도 멤버를 제거하지 않는다. 네트워크 참가 대기 중에는 솔로 멤버를 중복 생성하지 않는다.
- `TeamPortrait`는 실제 슈트와 현재 머리 장식의 메시를 128×128 원형 RenderTexture에 그린다. 모델·장식의 원본 재질 및 색상 PropertyBlock을 읽고, 별도 셰이더로 그린다. 카메라, 광원, 콜라이더, 물리 인형은 추가하지 않으며 원본 렌더러의 표시 여부·레이어·재질도 바꾸지 않는다.
- `PlayerAppearance.HelmetVisual`은 읽기 전용 참조다. 모델 뒤에 숨겨진 물리 머리 장식을 중복해서 그리지 않도록 실제 커스터마이징 장식만 조회한다.
- 초상화는 최초 표시, 외형 변경, 몸 교체, RenderTexture 유실 때 생성한다. 퇴장과 HUD 파괴 시 자원을 해제한다. 외형 모델의 `LateUpdate` 이후 캡처하도록 HUD 실행 순서를 1000으로 지정한다. 그래픽 장치 없는 전용 서버에서는 팀 표시용 작업을 생략한다.
- 컷신/엔딩/입력 차단 중, 태블릿이 열린 동안에는 팀 HUD를 숨긴다. 쓰러졌거나 탑승한 상태에서는 계속 보여준다. 기존 피해 테두리, 구조 UI, 입력 처리는 유지한다.
- `Stage2Hud`의 기존 상단 안내·오염 목록·경고 문구는 팀 HUD 아래로 이동한다. 두 HUD의 서로 다른 좌표 배율을 변환해 UI 확대 시 겹침을 방지한다. 가운데 상호작용 및 하단 조작 안내 위치는 유지한다.

## 검토한 경계 사례

- 참가 순서가 달라도 팀 슬롯 순서 유지; 한글/빈 닉네임/이름 갱신.
- 원격 체력이 로컬 몸에 반영되지 않아도 서버 생존 상태 표시.
- 생성 대기, 탑승, 퇴장, 파괴된 Unity 객체, 같은 슬롯으로 재접속.
- 초상화가 1인칭에서 숨겨진 메시도 읽을 수 있음; 원본 표시 설정 보존.
- 텍스처 속성이 없는 재질, 기본 슈트, 틴트 및 머리 장식.
- 이미지 캐시 및 정리, 렌더 타깃 복원, 투명한 원형 영역.

## 검증

Unity 6000.5.4f1, Windows의 별도 검증 프로젝트에 이 브랜치의 소스/셰이더/캐릭터 에셋을 복사하고 로컬에 설치된 패키지 캐시를 사용했다. 원본 프로젝트와 작업 중인 에디터는 열거나 조작하지 않았다.

최종 C# 컴파일 및 EditMode 테스트 **47/47 통과**:

| 테스트 | 통과 |
| --- | ---: |
| TeamStatusHudTests (신규) | 8 |
| TeamSlotsTests | 13 |
| KeyGuideHolderTests | 4 |
| HealthNetworkStateTests | 15 |
| DownedSyncTests | 7 |

Direct3D 12 / RTX 4050에서 실제 토끼 모델의 기본 외형과 분홍색+머리 장식 이미지를 생성해 확인했다. 처음 생성한 이미지에서 머리 윗부분이 잘려 구도를 조정했으며, 조정 후 신규 8개 테스트를 다시 실행해 **8/8 통과**했다. 최종 이미지에서 얼굴, 슈트 색상, 장식 및 원형 투명 영역을 확인했다. 그래픽 장치 없이 생략한 테스트는 없다.

검사 산출물은 워크트리의 `tmp/team-status-validation/` 아래에 있다(버전 관리 제외).

- `final-results.xml`: 47개 전체 결과.
- `portrait-results.xml`: 최종 구도에서 8개 재검사 결과.
- `final-unity.log`, `portrait-unity.log`: C# 및 GPU 렌더링 검사 로그.
- `rabbit-0-0.png`, `rabbit-3-1.png`: 확인한 최종 초상화.

초기 샌드박스 실행의 라이선스 연결 제한은 격리 검증 프로젝트를 일반 권한 환경에서 숨김 배치 실행해 해결했다. 기존 코드의 obsolete API 경고와 라이선스 서비스 진단 메시지는 로그에 남아 있으나, 변경 소스의 C# 컴파일 오류나 새 초상화 셰이더 오류는 없었다. 변경 파일의 공백 오류와 `.meta` 짝도 확인했다.

실제 게임 씬에서 해상도·UI 배율별 표시 및 호스트/원격 클라이언트 동시 플레이는 별도로 확인해야 한다. 자동 검사 통과를 전체 게임의 무오류 보장이나 최종 플레이어 빌드 검증으로 해석하지 않는다.
