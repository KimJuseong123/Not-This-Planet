# 681: ESC 팀 리트라이

- 브랜치: `S15P21B202-681-ui`, 기준 `ff436b84f2232f3d443b260cd6bc1e27759b6fdd`.
- 작업 폴더: `.local-worktrees/681-ui`. Unity 6000.5.4f1 / 기존 Mirror / IMGUI.
- 화면 직접 조작 없이 코드 수정과 `-batchmode -nographics` 검증만 수행했다.

## 동작

- Stage1/Stage2의 ESC 메뉴에 **리트라이** 버튼을 표시한다. 누르면 메뉴를 닫고 플레이를 계속한다.
- 우측 하단에 `리트라이를 원하는 팀원들이 있습니다 (n/m)`을 표시한다. 자신의 표가 서버에 반영되면 버튼은 `리트라이 요청 완료`로 비활성화된다.
- 현재 인증된 사람 연결이 모두 동의하면 서버가 **Stage1_Astra를 Single 모드로 새로 로드**한다. 솔로는 한 번 누르면 재시작한다. AI 동료는 투표 인원에 포함하지 않는다.
- 공세·입장 연출·운석 예고와 흔적·고정못·부품·플레이어·체크포인트는 새 씬/세션으로 초기화된다. 방 연결은 유지하고 기존 네트워크 플레이어 객체만 제거하여 새 씬 Ready 후 다시 생성한다.
- 재접속 위치 기억은 플레이어 제거 후 비운다. 리트라이 때 방 플레이 타이머도 다시 시작한다.
- 컷씬 스킵 투표와 별개다. R키 개인 리스폰, 설정 저장/취소, 타이틀 복귀, 게임 시간의 진행은 기존 경로를 유지한다.

## 오류·회귀 방지

| 조건 | 처리 |
| --- | --- |
| 연속 클릭 / 중복 패킷 | 연결당 한 표 |
| 이전 판의 지연 패킷 | 판별 무작위 투표 ID가 다르면 거부 |
| 재접속 / 연결 ID 재사용 | 연결 객체를 기준으로 표를 소유하여 이전 표를 상속하지 않음 |
| 중간 입장 / 이탈 | 현재 인증 인원을 재계산하고 떠난 표 제거. 준비 중인 참가자도 분모에 포함 |
| 인증 전 / Ready 전 / 플레이어 생성 전 요청 | 서버가 거부 |
| 참여자 0명 | 만장일치로 처리하지 않음 |
| 호스트 이전 / 연결 상실 | 로컬 솔로 재시작으로 오인하지 않음. 새 서버는 새 투표 시작 |
| 씬 로딩 / 자동 맵 복구 / 엔딩 | 투표 차단 및 기존 표 폐기 |
| 로딩이 늦은 클라이언트 | 연결별 상태 조회로 표/인원 복구 |
| 재시작 직후 옛 씬에서 엔딩 요청 | 진행 중인 재로딩을 엔딩이 덮어쓰지 못하도록 `EndingSceneFlow.Begin`에서 차단 |
| Stage2 → 리트라이 → 호스트 이전 | Stage1 로드 시 `NetworkManager.onlineScene`도 갱신하여 Stage2로 되돌아가는 경로 방지 |

`TeamRetryFlow`는 씬 로딩 동안 살아 있어 재시작 메시지와 상태를 수신한다. 로비/엔딩으로 떠나면 정리한다. 상태 변경은 reliable 메시지로 전파하고 클라이언트 복구 조회는 최대 초당 1회다. 씬/프리팹/패키지 연결 변경이나 Inspector 설정은 필요하지 않다.

## 검증

- Unity 배치 컴파일 및 Mirror Weaver 완료. 추가 테스트 4/4 통과 (`retry-final.xml`).
- 실제 `Stage1_Astra`를 로드하고 공세를 진행시킨 뒤 **두 번 연속 솔로 리트라이**: 새 GameSession/플레이어, 공세 비활성, 운석 초기화, 고정못 미해제, 체크포인트/시간/입력 초기화, Bootstrap 중복 없음 확인.
- 실제 Mirror 프레이밍/서버 메시지 디스패치에 가상 연결 4~5개를 연결: 3/4에서 재시작 없음, 준비 중인 새 참가자 반영, 만장일치 시 연결 보존 및 플레이어 제거, 중복/이전 판 패킷 거부, 재접속 표 초기화, 재접속 위치 삭제 확인. 이 테스트의 씬 전환은 NetworkManager 대역으로 관찰한다.
- 메시지 직렬화 왕복, 솔로 ESC 메뉴와 입력/시간 유지, 새 Stage1Sequence/MeteorSpawner 초기 상태 검사.
- 기존 회귀 범위: CutsceneSkipTests, Stage1CutsceneTests, MapRecoveryTests, RejoinMemoryTests, RejoinDuplicateTests, IndependentMeteorTests, NetworkSerializationTests, DemoEndingTests, EndingGreetingTests 중 Heavy 제외. **94개 중 91개 통과, 기존 실패 3개** (`regression.xml`).
- 기존 실패: `SerializedAssaultMultiplierControlsInterval`의 세 매개변수. 테스트는 탐색 간격 30초를 기대하지만 현재 값은 10초다. 관련 테스트/Stage1Sequence/MeteorSpawner는 HEAD와 동일하며 [666 기록](2026-09-21-666-cutscene-skip.md)에서도 같은 실패를 수정 전 코드로 확인했다. 이번 작업에서 이 기대값이나 난이도를 바꾸지 않았다.
- 최종 엔딩 경합 방지 변경을 포함한 TeamRetryTests / TeamRetrySceneTests / CutsceneSkipTests / DemoEndingTests / EndingGreetingTests는 **Heavy 포함 45/45 통과** (`final.xml`). 최종 컴파일 오류 및 예외 로그 없음. 리트라이 로딩 중 엔딩 요청이 추가 씬 전환을 만들지 않는 검사도 포함한다.
- 새 스크립트 세 개의 `.meta`와 GUID 유일성, 변경 diff 공백 검사를 통과했다. 에디터 자동 URP 설정이 수행되었지만 씬/프리팹/설정/재질에는 최종 내용 변경이 없다.
- 최초 제한 환경 실행은 라이선스 IPC 접근 실패로 중단했으며, 승인된 배치 실행에서 검증했다. 첫 테스트 작성 중 NUnit `Is.AnyOf` 호환 오류는 지원 구문으로 수정한 뒤 재컴파일했다.

## 남은 검증 범위

실제 여러 PC/프로세스의 호스트·원격 클라이언트·전용 서버 플레이, 실환경 호스트 이전, 화면 배치/한글 렌더링, Windows 플레이어 빌드는 실행하지 않았다. 서버 패킷 테스트와 솔로 실제 씬 재로딩이 이 범위까지 보장하지는 않는다.

실환경에서는 2~4명이 Stage1 탐색/공세 및 Stage2에서 투표하고, 일부 동의 시 플레이 유지, 만장일치 후 같은 방에서 시작 위치/공세 초기화, 재접속과 호스트 이전 후 같은 스테이지 유지, ESC 설정·컷씬 스킵·R키 리스폰을 확인한다.
