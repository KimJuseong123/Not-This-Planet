# AI 통합본의 최신 develop 이관 — S15P21B202-690

## 범위와 기준

- 기준: `origin/develop`의 `a0c76dbc`.
- 작업 브랜치: `S15P21B202-690-ai-develop-integration`.
- 원본 실험 폴더 `S15P21B202-ai-integration-20260920`는 보존한다.
- 최신 develop의 `TeamSeats`가 자리와 몸을 소유한다. 기존 실험의 `TeamRoster`는 이관하지 않는다.
- AI 명령/행동, STT·LLM 로컬 실행기, 선택형 추가팩 설치, V 음성 명령, 근접 음성 채팅을 이관한다.
- 기존 develop의 리트라이와 UI를 유지하며 AI 상태/음성 설정만 추가한다.
- 렌더링 설정, 운석 에셋, 복구 씬, 로컬 MCP 패키지는 이관하지 않는다.
- 새 기본 추종자 배분 정책은 이번 이관에 포함되지 않았다. 현재 추종은 명령으로 시작한다.

## 충돌 처리

1. `NetPlayer`: 최신 자리 인계 흐름을 유지하고 별도 partial에 AI 명령 API를 연결한다. AI 여부는 음성 수신 대상 판별을 위해 동기화한다.
2. `GamePauseMenu`: 기존 리트라이 버튼과 AI/음성 설정을 함께 유지하고 겹치지 않도록 배치한다.
3. `TractorBeamController`: 최신 develop의 버튼 상승 에지 처리를 그대로 사용한다.
4. `BuildStamp`: 최신 메타데이터 코드는 유지하고 Git 표준 출력/오류의 동시 읽기·시간 제한만 이관한다.

## 자리와 준비 상태

- 추가팩 미설치/로딩/실패 상태에서는 새 AI를 생성하지 않는다.
- AI 실행 준비가 끝나면 빈자리를 TeamSeats가 채운다.
- 실행 중 런타임이 중단되면 AI 행동을 중단하고 몸은 보존한다. 사람 재접속용 몸과 도구를 삭제하지 않는다.
- 사람이 AI 자리를 이어받을 때 AI 작업 정리는 대상 예약만 해제한다. 작업 취소가 추가로 도구나 탑승 상태를 변경하지 않도록 한다.
- 주의: develop의 기존 `NetPlayer.RemoveBody`는 pooled body의 견인 컨트롤러에 `ReleaseForRespawn`을 호출한다. 이 경로는 탑승을 해제하므로 **몸 유지와 탑승 유지가 동일하지 않다**. 이번 이관에서는 기존 정리 정책을 임의로 바꾸지 않았다. 탑승 중 재접속은 별도 실기 검증/후속 수정 대상이다.
- 추가팩은 Git에 넣지 않는다. Editor는 저장소의 개발 팩을 우선 사용하고, 없으면 사용자 경로에 설치된 팩을 사용한다.
- 다운로드 서버 주소는 별도 배포 담당자가 설정해야 한다. 실제 HTTPS 배포 검증은 아직 필요하다.

## 사용자 확인 순서

멀티플레이 참가자는 모두 이번 테스트 빌드를 사용한다. 기존 develop/실험 빌드와 새 SyncVar·음성 명령 구성이 다르므로 서로 섞어서 검증하지 않는다. 추가팩은 AI를 실행할 방장 PC에서 준비한다.

1. 새 프로젝트의 `Assets/Scenes/Lobby.unity`에서 시작한다.
2. 방장이 AI를 켜고 준비 완료 후 시작한다. 빈자리 3개가 채워지는지 확인한다.
3. 가까운 AI에게 V를 누른 채 “나 따라와”, “여기서 기다려”, “못 뽑아줘”를 말하고 놓는다.
4. 두 번째 사람이 입장하면 AI 한 명이 교체되고, 퇴장하면 AI가 이어받는지 확인한다.
5. 도구를 든 상태에서 퇴장·재접속해 같은 자리의 몸과 도구를 이어받는지 확인한다. 탑승 중 재접속은 위의 기존 하차 정책을 구분해 결과를 기록한다.
6. 두 PC에서 일반 대화가 가까울 때 들리고 멀어지면 줄어드는지, V 명령 중 일반 음성과 중복되는지 확인한다.
7. Esc의 기존 설정·리트라이·나가기 및 추가 음성 설정이 겹치지 않는지 확인한다.
8. AI를 끈 새 방에서도 원래 develop의 조작과 게임 진행에 문제가 없는지 확인한다.

컴파일/자동 테스트와 실제 두 PC 확인은 다른 증거다. 사용자 테스트 완료 전에는 push/MR을 만들지 않는다.
