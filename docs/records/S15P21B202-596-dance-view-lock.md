# S15P21B202-596 · 춤 추는 동안 시점으로 몸이 돌지 않게

F2 로 고른 춤이 **게임 안에서 미리보기와 다르게 보인다**는 지적을 고친다.
세 곡(뮤직챌린지 · REDRED · BAD) 전부에 걸린다.

## 원인은 춤이 아니라 몸의 방향이었다

춤 클립은 **뿌리를 돌리지 않는다.** `generate_rabbit_dance.py:173-176` 이
`body_yaw` 를 허리·척추 세 뼈에 3분의 1씩 나눠 **비틀** 뿐이고
(`applyRootMotion = false`), 캐릭터의 세계 방향은 전부 `PlayerRig.faceDir` 이다.

```
PlayerRig.cs:3014  faceDir = Slerp(faceDir, 카메라 앞방향, 1 - exp(-7 * dt));
PlayerRig.cs:3107  Balance() → Doll.Balance 조인트 목표를 faceDir 로
```

**이 줄에 조건이 하나도 없었다.** 춤 중에도 매 물리 스텝 시정수 1/7초로
카메라를 쫓는다. 위에서 상체가 이미 최대 ±76도 비틀려 있는데 골반까지 같이
도니 아예 다른 그림이 된다.

| 춤 | `body_yaw` 범위 |
|---|---|
| 뮤직챌린지 | 0 ~ 72.8도 |
| REDRED | −76.4 ~ 19.6도 |
| BAD | −65.7 ~ 58.9도 |

## 고친 곳 둘

### ① 춤 중에는 시점을 따라 돌지 않는다

`PlayerRig.Locomotion()` 에서 `faceDir` 슬러프를 건너뛴다.
**카메라는 그대로 돈다** — 막는 것은 몸이지 둘러보는 것이 아니다. 1인칭으로
제 춤을 보려면 시점은 돌아야 한다.

고정못을 잡고 있으면 **그쪽이 먼저다**(기획 §12.1). 그건 조작이 아니라
기획이 요구하는 자세라 춤보다 앞선다 — 순서로 표현했다(`else if`).

### ② 끊는 것은 속도가 아니라 방향키다

예전 조건은 하나뿐이었다:

```csharp
if (state.Blocked || (shot.CancelOnMove && state.Speed > 0.15f)) Cancel(shot);
```

**속도는 결과라서 늦고, 밀려서 난 속도와 제 발로 낸 속도를 구별하지 못한다.**
0.15 는 걷기 애니메이션이 켜지는 문턱이라, 방향키를 안 눌러도 제자리 흔들림이나
작은 접촉으로 넘어간다.

지금은 `State.MoveInput`(방향키 또는 점프)이 즉시 끊고, 속도는 **밀림만** 잡는
뒷문으로 남겨 문턱을 걷기 속도의 절반(1.45m/s)으로 올렸다. 남이 밀거나 경사에서
미끄러지면 여전히 끊긴다 — 안 끊으면 다리는 춤추고 몸은 미끄러진다.

## 멀티 — 여기가 이 티켓의 무게다

**물리는 서버가 돈다**(S15P21B202-145). 남의 화면에 보이는 골반 회전은
`NetworkTransform` 으로 온 서버의 값이다(`RemoteAvatar`). 그러니 **이 판단이
서버에서도 같아야** 한다. 한쪽만 고정하면 남의 화면에서만 도는 춤이 된다.

카메라를 보지 않고 **몸이 실제로 춤 클립을 돌리고 있는가**(`Doll.Suit.DanceActive`)
를 본다. 서버도 `NetPlayer.CmdPlayDance` 에서 같은 `Suit` 로 춤을 켜고
(`NetPlayer.cs:408`), 참가자 화면은 `danceSeq` 로 켠다(`:420`) — 세 경로가 같은
한 곳을 거치므로 답이 갈리지 않는다.

`input.Move` 도 마찬가지다. 서버에는 카메라가 없지만 클라이언트가 보낸
`InputFrame` 이 있다(`PlayerRig.CurrentInput`) — 그래서 "방향키를 눌렀나" 를
서버도 안다.

## 검증 38개 (`DanceEmoteTests`)

| 무엇을 지키나 | 어떻게 |

| 춤이 끝나면 잠금도 풀린다 | 취소 후 다시 돈다 |

| 방향키가 끊고 속도는 안 끊는다 | 0.4m/s 로 밀려도 살아 있고, 속도 0에 방향키만 눌러도 끊긴다 |
| 밀려서 걷는 만큼 움직이면 끊긴다 | |
| 목록의 춤 전부가 방향키에 끊긴다 | |

### 검증이 진짜 결함을 잡는지 확인했다

38개가 **처음부터 다 통과**했다. 그건 고쳤다는 뜻일 수도 있고 검증이 아무것도
안 본다는 뜻일 수도 있다. 그래서 잠금 두 줄을 잠깐 지우고 다시 돌렸다:

```
잠금 없이: 38개 중 35 통과 · 3 실패
  TurningTheViewWhileDancingDoesNotTurnTheBody
  EveryDanceLocksTheBody
  TheViewItselfIsNotBlockedWhileDancing
```

셋이 정확히 그 결함을 짚는다. **한 번에 통과한 검증은 반대쪽을 봐야 한다.**
