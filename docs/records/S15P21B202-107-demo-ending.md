# 데모 종료 조건·엔딩 구현 (S15P21B202-107)

## 2026-09-13 씬 전환 위험 점검 및 F12 테스트

- 에디터/개발 빌드에서 F12 확인 후 실제 조립 성공·엔딩 씬·멀티 동기화를 실행하는 기능을 추가했다. 솔로/호스트만 확정 가능하며 취소 시 입력과 일시 메뉴 상태를 복구한다.
- 준비 무한 대기, 큰 JSON 전송 한도, 빠른 재연결의 메시지 등록, 실패 시 로비 정리를 보완했다. 엔딩 중 호스트 이전으로 재생을 지속하는 기능은 지원하지 않는다.
- 자동 검사 40개, 검증용 개발/일반 빌드, 지연 및 후발 합류를 포함한 로컬 4프로세스 엔딩·로비 복귀를 확인했다. 자세한 발견 사항과 남는 제한은 [엔딩 씬 점검 기록](stage1-ending-scene-audit.md)을 참조한다.

## 2026-09-13 별도 엔딩 씬

- `Assets/Scenes/Stage1_Ending.unity`를 추가하고 Build Settings 및 `SpaceBuild` 필수 씬 목록에 등록했다. 로비의 온라인 씬은 기존 `Stage1_Astra`를 유지한다.
- `EndingSceneFlow`만 씬 사이에 유지한다. 서버가 성공 스냅샷을 보존하고 Mirror `ServerChangeScene`으로 게임 씬을 교체한다. 솔로는 `LoadSceneAsync`를 사용한다.
- 엔딩 씬의 `Stage1EndingBootstrap`은 직렬화된 파츠 원본 프리팹 4개와 서버 스냅샷을 이용해 표시 전용 무대를 만든다. 실제 파츠 위치·회전·크기·비드·참가자 외형·플레이 타임을 전달하며 게임 세션과 물리 오브젝트를 엔딩 씬에 남기지 않는다.
- 각 참가자가 표시 준비 완료 메시지를 보내면 서버는 모든 연결의 준비를 확인한 뒤 공통 시작 시각을 공유한다. 재접속자는 서버에 남아 있는 스냅샷과 시작 시각을 요청해 현재 단계로 합류한다. 끊긴 연결은 준비 대기를 막지 않으며 같은 연결 번호로 새로 접속해도 다시 준비해야 한다.
- 엔딩 씬에서는 Mirror 플레이어 자동 생성을 잠시 중지하고 로비 복귀 시 원래 설정을 복구한다. 월드 동기화 감시자도 엔딩 씬에서 물리 파츠를 찾지 않는다.
- 에디터에서 엔딩 씬만 직접 실행하면 4개 파츠와 4명 참가자로 만든 샘플을 재생한다. 실제 게임 경로에서는 샘플 대신 성공 스냅샷을 사용한다.
- 격리 Unity에서 씬 교체·원래 게임 씬 언로드·기록과 조립 자세 보존·4개 프리팹 참조·준비 대기·끊긴 연결/연결 번호 재사용·Mirror 메시지 직렬화·연결 종료 시 시계 유지 및 기존 엔딩 회귀 **25개 테스트 통과**. 결과: `tmp/demo-ending-validation/scene-tests-final.xml`.
- 검증용 Windows 실행 파일을 빌드해 로컬 호스트 + 참가자 3개 프로세스를 연결했다. 한 참가자는 준비를 2초 지연했고 다른 참가자는 실행 10초 뒤에 합류했다. 네 프로세스의 공통 시작 시각은 모두 `3.6915636904761904`, 플레이 타임은 모두 3723초, 파츠/참가자 수는 각각 4개/4명으로 일치했다. 늦은 참가자는 경과 6.947초에서 기존 엔딩에 합류했고 네 프로세스 모두 `LOBBY_OK`를 기록했다. 로그: `.local-validation/ending-peer/{host3,client3,slow3,late3}-result.txt`.
- 도중 합류 검증에서 발견한 연결 종료 후 로컬 시계 전환에 의한 단계 역행을 수정했다. 온라인 엔딩 시계는 연결 종료 시 마지막 값을 유지하며 로비 복귀 중 다시 탑승/발사 단계로 돌아가지 않는다.
- 멀티 실행 검증은 로컬 TCP 전송과 검증용 스냅샷을 사용했다. 실제 인터넷 릴레이·백엔드 인증·엔딩 중 호스트 이전은 별도 환경 검증 대상이다. 원본 Unity 화면은 조작하지 않았다.

## 2026-09-13 연출 수정

- 정지한 완성 우주선 앞에서 참가자가 2초간 서로 다른 팔 인사를 한 뒤 한 명씩 탑승한다. 인사·탑승 합계 8초.
- 주 추진 엔진 모듈 아래에만 불꽃을 표시하고 5초 동안 천천히 떠올라 가속한다. 카메라는 출발 위치와 화각을 유지하고 회전만으로 우주선을 추적한다.
- 실제 조립 배치와 참가자 외형을 복제한 무대에서 기념 포즈를 촬영한다. 사진 카드의 테두리·그림자·등장 효과를 표시하고 5초 중 마지막 1.5초에 검게 페이드한다.
- “데모 끝” 아래에 시·분·초 단위 플레이 타임을 표시하고 3초 종료 구간 뒤 기존 로비 이동을 실행한다. 방 생성 응답 수신부터 성공 확정까지의 호스트 시간을 스냅샷으로 공유하며, 방장 교체에는 초기화하고 같은 방 상태 갱신에는 유지한다. 방 없이 직접 실행한 솔로/로비 세션이 없는 서버는 기존 게임 경과 시간을 사용한다.
- 사진 촬영 뒤에도 배경용 카메라를 활성화해 카메라가 전부 꺼지는 문제를 방지한다.
- 원본 화면 조작 없이 격리 Unity 프로젝트에서 **31개 테스트 통과**. 단계 경계, 호스트 기록 고정 및 직렬화, 방장 교체 시 타이머 초기화, 실제 모델 렌더링, 카메라 위치 고정, 추진부 불꽃 1개, 사진 유지와 활성 카메라, 로비 복귀 요청을 확인했다. 결과: `tmp/demo-ending-validation/revision-tests.xml`. 렌더링 이미지: 같은 폴더의 `boarding.png`, `launch.png`, `escape.png`, `photograph.png`.
- 실제 다중 PC 방의 동시 재생·재접속·백엔드 왕복과 사진 카드/페이드/글자의 최종 화면은 별도 확인이 필요하다. 아래는 9월 11일 최초 구현 기록이며 연출 시간·표시 방식은 이 수정 사항을 우선한다.

## 목적

용접건이 만든 비드 접합으로 네 핵심 파츠가 모두 연결되면 곧바로 성공을 확정한다. 기존 수동 탑승·카운트다운·하중 시험을 데모의 종료 경로에서 제외한다.

## 구현

- `DemoEnding`이 네 파츠 종류를 확인하고 살아 있는 비드 접합(`IsIntact`, `BeadWeldRatio > 0`)만 따라 연결을 판정한다. 높이·순서·발사대·기울기·강도 100%는 검사하지 않는다. 직접 연결과 핵심 파츠를 통한 간접 연결 모두 허용한다.
- 서버 또는 솔로 권한만 성공을 확정한다. 성공 순간의 파츠 위치·회전·배율, 비드 사슬·기여 색상, 참가자 외형과 시작 시각을 저장한다. 성공 기록에는 컷씬 시간을 더하지 않는다.
- `ProgressSync`의 Mirror SyncVar가 완성 스냅샷을 전송한다. 클라이언트는 공통 서버 시각으로 단계를 구하므로 중간 재접속도 현재 단계부터 표시한다. 전용 서버 방식에서는 방장 클라이언트가 엔딩 종료를 로비 백엔드에 알린다.
- `DemoEndingView`는 원본 메시를 표시 전용 무대에 복사한다. 네트워크·물리 컴포넌트를 복제하지 않는다. 탑승 캐릭터는 기존 토끼 모델과 보행 모션을 사용하고, 우주선의 실제 상대 배치를 유지해 상승시킨다.
- 탑승 5초 → 불꽃을 내뿜으며 우주로 추진 7초 → 우주선 앞 전원 기념사진 4초 → 정확히 **“데모 끝” 3초** → 자동 로비 이동 요청 순서다. 앞 세 구간은 조정 가능한 연출값이다.
- 기념사진은 실제 무대와 일렬로 선 참가자를 RenderTexture에 한 번 렌더링한다. 이후 애니메이션·물리·접속 상태로 사진이 바뀌지 않는다. 사진 파일 저장 기능은 제품 기능에 추가하지 않았다.
- 엔딩 중 입력·개인 복구·파츠 유실 초기화·피해·견인 조작·위협 공세와 기존 플레이 HUD를 중단한다. 종료 중 방장 변경 이벤트가 새 게임을 시작하지 않게 한다.
- 기존 `LobbyTransition`으로 네트워크를 정리하고 메뉴형 로비 타이틀로 복귀한다. 현재 프로젝트의 기존 복귀 정책에 따라 게임 연결과 방 연결을 정리한다. 솔로에서 네트워크 씬 전환을 불필요하게 10초 기다리던 경로도 수정했다.
- `SpaceBootstrap`이 자동 설치하므로 Inspector 설정이나 씬·프리팹 수정이 필요 없다.

## 검증

- 원본 프로젝트의 Unity 화면을 직접 조작하지 않았다. 원본 프로젝트를 대상으로 한 별도 배치 테스트는 이미 열린 Editor의 프로젝트 잠금으로 실행되지 않았다.
- 원본의 Unity 참조와 C# 9 설정으로 Core·Gameplay·Network·UI·Bootstrap 소스를 별도 출력 위치에 컴파일했다. **5개 어셈블리 오류 0개**.
- 원본 소스와 로컬 패키지를 복사한 격리 Unity 프로젝트에서 `DemoEndingTests` **17개 통과**. 약한 비드·순서/위치/자세 무관·갈라진 두 덩어리·단순 접촉·사라진 조인트·중복 종류·부족한 파츠·서버 권한·한 번만 시작·재접속 시각·3초 종료 문구 경계를 검증했다.
- 격리 프로젝트에서 실제 아트 프리팹을 사용한 PlayMode 연출 테스트 **1개 통과**. 탑승·추진·기념사진을 이미지로 렌더링하고, 사진 유지와 로비 이동 요청 1회를 확인했다. 이 이미지는 검증용 조립체이며 실제 방 플레이의 녹화가 아니다.
- 같은 격리 프로젝트에서 실제 Mirror 소스와 Weaver를 실행했다. **스냅샷 직렬화 왕복 테스트 1개 통과**: 파츠 4개·참가자 4명·최대 비드 사슬 192개의 위치·회전·이름·기여 색상 배열이 보존되고 16KB 미만으로 직렬화됨을 검증했다.
- 최종 합산: **19개 통과, 실패 0개, 건너뜀 0개** (`DemoEnding.Tests`, 10.64초). 로컬 결과는 `TestResults/demo-ending-2026-09-11/final-tests-complete.xml`, 장면 이미지는 같은 폴더의 `boarding.png`, `launch.png`, `photograph.png`에 보관한다. 임시 테스트 코드도 같은 폴더의 `validation-harness/`에 남겼다. 결과 폴더는 Git 추적 대상이 아니다.
- 기존 코드의 사용 중단 예정 API 경고와 미사용 이벤트 경고는 남아 있다. 프로젝트 설정·패키지·아트 에셋은 변경하지 않았다.

## 한계와 후속 확인

- 실제 호스트+참가자 2인 방, 전용 서버 연결, 접속 해제·재접속, 로비 백엔드와의 전체 왕복은 아직 실행 검증하지 않았다. 한 프로세스의 직렬화·연출 테스트가 여러 클라이언트의 동시 복귀를 증명하지는 않는다.
- Windows 플레이어 빌드는 만들지 않았다. 실제 맵에서 다양한 비뚤어진 조립 형태의 카메라 구도와 탑승 동선은 추가 플레이 점검 대상이다.
- 연출은 코드로 구성한 첫 구현이다. 실제 메시와 기존 보행 모션을 재사용하며, 별도 해치 애니메이션·Timeline 에셋은 추가하지 않았다.
