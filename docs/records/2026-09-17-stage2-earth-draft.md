## 범위와 상태

후속 작업: [모델 통합 및 주변 환경 배치](2026-09-17-stage2-art-integration.md)를 완료했다. 아래 기록은 최초 기하 모델 초안의 구현 시점 기준이다.

Stage1_Astra의 SpaceBootstrap, PlayerRig, GameSession, NetPlayer, 메뉴·기절·구조·개인 복구를 재사용하는 별도 편집 가능 씬이다. Stage1_Astra 씬과 기존 아트 프리팹을 수정하지 않는다. 장비·로켓·환경은 초안용 기하 모델이며 정식 아트가 아니다. 아래 수치와 미정 사항의 채택은 시험판 구현 결정이며 원본 기획의 확정 사항으로 승격하지 않는다.

## 공간과 조작

좌표는 Unity 월드 미터. 크레인 중심 (-8,0,5), 발사대 (9,0,9), 컨테이너 (-8,0,22), (8,0,24), (16,0,-1). 준비 구역 (-27,0,-18), 고정 제독 (-17,0,-12). 전체 지면 86×78m, 가장자리 경계 포함.

- E: 조준한 개방·연결·조종·승강기·사다리·장비·발사 상호작용.
- 크레인 탑승: A/D 회전, W/S 반경, Space/Ctrl 상승·하강, Shift 정밀.
- 렌치: 볼트 조준 + 좌클릭 유지 + 원형 마우스 동작. 지지 후 좌+우클릭으로 해제.
- 분사기: 좌클릭 유지. 본인은 고정식 제독 설비 또는 다른 사람의 분사기를 이용.
- Tab: 로켓 실루엣·단계별 체결·장비 안내. R 개인 복구, G 기존 동료 구조.

## 검증 기록

- Unity에서 새 씬·재질 7개·26개 상호작용을 생성하고 Build Settings 등록 완료.
- 첫 자동 검사에서 MaterialPropertyBlock의 필드 초기화가 씬 로딩 시 허용되지 않는 오류를 발견해 Awake 초기화로 수정.
- 원격 거리 밖 요청이 상호작용 대기 시간을 소모하던 문제를 발견해 유효 요청에서만 소비하도록 수정.
- Unity EditMode + EnterPlayMode 검사 **16/16 통과**, 실패 0. `Stage2Tests;StageCatalogTests`, 결과: `artifacts/stage2-draft/test-results.xml`.
- 실제 Stage1_Ending 재생 종료를 유발해 Stage2_Earth 로딩과 새 플레이어 생성을 검증했다. 네트워크 연결을 유지한 장 간 전환의 백엔드 통합 검사는 별도다.
- 거리 밖 상호작용 거절, 극좌표 도달 범위, 거리·기울기 조립 조건, 원형/지그재그 입력 구분, 부분·완전 체결, 장력 해제, 점유 중 사다리 회수 금지, 연결 종료, 파츠 복구, 완성 로켓 발사 조건을 검사했다.
- 오염 구역에서 벽 차폐·동료 제독·자기 제독 금지를 시뮬레이션했다. 테스트 시간 대기를 실제 시뮬레이션 시간 기준으로 수정해 물리 틱 진행을 보장했다.
- 검증 중 사다리 플랫폼이 발사 패널을 가리는 배치 문제를 발견해 패널을 발사대 서쪽으로 이동했다.
- 씬 미리보기와 Play Mode 캡처를 확인했다. 현재 환경에서 SRP 배칭 시 블록아웃 색상이 뭉개져 `Stage2BlockoutPalette`가 이 씬의 메시 색상만 MaterialPropertyBlock으로 명시한다. 프로젝트 전역 렌더 설정은 변경하지 않는다. 해당 블록아웃의 배칭 효율은 정식 아트 전환 시 재검토한다.
- 미리보기: `artifacts/stage2-draft/overview.png`, 플레이 화면의 씬 카메라 캡처: `overview-play.png`.

### Windows 빌드 및 실제 네트워크

- Unity 6000.5.4f1 Windows Development 빌드 성공. 생성 위치 `artifacts/stage2-smoke/Stage2Smoke.exe`는 로컬 산출물로 Git에서 제외한다.
- 최종 빌드로 호스트·클라이언트·늦참 관찰자 프로세스를 실행했다. 양 참가자의 인증 입력으로 컨테이너 개방, 원격 크레인 조작과 상태 수신, 운전자 연결 종료 후 조종권 해제, 늦참 전체 상태 수신 **5개 체크 통과**.
- 로컬 로그: `artifacts/stage2-draft/host-final.log`, `client-final.log`, `observer-final.log`. 종료 시 Telepathy 수신 스레드 중단 메시지가 남으며 게임 진행 판정 실패와 구분한다.
- 자동 검사는 실제 장비 배치 조작의 재미나 사람 4인의 전체 완주 검증을 대신하지 않는다. 백엔드 없이 로컬 Mirror/Telepathy로 검증했다.

## 열기와 재검증

1. Unity Hub에서 이 워크트리의 `METAGAME` 프로젝트를 Unity 6000.5.4f1로 연다.
2. `Assets/Scenes/Stage2_Earth.unity`를 열고 Play. 씬 단독 실행은 솔로이며 기존 플레이어·복구 시스템을 재사용한다.
3. Test Runner의 EditMode에서 `Stage2Tests`, `StageCatalogTests`를 실행한다.
4. 네트워크 실행 파일 재생성은 `Metagame.EditorTools.Stage2Validation.BuildNetworkSmoke`를 batch executeMethod로 호출한다. 호스트는 `-stage2-smoke-host`, 참가자는 `-stage2-smoke-client`, 원격 조작 진행 후 관찰자는 `-stage2-smoke-observer`로 실행한다. 테스트 전용 씬은 빌드 후 제거된다.
5. 씬은 일반 Unity 오브젝트로 편집한다. `RefreshDraft`는 개발 중 생성 씬을 다시 만드는 함수여서 수동 편집 후 호출하면 덮어쓴다. 일반 메뉴의 `Create Stage2 Earth Draft`는 기존 씬을 덮어쓰지 않는다.

## 명확한 초안 한계

- 장비대에서 개인 도구를 장착하는 방식이다. Stage1 ToolBase의 물리 운반·던지기와 아직 통합하지 않았다.
- 부분 체결의 한쪽 처짐·브래킷 변형, 정식 캐릭터 도구 애니메이션, 원형 체결 접근성 대체 입력은 후속 작업이다.
- 기획의 첫 조작 체험, 2인 사각지대 의사소통 재미, 1~4인 난이도는 사람 플레이 테스트로 판단해야 한다.
- 백엔드 방의 stageId 갱신·재접속·호스트 이전의 장 간 경계도 별도 회귀 확인이 필요하다.
