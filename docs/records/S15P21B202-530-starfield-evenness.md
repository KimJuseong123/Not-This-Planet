## 1. 무엇이 문제였나

---

## 2. 실측 — "몰려 있다" 는 많은 쪽이 아니라 **비어 있는 쪽**이었다

프로브를 임시로 만들어 쟀다(조사용이라 커밋하지 않았다). 화면 하나(가로 90도·세로
50도, 20도 올려봄)에 들어오는 별을 방위각을 돌려 가며 셌다.

```
방위   0도 — 일반 156 + 띠  40 = 196
방위  45도 — 일반 141 + 띠 178 = 319
방위  90도 — 일반 126 + 띠 236 = 362
방위 135도 — 일반 165 + 띠 232 = 397   ← 최대
방위 180도 — 일반 174 + 띠 216 = 390
방위 225도 — 일반 168 + 띠 144 = 312
방위 270도 — 일반 135 + 띠  15 = 150
방위 315도 — 일반 136 + 띠   0 = 136   ← 최소
```

**최대 397 : 최소 136 = 2.92배. 그런데 차이가 전부 띠에서 나온다** — 일반별은
126~174로 고르다(±16%).

### 2-1. 띠는 결함이 아니다

띠 축은 `(0.32, 0.86, -0.40)`, **위에서 30.8도** 기울어 있다. 띠는 그 축에 수직인
대원이라 지평선에서 30.8도 올라갔다가 반대쪽에서 내려간다. **실제 은하수가 그렇다.**

### 2-2. 문제는 띠가 없는 쪽의 136개가 **1픽셀**이라는 것

```
난수 0.10 → 밝기 0.104  크기 0.147 → 화면 1.01 픽셀
난수 0.50 → 밝기 0.271  크기 0.222 → 화면 1.52 픽셀
난수 0.99 → 밝기 0.979  크기 0.540 → 화면 3.72 픽셀
```
(반지름 300 · 세로 화각 60도 · 1080p)

밝기가 `pow(난수, 2.4)` 로 어두운 쪽에 심하게 치우쳐 있고, **크기를 그 밝기로 정한다.**

```csharp
float size = Mathf.Lerp(settings.minimumSize, settings.maximumSize, brightness);
```

1920×1080 화면에 **1픽셀 점 136개는 검은 하늘**이다.

### 2-3. 확인하고 배제한 것

| 의심 | 결과 |
| --- | --- |
| 분포 수식이 틀렸나 | **아니다.** `z` 균등 + `r = √(1-z²)` 는 구면 균등 표집의 정석이고, 일반별 실측이 고른 것이 증거다 |
| 별 구가 카메라를 안 따라오나 | **아니다.** `AtmosphereBackdrop.LateUpdate` 가 카메라 위치를 따라간다 |
| 모바일 축소가 개수를 줄이나 | **아니다.** `Application.isMobilePlatform` 이 아니면 배율 1이다 |
| 레거시 `Starfield` 를 쓰나 | **아니다.** Stage1은 `Stage1AtmosphereProfile.asset` 을 쓴다(프로필 1개 확인) |

## 4. 해보고 **하지 않기로 한** 것 — 띠 두께

지라에 "띠 두께를 넓히면 경계가 덜 날카로워진다" 를 안 B 로 적었다. **재 보니 아니었다.**

```
bandSpread=0.22 → 최대=571 최소=319 비율=1.790 · 띠가 대원에서 평균  3.2도
bandSpread=0.45 → 최대=564 최소=319 비율=1.768 · 띠가 대원에서 평균  6.6도
bandSpread=0.70 → 최대=541 최소=319 비율=1.696 · 띠가 대원에서 평균 10.1도
```

**두 배 넓혀도 편차가 1.2%밖에 안 움직인다.** 띠만 두꺼워질 뿐이다 — 몰림은 띠 두께가
아니라 **띠가 없는 쪽이 비어 있어서**였다.

> **대조 실험이 먼저 말해 주었다.** 값을 되돌리는 대조에서 **0개**가 실패했다. 아무
> 검증도 그 값에 기대지 않는다는 뜻이고, 다시 재 보니 실제로 하는 일이 없었다.
> 값은 원래대로 돌리고 **필드 노출만 남겼다** — 별에 관한 다른 수는 전부 프로필에
> 있는데 이것만 메시 루프 안에 박혀 있었다. **기본값이 같으므로 동작은 그대로다.**

### 4-1. 고르지 않은 다른 안

| 안 | 판단 |
| --- | --- |
| 띠를 없앤다 | **기각.** 은하수는 의도한 연출이고 화면에서 가장 보기 좋은 부분이다 |
| `bandCount` 를 줄인다 | **기각.** 천장을 낮추는 방향이라 하늘이 전체적으로 더 비어 보인다 |
| 띠 축을 눕혀 지평선 아래로 | **기각.** 몰림은 사라지지만 은하수가 안 보이게 된다 |
| 밝기 분포(`pow 2.4`)를 완만하게 | **보류.** 별이 전체적으로 밝아져 "우주" 느낌이 옅어진다. 최소 크기를 올리는 쪽이 부작용이 적다 |

## 5. 겸사겸사 고친 것 — 사각형이 하늘 바깥을 보고 있었다

유니티 자신의 규약(`Mesh.RecalculateNormals`)으로 재니 별 사각형의 법선이 **카메라를
등지고** 있었다.

```
방향 (0,0,1) → 유니티 법선 (0,0,1) · 카메라(원점) 쪽=False
```

그런데도 별이 보인다. 이유는 재질에 있었다.

```
셰이더 = NotThisPlanet/Flat · _Cull 속성 없음
FlatUnlit.shader:19    Cull Off
```

**셰이더가 컬링을 꺼서 뒤집힌 감김이 가려져 있었다.** 지금 보이는 결과는 같지만,
재질을 바꾸는 순간 **별이 통째로 사라지는데 아무도 막고 있지 않았다.** 감는 순서를
뒤집고 검증으로 잠갔다.

## 6. 검증이 왜 하나도 없었나 — 잴 수가 없었다

**`AtmosphereBackdrop` 을 재는 EditMode 검증이 0개였다.** 방향·밝기·크기를 정하는 일이
**메시를 짜는 루프 안에만** 있어서 "별이 고르게 있나" 를 물어볼 방법이 없었다.

순수한 값으로 떼어 냈다.

```csharp
public readonly struct StarPoint { Vector3 Direction; float Brightness; float Size; bool InBand; }
public static StarPoint[] BuildStarPoints(StarSettings settings, int starCount, int bandCount)
public static void  StarQuadAxes(Vector3 direction, out Vector3 right, out Vector3 up)
public static void  StarQuadVertices(Vector3 direction, float radius, float size, Vector3[] v, int offset)
public static void  StarQuadTriangles(int vertexBase, int[] triangles, int triangleBase)
public static float StarPixelSize(float size, float radius, float verticalFov, float verticalPixels)
```

### 6-1. 검증이 자기 사각형을 재고 있었다

처음에는 `TheStarQuadFacesTheCamera` 가 **검증 안에서 사각형을 새로 만들어** 쟀다.
그러면 **제품의 감김을 되돌려도 통과한다** — 아무것도 잠그지 못한다.

`StarQuadVertices` · `StarQuadTriangles` 를 따로 빼서 **검증이 제품의 함수를 쓰게** 했다.
그러자 대조에서 잡힌다.

### 6-2. "같은 씨앗이면 같은 하늘" 도 못 잡고 있었다

```csharp
var first = BuildStarPoints(settings, 200, 100);
var second = BuildStarPoints(settings, 200, 100);   // 한 실행 안에서 두 번
```

**한 실행 안의 두 호출만 견준다.** 씨앗에 시각을 더하는 대조가 **통과했다** — 같은
밀리초 안이면 값이 같기 때문이다.

값을 **못 박는 검증**(`TheSkyIsTheSameEveryRun`)을 따로 넣었다. 생성 방식을 일부러 바꿀
때는 이 수도 함께 고쳐야 하고, 그때는 그것이 의도한 변경이라는 뜻이다.

## 8. 남은 것

- **인게임 확인.** 숫자로는 2.92 → 1.77 이지만 눈으로 봐야 한다. 별이 너무 많아
  "우주" 가 아니라 "밤하늘" 로 보이면 `starCount` 를 낮추면 된다 — 에셋 값 하나다.
- **레거시 `Starfield.cs` 에 같은 문제가 있다.** 상수(1500 / 900 / 0.22)와 감는 순서가
  똑같다. 지금 Stage1은 쓰지 않아 건드리지 않았다. 다른 씬이 그것을 쓰는지 확인이 필요하다.
- **다른 스테이지의 분위기 프로필**이 생기면 같은 값을 써야 한다. 지금은 프로필이 하나뿐이라
  검증이 그 하나를 직접 읽는다 — 여러 개가 되면 검증도 전부를 돌아야 한다.
