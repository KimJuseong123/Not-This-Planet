# S15P21B202-334 낙하를 피해에서 자세 단계로 바꾼다

## 기획과 코드가 어긋나 있었다

| 기획 | 예전 코드 |
|---|---|
| §20.1 **체력, 사망과 영구 탈락은 없다** | `MaxHealth 100` · `Health` · `IsDead` 존재 |
| §20.2 낙하는 정상착지 / 휘청 / 넘어짐 / 기절 **4단계** | `ApplyFallDamage` 가 **체력을 깎았다** |
| §20.2 낙하에 **피해 없음** | `FallDamageBase 10 + 15×초과속도` |
| §20.2 기절은 **매우 높은 곳 + 머리부터**만 | 누적 피해로도 기절했다 |

```csharp
ApplyDamage(damage, "낙하");
    → Health -= amount
    → if (Health > 0f) return;
    → GoDown(source);        // 기절
```

### 저중력에서 이 차이가 컸다

```
점프 최고점       JumpSpeed 3.4 → v²/2g = 2.06m
예전 피해 시작    FallDamageMinHeight = 2.75m
```

평지 점프는 무사했지만 **조금 높은 지형에서 점프하면 넘었다.**

그리고 우주선 4층 접합부가 **5.71m** 에 있다. 저중력장으로 떠서 공중 용접(§14.3)을
하다 영역을 벗어나면 그 높이에서 떨어지는데, **기획이 요구하는 작업이 상시 체력
소모였다.**

## 고친 것 — 자세 4단계

| 단계 | 기획 §20.2 | 초기 테스트값 | 근거 |
|---|---|---|---|
| 정상 착지 | 낮은 높이에서는 정상 착지한다 | ~2.5m 이하 | **점프 최고점 2.06m 을 반드시 포함** |
| 휘청 | 중간 높이에서는 잠시 휘청인다 | 2.5 ~ 4.5m | |
| 넘어짐 | 높은 위치에서는 넘어지고 1~2초 뒤 스스로 일어난다 | 4.5 ~ 9m | **우주선 4층 5.71m 이 여기** |
| 기절 가능 | 매우 높은 곳에서 **머리부터** 충돌하면 기절할 수 있다 | 9m 초과 **+ 머리부터** | |

경계값은 기획 §1 이 말하는 **초기 테스트값**이다. 확정 규칙은 4단계 구조와 "머리부터"
조건이고, 수치는 플레이로 조정한다.

### 넘어짐은 `KnockDown` 을 그대로 쓴다

그 메서드의 주석이 이미 이렇게 적혀 있었다.

> 넘어뜨린다. **기절시키지 않는다.** … 체력도 깎지 않는다. 기획이 §12.2("뒤로 넘어질
> 수 있다")와 §18.3("넘어지지만 기절하지는 않는다") 두 곳에서 기절과 구분하기 때문이다.
> **세 곳이 같은 것을 필요로 해서 여기로 모았다** — 마지막 고정못(§12.2), 방망이 직접
> 타격(§18.3), 발사 실패 사출(§22.4)이다.

**낙하가 네 번째 호출자가 됐다.** 넘어지는 규칙을 두 번 쓰지 않는다.

### 회복 시간은 이미 맞았다

`uprightBlend` 가 넘어짐의 0.18 에서 1.0 까지 0.8/초로 오른다 → **약 1.03초.**
§20.2 의 "1~2초 뒤 스스로 일어난다" 안에 이미 들어와 있어 손대지 않았다.

### 휘청임만 새로 만들었다

`Ragdolled` 는 완전히 자빠진 것만 본다("머리가 골반보다 낮으면"). 중간 단계가 없었다.

```csharp
float want = Ragdolled ? 0.18f
           : Staggering ? PhysicsScale.FallStaggerUpright
           : 1f;
```

**`Ragdolled` 를 켜지 않는다.** 그것이 넘어짐과 휘청임을 가르는 것이다 — 걷기와 점프가
유지되고 세우는 힘만 잠깐 약해져 몸이 흔들린다.

### 머리부터 판정도 기존 식을 쓴다

```csharp
bool LandedHeadFirst() =>
    Doll.Head.position.y < Doll.Hips.position.y + 0.12f;
```

`UpdateSpeed` 가 자빠짐을 판정하는 식과 **같은 것**이다. "머리가 골반보다 낮으면
자빠진 것" 이라는 규칙을 두 번 적지 않는다.

## 범위 밖

**§20.1 의 체력 전체 제거는 하지 않았다.** 운석 피해 · HUD 체력 표시 ·
S15P21B202-266 의 피해 진단 로그가 얽혀 있어 큰 별건이다. 이 이슈는 **낙하만** 체력에서
떼어냈고, 그것만으로 §20.2 는 지켜진다. 운석은 계속 체력을 깎는다.

후속 이슈로 남길 것: **"체력을 걷어내고 §20.1 의 상태 기반 피해로 바꾼다"**

## 왜 지금 했는가 — 발사 실패 연출의 전제다

§22.4 가 발사 실패 후를 이렇게 정한다.

> 플레이어는 날아가고 잠시 구르지만 **기절하지 않고 자동으로 일어난다.**

잘못된 조립이 공중에서 부서지며 떨어지는 연출을 만들려면 플레이어가 높은 곳에서
떨어져도 기절하지 않아야 한다. 예전 낙하 피해가 있으면 그 연출이 §22.4 를 어겼다.

## 검증

새 `FallImpactTests` 13개.

```
develop : 786개 중 759 통과 / 27 실패
334     : 799개 중 772 통과 / 27 실패

334 에서만 실패 : 없음
```

### 검증이 뒤 스위트를 오염시켰다 — 원인을 대조 실험으로 잡았다

처음 전체 실행에서 `ShipAscentTests.Ascent_EndsAtAViewableAltitude` 가 실패했다
(42.9m, 기대 약 108m 의 40% 하한 43.2m 를 근소하게 밑돎).

원인을 좁히려고 세 번 측정했다.

| 실행 | 결과 |
|---|---|
| `ShipAscentTests` 단독 | **10/10 통과** |
| `FallImpactTests` + `ShipAscentTests` 둘만 | **23/23 통과** |
| **운영 코드만 두고 이 검증 파일을 뺀 전체 실행** | **786개 / 27실패 — develop 과 완전히 동일** |

세 번째가 결정적이었다. **낙하 변경 자체는 아무것도 깨지 않는다.** 검증 파일이 존재할
때만, 그것도 중간 스위트를 거쳐서 상승 검증이 넘어졌다.

원인은 **씬에 남은 인형**이었다. `_spawned` 에 담은 오브젝트를 지우고 `PlayerRig.All` 을
비워도 씬에 인형이 남아 뒤 스위트의 물리 질의에 섞였다.
`MeteorSpawnerTests` 가 운석을 정리하는 방식을 그대로 쓰니 사라졌다.

```csharp
foreach (var rig in Object.FindObjectsByType<PlayerRig>(FindObjectsSortMode.None))
    if (rig != null)
        Object.DestroyImmediate(rig.gameObject);
```

**기절시킨 인형을 되살려 놓고 지우는 것도 함께 넣었다** — `GoDown` 이 인형의 레이어를
`PlayerDowned` 로 바꾸고 구조·운반 상호작용 대상을 켜므로, 그 상태로 파괴하면 전역
등록이 남는다.

## 남은 것

- **인게임 확인이 필요하다.** 경계값이 초기 테스트값이다. 점프해서 떨어져도 멀쩡한지,
  우주선 4층에서 떨어지면 넘어지고 스스로 일어나는지, 매우 높은 곳에서 발부터
  떨어져도 기절하지 않는지 봐야 한다
- **휘청임의 세기(`FallStaggerUpright` 0.55)는 눈으로만 판단된다.** 너무 약하면 안
  보이고 너무 세면 넘어짐과 구분이 안 된다
