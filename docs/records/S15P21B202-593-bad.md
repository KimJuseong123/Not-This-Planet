F2 목록에 세 번째 춤 `BAD`(24.37초)를 넣는다. 지금까지 중 가장 길다.

두 곡일 때는 "둘로 늘려도 안 깨지는가" 가 물음이었다(576). 셋이 되면 물음이
바뀐다 — **개수를 박아 둔 자리가 어디인가.** 이 티켓에서 실제로 걸린 것도
동작이 아니라 그런 검증 한 줄이었다.

## 576 이 깔아 둔 길을 그대로 탄다

| 층 | 무엇 | 새로 쓴 것 |

믹서 입력 수는 576 에서 `2 + OneShots.Length` 로 고쳐 뒀으므로 따라왔다.
멀티는 새로 할 일이 없다 — `NetPlayer.danceSeq/danceId` 가 이미 **번호만**
나르므로 목록이 셋이 되어도 호스트와 참가자가 같은 클립을 돈다.

## 개수를 박아 둔 검증 하나가 있었다

```csharp
Assert.AreEqual(2, DanceCatalog.Count, "춤이 둘이 아니면 아래 검증이 뜻을 잃는다.");
```

셋을 넣는 순간 **동작은 멀쩡한데 이 줄이 먼저 터진다.** 576 에서 네 번 겪은
유형 R(고친 것을 재는 검증이 같이 안 낡는다)과 같은 모양이다. 그때는 매번
"동작이 틀렸나" 를 먼저 의심하느라 시간을 썼다.

그래서 개수를 빼고 **개수에 따라 갈리는지**를 보게 바꿨다
(`TheWheelHasExactlyOneSliceForEveryDance`) — 목록이 몇이든 칸의 한가운데를
가리키면 그 번호가 나오고, 두 칸이 같은 춤을 가리키지 않는지 본다. 네 번째
춤을 넣을 때 이 줄은 안 낡는다.

`OnlyTheLastPickedDanceIsLeftRunning` 도 같은 이유로 둘이 아니라 목록 전체를 돈다.

## 클립이 19.1MB 라 LFS 로 보냈다

732프레임 x 18뼈 x 쿼터니언 4성분 = 키 52,704개.

| | 키 | 최대 틀어짐 |
|---|---|---|
| 그대로 | 52,704 | — |
| 솎은 뒤(공차 0.0008) | **27,013** | **0.949도** (R_Forearm) |

굽기가 1.5도를 넘으면 실패한다. 더 깎을 이유는 없다 — 732프레임이라 어떻게
줄여도 비-LFS 한도(5MB)에는 못 들어가고, 깎을수록 회전 오차만 커진다.
`.gitattributes` 에 이 파일만 LFS 로 건다(563·576 과 같은 이유: 생성물이라
리뷰 가치가 없고, 읽을 수 있는 원본이 json 과 파이썬으로 커밋돼 있다).

`.gitattributes` 는 **바이트 단위로** 만졌다. 576 에서 파이썬 텍스트 왕복이
파일 안의 고립된 CR 을 줄바꿈으로 바꿔 주석 한 줄을 갈라놓은 적이 있다.

## 모션은 어디서 왔나

사람 영상 → MediaPipe world landmarks → 토끼 뼈대. 뼈 길이가 흔들리지 않아
3D 를 그대로 썼다(576 과 같다).

커밋한 json 은 소수 4자리로 줄였다 — REDRED 와 같은 형식이고, **반올림이
동작을 바꾸지 않는지 쟀다: 최대 각오차 0.0047도.** 툴이 읽지 않는
`dirs["Head"]` 는 뺐다(머리는 방향벡터가 아니라 세 각도로 얹는다). 안 읽는
값을 커밋해 두면 다음 사람이 그걸 고치려 든다.

### 손으로 고친 자리 넷 — 전부 사용자가 그림으로 짚었다

| 구간 | 무엇을 | 잰 값 |
|---|---|---|
| 1.0~2.4초 | 화면 오른쪽 다리를 들었다 **꽂기** 2번 | 봉우리 2번 · 최고 102도 |
| 2.4~4.3초 | 같은 다리를 **일자로** 바닥에 | 바닥에서 6.9도 · 무릎 굽힘 3.6도 |
| 10.0~11.7초 | 화면 오른쪽 팔이 왼쪽 팔을 **받친다** | 팔뚝 좌우 성분 −0.84 |
| 11.7~13.0초 | 팔꿈치는 하늘 · 팔뚝은 수직 아래 | 하늘에서 42도 · 아래에서 18도 |

좌우는 렌더로 확정한 것을 그대로 썼다: **`R_` 뼈 = 화면 왼쪽 = `−X`**.
576 에서 이름과 부호를 따로 정했다가 두 번 틀렸다.

### 구간 끝의 이음새가 모캡을 되살린다

두 번째 자리를 한 번 틀렸다. 붙이는 구간을 4.0초에 끝냈는데, 램프가 빠지면서
모캡이 돌아왔고 **하필 그 자리의 모캡이 다리를 드는 동작**이었다.

| 시각 | 허벅지가 바닥에서 |
|---|---|
| 2.8~3.8초 | 6.9도 |
| 3.9초 | **41.1도** |
| 4.0초 | **58.1도** |

"3~4초" 를 온전히 덮으려면 그보다 **뒤에서** 놓아야 한다. 구간을 2.4~4.3초로
늘려서 해결했고, 다시 재니 3~4초 최대 6.9도다.

**구간을 사용자가 말한 시각에 딱 맞춰 끊으면 그 끝이 덮이지 않는다.**
