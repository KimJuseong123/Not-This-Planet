# 원형 접합선 절단과 재조립 (S15P21B202-209)

[문서 안내](../README.md) → [작업 기록](README.md) → 조립·용접·발사

원형 접합선을 절단해 강도를 낮추고 재조립할 수 있도록 변경한 기록입니다. 절단 진행과 시간, 기존 강도 보간을 이용한 단계별 거동을 설명합니다.

본문의 “현재”, 검증 수치, 미완료 항목은 **기록 당시 기준**입니다. 후속 변경은 관련 이슈와 [주제별 색인](README.md)을 함께 확인합니다.

<a id="먼저-확인한-것--단계별-임계는-이미-나온다"></a>

## 기존 강도 보간에 따른 단계별 절단 반응

기획 §16.3 의 50%·75% 거동을 새 상수로 만들지 않았다. 접합부 강도가 이미 용접
비율로 보간되므로, 절단한 만큼 비율이 내려가면 강도가 그대로 따라온다.

| 절단 | 남은 용접 | breakForce | 기획 §16.3 |
| --- | --- | --- | --- |
| 0% | 100% | 200,000 | — |
| 50% | 50% | 104,000 | "즉시 분리되거나 기능을 잃지 않는다" |
| 75% | 25% | 56,000 | "강한 충격에 흔들리거나 변형될 수 있다" |
| 99% | 1% | 9,920 | "작은 충격에도 분리될 위험이 크다" |

처음에 "50%·75% 임계 구현" 을 할 일로 잡았다가 값을 계산해 보고 뺐다.
**새로 만든 것은 100% 절단 시 분리 하나다.**

<a id="절단을-용접-진행분-깎기로-표현할-수-없다"></a>

## 용접과 절단 진행도 분리

100% 절단하면 용접 비율이 0 이 되는데, 그 상태는 한 번도 용접하지 않은 접합과
같아진다. 그런데 기획은 두 경우를 다르게 다룬다.

- §15.1 — "잘 올리면 용접 전에도 서 있을 수 있고" → 용접 0% 는 **붙어 있다**(8,000)
- §16.3 — "100% 절단하면 해당 접합부 위쪽 파츠들이 하나의 덩어리로 분리된다"

값이 하나면 두 경우가 같아진다. 그래서 조각마다 절단 진행분을 **따로** 두고,
강도 기여를 `용접 × (1 - 절단)`으로 계산한다. 다 자르면 기여가 0 이면서
`IsSevered`로 분리까지 구분된다.

## `Welded` 가 종착 상태였다

`SpaceshipPart`의 전이표에서 `Welded`가 나가는 길이 없었다. 그러면 완전 절단해도
다시 들 수 없어 §16.3 의 "재조립" 과 "절단 전에 견인 조종 모듈로 받치면 안전하게
재배치할 수 있다" 가 성립하지 않는다.

`Welded → Placed` 하나만 열었다. `Carried`로 바로 가지 않는 이유는 **절단한 순간
파츠가 손에 들리는 것이 아니기 때문**이다 — 떨어지거나 견인빔에 받쳐 있다.
그 뒤에 집으면 된다.

기존 `Welded_IsTerminal` 검증을 `Welded_OnlyGoesBackToPlaced`로 고쳤다. 기대값만
바꾸지 않고 왜 종착이 아니게 되었는지를 남겼다.

## `CanWeld` 와 `CanCut` 을 합쳤다

처음에는 용접용·절단용 조건을 나누고 용접은 `Placed`만 받게 두었다. 검증을 쓰다가
**재용접을 확인하려면 파츠를 강제로 `Placed`로 돌려야 한다**는 것을 알았다. 그것은
실제 게임에서 §16.3 의 "절단한 구간은 좌클릭으로 다시 용접할 수 있다" 가 안 된다는
뜻이었다 — 주석으로 덮을 문제가 아니었다.

조건을 넓혀 `CanWork()` 하나로 합쳤다. 안전하다: 완전히 용접되고 잘리지 않은
접합선에서는 `TryWeld`가 채울 조각을 찾지 못해 아무것도 하지 않는다.
**"할 수 있는가" 와 "할 것이 있는가" 를 다른 곳에서 판정하는 편이 맞다.**

두 조건이 같아지자 `FindNearest(nozzle, forCutting)`의 인수도 필요가 없어졌다.

## 시간

| 상수 | 값 | 근거 |
| --- | --- | --- |
| `CutSeamSeconds` | 6초 | §16.3 "완전 절단의 최단 시간은 약 6초" |
| — | (조각당 0.5초) | 12조각 |

§16.3 의 "일반적인 시간 8~10초" 는 **상수로 넣지 않았다** — 206 과 같은 이유로,
겹쳐 대거나 되돌아오는 실제 플레이에서 나오는 값이다.

용접(10초)보다 빠른 것이 기획 의도다. 부수는 것이 만드는 것보다 쉬워야 실수를
되돌리는 부담이 작다.

<a id="한-자리-규칙을-다시-쓰지-않았다"></a>

## 기존 규칙의 재사용

§16.1 의 "같은 위치에 계속 대고 있어도 추가 진행되지 않는다" 가 절단에도 적용된다.
조각 구조가 이미 그것을 만든다 — 206 에서 규칙을 코드로 두 번 쓰지 않은 것이 여기서
값을 했다.

## 이번 작업에서 제외한 범위

- 견인으로 받치기 — `TractorBeam`이 이미 한다
- 위쪽 파츠를 덩어리로 묶기 — 서로의 접합이 남아 있으므로 필요가 없다
- 절단 자국·불꽃·절단음 ([Art]·[Sound]) — `Severed` 이벤트가 붙을 자리다
- 절단률 표시 — §16.2 가 **금지한다**
