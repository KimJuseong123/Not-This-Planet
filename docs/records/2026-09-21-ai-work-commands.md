# AI 작업 명령 통합 — 플레이 검증 전 초안

기준: `codex/ai-team-slots-local`, `S15P21B202-ai-integration-20260920/METAGAME`.
요청: 명령 실행 기능과 LLM 연결을 먼저 구현하고 실제 플레이 테스트는 추후 일괄 진행.

**완성 판정이 아니다.** 아래 명령에는 실행 코드와 라우팅이 있지만 실제 Stage1, 두 PC,
다양한 표현의 인식률은 이번 작업에서 검증하지 않았다. 자유 비행 및 정밀 작업에는 아래 제한이 있다.

## 실행 경로

ESC 개발 메뉴 → 직접 실행 버튼 또는 LLM 전송 → 로컬 실행기 `/api/companion-plan/text`
→ 허용 목록/계획 검사 → 방장 AI 대상 배정 → 기존 `InputFrame` 조작 → 실제 게임 판정.

- 명령 형식 버전: `work-v1`. 오래된 `social-v1` 실행기는 준비 완료로 인정하지 않는다.
- 최대 3개의 역할 배정, 배정당 최대 4단계. 무한 행동은 마지막 단계에만 허용한다.
- 대상: 선택한 AI(default), 한 명, 두 명, 전원, 빨강/파랑/노랑/초록, 앞 배정을 제외한 나머지.
- 명령을 기다리는 사이 사람이 들어오거나 AI에게 새 명령이 들어오면 기존 스냅샷/리비전 검사로 제외한다.
- 알 수 없는 계획은 실행하지 않는다. LLM이 허용된 다른 행동으로 오분류하는 문제까지 해결된 것은 아니다.
- 전역 중단은 진행 중 추론도 무효화한다. 실패한 작업 뒤의 예약 단계는 취소한다.
- 손 흔들기 외형은 이번에 수정하지 않았다. STT 연결과 참가자 PC 음성 전달도 범위 밖이다.

## 복합 명령

- `몽둥이 집고 운석 막아줘`: 같은 AI의 순차 작업 또는 도구 확보가 포함된 방어 작업.
- `노랑이는 못 다 뽑고 초록이는 운석 막아줘`: 대상별 별도 작업.
- `둘은 따라오고 나머지는 기다려`: 중복되지 않는 대상 배정.
- `못 다 뽑고 나한테 와`: 못 작업이 실제 완료되어야 다음 단계로 이동.

이 표현들은 **테스트용 예시**이며, 모든 문장을 LLM이 정확하게 분류한다고 검증한 결과가 아니다.

## 목적지 및 대상 규칙

- `default/speaker`: 요청자 옆 위치를 작업 시작 시 기록. 이동 중 요청자가 움직여도 목적지를 무한히 추적하지 않는다.
- `assembly`: 조립대 옆 하역 공간. 실제 씬의 장애물과 배치에 맞춘 조정이 필요하다.
- `aim/high`: 요청자가 바라본 걸을 수 있는 표면. 현재 언덕을 이름만으로 찾아내는 의미 지도는 없다.
- 파츠는 현재 상호작용 대상이 있으면 우선, 아니면 요청자 가까운 파츠를 선택한다.
- 못 여러 개는 한 파츠에 한정한다. 전체 맵의 모든 못을 자동으로 제거하지 않는다.
- 새로 생긴 오브젝트를 아무거나 선택하지 않도록 도구·파츠·장치 참조를 작업 동안 보존한다.

## 견인과 플레이어 보조의 중요한 경계

- 기존 광역 저중력장을 사용한다. 대상 위치/회전을 강제로 설정하거나 임의 조인트로 붙이지 않는다.
- 대상이 장 밖으로 벗어나거나 뒤처지면 운반을 멈추고 재확보한다.
- 비행은 현재 높이 확보 + 직선 이동 + 적재물 크기를 고려한 장애물 감지다.
  **복잡한 장애물을 돌아가는 완전한 3D 경로 탐색은 아직 없다.** 막히면 실패를 표시하고 정지한다.
- 저중력장은 특정 대상만 드는 도구가 아니다. 주변 다른 파츠에 영향을 줄 수 있다.
- 기존 플레이어는 장 안에서 자기 입력으로 이동하므로, `lift_player` 요청 중에만 짧은 수명의
  서버 부유 보조를 갱신한다. 수동 이동/상승/하강 입력이 우선하며 즉시 보조를 해제한다.
- 부유 보조는 기존 이동/수직 속도 처리에 들어가며, 순간이동이나 플레이어 입력 덮어쓰기를 하지 않는다.
- 중단은 장치를 정지시키되 저중력장을 끄지 않는다. 공중의 사람/파츠를 갑자기 떨어뜨리지 않기 위해서다.
- 파츠 하역은 기존 최소 부양 높이를 고려해 지면 가까이에서 필드를 끈다. 아래 파츠 자동 고정/자동 정렬 없음.

7. 종료·AI 토글·재접속·씬 전환 중 예약과 소유권 정리.

## 다음 일괄 플레이 테스트 순서

1. 직접 버튼으로 못 하나/모두 → 두 AI가 서로 다른 못을 맡는지.
2. 도구 집기/놓기/가져오기 → 누가 도구를 먼저 가져가면 안전하게 중단하는지.
3. 연습공 타격 → 운석 방어 → 중단 시 타격 입력이 남지 않는지.
4. 파츠 잡기/같이 끌기/놓기 → 벽이나 낙차에서의 실패 표시.
5. 낮은 파츠 용접/해제 → 실제 비드와 연결 변화, 높은 곳은 무리하게 실행하지 않는지.
6. 견인 탑승/이동/하차 → 파츠 인양/운반/하역 → 플레이어 운반과 수동 탈출.
7. 위 행동을 텍스트 LLM으로 동일 실행 → 대상별 분담 → 순차 작업 중 실패/중단.
8. 마지막으로 다른 PC에서 관찰·접속/퇴장·AI 토글 검증.
