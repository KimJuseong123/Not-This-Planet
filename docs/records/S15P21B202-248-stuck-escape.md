# S15P21B202-248 끼임 탈출을 §21 대로 고친다

## 기능은 이미 있었다

`Controls.Respawn = KeyCode.T` 에 **"끼었을 때 탈출" 이라는 주석까지** 달려 있었고
`GameSession:128` 이 그것을 읽었다. 다섯 군데에서 §21 을 어겼다.

| § | 기획 | 예전 |
| --- | --- | --- |
| 21 | `T`를 **3초 동안 유지**하면 | `GetKeyDown` — 즉시 |
| 21 | **가까운 안전 지면**으로 이동 | 스테이지 **스폰 지점**으로 순간이동 |
| 21 | **기절 중에는 사용할 수 없다** | `Revive` 를 불러 **스스로 일어난다** |
| 21 | 장비는 **이동 전 위치에 떨어진다** | 처리 없음 |
| 21 | 파츠·비행체·장비를 **복구하는 기능은 아니다** | `Transport?.Reset()` |

## 가장 심한 것 — 기절이 한 키로 풀렸다

`Revive(MaxHealth)` 가 §21 뿐 아니라 **§20 을 통째로 무너뜨렸다.**

- §20.3 "기절한 플레이어는 **동료가 구조할 때까지** 일어나지 않는다"
- §20.3 "솔로는 기절 후 **6초**가 지나면 자동으로 일어난다"
- §20.5 "모든 플레이어가 동시에 기절하면 **스테이지 실패**이다"

셋 다 `T` 한 번으로 우회됐다. **S15P21B202-247 이 방금 운석 직접 충돌을 한 번에 기절로
만들었기 때문에 지금부터 실제로 눌러서 쓰게 된다** — 그전에는 네 번을 맞아야 기절했으니
눈에 띄지 않았다.

기절과 구조는 1장의 협동 긴장(§26-13)이다. 자력으로 우회할 수 있으면 그 축이 없어진다.

## 무엇을 만들었나

`Respawn()` 을 **고치지 않고 놔뒀다.** 그것은 `Restart()` 도 부르는 함수고, 재시작에는
스폰 복귀·`Transport.Reset`·`Revive` 가 다 맞다. 잘못은 함수가 아니라 **`T` 가 그것을
부른 것**이었다.

`StuckEscape` 를 따로 만들고 `T` 를 그쪽에 붙였다.

```csharp
Escape?.Tick(Time.deltaTime, f.StuckEscapeHeld);
```

`MonoBehaviour` 가 아니다. 소유자가 `Tick` 을 부르므로 EditMode 에서 시간을 직접 넣어
검증할 수 있다 — **3초를 실제로 기다릴 수는 없다.**

### 진행분은 놓으면 버린다

고정못(§12.1)은 "좌클릭을 놓거나 운석에 맞아도 빠진 정도는 유지된다" 지만 여기는
반대로 했다. 유지하면 끼지 않았을 때 조금씩 눌러 모아 둘 수 있고, 그러면 "3초 유지" 가
아니라 **"합쳐서 3초"** 가 된다.

### 기절 중에는 쌓이지도 않는다

`Downed` 면 진행분을 **버린다.** 맞기 직전에 눌러 두고 기절한 뒤에 채우는 것이 되면
§20.3 의 구조 대기가 의미를 잃는다.

### 가까운 안전 지면

`SafeGround.TryFind` 가 반지름을 1m 씩 늘려 가며 8방향을 훑는다. 후보마다 위에서
지면을 향해 훑고, 그 위에 몸이 들어갈 자리가 있는지 캡슐로 본다.

**제자리는 후보가 아니다** — 끼어 있다는 것은 지금 자리가 안전하지 않다는 뜻이다.

못 찾으면 아무것도 하지 않고 `WaitingForRoom` 을 세운다. 벽 속으로 옮기는 것보다 낫고,
화면에 이유를 보여줄 자리가 필요하다 — 안 그러면 3초를 눌렀는데 아무 일도 없는 것으로만
보인다.

몸 크기를 새 상수로 두지 않았다. `RagdollBuilder.HelmetD`(0.636m, 가장 넓은 곳)와
`TotalHeight`(1.147m)에서 끌어낸다.

**지면과 자기 몸은 세지 않는다.** 발이 지면에 닿아 있는 것이 정상이고, 자기 팔다리가
"자리가 없다" 를 만들면 영영 못 나온다.

### 장비는 순간이동보다 먼저 놓는다

`DropEquipment()`(S15P21B202-247 에서 열렸다)를 `Teleport` **앞에** 부른다. 뒤에 놓으면
도구가 새 자리까지 따라온다.

`Teleport` 자체가 `ResetToolState()` 를 **순간이동 뒤에** 하는 순서라서, 앞에서 놓지
않으면 실제로 따라올 수 있는 구조였다.

## 검증 15개

| 묶음 | 무엇 |
| --- | --- |
| 3초 유지 | 2.9초엔 안 됨 · 3초에 됨 · 진행도 표시 · **놓으면 진행분 버림** |
| **기절 중 금지** | 진행도 안 쌓임 · **`T` 로 기절이 안 풀림** · 유지 중 기절하면 버림 |
| 가까운 안전 지면 | 지면 위에 섬 · 8m 안 · 지면 없으면 아무것도 안 함 · 막힌 자리 판정 · **지면과 자기 몸은 안 막음** |
| 장비 | 도구가 **이동 전 위치에** 남음 |
| 캐릭터만 | 옮긴 뒤 서 있음 · 두 번째는 3초 다시 |

전체 509개 중 496 통과. 실패 13개는 develop 에 이미 있던 것이다(S15P21B202-232 건).
494 + 15 = 509, 481 + 15 = 496 — **늘어난 실패가 없다.**

## 하지 않은 것 — 팀에 물을 것

**`Controls.Restart = KeyCode.R` 을 건드리지 않았다.**

§21 은 "게임 내 수동 스테이지 재시작 기능은 **제공하지 않는다.** 처음부터 다시 하려면
세션을 나가 새 게임을 시작한다" 고 정하는데, `R` 이 `GameSession.Restart()` 를 부르고
`Clear()` 가 남기는 안내문이 아예 **"R 을 누르면 처음부터 다시"** 다.

기획과 정면으로 어긋나지만 개발 편의 기능이기도 하고, 멀티에서 한 사람이 눌렀을 때의
동작은 [Network] 와 걸린다. 별 이슈로 떼어 팀에 물을 항목으로 남긴다.

그 밖에:

- 지형·콜라이더 개선(§21 "최종적으로 사용 빈도를 낮추되") — [Level] 몫이다
- 진행도 화면 표시 — `Progress01` 과 `WaitingForRoom` 을 열어 뒀다. UI 는 붙일 자리가 없다
- 소리·연출 — 재생 경로가 없다([Sound] · [Art])

## 인게임 확인은 못 했다

빌드가 develop 에서 멈춘다(지형 자산 체크아웃 손상 + 로비 씬 Volume Profile 누락).

EditMode 로 잠근 것은 **유지 시간·기절 금지·안전 자리 판정·장비 순서**다. 8m 탐색 범위가
실제 지형에서 충분한지는 인게임에서 봐야 한다 — 지형이 아직 손상돼 있어 더욱 그렇다.
