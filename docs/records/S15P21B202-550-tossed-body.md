# S15P21B202-550 — 던져진 몸이 실제로 던져진 상태가 되게 한다

> 신고: "던지면 던져지는 사람은 시점에 맞춰 몸이 래그돌 상태로 막 뒤집혀야 한다. 또
> 참가자는 시야가 뒤집히고 행동이 제어가 되는데 호스트는 시야도 안 뒤집히며 공중에서
> 행동이 자유로울 때가 있다."

## 한 줄

**`Tossed` 는 카메라 플래그 하나였다.** 몸에는 아무 일도 하지 않아, 던져진 사람이 선
자세로 날아가며 평소처럼 조종했다.

## 무엇이 잘못돼 있었나

`LaunchTossed` 가 하는 일은 셋뿐이었다 — `Doll.Bodies` 에 속도를 더하고, `Tossed = true`,
카메라·표시 갱신. 그리고 `Tossed` 를 읽는 곳은 `BodyViewActive` 와 `TickTossed` 둘뿐이었다.

**실측**(임시 EditMode 프로브, 커밋하지 않았다):

| 잰 것 | 값 |
| --- | --- |
| 던져진 뒤 1.2초 골반 기울기 | 0.8 → 1.6도 |
| 같은 구간 머리 기울기 | 8.0 → 2.8도 |
| **아무것도 아닌 몸**을 같은 속도로 띄웠을 때 | 0.7 1.3 1.5 1.6 1.6 1.5 |
| 던져진 몸의 같은 계열 | 0.7 1.3 1.5 1.6 1.6 1.5 — **완전히 동일** |
| 공중에서 옆으로 민 거리 · `Tossed=false` | 1.804m |
| 같은 것 · `Tossed=true` | **1.804m — 동일** |

**왜 안 뒤집혔나.** `UpdateSpeed` 가 매 틱 다시 계산한다.

```csharp
bool down = Doll.Head.position.y < Doll.Hips.position.y + 0.12f;
Ragdolled = down && !Hanging;
float want = Ragdolled ? 0.18f : Staggering ? FallStaggerUpright : 1f;
uprightBlend = Mathf.MoveTowards(uprightBlend, want, ...);
```

던져진 몸은 머리가 골반 위에 있으므로 `Ragdolled` 가 거짓이고 `uprightBlend` 가 1 로 남는다.
**세우는 힘이 계속 일해서 똑바로 선 채 날아간다.** `LaunchTossed` 에서 `Ragdolled = true` 를
한 번 써 봐야 **다음 틱에 지워진다.**

**호스트/참가자.** 경로 자체는 대칭이었다(실측) — 양쪽 다 `BodyViewActive` 가 참이 된다.
호스트 화면이 안 뒤집힌 것은 카메라가 `Doll.Head` 를 따라가는데 **머리가 2.8도밖에 안
기울어서** 뒤집힐 것이 없었기 때문이다. 공중에서 자유로운 것도 호스트만의 문제가 아니라
**원래 아무도 안 막혔다.**

## 고친 것

**고치는 자리는 `LaunchTossed` 가 아니라 기절 분기가 있는 그 자리다.** 한 번 쓰는 값은
`UpdateSpeed` 가 다음 틱에 지운다.

```csharp
public bool BodyOutOfControl => Downed || Tossed;
public bool BodyViewActive => BodyOutOfControl;
```

```csharp
if (BodyOutOfControl)      // 예전에는 if (Downed)
{
    UpdateFloating();
    Speed = 0f;
    Ragdolled = true;
    uprightBlend = 0f;
    Balance();
    return;                // 입력 처리를 통째로 건너뛴다
}
```

기절과 던져짐은 같은 것을 뜻한다 — 넉백은 받되 입력은 없고, 몸을 세우지 않으며, 시야는
몸을 따라 넘어갔다가 3인칭으로 물러난다. 조건을 두 곳에 따로 적어 두면 한쪽만 고치는
날이 온다.

**결과**(실측):

| | Ragdolled | 골반 기울기 계열 |
| --- | --- | --- |
| 그냥 띄운 몸 | False | 2.2 2.5 2.4 2.1 2.0 1.8 |
| **던져짐** | True | **2.0 2.8 2.8 2.5 2.4 2.4** |
| 기절 | True | **2.0 2.8 2.8 2.5 2.4 2.4** |

**던져짐과 기절이 숫자 하나 다르지 않다.** 이미 돌고 있던 기준과 같아졌다는 뜻이다.

## 제일 위험했던 자리 — `Grounded`

티켓에 "반드시 확인" 으로 적어 둔 것이다. 몸을 늘어지게 해 놓으면 발이 아니라 등으로
떨어질 수 있고, `Grounded` 가 발 기준이었다면 **던져짐이 영영 끝나지 않아 그 사람은
다시는 못 움직인다.**

읽어 보니 `ProbeGround` 는 **골반에서 아래로 쏘는 레이캐스트**이고 발을 보지 않는다.
하지만 영영 못 움직이는 결함은 읽고 넘길 종류가 아니라 **재서 지킨다** —
`ATossedPlayerLandsAndGetsControlBack` · `AfterLandingTheBodyStandsUpAgain` ·
`ControlComesBackAfterLanding` 셋이 바닥을 깔고 실제로 던져 착지시킨다.

## 검증

`TossedBodyTests` 9개.

- 던져진 몸이 기절한 몸과 **같게** 구는가 — 절대 허용치가 아니라 **거리 견주기**다
  (`|던져짐−기절| < |던져짐−그냥| × 0.4`). 처음에는 0.3도 절대 허용으로 쟀고, 솔버
  흔들림이 걱정돼 2.0도로 넓혔더니 실측값이 전부 그 안에 들어와 **회귀를 못 잡는
  테스트**가 됐다. 눈금이 아니라 비율로 재야 한다 (!460 AI 리뷰)
- 그리고 둘 다 아무 일 없는 몸과는 **다른가** — 예전에는 던져짐이 이쪽과 같았다
- 공중에서 못 움직이는가 · 점프가 막히는가
- 착지하면 끝나는가 · 일어서는가 · 조종이 돌아오는가
- 시야 규칙과 조종 규칙이 같은 조건인가
- 기절이 안 부서졌는가
- 참가자가 SyncVar 로 같은 몸을 받는가

### 테스트를 두 번 틀렸다

**(1) "던져지면 기울어질 것" 으로 쟀다가 0.0도가 나왔다.**
자유낙하에는 토크가 없다. 세우는 힘을 끄기만 하면 몸은 **선 자세 그대로** 떨어진다.
늘어지는 것과 구르는 것은 다른 일이다.

**(2) 회전을 억지로 넣어 봤더니 그것도 거의 안 굴렀다.**

| 준 각속도 | 최대 기울기 | 0.15초 뒤 남은 각속도 |
| --- | --- | --- |
| 2 rad/s | 1.4도 | 0.00 |
| 6 rad/s | 4.3도 | 0.00 |
| 12 rad/s | 8.5도 | 0.01 |
| **25 rad/s** | **15.7도** | 0.01 |

관절과 각저항(0.70)이 각속도를 0.15초 안에 먹는다. **다음 티켓(구르는 연출)은 각속도
임펄스만으로는 안 된다** — 관절 드라이브나 각저항까지 손대야 한다. 이 티켓에서 알아낸
것이므로 다음 티켓의 범위를 그만큼 다시 잡아야 한다.

그래서 최종 지표는 **"기절한 몸과 같게 구는가"** 다. 기절 쪽은 이미 그렇게 돌고 있으니
그것이 기준이고, 절대 각도로 재면 이 티켓이 내놓지 않는 것을 요구하게 된다.

## 남은 것

1. **2프로세스 눈 확인.** 특히 **참가자 화면이 왜 뒤집히는지**는 EditMode 로 확정하지
   못했다. 참가자 기계에서는 자기 몸이 로컬 물리로도 돌고 서버 자세로 보정되는데 그
   둘이 싸우는 것일 수 있다 — 참가자 쪽 뒤집힘이 **의도된 연출이 아니라 또 다른 결함**일
   가능성이 있다. 이 티켓에서는 건드리지 않았다.
2. **구르는 연출**은 위에 적은 대로 각속도만으로는 안 된다. 범위를 다시 잡는다.
3. **장비를 떨어뜨릴지** 정하지 않았다. 기획 §20.1 의 "강한 충격: 크게 날아가고 들고
   있던 장비를 떨어뜨림" 과 겹치는데, 던져짐이 그 "강한 충격" 인지는 기획에 없다.
   지금은 **떨어뜨리지 않는다** — 팔 구동은 `Ragdolled` 가 다리만 줄이므로 그대로 든다.
4. 착지 직후 바로 일어나는지 잠깐 누워 있는지도 기획에 없다. 지금은 `Balance` 가
   곧바로 일으킨다(측정: 착지 후 3초에 25도 미만).
