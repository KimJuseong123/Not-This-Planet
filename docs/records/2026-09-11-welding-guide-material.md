# 용접건 표면 가이드와 재료 잔량

## 동작

- 발사와 가이드는 `PlasmaWeldingTool.TryGetBeamHit`을 공유한다. 실제 월드 총구에서 조준 방향으로 `min(beamRange, 0.8m)` 안의 첫 외부 콜라이더를 찾는다. 자신과 소유자의 콜라이더, 트리거는 제외한다. 가리는 벽을 건너뛰어 뒤의 파츠를 선택하지 않는다.
- 기존 실제 판정은 조준 레이가 아닌 총구 주변 최근접 탐색이었다. 도구 입력을 레이 기반으로 변경했고 기존 `TryGrowNear` / `TryShrinkNear` API는 기존 호출자·검증 호환성을 위해 유지했다.
- 좌클릭은 맞힌 Part 몸체에 표면 법선 방향으로 비드를 시작하거나 맞힌 비드 사슬을 성장시킨다. 우클릭은 맞힌 비드 사슬을 절단한다. 기존 파츠별 개수·사슬 길이·접합 후 성장 제한은 유지한다.
- 클릭 전에는 용접 또는 절단 가능한 표면에 보라색 원을 표시한다. 누르고 있을 때는 해당 모드의 가능 여부를 따른다. 양 버튼 동시 입력, 사거리 밖, 무효 표면에서는 숨긴다. 잔량이 없어도 기존 비드 절단 예고는 가능하다.
- 원 둘레를 동일 콜라이더에 레이캐스트로 재투영한다. 표면에서 2mm 띄우고, 표면 밖 구간은 그리지 않는다. 작은 구형 비드에서는 원 크기를 줄인다. 표시에는 콜라이더가 없으며 로컬 소유자에게만 보인다.

## 재료와 UI

- 원래 제한은 파츠별 비드 개수와 길이이며 도구별 탄약은 없었다. 별도의 용접 재료를 도구 인스턴스에 추가했다.
- 기본 용량은 실제 용접 진행 시간 60초. `materialCapacitySeconds`로 조정한다. 성공한 용접 틱만 소모한다. 실제 절단이 진행된 시간만큼 절단한 용접건의 재료를 회수하며, 100%를 넘지 않는다. 헛발사·빈 공간 절단은 잔량을 바꾸지 않는다.
- 내려놓기·재장착·소유자 교체는 잔량을 초기화하지 않는다. 다른 용접건은 별도 잔량을 가진다. 새 도구 인스턴스는 가득 찬 상태로 시작한다. 세션 간 저장은 추가하지 않았다.
- `ViewProgress`에 남은 비율을 보내며 `WorldSync`는 내려놓은 도구도 전송한다. 권한 있는 서버만 소비하고 원격 화면은 받은 값으로 갱신한다. 기존 주기적 도구 스냅샷으로 패킷 손실 및 늦은 참가자에게 재전송된다.
- 레이 기반 비드 결과는 기존 비드 상태 스냅샷으로 전송한다. 도구에서는 기존 근접 탐색 재생 RPC를 호출하지 않아 원격에서 다른 사슬을 중복 성장시키지 않는다.
- 기존 `GameHud`에 용접건 위치를 화면으로 투영하는 잘린 부채꼴 게이지를 추가했다. 용접건 오른쪽에 노란색 연속 잔량과 0/25/50/75/100% 고정 눈금을 그린다. 현재 잔량을 나타내는 숫자는 표시하지 않는다. 용접하면 채움이 줄고 절단하면 늘어난다. 기존 UI 크기 설정을 적용한다.
- 씬·프리팹의 별도 연결이나 패키지 추가는 필요 없다.

## 검증

- 채움 미표시 후속 조사: 사용자는 고정 눈금은 보이나 노란색 채움은 보이지 않는다고 확인했다. 따라서 공통 표시 조건보다 잔량값 또는 채움 그리기 경로를 조사했다. 회전된 짧은 사각형으로 배경과 채움을 교차 그리던 방식을 `WeldingGaugeTexture`의 단일 부채꼴 이미지 합성으로 교체했다. 배경이 채움 위에 다시 그려지는 경로를 제거하고, 잔량 변경 시에만 이미지를 갱신한다. 기존 상태 소비·회수·네트워크 코드는 이번 표시 수정에서 변경하지 않았다.
- 표시 수정 검증: Unity 컴파일 및 `WeldingGaugeTextureTests;PlasmaWeldingToolTests` **16/16 통과** (`.local-validation/gauge-visible.xml`). 노란색 픽셀 면적이 100%→50%→0%→100%로 변하고, 절반 상태에서 아래쪽 채움만 유지되는지 검증했다. Unity에서 내보낸 `gauge-fill-100.png`, `gauge-fill-50.png`를 육안 확인했다.
- 원래 증상의 화면 재현은 미확정이다. 격리 진단 플레이어는 빌드·실행됐으나 숨긴 창의 캡처가 전부 검은 화면이어서 원본/수정본 인게임 시각 비교의 증거로 사용하지 않았다. 실제 Main 화면에서 채움 표시 및 소모·회수를 재확인해야 한다.

- 후속 변경(노란색 바·숫자 잔량 제거·절단 시 회수): Unity 스크립트 컴파일 및 `PlasmaWeldingToolTests` **14/14 통과**. 점진 회수, 100% 상한, 빈 공간 비충전, 절단한 도구만 충전되는 조건을 포함한다. 결과: `.local-validation/welding-refill.xml`. 화면의 실제 색상·배치는 플레이 검증하지 않았다.

- Unity 6000.5.4f1의 별도 검증 프로젝트 `outputs/tractor-tests`에서 스크립트 컴파일 및 관련 EditMode 테스트 **90/90 통과**. 결과: `.local-validation/welding-guide-final.xml`, 로그: `.local-validation/welding-guide-final.log`.
- 실행한 테스트 클래스: `PlasmaWeldingToolTests`, `WeldBeadTests`, `WeldBeadJoinTests`, `WeldBeadRestoreTests`, `NetworkReceivedStateTests`, `FirstPersonToolVisualTests`. 첫 실행의 2개 오류는 검증 복사본의 용접건 프리팹 누락이었다. 원본 프리팹과 참조 리소스를 복사한 최종 실행에서 두 오류 모두 해소되었다.
- 추가 검사는 예고/생성 위치 일치, 벽 차폐, 트리거 제외, 사거리, 헛발사 비소모, 도구별 잔량, 재장착 및 원격 복원, 빈 상태 절단, 원격 권한 차단, 마지막 소모량 제한, 클릭 전 표면 투영 및 해제 시 숨김을 포함한다.
- 실제 Main 플레이 화면의 배치·곡면 가독성과 두 PC 사이의 용접건 교환·늦은 참가 동기화는 별도의 플레이 확인이 필요하다. 자동 테스트 결과는 화면 및 다중 피어 검증을 대신하지 않는다.
