# S15P21B202-631 · 커마 미리보기 스포트라이트와 줌

외형을 고르는 화면에 무대 조명을 세우고, 휠로 줌 인/아웃 할 수 있게 한다.

## 조명을 얹기 전에 왜 어두운지부터 쟀다

지라에 "먼저 잴 것" 으로 적어 둔 대로 했고, **그 덕에 헛수고를 피했다.**

측정 장치를 세우는 데만 네 번 틀렸다. 그 과정 자체가 기록할 값이 있다.

| # | 무엇이 틀렸나 | 어떻게 드러났나 |
|---|---|---|
| 1 | 배경을 안 끄고 쟀다 | 밝은 화소가 **99.3%** — 캐릭터가 아니라 배경을 재고 있었다 |
| 2 | URP 에서 `Camera.Render()` 를 직접 불렀다 | 배경을 껐는데 숫자가 **한 글자도 안 바뀌었다**. 파이프라인이 그 호출을 안 탄다 |
| 3 | `GameObject.Find` 로 껐다 켰다 하려 했다 | **꺼진 오브젝트는 못 찾는다.** 배경 밝기를 잰다면서 카메라 단색(0.018)을 쟀다 |
| 4 | 평균만 봤다 | 평균 0.495 는 멀쩡한데 **하위 25% 가 0.196** 이었다 |

고치고 나서 나온 값(색공간 Gamma, 표시값 그대로):

```
캐릭터 평균 0.495 · 중앙값 0.620 · 하위25% 0.196 · 포화 0.0%
배경 0.018 · 대비 28배
```

밝은 면은 충분하고 **그늘진 쪽만 뭉개지고 있었다.** 포화 0% 라 더 밝힐 여유도
남아 있었다.

## 그런데 광원으로는 못 고친다

정면 스포트라이트를 넣고 다시 쟀더니 **숫자가 하나도 안 변했다.** 확인 사살:

| 잰 것 | 결과 |
|---|---|
| 광원을 **전부** 끄기 (키 3.5 · 필 2.5) | 그림 **완전히 동일** (0.495 → 0.495) |
| 스포트라이트 켬 vs 끔 | 차이 **0.000 · 최대 0** |
| GPU | 진짜 (RTX 4050 · D3D11) — 렌더 자체는 정상 |

셰이더(`CharacterSuitTint` · `DoughSurface`) 둘 다 `GetMainLight` 와
`_ADDITIONAL_LIGHTS` 를 쓰도록 **작성되어는 있다.** 그런데 이 씬에서는 그
경로가 전혀 기여하지 않는다 — 보이는 밝기는 환경광(`SampleSH`)과 셰이더에
박힌 평평한 항(`albedo * 0.30`)에서만 나온다.

본체 셰이더에 이미 이런 주석이 있다: *"커스터마이저의 어두운 배경에서도 흰
슈트의 형태와 색이 묻히지 않게 환경광에 부드러운 최소 밝기를 더한다"*.
**같은 문제를 한 번 겪고 조명 대신 셰이더로 해결한 자리다.**

그래서 실제 `Light` 컴포넌트는 **넣지 않았다.** 남겨 두면 다음 사람이
"이 광원이 뭔가 하고 있다" 고 오해한다.

## 요구가 바뀌었다 — 조명이 아니라 그림이다

사용자가 참고 그림을 줬다. 무대 조명의 **보이는 빛줄기**였다.

**Unity 의 Light 는 이걸 절대 안 그린다.** 광원은 표면을 밝힐 뿐이고 공기
중의 빛줄기는 URP 기본으로 렌더되지 않는다(볼류메트릭이 필요하다). 저렇게
보이려면 직접 그려야 한다 — 그리고 **그게 오히려 잘 됐다.** 가산 합성 메시라
위의 "광원이 안 먹는다" 와 무관하게 항상 보인다.

| 조각 | 무엇 |
|---|---|
| 빛기둥 | 원뿔 메시. 위가 밝고 아래로 옅어지며, **가장자리는 시선 각도로** 부드럽게 |
| 바닥 웅덩이 | 원반 메시를 눕혀서, 중심에서 방사로 옅어지게 |
| 위쪽 광원 | 같은 원반을 **카메라 쪽으로 돌려** 어느 각도에서나 동그랗게 |

`TractorFieldBeam` 을 재활용할까 했는데 트랙터빔용 줄무늬 애니메이션이 섞여
있어 무대 조명엔 안 맞았다. 전용 셰이더(`SpotlightGlow`)를 썼고, 셋의 모양은
`_RadialMix` 하나로 가른다.

### 축이 맞아야 한다

처음에는 광원을 앞옆으로 비스듬히 뒀다. 그랬더니 **정면에서는 왼쪽으로,
옆에서는 뒤로 쏠려** 보였다. 광원을 캐릭터의 세로축 위로 올리고 바닥 웅덩이
중심도 광원 바로 아래로 맞췄다 — 그래야 머리 위 고리·귀와 한 축에 놓인다.

(원래 바닥 중심을 광원의 35% 지점에 두고 있었다. 그게 원뿔을 기울인 원인이다.)

### 구도도 두 번 맞췄다

광원을 3.05m 에 뒀더니 **원뿔이 화면을 덮고 광원은 프레임 밖**이었다.
1.98m 로 낮추고 아래 반지름을 1.28 → 0.78 로 좁혔다. 줌아웃 범위도
1.35 → 1.75배로 늘려, 줌아웃하면 광원까지 다 들어온다.

## 줌

```
CustomizerBootstrap.cs  distance = Max(2.55, 1.48 / aspect) * zoom
```

**거리에만 건다.** 시야각을 건드리면 원근이 바뀌어 얼굴 비율이 왜곡된다.

입력은 기존 회전 입력과 **같은 자리**에서 받는다(`HandlePreviewRotation` 의
`ScrollWheel`). 미리보기 영역 안에서만 먹어야 오른쪽 선택 패널을 스크롤할 때
캐릭터가 딸려오지 않는다. **이 저장소의 첫 휠 입력이다** — 선례가 없었다.

## 검증

| 무엇을 지키나 |
|---|
| 빛기둥·웅덩이·광원 셋이 만들어진다 |
| **광원이 캐릭터 세로축(x=0, z=0)에 있다** |
| 웅덩이가 광원 바로 아래에 있다 |
| 광원이 캐릭터 키(1.147m)보다 높다 |
| 셋 다 가산 합성이다 — 불투명이면 캐릭터를 가린다 |
| 캐릭터가 어둡지도 하얗게 뜨지도 않는다 (렌더해서 화소로 잰다) |

밝기 검증은 **차지 비율에 위아래 한계를 둔다.** 너무 크면 배경을 재고 있다는
뜻이라, 1번 실수가 다시 나면 잡힌다.

## 남은 것

* **캐릭터 자체 밝기는 안 건드렸다.** 더 밝히려면 `previewBrightness`(1.65)가
  유일하게 확실히 먹는 손잡이다. 빛기둥이 생겨 무대처럼 보이므로 이번엔 두었다
* **광원이 왜 표면에 기여하지 않는지**는 안 팠다. 별개 작업이다 — 풀면
  입체감 있는 하이라이트를 쓸 수 있다
* 엔딩 개인 컷씬에도 같은 스포트라이트를 쓴다. `SpotlightGlow` 셰이더와 메시
  빌더를 그대로 재사용하되 **무대 레이어(31) 컬링 마스크**를 맞춰야 한다
