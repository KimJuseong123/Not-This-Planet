# Stage1 공세 컷씬 운석 연출 (630)

- 브랜치: `S15P21B202-630-art`, 기준 `85ed2c03`.
- 대상: `Stage1_AssaultCutscene` (8초).
- 1초부터 기존 운석 모델 12개가 서로 다른 낙하 단계로 반복 등장한다. 크기, 회전, 궤적 길이에 차이를 주고 낙하 중 가속한다.
- 컷씬의 공통 시각을 기준으로 위치를 계산하며, 매 프레임 생성하지 않는다. 각 궤적의 시작과 끝에서는 크기와 꼬리를 줄여 반복 위치 이동을 감춘다.
- 2~5초 하늘 샷에 이어 5~8초에도 조립대 주변 넓은 구도를 유지한다. 마지막 샷의 시선을 높여 여러 운석과 기지가 함께 보이게 한다.
- 경고음과 조명 점멸은 기존 흐름을 사용한다. 추가 운석은 피해와 충돌이 없는 로컬 연출이며 기존 실제 공세의 생성 간격과 네트워크 권한은 변경하지 않는다.
- 종료 시 추가 모델과 궤적을 제거한다. 씬 재생성 도구에도 같은 마지막 샷 시선을 적용했다.
- 확인 방법: 이 워크트리의 `METAGAME`을 Unity 6000.5.4f1로 열고 `Stage1_AssaultCutscene`을 재생하거나 Stage1 탐색 중 F9를 누른다.

## 검증

`Stage1CutsceneTests.ActualWorldSurvivesBothCutscenesAndRestoresCamera`에 운석 12개 생성, 물리/피해 컴포넌트 부재, 마지막 샷 화면 안 운석 3개 이상 배치, 종료 후 제거 검사를 추가했다.

- Unity 6000.5.4f1 컴파일 및 `Stage1CutsceneTests` **11/11 통과**. 워크트리의 `tmp/assault630/assault-tests.xml`, 루트 `assault-tests-retry.log`에 로컬 결과를 남겼다.
- 그래픽 Play Mode에서 F10/F9 재생 후 동일 플레이어 유지, 카메라·입력 복구, 공세 간격 10.5초를 확인했다. `tmp/assault630/runtime.txt`에 결과가 있다.
- 같은 폴더의 `assault-0004.jpg` (3.043초), `assault-0008.jpg` (6.077초)를 직접 확인하여 하늘과 기지 구도 모두 여러 운석과 궤적이 함께 보임을 확인했다. 캡처는 카메라 렌더이며 IMGUI 레터박스는 포함하지 않는다.
- 그래픽 검증에서는 기존에 기록된 `UrpProjectSetupAutoRunner`의 Play Mode 저장 예외와 Unity 검색 인덱스 예외가 관찰됐다. 검색 예외의 기존 발생 여부는 확인하지 않았다. 컷씬 재생과 복구는 완료됐으며 해당 도구는 수정하지 않았다.
- 실제 다중 클라이언트 및 배포용 Player 빌드는 수행하지 않았다.
