# 방장 기준 AI 사용 정책 — 로컬 작업

기준 체크포인트: `d60c4c8f` (AI 자리 관리 `9be02d42`).
기존 사용자의 렌더링/빌드 설정 변경은 보존한다. 이번 작업은 씬/프리팹/물리 설정을 바꾸지 않는다.
초기 작업은 로컬 변경으로 진행했다. 2026-09-21 사용자 요청으로 로컬 체크포인트 커밋을 남긴다. Jira 등록, push, MR은 하지 않는다.

## 동작

- 새 방은 AI 사용 꺼짐으로 시작한다. WAITING 상태 로비의 방장만 설정할 수 있다.
- 게임 접속/서버 실행 중에는 방장도 사용 선택과 개발용 테스트 선택을 바꿀 수 없다. 실행기 상태 변화와 방장 이전 승계는 별도로 처리한다.
- `사용 선택`과 `실제 로컬 실행기 준비 상태`를 분리한다.
- 사용 켜짐 + Ready일 때만 빈자리를 채운다. Missing/Loading/Failed이면 사람들만 플레이한다.
- 실행 준비를 잃으면 서버가 AI의 장비를 내려놓고 AI를 제거한다. 사용 선택을 켜 둔 실행기가 회복되면 빈자리를 다시 채운다.
- 기존 4자리 배정, 사람 입장 시 AI 교체, 퇴장 5초 후 빈자리 채우기는 정책이 허용할 때만 작동한다.
- 게임에서 상태는 기존 WorldSync의 SyncVar로 공유한다. 늦게 참가한 사람도 현재 상태를 받는다.
- 참가자의 모델 설치/로컬 준비 상태는 방의 판단에 쓰지 않는다.
- 방장 이전에는 이전 방의 사용 선택만 승계하고, 새 방장 PC의 준비 상태를 다시 적용한다.
- 개발용 테스트 모드는 새 방장에게 자동 승계하지 않는다.

## 화면

- 로비 → 새 방 만들기 → `AI 동료 사용` (방장만 변경).
- 게임 → Esc → 현재 상태와 로비에서 변경할 수 있다는 안내만 표시 (방장·참가자 모두 읽기 전용).
- 로비는 Spring WebSocket, 게임은 Mirror를 사용한다. 이번 변경은 백엔드를 수정하지 않는다.
  따라서 로비 참가자에게는 `게임 입장 후 방장의 AI 상태가 표시됩니다`라고 명시한다.

## 지금 가능한 테스트

현재 브랜치에는 행동/모델 실행기가 없다. 기본 상태는 `Missing`이며, 일반 사용을 켜도 AI가 생기지 않는 것이 정상이다.
에디터 또는 Development Build의 대기 로비에서만 `대기 AI 테스트`를 명시적으로 켤 수 있다.
그 경우 상태는 `대기 AI 테스트 · 명령 수행 없음`이며 Ready로 위장하지 않는다.
일반 배포 빌드에는 이 테스트 버튼/활성 경로가 없다. 테스트 선택은 저장하지 않는다.

추후 실행기는 `IAiRuntimeStatus`를 구현하고 `AiHostSettings.BindRuntime`으로 연결한다.
모델 존재만으로 Ready를 주면 안 된다. 로딩/추론과 결정론적 행동 실행 준비까지 확인해야 한다.
종료/실패 시 상태를 갱신하고, 실행기 해제 시 `BindRuntime(null)`을 호출한다.
이 연결 지점은 로컬 코드 전용이다. 클라이언트가 Ready라고 주장하는 Command는 만들지 않는다.
