# 663: 식생·오브젝트 텍스처 조사

- 기준: `S15P21B202-663-qa`, `7b69e199`, Unity 6000.5.4f1 / URP 17.5.0.
- 워크트리: `.local-worktrees/663-qa`.
- 요청: 혼자하기와 멀티플레이에서 일부 식생·오브젝트의 텍스처가 보이지 않는 원인 조사 및 수정. 화면 직접 조작 금지.
- 상태: **사용자가 제공한 런처의 v1.2.0 배포본에서 텍스처 누락 확인. Linux의 대소문자 구분으로 Git LFS 복원이 빠지는 원인을 재현하고 수정했다.** 아래 첫 조사는 Windows 소스 검사였으며 배포본의 정상 동작을 보장하지 못했다.

## v1.2.0 배포본으로 확인한 원인

1. `NotThisPlanetLauncher.exe --check`를 숨김 실행했다. 서버 버전 v1.2.0, 설치된 225개 파일(928.8MB)이 모두 일치하며 받을 파일은 0개였다. 설치 파일 손상이나 구버전 혼합이 아니라 배포된 에셋 자체의 문제다.
2. 설치된 게임의 `resources.assets` 및 `sharedassets*.assets`를 읽기 전용으로 분석했다. 소스에서 `.JPEG`를 참조하는 **머티리얼 24개**의 `_BaseMap` 참조가 배포본에서는 비어 있었다: 번호 식생 7종, 큰/작은 보라꽃 2종, 조립 시설 5종, 볼라드 8종, 방망이/용접건 받침대 2종. 의도된 단색 머티리얼과 사용하지 않는 `_MainTex` 제거는 이 숫자에서 제외했다.
3. 설치된 게임의 내장 `-space-screenshot` 모드로 실제 실행 및 자동 촬영을 수행했다. UI 직접 조작 없이 실행·종료됐으며, 시작 장면의 도구 받침대가 흰색 단색으로 출력되는 것을 확인했다. 자동 촬영 모드에는 진입 컷신의 카메라 제어가 개입하므로 모든 식생 위치를 시각 재현한 것으로 주장하지 않는다.
4. 저장소에는 대문자 `.JPEG` 파일이 **161개** 있다. 기존 `.gitattributes`는 `*.jpeg`만 지정했다. Windows 저장소의 `core.ignorecase=true`에서는 LFS가 적용되지만 Linux와 같은 `core.ignorecase=false`에서는 `filter: unspecified`가 된다. Linux CI는 이미지를 받지 않고 LFS 포인터 텍스트를 Unity에 전달한다. 유효한 텍스처로 임포트되지 않아 결과물의 참조가 null로 저장된다. 솔로/멀티가 같은 에셋을 사용하므로 양쪽에 나타난다.
5. 대표 파일 `01-ribbon-grass_basecolor.JPEG`에 `git -c core.ignorecase=false cat-file --filters HEAD:<path>`를 적용해 재현했다. 수정 전은 **135바이트 LFS 포인터**, 수정 후는 **1,349,431바이트 실제 이미지**다. 수정 후 SHA-256은 Git LFS 포인터에 기록된 `6e53d463cd661cbc746ffee66eb6a12af5fe3da1eb9d8df13557cfea922368be`와 일치한다.

## 수정과 회귀 방지

- `.gitattributes`: JPEG 확장자를 `[jJ][pP][eE][gG]`로 지정해 Linux에서도 같은 바이너리가 복원되게 했다. 파일 이름·GUID·씬·프리팹·머티리얼을 변경하지 않는다.
- `scripts/ci/validate_unity_lfs.py`: 추적 중인 Unity 에셋을 읽어 아직 포인터이거나 읽을 수 없는 파일이 있으면 실패한다. 확장자나 현재 LFS 속성에 의존하지 않으므로 같은 형태의 누락을 감지한다.
- `.gitlab-ci.yml`: 컴파일, 릴리스, 개발/QA 빌드에 Unity 실행·테스트 결과 재사용 전 검사를 추가했다. MR에서 속성/검사 스크립트만 바뀌어도 Unity 검사를 실행한다.
- `unity_reuse.py`: LFS 속성 및 사전 검사 스크립트가 바뀌면 이전 Unity 검사 결과를 재사용하지 않도록 입력 지문에 포함했다.
- 새 회귀 검사에서 수정 전 `.JPEG`/`.Jpeg`/`.jPeG`가 실패했고 수정 후 통과했다. 미복원 포인터 차단, 정상 이미지/텍스트 허용, 누락 파일 차단, 세 CI 작업의 사전 검사 순서도 검증한다.
- Linux 대소문자 조건에서 `.JPEG` **161/161개**에 LFS 속성이 적용되고, 현재 체크아웃의 Unity 에셋 **5,657개** 사전 검사가 통과했다.
- CI 오프라인 검사 전체 **79개 통과, 0개 실패**(`scripts/ci/tests/run_all.py`, Git Bash 사용). 새 LFS 회귀 검사 5개도 포함한다. 최초 제한 환경의 WSL 접근 거부로 실패한 셸 검사 5개는 Git Bash에서 모두 통과했다.

배포된 v1.2.0 설치 파일은 수정하지 않았다. 실제 사용자에게 반영하려면 이 수정으로 Linux CI에서 새 게임을 빌드하고 새 버전을 배포해야 한다. 이번 작업에서는 원격 빌드/배포와 실제 멀티클라이언트 실행을 하지 않았다. 런타임 로직 변경이 없어 물리·식생 상호작용·네트워크 동기화 경로는 그대로다. 사전 검사는 불완전한 체크아웃을 새로 차단하는 의도적인 CI 동작 변경이다.

런처 검사 출력, 배포 머티리얼 비교 JSON, 실제 실행 로그 및 자동 촬영 이미지는 `.local-validation/texture-663/`에 보관했다. 이전 조사의 임시 진단 스크립트도 같은 폴더에 있다.

## 배포본 제공 전 Windows 소스 조사 근거

1. 모든 `.mat`의 저장된 텍스처 GUID를 에셋 `.meta`와 대조했다. 참조가 있는 텍스처의 누락이나 LFS 포인터만 남은 파일은 발견하지 못했다.
2. 새 워크트리에서 에셋을 임포트하고 Unity 배치모드로 빌드에 등록된 9개 씬을 읽었다. Renderer의 실제 머티리얼 슬롯에서 null 및 Standard 셰이더를 발견하지 못했다. 텍스처가 연결된 메시의 UV0 누락도 발견하지 못했다. 씬은 저장하지 않았다.
3. Stage1_Astra를 자동 Play Mode로 진입시켜 60 프레임 후 Renderer를 조사했다. 번호 식생 7종(총 459개 렌더러), 버섯나무 95개, 꽃 무리 23개, 작은 보라꽃 17개, TinyFlowerPatch 10개의 텍스처 연결이 유지됐다. null 머티리얼/셰이더는 없었다. 이 검사는 혼자하기 경로이며 다중 클라이언트 검증이 아니다.
4. 번호 식생 7종을 별도 빈 씬에 배치해 GPU RenderTexture로 실제 출력했다. 잎·꽃의 색과 텍스처가 표시됐다. 사용자 화면 캡처 또는 UI 조작 없이 자동 생성한 이미지다.
5. 회귀 테스트 **35/35 통과**: VegetationInteractionTests(실제 Play Mode 접촉·흔들림 포함), TinyFlowerPatchBuilderTests, AssemblyDockVisualTests, PlayerFogExemptionTests, ArtLinkCleanupTests, AuthoredMapSettingsTests.

## 조사 중 구분한 사항

- 일부 장식, 안내등, 임시 지오메트리, Stage2 블록아웃, 발사대 상태 표시는 의도적으로 단색 또는 절차적 셰이더를 사용한다. `mainTexture == null`만으로 이들을 결함으로 판정하면 기존 상태 표시와 연출을 훼손할 수 있다.
- PlantRustle은 시각 자식의 회전을 변경하며 머티리얼 또는 텍스처를 교체하지 않는다.
- UrpRenderValidation.AddMaterialDependencies는 `.mat` 경로만 수집하므로 주석과 달리 FBX 내장 머티리얼 검사가 빠진다. 이번 실제 씬 조사에서 사용 중인 내장 재질 문제는 발견되지 않았으므로 보고 증상의 원인으로 확정하지 않았다.
- 자동 Play Mode 진입에서 기존 convex mesh의 256 폴리곤 제한 경고 4개가 발생했다. 텍스처 오류는 아니며 테스트 실패나 C# 컴파일 오류는 없었다.

## 배포본 제공 전 변경 및 증거

게임 코드·씬·프리팹·머티리얼에 추측성 수정을 적용하지 않았다. 임시 검사 코드는 Assets 밖으로 옮겼다. Unity 자동 설정/직렬화 변경은 원복했다. 원래 develop 작업 폴더의 사용자 수정은 건드리지 않았다.

검사 스크립트, 로그, XML 결과, 씬/런타임 머티리얼 목록과 `texture-plants.png`는 워크트리의 `.local-validation/texture-663/`에 로컬 증거로 보관한다.

## 당시 남았던 재현 정보와 한계

- 텍스처가 빠진 스테이지·위치 또는 오브젝트 이름.
- 흰색/회색 단색, 분홍색, 면의 투명화 중 실제 증상.
- Unity Editor 실행인지 배포된 게임인지, 배포 버전과 그래픽 품질.

확인 후 같은 위치에서 재현하고 셰이더 출력/조명·안개/모델 면/빌드 셰이더 변형 제거 문제를 구분해야 한다. 이번에는 실제 배포 플레이어 빌드 및 호스트·클라이언트 동시 실행을 검증하지 않았다. 연결 검사와 대표 렌더링의 성공이 사용자가 보고한 모든 위치의 정상 동작을 보장하지 않는다.
