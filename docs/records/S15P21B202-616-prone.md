# S15P21B202-616 · Z 로 엎드려 폭풍을 피하고 기어다닌다

`Z` 토글로 엎드린다. 엎드린 동안은 **모래폭풍에 맞지 않고** 0.9m/s 로 기어서
이동한다. 다시 누르면 일어선다.

## 폭풍은 자세를 전혀 보지 않았다

`Stage1DustStormHazard.ApplyImpulses` 가 하는 일은 하나다:

```csharp
Physics.OverlapBoxNonAlloc(pose.Center, pose.HalfExtents, overlapBuffer,
                           pose.Rotation, settings.affectedLayers, ...)
```

**래그돌 콜라이더가 상자에 겹치는가.** 레이캐스트도 시야도 엄폐도 없다
(런타임 전체에서 `shelter` 류 0건). 상자 밑면은 사실상 지면이고
(`groundClearance = 0.08m`) 캐릭터는 1.147m 다 — **누워도 그대로 걸린다.**

그래서 면제를 한 줄로 넣었다. `wake` 가 이미 같은 자리에서 세기 배수를 곱하고
있어 자리가 자연스럽다. **서버에서만 도는 자리**라(`physicsAuthority`)
남의 화면과 판정이 갈리지 않는다.

> 덧: 지금 폭풍은 **피해를 주지 않는다.** 맞으면 `KnockDown` 뿐이고,
> 피해를 주는 `Stage1DustStormFragment` 는 생성하는 곳이 없다. 바람 관련 필드
> 셋은 `[HideInInspector]` 에 읽는 곳이 없는 죽은 값이다. 이 티켓이 주는
> 이득은 현재 "넘어지지 않는다" 까지다.

## 물리를 새로 만들지 않았다

| 무엇 | 선 자세 | 엎드린 자세 |
|---|---|---|
| `Hover` 목표 높이 | `Tuning.RideHeight` 0.30m | `ProneRideHeight` **0.13m** |
| `Balance` 목표 회전 | `LookRotation(faceDir, up)` | 거기서 **84도 앞으로** |
| 이동 상한 | 걷기 2.9 · 달리기 4.6 | **0.9m/s** (곱이 아니라 상한) |

### `uprightBlend` 을 0 으로 하지 않았다

그게 제일 싸다 — 기절(`GoDown`)이 그렇게 한다. 하지만 그건 곧 **래그돌로
무너지는 것**이고, 그러면 기어가는 방향을 못 잡는다. 세우는 힘은 살려 두고
**목표 회전만 눕혔다.**

### `Ragdolled` 가 저절로 켜진다

```csharp
bool down = Doll.Head.position.y < Doll.Hips.position.y + 0.12f;
Ragdolled = down && !Hanging && !Prone;
```

엎드리면 머리가 골반보다 낮아져 이 검사가 켜진다. `Ragdolled` 는
`State.Blocked` 에 들어가므로 그대로 두면 **기어가기가 통째로 죽는다** —
눈으로는 "엎드려는 있는데 안 움직인다" 로만 보인다. 매달림과 같은 이유로 뺐다.

## 검증이 진짜 결함을 하나 잡았다

`BeingDownedClearsTheProneState` 가 실패했고 **테스트가 아니라 구현이
틀렸다.** 자세 해제를 보행 계산 옆에 뒀는데, 기절하면 `BodyOutOfControl` 분기가
**그 전에 `return`** 한다. 그래서 엎드린 채 기절하면 `Prone` 이 켜진 채 남고
**기절한 사람이 폭풍 면제를 계속 받았다.** 해제를 `Tick()` 맨 앞으로 옮겼다.

## 입력 — 토글인데 눌린 상태를 보낸다

누름(`GetKeyDown`)은 한 프레임짜리 펄스라 중복 제거나 유실에 걸리면 토글이
통째로 사라진다. **눌린 상태를 계속 보내고 서버가 가장자리를 잡는다** —
구조(G)와 같은 모양이다.

입력 하나에 다섯 곳이 붙는다: `InputFrame` · 키 상수와 리매핑과 중복검사와
로비 설정 UI · `Controls.Read()` · **`NetPlayer.Same()`** · 억제 2곳.
네 번째가 빠지면 **눌러도 서버가 모른다**(같은 프레임으로 보고 안 보낸다).
`StuckEscapeHeld`(T)가 지금 그 상태로 죽어 있다 — 검증으로 잠갔다.

## 멀티

`downed` 와 같은 모양이다: **입력 비트(클라→서버) + 결과 SyncVar(서버→전원).**
서버가 `prone = body.Prone` 로 물리 결과를 적고, 훅이 남의 몸에
`SetRemoteProne` 을 건다. 이게 없으면 **남의 화면에서 그 사람의 `Balance` 와
`Hover` 가 선 자세를 목표로 잡아** 자세가 어긋난다 — 골반은 서버가 보내 주지만
팔다리는 각자 기계의 조인트가 잡기 때문이다.

## 클립 넷

| 클립 | 길이 | 순환 |
|---|---|---|
| `Rabbit_ProneIdle` | 1.97초 | ○ |
| `Rabbit_Crawl` | 1.17초 | ○ |
| `Rabbit_LieDown` | 0.60초 | ✕ |
| `Rabbit_StandUp` | 0.90초 | ✕ |

**대기와 기어가기가 순환이 아니면 클립이 끝나는 자리에서 굳는다** — 에러 없이
"엎드려서 안 움직이는" 그림만 남는다. 검증이 이 넷의 순환 여부를 잠근다.

**몸이 눕는 것은 클립에 없다.** 그건 물리가 한다. 클립은 그 위에 얹히는 팔다리
모양만 맡는다 — 둘 다 눕히면 두 번 눕는다.

기어가는 주기는 **실제 속도에 맞춘다.** 고정 속도로 돌리면 제자리에서 팔다리만
젓거나 미끄러지듯 밀려간다.

### 완전히 굳은 대기는 구울 수 없다

굽기가 "안 움직이는 뼈" 를 거부한다(563 부터의 가드 — 뼈 이름이 어긋난 것과
구별할 수 없어서다). 처음 만든 대기는 8/18 이 정지였다. 숨 쉬는 정도의 흔들림을
팔다리에도 줘서 풀었다 — **어차피 완전히 굳은 대기는 죽어 보인다.**

손과 발은 팔뚝·종아리에서 파생되므로(손목 지연 · 발 평탄화) 진폭이 너무 작으면
파생 뒤에 값이 같아져 여전히 "정지" 로 잡힌다. 두 번 만에 맞췄다.

## 검증 13개 (`ProneTests`)

| 무엇을 지키나 |
|---|
| Z 로 켜지고 다시 눌러 꺼진다 |
| **누르고 있는 동안 매 틱 뒤집히지 않는다** |
| **엎드린 것과 조종을 잃은 것이 다르다** (`Ragdolled` 가 안 켜진다) |
| 기어가는 속도가 걷기의 40% 아래다 |
| 엎드리면 골반이 낮아진다 |
| 기절하면 자세가 풀린다 (폭풍 면제가 따라가지 않는다) |
| 남의 몸에도 자세가 선다 |
| **눌린 상태가 `Same()` 에 들어 있다** |
| Z 가 기어오르기(LeftCtrl)와 안 겹친다 |
| 폭풍 판정이 자세를 본다 |
| 클립 넷이 다 들어 있다 |
| **유지 자세는 순환, 전환은 아니다** |
| 엎드린 자세가 실제로 뼈를 움직인다 |

### 검증이 남의 스위트를 깨뜨렸다

엎드리기는 접지 상태에서만 켜지므로 검증에 바닥을 놔야 한다. 그런데
`DestroyImmediate` 로 지워도 **물리 씬은 다음 동기화까지 콜라이더를 들고
있어서**, 다음 스위트의 레이캐스트가 이미 지운 바닥을 맞혔다 —
`StuckEscapeTests` 의 "지면이 아무 데도 없을 때" 가 실제로 깨졌다.
뒷정리에 `Physics.SyncTransforms()` 를 넣어 고쳤다.

바닥을 놓을 때도 같은 함정이 있었다. **놓자마자는 물리 씬에 등록되지 않아**
`Grounded` 가 끝내 false 였다 — "토글이 안 된다" 로 네 번 봤다.

## 곁가지 하나를 같이 고쳤다

`WeldingJointGuide.Hide()` 가 `root.SetActive(false)` 를 널 검사 없이 한다.
바로 위 `Visible` 은 `root != null` 을 이미 검사하는데 여기만 빠져 있어,
안내선 오브젝트가 먼저 지워진 뒤 `OnDisable` 이 오면
`MissingReferenceException` 이 난다. 씬 정리 순서에 따라 터지는 자리이고,
이 티켓의 검증이 그 순서를 만들어 드러났다. 한 줄 널 가드를 넣었다.

  위험이다. QA 에서 이 균형을 본다
