# 1번 파츠 견인 전환 시 위치 보존

- 기준: `docs/planning/chapter-1-detailed-design.md`의 고정못 제거 및 견인 조종 모듈.
- 환경: Unity 6000.5.4f1. 화면 조작 없이 별도 `outputs/tractor-tests` 사본에서 EditMode 테스트 실행.
- 원인: 마지막 고정못의 `Free` 전환 이벤트에서 `PartTractorActivator.Activate`가 `PlaceOnGround`를 호출했다. 이 함수는 루트 높이를 지면 + 0.06m로 재설정하고 외형/충돌체를 최저면 기준으로 다시 배치한다. 기존 물체와 겹칠 수 있는 순간 이동 경로다.
- 수정: 전환에만 `AdoptPartPose`를 사용한다. 루트 위치를 유지하고 빔 기준축을 아래로 바꾸되, Visual과 그 아래 복제된 몸체 충돌체 및 소켓의 월드 위치/회전을 복원한다. 기존 지면 배치/리셋 API는 유지한다.
- 회귀 검사: 기울어진 파츠와 중심 오프셋이 있는 충돌체를 높이 3m에 배치하고 마지막 고정못을 해제한다. 호스트/원격 상태 각각 루트 위치, Visual 자세, 소켓 자세, 충돌체 중심/회전/크기 및 원격 kinematic 상태를 검사한다.
- 수정 전: 두 검사 모두 2.94m 순간 이동을 검출해 실패 (`.local-validation/activation-pose-before.xml`).
- 수정 후: 관련 69개 중 68개 통과, 위치 보존 검사 2개 모두 통과 (`.local-validation/activation-pose-after.xml`).
- 나머지 1개 `ActivatedPart1_IsRegisteredAsTransportInteractionTarget`은 원본 코드에서도 동일하게 실패함을 별도 확인했다 (`.local-validation/activation-focus-baseline.xml`). 해당 기존 테스트는 수정하지 않았다.
- 생성된 C# 테스트 프로젝트 빌드: 오류 0개. 기존 obsolete API 등 경고 93개. `git diff --check` 통과.
- 한계: 실제 Main 씬에서 플레이어/주변 물체에 전달되는 충격과 실시간 다중 접속은 직접 재현하지 않았다. 이후 플레이 검증 시 파츠 옆에 플레이어와 소품을 두고 네 번째 고정못을 제거해 순간 이동/밀침이 없는지, 이후 탑승/견인/하차가 정상인지 확인한다.

## 후속: 기존 몸체와 용접 비드 보존

- 전환 코드가 자식 Collider 전체를 비활성화해 기존 비드의 충돌체까지 껐다. 비드 컨테이너는 회전하는 빔 루트 아래에 남아 외형과 다른 자세를 따랐다.
- 실제 씬의 `Body_*` 자식 충돌체는 복제하지 않고 동일 인스턴스를 Visual 아래에서 재사용한다. 루트에 직접 붙은 구형 BoxCollider에 한해서 기존 복제 호환 경로를 유지한다.
- 전체 충돌체 비활성화를 제거했다. WeldBead 관리자와 기존 비드 컨테이너, 비드 오브젝트, 충돌체, 사슬 데이터는 그대로 유지하며 컨테이너만 외형을 따라가도록 연결한다. 비드가 없는 전환에서도 같은 빈 컨테이너를 준비한다.
- 비드 렌더러는 조종석/회전 중심의 외형 경계 계산에서 제외해 용접량이 운전 기준점을 바꾸지 않게 한다.
- 새 회귀 검사 4개: 기존 비드 유무 × 호스트/원격 상태. 원래 충돌체의 활성 상태와 동일 인스턴스 재사용, 새 비드 생성, 기존 비드 위치/충돌 유지, 외형 회전 추종, 레이 기반 절단을 검사한다. 수정 전 4개 모두 실패, 수정 후 모두 통과했다.
- 최종 Unity EditMode 검사 134개 중 133개 통과 (`.local-validation/activation-beads-final.xml`). 나머지는 위에서 원본 코드에서도 확인한 기존 상호작용 대상 등록 검사 실패다. 실제 화면 및 실시간 다중 접속 조작은 수행하지 않았다.
