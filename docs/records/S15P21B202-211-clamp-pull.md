# 바닥 고정못 해제를 뒤로 이동 방식으로 (S15P21B202-211)

## 무엇이 달랐나

기획 §12.1 · §12.2 를 코드와 대조한 결과다.

| 기획 | 예전 |
| --- | --- |
| "좌클릭을 유지한 채 고정못 반대 방향으로 **뒤로 이동**해 뽑는다" | **마우스를 위로 16도** 들어 홀드를 시작 |
| "놓거나 운석에 맞아도 빠진 정도는 유지된다" | 놓으면 0 으로 |
| "다른 플레이어가 이어서 수행할 수 있다" | 누적이 없어 불가 |
| §12.2 "1명 약 8초" | `DefaultHoldSeconds` 1.5초 |
| §12.2 "같은 고정못은 최대 2명" | 인원 개념 없음 |
| §12.2 "마지막 고정못이 빠지면 뒤로 넘어질 수 있다" | 없음 |

## 이동 입력을 본다. 이동한 거리를 보지 않는다

고정못이 몸을 붙들고 있으므로 아무리 밀어도 거의 제자리다 — 기획의 "발을 구르며
낑낑대는" 그림이 그것이다. 거리로 재면 진행이 사실상 멈춘다.

방향은 고정못에서 몸을 향하는 수평 방향이고, 허용 범위는 `ClampPullAlignment` 0.5
(약 60도)다. 정확히 180도로만 받으면 조작이 지나치게 까다롭다.

**제자리에서 버튼만 누르면 진행되지 않는다.** 예전 방식은 한 번 들어올린 뒤에는
가만히 있어도 시간이 흘렀다.

## 인원별 시간은 1/n 이 아니다

기획 §12.2 는 1명 8초 · 2명 약 4.5초다. 8/4.5 = 1.78 이므로 사람이 하나 늘 때마다
0.78 배가 더해진다(`ClampPullAssist`). 1/n 이면 2명이 4.0초로 표와 어긋난다 —
둘이 붙으면 서로 방해도 되기 때문에 정확히 절반이 되지 않는 것이 의도로 보인다.

시간을 나누는 대신 **속도를 곱한다.** 그래야 도중에 한 명이 붙거나 떠나도 그때까지의
진행분이 그대로 유지된다.

## 검증이 드러낸 것 두 가지

구현을 끝내고 검증을 쓰다가 실제 조작에 두 구멍이 있는 것을 알았다.

### 1. 잡은 뒤 범위를 보지 않았다

`clampGrabbed` 가 한 번 참이 되면 거리를 다시 재지 않았다. 그래서 **고정못을 잡은
채 걸어서 멀어지면서 계속 뽑혔다.** 8초면 20m 넘게 간다. 조준 범위를 벗어나면 손을
떼게 했다(진행분은 남는다).

### 2. 뒤로 걸으며 고정못을 등졌다

`Locomotion` 이 `faceDir` 을 이동 입력 쪽으로 돌린다. 뒤로 당기는 입력이 곧 뒤로
걷는 입력이므로 캐릭터가 몸을 돌려 고정못을 등졌고, 조준이 벗어나 **놓은 뒤 다시
잡을 수 없었다.** 기획 §12.1 은 "몸을 뒤로 젖히고" 이지 등을 돌리는 것이 아니다.
잡고 있는 동안은 고정못을 계속 보게 했다.

### 그리고 붙들려 있어야 한다

위 둘을 고치는 과정에서 `ClampPullTetherSpeed`(0.3 m/s)를 넣었다. 뒤로 이동 입력이
그대로 보행이 되면 §12.1 의 "거의 제자리에서 낑낑대는" 이 성립하지 않는다.
0 이 아니라 조금 남기는 것은 완전히 붙들면 조작이 얼어붙은 느낌이 나기 때문이다.

## 마지막 고정못

§12.2 "마지막 고정못이 빠지면 플레이어가 뒤로 넘어질 수 있다". 넘어짐을 새로 만들지
않았다 — `Balance` 가 이미 스스로 세운다(S15P21B202-201 의 사출과 같은 구조).

## 검증을 짜며 겪은 것

**고정못 4개를 두면 어느 것이 잡히는지 통제할 수 없다.** 조준(3m)에 반대편 고정못까지
들어와 대상이 오가고, 기준으로 둔 것은 진행이 0 으로 남았다. 검증마다 필요한 개수만
두고, 여벌은 손이 닿지 않는 곳에 보냈다.

**Fixed Timestep 이 0.01초다.** 검증을 0.02초로 돌렸더니 진행이 정확히 절반으로
보였다 — `PlayerRig` 내부가 `Time.fixedDeltaTime` 을 쓴다.

**해제된 고정못이 새어 나갔다.** `PartClamp.Release` 가 `SetParent(null)` 로 파츠에서
떨어져 나오므로 파츠를 지워도 남는다. 그것이 다음 픽스처까지 살아 저중력장 검증
4개를 깨뜨렸다(`Field_LiftsSeveralBodiesAtOnce` 가 3 대신 4 를 셌다). 해제 이벤트로
정리 목록에 넣었다.

## 손대지 않은 것

`Hand.Release()` 의 `Destroy(Grip)` 이 EditMode 에서 에러 로그를 남긴다. 이 저장소가
`Prim.Decor` 등에서 이미 고친 것과 같은 종류다. 고쳐 봤더니 **EditMode 에서 조인트가
실제로 파괴되면서 무관한 검증 3개가 깨졌다**(운반체 하차 회귀 검증 포함) — 예전에는
`Destroy` 가 아무 일도 하지 않아 조인트가 남아 있었고, 그 상태를 전제한 검증이 있다.
범위를 넘으므로 되돌렸고 로그는 픽스처에서 무시한다. **별 이슈로 다뤄야 한다.**

## 하지 않은 것

- 몸을 뒤로 젖히고 발 구르는 애니메이션 (§12.1, [Character])
- 에너지 선 VFX 와 점멸 (§12.1, [Art])
- 2명 동시 작업의 동기화 (§12.2, [Network] — `ClampMaxPullers` 한 곳에 모아 둠)
- §12.2 "솔로 보조 약 6초" — 무엇이 보조하는지 기획에 없어 보류
