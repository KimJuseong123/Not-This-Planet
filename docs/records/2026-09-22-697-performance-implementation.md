## 구현

### AI 내비게이션

- 실제 AI 자리가 없으면 자동 소스 수집/빌드를 중단한다. AI 자리가 생기면 최초로 빌드한다.
- AI가 있으면 대기 중에도 기존 2초 간격 소스 수집을 유지한다. 도구 줍기/탑승 등이 명령 수락 단계에서 경로를 조회하므로, 대기 중 변한 장애물을 계속 감지해야 첫 명령이 오래된 경로로 거절되지 않는다. 작업 중에만 갱신하는 초기 안에서 이 정확성 문제를 확인해 보수적으로 조정했다. 지형이 같으면 아래 비교로 빌드를 생략한다. 완전한 이벤트 기반 지형 갱신이나 사전 베이크 도입까지 완료한 것은 아니다.
- 필터링된 소스의 객체·변환·크기·형상·area와 범위가 같으면 비동기 빌드를 생략한다. 처음 빌드가 끝난 이후의 갱신은 이전 내비게이션을 사용할 수 있도록 Ready를 유지한다. 초기 빌드/비활성화 때는 Ready=false다.
- 길찾기의 기존 실시간 장애물/지면 검사와 복구 안전 검사는 유지한다. 이동한 장애물 때문에 경로가 오래 유효하다고 가정하지 않는다.
- `IsBuilding`, `BuildCount`, `AI.Navigation.CollectSources`, `AI.Navigation.ScheduleBuild`, `AI.Companion.Tick` 마커를 추가했다.
- Unity 비동기 갱신 자체도 incremental 방식이다. 이번 수정은 이를 전체 빌드로 오인한 교체가 아니라 불필요한 호출/준비 중 상태 전환을 줄이는 조치다. [Unity API](https://docs.unity.cn/Documentation/ScriptReference/AI.NavMeshBuilder.UpdateNavMeshDataAsync.html)

### 부품 테두리

- 실행 중 전체 씬 검색을 최초 1회 시드 + SpaceshipPart OnEnable/OnDisable 등록으로 대체했다. 도메인/씬 재로드 옵션과 일반 EditMode에서는 초기 검색 또는 기존 검색 경로를 사용한다.
- 활성 핵심 부품과 링크의 양 끝/용접 여부를 비교해 그룹이 바뀔 때만 union-find를 수행한다. 용접 강도 변화라도 연결 여부가 같으면 다시 그룹을 만들지 않는다.
- union-find, 멤버 집계, 제거 목록을 호출자 소유 Workspace로 재사용한다.
- 렌더러 활성화/자식 교체/서브메시 변경을 놓치지 않도록 렌더러 목록은 매 프레임 재사용 버퍼에 수집한다. 렌더러의 동적 변경을 캐시로 숨기지 않는다.

### AI 음성 명령

- 서버 승인 전에는 청크를 보내지 않는다. 거절/Busy 상태에서는 본문 업로드를 생략한다.
- 승인 후 40ms 이상 간격으로 최대 2KiB 한 청크만 보낸다. 낮은 FPS에서 밀린 청크를 한 프레임에 몰아 보내지 않는다. 최대 payload 속도는 약 50KiB/s이고 최대 녹음은 정상 프레임에서 약 5초에 걸쳐 전송된다. 종전 일괄 전송보다 명령 시작이 늦어지는 명시적 절충이다.
- uint 업로드 ID로 이전 승인/청크/종료를 새 요청과 구분한다. 취소, 씬 변경, 기절, 컷씬/엔딩, 서버/클라이언트 타임아웃, 연결 종료 시 정리한다.
- 청크는 원본 WAV의 ArraySegment로 직렬화한다. Mirror writer가 전송 시 내용을 복사하므로 개별 청크 배열은 만들지 않는다. 수신은 segment offset을 포함해 복사한다.
- WAV는 입력 List를 직접 읽어 정확한 길이의 byte[] 한 개에 기록한다. samples.ToArray(), MemoryStream 확장, 최종 ToArray 복사를 제거했다.
- 일반 근접 음성 채팅의 코덱/거리/VAD/unreliable 정책은 변경하지 않았다.

### 멀티 입력

- RemoteInputBuffer가 이동·잡기 등 지속 상태는 최신 값으로 유지하고, E/핑/F의 상승 사건은 수신 순서대로 별도 보관한다.
- 기존 소비자의 edge 감지를 보존하기 위해 연속 사건 사이에 한 물리 스텝의 해제를 삽입한다. 컷씬에서 사건 큐를 비워 종료 후 지연 재생을 막는다.
- 순번 중복/역전은 무시하며 uint wrap을 처리한다. 큐는 32개로 제한하고 초과 횟수를 노출한다. 정상 사용의 짧은 입력 누락을 고치되 악의적 전송으로 무한 메모리나 이동 backlog를 만들지 않는다.
- 호스트 자신의 직접 입력 경로와 AI 입력 경로는 그대로 유지한다. 잡기·점프·엎드리기 등 모든 held 입력의 짧은 상승/하강까지 별도 사건으로 바꾸지는 않았다. 과거 예측/보정 시간축 문제도 이번 변경에 포함하지 않았다.

## 남은 실기 검증과 후속 작업

60FPS 달성률 및 다중 PC 실제 통신은 아직 별도 측정 대상이다. 이번 headless/배치 테스트를 실제 플레이의 FPS 측정으로 해석하면 안 된다.

1. 동일 해상도/품질/전원 설정에서 AI 끔/유휴/추종/부품 작업/V 명령을 각각 녹화 없이 프로파일링한다. 호스트와 참가자 모두 CPU/GPU/물리/GC와 입력 소비 지연을 기록한다.
2. V 명령 전송 중 이동/잡기/탑승과 취소·재접속을 2인 및 4인 환경에서 확인한다. 음성 RPC 형식이 변경됐으므로 호스트·참가자는 같은 빌드를 사용한다.
3. NavMesh 소스 수집이 여전히 병목이면 정적 사전 베이크/변경 구역 갱신을 추가한다. 동일 Mesh/Terrain 객체 내부의 런타임 변형을 도입할 때는 `Rebuild(region, force: true)`로 명시적으로 갱신한다.
4. AI 탐색 프레임 예산과 추론 스레드 조절은 새 마커와 외부 프로세스 측정을 근거로 결정한다.
5. 물리 주기/CCD/solver, SSAO/그림자/LOD/메시 설정은 실제 CPU/GPU 병목 결과에 따라 별도 적용한다. 운반·관절·시각 품질을 추정만으로 바꾸지 않았다.
6. 기존 멀티 T 탈출 서버 경로 및 예측 시간축 문제는 별도 정확성 수정 대상으로 남아 있다.
