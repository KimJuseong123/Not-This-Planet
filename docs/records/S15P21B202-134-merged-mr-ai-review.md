# 이미 머지된 MR 의 AI 리뷰 — 남아 있던 지적과 처리 결과 (2026-08-28)

[문서 안내](../README.md) → [작업 기록](README.md) → 협업·자동화

머지된 MR의 AI 지적을 코드와 대조한 기록입니다. Infra·Network 수정, 다른 파트의 확인 대상, 오탐으로 제외한 항목을 구분합니다.

본문의 “현재”, 검증 수치, 미완료 항목은 **기록 당시 기준**입니다. 후속 변경은 관련 이슈와 [주제별 색인](README.md)을 함께 확인합니다.

> **무엇** — 이미 머지된 MR 들의 AI 리뷰를 다시 열어, 확인 없이 넘어간 지적이 남아 있는지 대조한 기록입니다(2026-08-28).
> **결과** — 내 파트([Infra]·[Network]) 지적은 이 기록을 근거로 전부 처리했습니다 — Jira -134 · -135 · -136 (MR !78 · !79 · !80).
> **성격** — AI 의견이므로 차단 조건이 아닙니다. 다른 파트 지적 목록은 §4 에 남겨 두었습니다.

AI 리뷰가 달린 채 머지된 MR 18건 중 **내가 올린 것 10건**(전부 [Infra])의 리뷰와, 2026-08-27 develop 전수 리뷰의 **[Infra]·[Network]** 항목을 오늘 코드와 대조했다.
판정이 `⚠️ 확인 후 머지` 였던 내 MR은 6건(!36 !37 !39 !40 !43 !46). 그 "팀장이 확인할 것" 항목들은 **후속 이슈로 남은 것이 하나도 없었다.**

내 파트 지적은 **오늘 전부 처리했다**(MR !78 · !79 · !80). 다른 파트(퍼즐·아트·캐릭터) 지적은 담당이 그 코드를 다시 만질 때 정리하는 것이 맞다고 보고 변경하지 않았다 — 목록은 §4 에 남겨 둔다.

## 1. 내 파트에서 고친 것 — CI 스크립트 (MR !78, Jira -134)

지적 대부분이 한 형태였다: **환경변수나 파일 하나가 어긋나면 검사·알림이 통째로 죽는다.** 오늘 아침 점검에서 같은 형태(`DIGEST_PENDING_HOURS`)를 실제로 만나 고쳤는데, 같은 코드가 다른 곳에도 있었다.

| 무엇이 문제였나 | 어떻게 고쳤나 |
| --- | --- |
| `mr_lint:41` `STALE_WARN = int(env(...))`가 **임포트 시점** — CI 변수에 숫자가 아닌 값이 들어가면 차단 잡이 죽어 **머지가 막힌다** | `stale_warn()` 지연 평가 + 기본값 25 로 계속 |
| `mr_lint:13` · `mm_notify` · `mm_digest`의 `team.json` 로드·`roles` 접근이 예외 없이 임포트 시점 | `ci_common.load_team()` · `normalize_team()` · `role_member()` — 파일이 깨져도 빈 팀으로 계속 |
| `mm_digest`의 `LEAD_MM = next(...)`가 `StopIteration` → **알림 전체 유실** | 폴백. 못 찾으면 멘션만 생략하고 카드는 보낸다 |
| `mr_title`이 `jira.get_issue` 예외를 감싸지 않아 Jira 장애 때 보정 잡이 죽음 | `try/except` 후 보정만 생략 |
| `ci_common.mr_commits`가 페이징 없이 100개만 — 커밋 많은 MR에서 **다른 이슈 키 미탐** | 페이징(최대 5페이지) |
| `ai_review`가 리뷰어 응답을 **하나도 해석하지 못했을 때도** "발견 사항 없음" 출력 → 통과로 읽힌다 | "판단하지 못했습니다" 로 명시 |
| `mm_notify.mr_opened`가 파이프라인 **개수**로 첫 회를 판정 → 재시도로 2개가 된 MR은 리뷰 요청 알림이 **영구 미발송** | id가 가장 작은 파이프라인만 발송 |
| 실패 코멘트에 길이 상한이 없어 위반 수십 건이면 코멘트 비대·API 한도 | 이유 20개 · 8000자 상한 + "외 N건" |
| `mm_digest.merged_not_done`이 매 실행마다 **미완료 이슈 전량** 조회 | 키로 직접 조회 → 거부되면 전량 조회 폴백 |
| `repo_hygiene`가 에셋 위치 통과를 **fail 메시지 접두사**로 판정(문구만 바꿔도 조용히 ok) | 카운터로 판정 |
| `repo_hygiene`의 `base_top`이 `split()` — 공백 폴더명 쪼개짐, `ls-tree` 실패 시 모든 폴더가 새 폴더로 실패 | `splitlines()` + 트리가 없으면 위치 검사 생략(경고) |
| `mr_lint` 주석·경고문이 R6 조건을 "대상이 develop 일 때만 완료" 로 단정(실제는 대상 이름에서 키가 잡히면 건너뛰는 fail-open) | 실제 식을 주석에 명시 · `hotfix/*` 대상 MR은 실패 처리 |

새 테스트 2개(`test_hardening` · `test_notify_once`)로 지적별 케이스를 잠갔다. 전체 오프라인 테스트 9개 통과.

## 2. 내 파트에서 고친 것 — 러너 스크립트 (MR !79, Jira -135)

- `runner-claude-env.ps1`이 `[[runners]]`가 **둘 이상일 때** 두 번째 이후 러너의 기존 `environment` 줄을 지우고 대체 줄도 넣지 않았다(설정 손실). EC2 상시 러너 + Unity 러너를 한 PC에 등록하는 다음 단계에서 바로 걸린다.
- 리뷰가 추가로 짚어 준 것도 고쳤다: 러너 구역을 벗어날 때 상태를 리셋하지 않아 `[session_server]` 같은 다른 섹션의 `environment` 줄까지 삭제될 수 있었고, `[runners.docker]` 하위 테이블의 값도 우리 것이 아니므로 손대지 않게 했다.
- `-SelfTest` 스위치 — 관리자 권한·러너 설치 없이 변환 규칙을 검증한다(러너 3개 반영 · 각 블록에 새 줄 정확히 1개 · 보존 대상 3줄).
- `setup-windows-runner.ps1` — pwsh MSI 자산을 못 찾을 때 무엇을 해야 하는지 알려 준다.

## 3. 내 파트에서 고친 것 — 네트워크·부트스트랩·빌드 도구 (MR !80, Jira -136)

| 위험 | 무엇이 문제였나 | 어떻게 고쳤나 |
| --- | --- | --- |
| 🔴 | `NetworkSession.Send()`가 `socketCancellation.Token`을 쓰는데 `CloseSocket()`이 그 CTS를 `Cancel → Dispose → null`로 만든다 — 나가기·재연결과 겹치면 예외 | 소켓·토큰을 **한 짝으로** 잠금 안에서 읽고 `ObjectDisposedException` 처리 |
| 🟠 | `ConnectSocketAsync`가 백그라운드에서 `socket`에 직접 대입 → 늦게 끝난 옛 연결이 **새 소켓을 덮어씀**(조용히 옛 소켓으로 통신) | 연결 세대 번호 + 대입·종료를 같은 잠금에서 |
| 🟠 | 보내는 사이 소켓이 닫히면 "송신 오류" 로 올라가 `CloseSocket` + `Fail`까지 이어짐 | 나가기·재연결 중 종료는 조용히 넘김 |
| 🟡 | `LobbyBootstrap`이 `LobbyHud`를 무조건 `AddComponent` — 중복 생성 | 있으면 재사용(`??`는 Unity `==` 오버로드를 우회하므로 쓰지 않음) |
| 🟠 | `SpaceBuild`의 셰이더 포함 보장이 **사실상 동작하지 않았다** — `AssetDatabase.LoadAllAssetsAtPath`는 `ProjectSettings` 경로에서 빈 배열 | `GraphicsSettings.GetGraphicsSettings()` + 실패 시 경고 로그 |

Unity를 열지 않고 검증했다: 로컬 `dotnet`으로 Unity 관리 DLL 78개에 대고 Runtime·Editor 스크립트를 컴파일 → **수정 파일 오류 0**. (남은 오류 2건은 로컬 Unity 6000.0 과 프로젝트 6000.5 의 `FindObjectsByType` 오버로드 차이로 생기는 기존 코드 문제다.)
**에디터 실행 확인은 남아 있다** — 로비 HUD 1개 · 입장/나가기/재입장 3회에 예외 없음 · 윈도우 빌드에서 셰이더 경고 유무.

### 프로세스에서 드러난 것
- **-84(!38) · -91(!41) · -96(!42) 는 Jira 완료 조건이 템플릿 그대로 비어 있었다.** AI가 `❓ 완료 조건: 판정할 근거가 없다`로 표시했는데 그대로 머지됐다 — 리뷰가 못 잡은 게 아니라 **판정 기준이 없었던** 것이다. 세 이슈는 지금도 완료 조건 없이 완료 상태다.
- **"테스트 파일이 diff에 없다" 는 지적이 4번 반복**(-82 -83 -90 -94) → 오늘 -103 에서 구조적으로 끊었다(`scripts/ci/tests/` + 차단형 `ci-tests` 잡).
- **-99(!43) 의 높음 지적**(mr-lint만 먼저 머지되면 R6가 스택 MR을 조기 완료) → 오늘 R6 조건 적용·검증으로 해소.
