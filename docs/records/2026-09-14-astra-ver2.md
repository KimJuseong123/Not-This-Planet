# Stage1_Astra_ver2 구현 및 검증

2026-09-14 · Unity 6000.5.4f1 · URP 17.5.0

## 결과와 실행

`METAGAME/Assets/Scenes/Stage1_Astra_ver2.unity`를 열고 Play한다. 원본 `Assets/Scenes/Stage1_Astra.unity`를 Unity AssetDatabase로 복제한 뒤 환경과 동선을 재구성했다. 새 씬을 Build Settings에 추가했으며, 원본 씬과 Lobby의 기본 이동 대상은 유지했다.

이번 결과는 기존 환경 에셋과 원래 파츠 모델로 컨셉의 접근·반출 구조를 구현한 씬이다. 컨셉 이미지와 동일한 신규 조형물을 제작한 것은 아니다. 중앙 조립장을 기준으로 네 구역과 수동 운반로를 배치했다.

| 구역 | 접근 및 운반 | 암시와 안전 장치 |
|---|---|---|
| A / Part_1 | 시작점 옆 열린 공터, 고정못 해제 후 중앙으로 밀기 | 주황 기둥·경로, 첫 롤러/지렛대 |
| B / Part_2 | 약 0.8m씩 높아지는 7개 돌부리 → 정상 → 화물대 → 지상 반출 | 청록 착지 표시, 필수 못 해제 후 정상 잠금 해제, 손잡이를 잡는 동안만 하강, 놓으면 정지, 하부 장애물 감지, 빈 화물대만 복귀 |
| C / Part_3 | 다이얼 3개 정렬 → 발판 출현 → 살아 있는 동료가 밟아 문 유지 → 파츠 반출 | 회전 바늘과 목표 홈, 연결선·발자국, 충돌 없는 문턱, 출입구 끼임 시 닫힘 정지 |
| D / Part_4 | 낮고 열린 L자 통로 → 눕힌 파츠를 밀고 굴려 반출 | 연두 방향 표시, 약 2.17m 천장과 약 1.90m 눕힌 파츠, 문 밖으로 완전히 나온 뒤 방향을 트는 경로 |

각 구역에 롤러 3개와 지렛대 1개를 두었다. 견인 장치 탑승 없이 수동 밀기와 물리 도구를 사용할 수 있다. C의 발판은 동료가 유지해야 하므로 전체 스테이지의 1인 완주를 보장하는 설계는 아니다.

## 원본 보존

[안내 요소 전체 분석](../planning/stage1-astra-ver2-guidance-audit.md)에 원본 근거와 보존 방식을 기록했다. 핵심 사항은 다음과 같다.

- 원본 핵심 파츠 4개, 고정못 16개, 소켓 8개, 조립대·부트스트랩 연결 유지.
- 색상 기둥, 조립 순서에 반응하는 조립대 링, NoFog 색 재질, 진행도에 반응하는 형광 끈 유지.
- 태블릿·발견 알림·고정못 및 용접 HUD·동료 핑·구조·낙하 복구 흐름 유지. 새 위치 설명은 ver2 표식이 있는 파츠에만 적용.
- 원본 실제 씬의 Part_4 견인 활성화 연결 유지. ver2의 `AstraV2ManualPart`가 비탑승 상태에서 수동 밀기를 계속 허용.
- 기존 버섯·바위 에셋과 하늘·볼륨·주광·림광 사용. 원본 국소 조명을 새 파츠 위치와 색으로 재배치.

## 코드와 동기화 범위

- `Stage1AstraVer2Builder`: 원본을 보존하는 씬 생성, 구조 검사, Unity 실제 렌더 미리보기. 기존 ver2가 있으면 덮어쓰기를 거부한다.
- `AstraV2Puzzle`: 회로 정렬, 출현 발판, 생존·접지·발 위치 확인, 문 끼임 방지.
- `AstraV2FreightLift`: 정상 잠금 해제, 잡기 브레이크, 빈 화물대 복귀, 하부 감지.
- `AstraV2ManualPart`: 기존 PartPush 연결 및 Part_4의 비탑승 수동 운반 복구.
- `AstraV2CargoTool`: 씬에 배치한 물리 도구 추적 표식과 지면 아래 이탈 시 복귀.
- `WorldSync`: 새 장치는 서버만 판정하고 상태 스냅샷을 최대 약 10Hz 전송. 롤러/지렛대는 기존 포즈 추적에 포함. 새 장치가 없는 원본 씬에는 추가 상태를 송신하지 않는다.

## 실제 검증

사용자가 열어 둔 Unity Editor와 원본 씬을 건드리지 않도록 `.local-validation/astra-ver2` 사본에서 설치된 Unity를 실행했다. 컴파일·씬 생성·URP 렌더 후 Unity가 생성한 새 에셋과 `.meta`를 함께 본 프로젝트에 반영했다.

### 컴파일·구조·그림

- Unity 스크립트 컴파일과 Mirror 코드 생성 성공. 신규 컴파일 오류 없음.
- 누락 스크립트 없음, 원본 파츠 식별자 4개, 안내 컴포넌트·부트스트랩 각 1개, 퍼즐·화물대 각 1개 확인.
- 모든 고정못 밑에 실제 지면이 있는지 Unity Physics.Raycast로 확인.
- URP로 전체 맵·절벽·압력문·낮은 밀실의 1600×1000 미리보기 4장을 생성하고 직접 확인.
- 납작한 Unity 기본 원기둥의 캡슐 충돌체가 외형보다 크게 남는 문제를 발견해 조립대·발판·롤러를 실제 원기둥 메시 기반 convex 충돌체로 수정.
- 파츠의 실제 hull 크기로 정상 하역 경로와 네 구역의 중앙 반출로 **451개 지점**을 검사해 통과. D 출구에서 너무 일찍 꺾으면 북쪽 벽에 걸리는 점을 발견해 직진 여유 구간을 추가했다. 결과는 아래 `geometry.txt`에 보관한다. 이 검사는 경로의 정적 간섭·바닥 연속성이며, 사람의 실제 협동 운반 완주 시험을 대체하지 않는다.
- 본 프로젝트에서 새 씬·재질의 참조 GUID와 새 스크립트/에셋의 `.meta`, Build Settings의 씬 GUID를 확인. 격리 사본에서 생성한 에셋과 전송된 파일이 동일하고 원본 Stage1_Astra가 변경되지 않았음을 확인.
- 최종 씬 SHA-256: `5145917d0ae7b4a1941b76058c327115599251c107124d7ae45e7b609045d547`.

### 플레이 모드 15개 점검 통과

1. 원본 파츠 4개 존재.
2. 수동 밀기 컴포넌트 4개 존재.
3. 새 퍼즐과 화물대 작동.
4. 필수 못의 형광 끈 생성.
5. 회로 완성 후 발판이 나와도 빈 상태에서는 문이 열리지 않음.
6. 살아 있고 접지한 플레이어가 발판을 밟으면 문이 완전히 열림.
7. 플레이어가 떠나면 문이 닫힘.
8. 원본 고정못 규칙으로 절벽 파츠 해제.
9. 못 제거 후 정상 해제 허용.
10. 브레이크 손잡이를 잡으면 화물대 하강.
11. 화물대 위 실제 Rigidbody 파츠도 함께 하강.
12. 브레이크를 놓으면 화물대 정지.
13. 원본 Part_4 활성화 유지.
14. 활성화 후 비탑승 Part_4의 수동 밀기 가능.
15. 활성화 후에도 눕힌 Part_4가 낮은 천장 아래에 들어맞음.

자동 점검은 플레이어를 지정 위치로 이동시키고 기존 고정못·잡기 이벤트 API를 호출했다. 운석은 이 진단 실행에서만 비활성화했다. 실제 씬의 운석 설정은 유지했다.

### EditMode 회귀 테스트

| 실행 | 전체 | 통과 | 실패 |
|---|---:|---:|---:|
| 변경 후: 새 장치 + 고정못·조립·탐험·키 안내 | 84 | 75 | 9 |
| 변경 전 공용 코드로 같은 기존 테스트 비교 | 79 | 70 | 9 |

새 `AstraV2MechanismTests` 5개는 전부 통과했다. 실패한 기존 테스트 이름은 전후가 동일하다. `ClampPullTests` 8개는 잡기/당기기 결과, `PartClampTests.Pull_TakesThePlannedTime` 1개는 기대 4.5초와 실제 약 1.12초 차이로 실패한다. 이번 씬 작업에서 기존 고정못 동작을 바꾸지 않았다.

## 남은 검증 범위

- 실제 호스트·참가자 2명 이상의 접속, 도중 합류, 지연 상황에서 새 장치와 운반 도구를 함께 조작하는 시험은 수행하지 않았다.
- 사람이 점프 구간을 등반하고 네 파츠를 중앙에 운반·조립해 끝까지 완주하는 난이도와 소요 시간은 측정하지 않았다.
- 전체 프로젝트의 모든 테스트와 배포용 플레이어 빌드는 실행하지 않았다. 위 범위를 넘어 멀티플레이 완주나 출시 준비 완료로 간주하지 않는다.
