- 선행 작업: S15P21B202-529 연습 로비, 기준 `6ce3f1d`.

- 사용자 요청에 따라 MR/merge 없이 공유하며, 검증된 스냅샷에 최신 develop을 자동 rebase하지 않는다.

## 현재 구현

`Unity V 녹음 → 같은 PC Python HTTP 8765 → Whisper base → Qwen3 1.7B (Ollama 11439) → 허용 행동 검사 → 방장 PlayerRig → Mirror 관찰자`

- AI가 정하는 것은 행동 종류다. 자유 생성 코드, 도구 실행, 물리 시뮬레이션을 LLM에 맡기지 않는다.
- 따라오기, 대기, 중단, 고정못 하나 뽑기. 기존 PlayerRig 이동·손 잡기·뒤로 당기기를 재사용한다.
- 못 뽑기: 접근 → 잡기 → 뒤로 당기기 → 완료. 중단 시 손 해제, 진행도 보존, 재요청 시 재개.
- 조준 대상 우선. 그렇지 않으면 화자 12m 이내 유효 고정못이 하나일 때만 선택. 복수 후보는 재확인 요청.
- 인식 실패·미지원·통신 오류는 현재 작업 유지. 명시적 cancel/wait 및 F8 수동 중단과 별도 표시한다.
- 로비 복제 씬 2개와 독립 실험 코드. 원본 PracticeLobby, Stage1, 기존 고정못/물리/네트워크 코드는 변경하지 않는다.
- 동료 1명, 방장 음성만 지원. 같은 PC 직접 연결만 허용한다. 인터넷용 인증/매치메이킹은 아니다.
- 실행 중인 다른 Ollama 인스턴스/기존 lab 서버는 건드리지 않는다. API 키와 유료 추론 API는 사용하지 않는다.

## 검증 결과 및 해석

| 검사 | 결과 | 해석 한계 |
| --- | --- | --- |
| Unity 실험 EditMode + 실제 로비 Play 통합 검사 | 13/13 통과 | 전체 프로젝트 테스트 아님 |
| 실제 이동 | 4.22m → 1.80m | 단순 로비 경로 |
| 못 뽑기 중단·재개 | 실제 손 잡기, 진행도 증가·보존, 최종 해제 | 복잡한 배치/다중 작업 미검증 |
| Windows x64 Development | v2 빌드 성공 | 배포판 패키징/사용자 PC 설치 미검증 |
| 같은 PC 2개 실행 파일 | netId=2 공유, 못 진행도 0→0.390→0.890→1.000 및 해제 복제 | 실제 두 PC·지연·재접속·호스트 이전 미검증 |
| Qwen v2 텍스트 확인 세트 | 12/12 예상 행동, 약 0.39~0.53초 | STT 제외, 소규모 반복 예문, 정확도 보장 아님 |

초기 확장 프롬프트에서는 금지/미지원 요청을 못 뽑기로 오분류했다. 한국어 행동 정의와 긍정·금지 구분을 수정 후 재검사했다. 작은 모델의 의미 이해가 보장된다는 뜻은 아니다.
앞선 v1 검사에서 서버+모델 RSS 합계 약 1.9~2.1GiB(공유 페이지 중복 포함)였으며 v2 전용 자원 벤치마크는 아직 없다.
콜드 STT가 빌드와 겹쳐 약 122초 지연된 기록도 있다. 이를 정상 반응속도로 해석하지 않는다.
사용자 마이크 정확도, 애니메이션의 시각적 자연스러움, 긴 플레이 중 메모리·프레임 안정성은 별도 확인이 필요하다.

검증 로그/빌드는 로컬에 보존하고 Git에는 넣지 않는다. `AI-EXPERIMENT.md`에 검사 파일명과 실행법을 기록했다.
서비스 모의 단위 테스트와 `check_companion.py` 확인 세트는 코드로 공유한다. 개인 발화 로그는 공유하지 않는다.

공유 준비 시 저장소로 옮긴 서비스에서 모의 단위 테스트 7/7, Python 구문 검사, setup/start PowerShell 구문 검사, v2 API 스키마 등록을 확인했다.
공유용 확인 스크립트로 기존 실행 중인 로컬 서버에 12개 문장을 재전송해 모두 통과했다. 새 PC의 설치/모델 다운로드나 새 사본 서버 전체 기동은 실행하지 않았고, 기존 환경을 중단하지 않았다.

- 비교용 0.6B와 Whisper small은 최종 게임 필수 모델이 아니다.

## 향후 개발 계획 (미구현)

### 1. 명령 품질과 실제 협동 검증

실제 사용자 발화로 음성 인식 성공률, 올바른 행동 선택률, 잘못 실행한 비율, 실제 작업 완료율을 각각 측정한다.
STT/판단/이동·작업 대기 시간을 분리하고 cold/warm P50·P95, CPU/RAM, 게임 FPS를 함께 잰다.
다양한 말투, 부정, 정정, 모호한 지시, 소음, 다수 플레이어 요청 충돌과 취소를 포함한다.
현재 12개 확인 예문은 개발 smoke test이고 새로운 사용자 발화를 평가하는 세트는 별도로 확보한다.

### 2. 게임 통합

대상 지시·명령 대기열/우선순위, 참가자 음성, 여러 고정못, 다른 도구와 파츠 작업을 순차 확장한다.
4인 슬롯의 AI 자동 충원·사람 참가 시 교대, 작업 중 기절/목표 소실/길 막힘, 장시간 플레이를 검증한다.
AI 서비스가 실패해도 사람 플레이는 유지하며 동료 상태를 명확하게 표시한다.
본편 통합은 새 Jira Task와 develop 기반 브랜치에서 별도로 진행한다.

### 3. 배포 구조 결정

최종 배포 방식은 아직 정하지 않았다.

| 후보 | 장점 | 비용·미해결점 |
| --- | --- | --- |
| 방장 PC 로컬 AI | 요청당 추론 API 비용 없음, 중앙 서버 의존 축소 | 방장 CPU/RAM, 모델 설치/업데이트, 호스트 이전 |
| 중앙 AI 서버 | 사용자 모델 설치 없음, 모델 운영 통일 | 서버 비용, 네트워크 지연/장애, 음성 전송·보관 정책 |
| 각자 STT + 방장 판단 | 음성 전송을 줄일 가능성 | 각 PC STT 설치/성능 차이, 명령 검증 필요 |

로컬을 선택한다면 게임과 AI 실행팩을 나누고, AI 동료를 쓰는 방장이 처음 한 번 모델을 내려받는 방안을 우선 검토한다.
누구나 방장이 될 수 있으면 잠재적 방장은 모델이 필요하다. 모든 사용자에게 처음부터 받게 하거나, 방 생성 시 설치하는 정책 중 선택한다.
모델 파일은 소스 Git 대신 용량/트래픽 제한을 확인한 아티팩트 저장소에 두고 버전별 GitLab Release 링크로 연결할 수 있다.
자동 실행/종료 런처, 모델 revision/digest·파일 해시 검증, 다운로드 실패/재개, 최소 사양, 라이선스 고지·재배포 조건 확인이 필요하다.
이번 작업은 Release 업로드·서버 개설·유료 결제·모델 추가 다운로드를 수행하지 않는다.

### 4. 호스트 이전

게임의 호스트 이전과 AI 처리 인계를 함께 설계해야 한다. 모델이 없는 새 방장은 곧바로 추론할 수 없다.
모델 준비된 후보에게만 이전하거나 AI를 명시적으로 대기시키는 정책을 검토한다.
현재 작업 종류/대상/취소 세대·진행 상태 인계, 이전 방장 응답 폐기, 중복 실행 방지까지 검증해야 한다.
현재 프로토타입에서는 구현하지 않았다.

Jira 완료 전환/개발 브랜치 MR 생성은 하지 않는다. 이 기록의 실험 결과와 제품 통합 완료는 별개다.
공유 브랜치는 검증 당시 환경 보존 목적이며 develop 머지 준비 상태를 의미하지 않는다.
