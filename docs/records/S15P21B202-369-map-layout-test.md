## 목적

컨셉 맵의 배치·동선·분위기를 직접 살펴보기 위한 작업 중 스냅샷이다.
공유용 브랜치만 올리며 MR 생성, develop/master 머지, Jira 완료 처리는 하지 않는다.

## 실행 순서

1. 기존 작업을 저장하고, 가능하면 별도 폴더에서 이 브랜치를 받는다. Git LFS를 설치하고 `git lfs pull`로 에셋을 받는다.
2. Unity Hub에서 저장소의 `METAGAME` 폴더를 Unity **6000.5.4f1**로 연다.
3. `Assets/_Project/Scenes/Stage1_Concept_Playable.unity`를 열고 Play를 누른다.
   메뉴 `Tools → NOT THIS PLANET → 컨셉 맵 → 플레이용 씬 열기`로도 열 수 있다.
4. 남서 시작기지에서 중앙 조립대, 남동 견인 모듈, 동쪽 언덕, 북서 격납고의 배치와 접근 경로를 살펴본다.

`Stage1_Concept.unity`는 자유 카메라로 보는 아트 검토용이다.
`Stage1_Concept_Lobby.unity`는 기존 로그인 서버가 필요한 별도 로비 복사본이며 멀티플레이 검증용 완성본이 아니다.
맵을 보기 위해 씬 생성·재구성 메뉴를 실행할 필요는 없다. 재구성은 수동 배치를 덮어쓸 수 있다.

## 현재 포함한 작업

- 별도 컨셉 씬 3개, 지형·시설·재질·조명과 도보 접근 경로.
- 기존 4개 파츠, 고정못, 도구, 태블릿, 조립·발사·운석 시스템 연결.
- 고정못 해제 후 약 0.25m 부유 및 직접 밀기·당기기.
- 견인체를 최상단 파츠 하나로 통합하는 코드와 씬 설정.
- 조립대에 놓인 파츠 보호 및 저중력 운반 추종 개선 코드.
- 컨셉 씬을 위한 시작점·비행 범위·분위기 옵션과 Build Settings 추가.

원본 Main/Lobby 씬과 공유 프리팹 원본은 변경하지 않았다. 다만 공유 런타임 코드도 포함되어 있으므로 정식 통합 전에 기존 씬 회귀 검증이 필요하다.

## 기본 조작과 조정

- 이동 WASD, 점프 Space, 태블릿 Tab. 장비는 가까이에서 클릭해 줍는다.
- 용접건 좌클릭 용접 / 우클릭 절단.
- 고정못을 잡고 뒤로 이동해 해제한다. 파츠는 몸으로 밀거나 몸체를 클릭한 채 뒤로 당긴다.
- 견인 모듈은 고정못 해제 후 E 탑승, WASD 이동, Space 상승 / Ctrl 하강, Shift 가속.
- F 또는 좌·우클릭으로 저중력장을 켜고 끈다. E 하차.
- 최상단 도킹은 저중력장을 끄고 거주 모듈 위에 내려놓아 하차하는 경로로 구현 중이며 **최종 실제 플레이 검증 전**이다.
- 수동 운반 속도: Play 종료 후 파츠의 `Part Push > Speed Multiplier`. 1 기본, 2 두 배, 0.5 절반.

## 검증 범위와 남은 것

- 이전 실제 씬 검사에서 대표 고정못 해제, 도구 줍기·재줍기, 엔진 부유·밀기·당기기를 확인했다.
- 최근 견인 회귀 검사 기록은 67개 통과 / 1개 실패였다. 이후 등록 초기화 코드를 수정했지만 전체 재실행 전 작업을 공유용으로 전환했다. 모든 테스트 통과를 주장하지 않는다.
- 최신 견인 변경의 실제 운반→적층→최상단 도킹 전체 과정, 다중 클라이언트, 플레이어 빌드, 성능은 미검증이다.
- 색상 암호, 신호와 태블릿 연동, 필수 플레이어 던지기, 인원별 퍼즐은 미구현이다.
- 로컬 백업·로그·임시 검사 결과·Library·Temp는 커밋하지 않았다. 문서의 과거 로컬 검사 파일 경로는 팀원 체크아웃에 없을 수 있다.
- 추가 유료 서비스, 에셋 구매, 크레딧 사용 없음.

후속 작업은 공유 피드백을 받은 뒤 진행한다. 이 브랜치를 그대로 정식 머지 대상으로 간주하지 않는다.
