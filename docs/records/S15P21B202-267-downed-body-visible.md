# S15P21B202-267 기절 3인칭에서 쓰러진 몸이 보이게

[문서 안내](../README.md) → [작업 기록](README.md) → 도구·캐릭터

기절 시 3인칭으로 전환되어도 캐릭터 몸이 보이지 않던 문제를 수정했습니다. 가시성 갱신 시점과 렌더링 외에 필요한 처리, 앞선 테스트의 누락을 설명합니다.

본문의 “현재”, 검증 수치, 미완료 항목은 **기록 당시 기준**입니다. 후속 변경은 관련 이슈와 [주제별 색인](README.md)을 함께 확인합니다.

## 3인칭인데 그림자만 보였다

S15P21B202-259 가 기절 시 3인칭 전환을 만들었다. 카메라는 물러나는데 **몸이 보이지
않았다.**

```csharp
// PlayerRig.RefreshDollVisibility()
if (IsRiding) Doll.SetVisible(false);
else if (Cam != null && Cam.FirstPerson) Doll.SetVisible(false, keepShadow: true);
else Doll.SetVisible(true);
```

`SetVisible(false, keepShadow: true)`는 렌더러를 **켠 채** `ShadowsOnly`로 둔다. 1인칭에서
제 몸이 시야를 막지 않게 하면서 발밑을 읽는 단서로 그림자는 남기는 것 — 그것 자체는 맞다.

**문제는 이 함수가 매 프레임 돌지 않는 것이다.** 호출 지점이 여섯 곳이고 전부 *사건*이다.

```
Cam setter · Teleport · AttachTo(2) · TryBoardShip · CompleteTransportVehicleExit
```

`GoDown`·`Revive`에 없고, `Cam.FirstPerson`이 바뀔 때도 없었다. 259 는
`TickDownedView` 안에서 5초 뒤 `FirstPerson = false`로 바꾸는데 그 뒤에 아무도 갱신하지
않으므로 **몸은 1인칭 때 감춰진 상태 그대로** 남았다.

## 갱신 지점을 세 곳 늘렸다

```
GoDown                기절하는 순간
Revive                구조받는 순간
Tick 맨 앞             시점이 바뀌었으면 (아래)
```

### 매 프레임 갱신하지 않는다

`RefreshDollVisibility`는 인형 아래 **모든** 렌더러를 훑는다(장식이 강체의 자식이라
그래야 한다 — 주석에 근거가 있다). 매 프레임 돌리면 사람 수만큼 그 비용이 든다.

`lastFirstPerson`을 기억해 **바뀔 때만** 부른다. 그것이 지금 구조가 "사건마다 부르는"
이유이고 그 구조를 지켰다. 검증이 그것도 잠근다 — 렌더러를 밖에서 끄고 20틱을 돌려도
다시 켜지지 않는다.

### 카메라가 인형을 만지지 않는다

시점을 바꾸는 것은 `OrbitCamera` 안에서 일어나지만 인형을 그릴지 정하는 것은
`PlayerRig`의 일이다. 카메라가 인형을 직접 만지면 의존 방향이 뒤집힌다(지금은
`PlayerRig` → `OrbitCamera` 한쪽이다).

**소유자가 물어보게 했다.** `Tick` 맨 앞에서 시점이 바뀌었는지 보고 갱신한다. 기절
조기 반환보다 앞이어야 한다 — 기절 중에 일어나는 전환이기 때문이다.

## 렌더링 복구 외의 가시성 처리

작업 도중 확인한 것이 이 이슈를 넓혔다. 259 가 3인칭으로 물러날 때 **쓰러진 머리의
회전을 그대로 이어받았다.**

```csharp
var euler = downedEyes.rotation.eulerAngles;   // 땅에 처박힌 머리
yaw   = euler.y;
pitch = Mathf.Clamp(NormalizePitch(euler.x), MinPitch, MaxPitch);
```

두 가지가 어긋난다.

| 자세 | 무엇이 일어나나 |
| --- | --- |
| 얼굴이 땅을 봄 | 각도가 극단으로 가 `MinPitch`(−42도)에서 잘리고 **카메라가 지면 아래**를 향한다 |
| 옆으로 누움 | `eulerAngles`의 x·y 분해에 roll이 섞여 **엉뚱한 방향**이 된다 |

어느 쪽이든 **몸이 프레임에 없다.** 렌더링을 살려도 보이지 않는다.

기획 §10.3 은 "쓰러진 캐릭터 **중심**의 3인칭 자유 시점" 이다 — 중심에 몸이 있어야 한다.

### 전환 순간만 고정한다

```csharp
void FrameDownedBody()
{
    pitch = PhysicsScale.DownedThirdPersonPitchDegrees;   // 25도 내려봄

    var along = downedEyes.position - Target.position;    // 골반 → 머리
    along.y = 0f;
    if (along.sqrMagnitude < 1e-4f) return;

    yaw = Mathf.Atan2(along.x, along.z) * Mathf.Rad2Deg;
}
```

좌우를 **머리의 회전이 아니라 누운 방향**에서 가져온다 — 골반에서 머리로 향하는 벡터는
어떤 자세로 넘어져도 신뢰할 수 있다. 그 방향을 바라보면 몸이 세로로 화면에 들어온다.

**고정하는 것은 전환 순간뿐이다.** 그 뒤에는 마우스로 자유롭게 돌린다 — §10.3 의
"자유 시점" 을 지킨다.

25도를 고른 근거는 계산이다.

```
초점    골반 + CamHeight(0.55m) ≈ 0.8m (엎드린 상태)
카메라  CamDistance(3.6m) 뒤 · 2.3m 높이
화각    64도 → 3.6m 거리에서 상하 ±2.2m
몸      초점보다 0.55m 아래 → 넉넉히 들어온다
```

`NormalizePitch`는 쓸 곳이 없어져 지웠다.

## 259 의 검증이 왜 놓쳤나

259 의 검증 16개는 **카메라 상태와 전환**만 봤다. 이유는 "카메라가 `LateUpdate` 표현이라
EditMode로 화면을 볼 수 없다" 였고 그것은 맞다.

그런데 **몸이 보이는지는 카메라 상태가 아니라 인형의 렌더러 상태**이고, 그것은 EditMode
로 볼 수 있었다. 검증의 범위를 좁게 잡은 것이 빈틈이었다 — S15P21B202-254(지면 레이어)와
같은 종류의 실수다.

## 검증 15개

| 묶음 | 무엇 |
| --- | --- |
| 1인칭 (기존) | 몸이 감춰짐 · **그림자는 남음**(`ShadowsOnly`) · 넘어지는 동안 계속 감춰짐 |
| **3인칭** | **몸이 보임** · 그림자가 정상으로 · 끌려가도 유지 |
| 구조 복귀 | 다시 감춰짐 · 두 번 기절하면 다시 보임 |
| 다른 시점 | 카메라 없는 원격은 늘 보임 · 처음부터 3인칭이면 계속 보임 |
| **비용** | 시점이 안 바뀌면 렌더러를 훑지 않음 |
| **프레이밍** | 얼굴이 땅을 봐도 25도 내려봄 · 옆으로 누워도 같음 · **누운 방향을 바라봄** · 그 뒤 마우스 동작 |

전체 625개 중 612 통과. 실패 13개는 develop에 이미 있던 것이다(S15P21B202-232 건).
610 + 15 = 625 — **늘어난 실패가 없다.**

## 인게임 확인

머지 후에 봐야 한다. EditMode로 확인한 항목은 **렌더러 상태와 전환 각도**다.

- 엎드린 몸이 실제로 화면 중앙에 들어오는지
- 카메라가 지면에 끼지 않는지 — 초점이 낮아 `SphereCast` 회피가 자주 걸릴 수 있다
- 25도가 적당한지
