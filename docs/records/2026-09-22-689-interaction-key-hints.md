# 689 상호작용 키 안내 대조 및 수정

## 기준과 범위

- 브랜치: `S15P21B202-689-ui-e-ui`, 시작 커밋 `b61bc952`.
- 워크트리: `.local-worktrees/689-ui`. 원래 develop 작업 폴더의 수정 사항은 건드리지 않았다.
- Unity 6000.5.4f1. 기존 프로젝트 문서와 실제 `Controls.Read`, `PlayerRig`, `TractorBeamController`, `Stage2Bootstrap`, `Stage2Yard`를 대조했다.
- 화면 직접 조작 없이 파일 조사 및 별도 검증 프로젝트의 숨김 배치 테스트를 사용했다.
- 입력 매핑, 게임플레이 처리, 네트워크, 씬, 프리팹, 프로젝트 설정은 변경하지 않는다. 런타임 변경은 UI 파일 3개다.

## 원인

`GameHud.PromptFor`의 `Grabbable` 분기가 마우스 입력 대신 `Controls.TransportAction`을 표시했다. 고정물과 일반 운반물, 동료, 방망이, 용접 건이 모두 이 분기를 사용해 `[E] 잡기`가 나왔다. 실제 `Controls.Read`와 `PlayerRig`는 좌/우클릭을 읽는다. 태블릿의 운반 안내에도 E로 장비를 줍거나 교환한다고 적혀 있었다.

기존 `HudNoticeStyleTests` 중 두 검사는 잡기 안내가 탑승 키를 따라야 한다고 잘못 가정했다. 탑승 안내의 키 재지정 검사로 바로잡고, 잡기 안내는 좌클릭으로 유지되는지 별도로 검사했다.

| 2장 고정 샤워 | 2m 안에서 자동 제독 | 해당 대상 종류에 버튼 없는 거리 안내 사용 |

첫 번째 행은 `PlayerInteractionKind.Grabbable` 전체를 고치므로 에셋 이름별 예외나 일부 오브젝트만 바뀌는 문제가 없다. 입력 불가·빈 공간은 기존대로 숨기며, 고정못/도구 사용 중 숨김과 끼임 탈출 우선순위도 보존했다.

`Stage2Hud`의 상호작용, 감압, 고리 해제, 구조, 태블릿, 복구 문구는 현재 키 설정을 읽는다. 볼트 상태 문구는 그대로 전달하며 일반 장비 안내에 섞지 않는다. 공통 도움말의 기어오르기 안내도 현재 전진 키를 읽는다.

사용 중인 UI 소스와 직렬화된 에셋의 잡기/줍기/탑승 문구를 검색했다. 별도 ‘만지기’ 키 분기는 없으며 손 접촉/잡기는 기존 손 입력 처리다. 현재 UI에서 참조하지 않는 `TractorBeamController.StatusMessage`의 과거 안내 문자열이나 게임플레이 진단 로그는 수정하지 않았다.

## 회귀 및 오류 검토

- `Controls` 및 입력 소비 코드 변경 없음. E로 방망이·용접 건을 집는 기능을 추가하지 않는다.
- 양쪽 마우스로 각 도구를 집고 Q로 충전·놓기/투척하는 기존 동작, 고정물의 좌/우손 잡기, E 무반응을 같은 테스트에서 대조한다.
- 탑승 키를 F7로 바꾸어도 잡기는 `[좌클릭]`, 탑승과 2장 장비는 `[F7]`인지 검사한다.
- `GameHud.AppendPromptGlyphs`에 마우스 안내를 명시적으로 등록했다. 도움말은 기존 공통 글자 수집 경로를 사용한다.
- 태블릿 손/도구 항목은 7개로 최대 카드 수 12개 이내다. 키캡이 길어지지 않도록 유지 동작은 설명 본문에 넣었다.
- 새 에셋·직렬화 필드·종속성·네트워크 메시지를 추가하지 않는다.

## 자동 검증

산출물: 저장소 루트 `.local-validation/689-ui/`. 검사 프로젝트에는 이 브랜치의 코드, 셰이더, Mirror, 안내 이미지와 설정을 복사하고 기존 로컬 패키지 캐시를 사용했다. 검증 프로젝트에 게임 씬 전체를 복사하지 않았다.

1. 변경 전 런타임 코드 + 새 회귀 검사: 44개 중 37 통과, 7 실패. 잡기 키와 도움말 불일치를 재현했다 (`before.xml`, `before-retry.log`).
2. 최초 확대 검사: 166개 중 144 통과, 22 실패 (`final.xml`, `final.log`). 관련 UI·도구·고정물 잡기·탑승 검사는 모두 통과했다. 고정못 관련 10개와 2장 씬/리소스가 필요한 12개 실패를 별도 기준 검사로 분리한다.

3. 변경 전 소스로 실패가 있던 4개 픽스처 재실행: 40개 중 18 통과, 22 실패 (`baseline-existing.xml`, `baseline-existing.log`). 최초 확대 검사와 실패 이름 및 메시지가 모두 같다.
4. 최종 수정본 재컴파일 및 동일 확대 검사: **166개 중 144 통과, 22 실패, 생략 0** (`verified.xml`, `verified.log`). 변경 전과 실패 이름/메시지 차이 0건, C# 컴파일 오류 0건. 워크트리의 변경 소스 7개와 실제 검사한 파일의 해시가 모두 일치한다.

이번 변경과 직접 관련된 UI·도움말·양손 도구 집기·일반 고정물 잡기/탑승·조준·키 가이드·동료 잡기/구조 연결·고정못 점유·온보딩 10개 픽스처는 **126/126 통과**했다. 추가 범위에서 18개가 통과했다.

기존/환경 실패는 다음과 같다. 이 실패를 숨기거나 테스트를 비활성화하지 않았다.

- `ClampPullTests` 8개, `DownedRescueTests` 2개: 수정 전부터 같은 고정못 잡기/당기기 선행 조건에서 실패한다. 이번 UI 변경의 회귀는 아니지만 실제 고정못 동작의 무오류를 보장하지 않으며, 테스트 조건과 실제 동작 중 어느 쪽의 문제인지 별도 조사가 필요하다.
- `Stage2PressureTests` 6개, `Stage2Tests` 6개: 격리 검사에 `Stage2_Earth` 씬과 엔딩 연결 리소스가 없어 씬 열기/리소스 선행 조건에서 실패한다. 2장 전체 씬 통합 검사는 미완료다. 2장 모든 대상 종류의 키 안내 및 볼트 입력 계산 검사는 통과했다.

`git diff --check` 통과. 변경 파일은 UI 3개, 기존 테스트 4개, 이 기록 1개다. 원래 작업 폴더의 렌더링 설정 수정 6개는 그대로 유지했다.

## 실제 플레이에서 남은 확인

화면 직접 조작은 하지 않았다. 다음 항목은 자동 검사를 통과한 것으로 간주하지 않는다.

1. Stage1/연습실에서 고정물, 파츠, 방망이, 용접 건, 동료를 조준해 `[좌클릭] 잡기`를 확인하고 양쪽 클릭으로 잡는다. 도구는 클릭을 뗀 뒤 다시 눌러 사용한다.
2. 고정못은 클릭 유지·뒤로 이동, 운반 장치는 E 탑승/하차, 동료 구조는 G 유지, 도구 버리기·투척은 Q가 그대로인지 확인한다.
3. 탑승 키를 재지정하고 일반 잡기와 2장 장비 안내가 각각 마우스/재지정 키로 구분되는지 확인한다.
4. 태블릿, 메뉴, 컷신, 다운 상태에서 안내 숨김/복귀 및 해상도별 문구 잘림을 확인한다.
5. 호스트와 원격 참가자에서 같은 대상을 조준·장착·해제하고 잘못된 안내가 다시 나타나지 않는지 확인한다.

전체 플레이어 빌드, 실제 씬의 화면 배치, 다인 네트워크 플레이는 이번 검증 범위 밖이다. 자동 검사 결과는 프로젝트 전체 무오류 보장이 아니다.
