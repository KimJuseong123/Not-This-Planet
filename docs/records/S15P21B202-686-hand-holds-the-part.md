# S15P21B202-686 · 손이 파츠를 실제로 잡고 있게

> S15P21B202-667 에서 "손으로 잡고 밀거나 당겨도 끙끙 끌리게 되어야 한다" 를 받고
> **걷는 속도를 파츠에 맞춰 늦추는 것까지** 했다. 손은 아직 허가증일 뿐이었다.

## 먼저 쟀다 — 셋 중 하나가 결함이었다

지라에 "먼저 잴 것" 으로 적어 둔 세 가지다.

| 무엇 | 결과 |
|---|---|
| 잡은 채 멀어져도 계속 끌리는가 | **그렇다. 73m 떨어져서도 0.62m/s 로 끌렸다** |
| 끄는 동안 손과 표면이 얼마나 벌어지는가 | 3초에 0.16 → 0.83m (하네스 한계 있음, 아래) |
| 놓인·박힌 파츠에 붙을 수 있는가 | 아니다. `TryGrab` 이 `Free` 만 받는다 |

세 번째는 이미 안전했다. **-667 에서 고정못을 잡은 사람이 밀리지 않는 벽이 되는
문제를 겪었기 때문에** 이것부터 확인했고, 그 경로는 막혀 있었다.

### 첫 측정은 틀렸다 — 계측이 조건을 지우고 있었다

사람을 `PlayerRig.Teleport` 로 옮겨 놓고 쟀더니 이렇게 나왔다.

```
[M1] 거리 3m: HaulerCount=0 Gripping=False
[M1] 거리 100m: HaulerCount=0 Gripping=False
```

"거리로 잘 놓고 있다" 로 읽힌다. **그런데 `Teleport` 가 스스로 `ReleaseHand` 를
부른다.** 내가 놓아 놓고 "놓아지네" 를 재고 있었다. 인형을 통째로 옮기는 방식으로
바꾸니 진짜 값이 나왔다.

```
[M1] 1.6m: HaulerCount=1 Gripping=True 1초이동=0.745m
[M1] 70m:  HaulerCount=1 Gripping=True 1초이동=0.622m   ← 손-표면 73.16m
```

## 원인

`PartPush.Gather` 에 이렇게 적혀 있었다.

```csharp
// 손으로 잡았으면 접촉·조준을 다시 보지 않는다.
var holding = able && (IsHoldingPart(player.LeftHand) || IsHoldingPart(player.RightHand));
```

`able` 은 `!Downed && !IsRiding` 뿐이다. **거리 항이 없다.** 그리고 손을 거리로
놓는 경로도 `PlayerRig` 어디에도 없었다 — `ReleaseHand` 를 부르는 자리를 전부
봤지만 거리 조건은 하나도 없다.

## 고친 것

### 1. 팔 길이를 벗어나면 놓는다

`PartPush` 가 손에서 표면까지의 거리를 보고, 벗어나면 **그 자리에서 놓는다**
(`PlayerRig.ReleaseHaulGrip`).

**세지 않기만 하면 안 된다.** 밀기 집계에서 빼기만 하면 손은 영영 붙어 있는
것으로 남아 다시 잡을 수도, 다른 것을 잡을 수도 없다.

값(`PartPushHoldReach = 1.4`)은 **일부러 넉넉하다.** 실제로 끄는 동안의 간격은
EditMode 에서 못 잰다 — 인형을 키네매틱으로 두지 않으면 하네스가 밀기가 아니라
**밀어내기를 재고**(-667 에서 겪었다), 키네매틱으로 두면 사람이 파츠를 통과해
지나가 거리가 가짜로 커진다. 그래서 "정상 운반을 절대 끊지 않는다" 쪽으로 잡았다.
**73m 를 50분의 1로 줄이는 것이 이 값의 일이고**, 조이는 것은 인게임에서 볼 일이다.

### 2. 팔이 잡은 지점을 향한다

`DriveArm` 은 팔을 **조준 방향(카메라 앞)** 으로만 뻗었다. 파츠를 잡고 있어도
그랬다 — `hand.AimedPoint` 만 파츠로 바뀌고 팔이 향하는 곳은 그대로였다.

그래서 옆이나 뒤로 걸으면 몸은 카메라를 보는데 파츠는 옆에 있어 **손만 따로
논다.** 이제 잡고 있는 동안에는 `HaulGrasp` 쪽으로 뻗는다.

**팔 길이 안으로 자른다.** 넘기면 뻗다 못해 뜯긴다 — 자석 손이 같은 이유로 같은
것을 한다. 잡은 지점이 어깨와 겹치면 조준 방향으로 돌아간다(방향이 0 이면
`FromToRotation` 이 쓰레기 회전을 내놓는다).

지점은 `HaulGrasp` 를 쓴다. 그 값은 이미 밀기 카메라가 쓰려고 서버에서 내려오는
것이라 **호스트와 참가자가 같은 값을 본다** — 새 동기화를 만들지 않았다.

## 조인트는 안 넣었다 — 지라와 달라진 점

지라에는 "유연한 `ConfigurableJoint` 로 손과 파츠를 잇는다" 로 적었다. 재고 나서
**안 넣는 쪽이 맞다고 판단했다.**

파츠를 움직이는 권위는 `PartPush.Drive` 하나여야 한다. 인원별 속도표(§13.2)는
`Drive` 가 `along >= top` 으로 지키는데, **조인트의 구속력은 그 검사를 통과하지
않는다.** 조인트가 파츠를 끌면 표를 넘고, 안 끌 만큼 약하게 하면 조인트가 할 일이
없다. 그리고 끼임·튕김이라는 대가가 남는다.

실제로 느껴지던 문제 둘은 **팔이 파츠를 안 보는 것**과 **거리를 안 보는 것**이었고,
둘 다 조인트 없이 고쳐진다. 조인트는 "파츠가 바위에 걸렸을 때 버티는 느낌" 을
주지만 그것은 이 이슈가 받은 주문이 아니다.

## 검증

`PartHaulGripTests` 10건 신규.

| 무엇을 지키나 |
|---|
| 팔 길이를 벗어나면 **손을 놓는다** |
| **70m 떨어진 사람은 파츠를 못 끈다** |
| 닿는 거리에서는 절대 안 놓는다 |
| 놓으면 손이 비어 **다시 잡을 수 있다** |
| 놓는 거리가 실측 최대치(0.83m)보다 넉넉하다 |
| 팔이 **조준 방향이 아니라 잡은 지점**을 향한다 |
| 팔이 팔 길이를 넘어 뻗지 않는다 |
| 가까운 지점을 바깥으로 늘리지 않는다 |
| 잡은 지점이 어깨와 겹치면 조준 방향으로 돌아간다 |
| 놓인·박힌 파츠는 여전히 손으로 못 잡는다 |

## 기존 검사 12건을 고쳤다 — 전부 같은 이유다

`PartPushTests` 가 **사람을 출발선에 세워 둔 채 파츠만 3초 보내고 있었다.** 그때는
그래도 됐다 — `PartPush` 가 거리를 아예 안 봤기 때문이다. 이 이슈가 그것을 고쳤으니
하네스도 실제 운반처럼 따라가야 한다.

`FollowPart` 를 넣어 잡은 사람이 파츠를 따라가게 했다. `Freeze` 가 콜라이더를
껐으니 따라가도 접촉은 안 생긴다 — 재는 것은 여전히 지면 마찰뿐이다.

`WithNobodyPushing_ItCoastsToAStop` 에는 *"손은 놓지 않고 걸음만 멈춘다 — 잡기는
거리로 끊기지 않는다"* 라고 적혀 있었다. **이 이슈가 일부러 바꾼 바로 그 문장**이라
따라가게 고치고 주석을 다시 적었다.

기존 하네스의 `Tick(..., followers)` 는 따라가는 데 `Teleport` 를 쓴다 — 그것이
손을 놓는다. 잡기 경로에는 `ShiftDoll` 을 따로 뒀다.

## 남은 것

* **놓는 거리 1.4m 를 조이는 것** — 인게임에서 손이 파츠에 붙어 보이는지 보고
  줄인다. 지금 값은 결함을 없애는 데 필요한 만큼만이고, 넉넉한 쪽으로 틀렸다
* **파츠가 걸렸을 때 손을 놓치는 느낌** — 지금은 거리 하나로만 끊는다. 잠깐
  벗어났다 돌아오는 것과 정말 놓친 것을 가르려면 유예 시간이 필요하다
* **2프로세스 눈 확인** — 참가자 화면에서도 팔이 파츠를 향하는가. `HaulGrasp` 가
  이미 동기화되므로 원리상 같아야 하지만 EditMode 가 대신 못 하는 자리다
* **팔이 잡은 지점을 향하는 것의 실제 모습** — `DriveArms` 는 EditMode 에서 안 돈다.
  여기서 잰 것은 **어디를 향할지 정하는 규칙**이지 팔이 실제로 간 자리가 아니다
