# S15P21B202-699 · 살리러 다가가면 안내가 사라졌다

> "살리는 사람 입장에서는 살리는 UI가 안 보임 (살려짐당하는 사람은 보임)"

## 재서 찾았다

구조 지점은 **바닥**에 있고(높이 0.30m) 눈은 0.83m 다. 가까이 갈수록 내려다보는
각이 가팔라져 시야각 35도를 넘는다.

| 거리 | 내려다보는 각 | 후보 |
|---|---|---|
| 0.3m | — | **X** |
| 0.5m | **46.6°** | **X** |
| 0.7m | **37.1°** | **X** |
| 0.9m | 30.4° | O |
| 1.6m | 18.3° | O |
| 2.6m | 7.1° | X (사거리 2.5m — 맞다) |

**살리러 다가가면 후보에서 떨어진다.** 안내를 그리는 조건이 `RescueCandidate != null`
이라, 안내도 같이 사라진다.

### 두 번 틀렸다

1. 처음에는 "각도가 원인일 것" 이라고 **읽어서** 짐작했다. 그다음 잰 값이
   `0.5m → 31.0도` 로 상한 안이라 **가설이 죽은 줄 알았다.** 원점을 리그 루트
   (y=0)로 찍었기 때문이다 — 실제 기준은 조준 피벗(y=0.83)이다. **계측이 틀렸고,
   고치니 46.6도가 나왔다.**
2. 그 전에는 "`Interactor.Tick` 을 게임이 안 부르는 것 아닌가" 를 의심했다. 부른다.

## 고친 것

`Interactor.NearRadius` — **이 거리 안이면 시야각을 안 본다.** 기본값 0 이라 다른
인터랙터는 그대로다. 구조에만 `DownedRescueNearReach = 1.2m` 를 켠다.

**원뿔은 바닥에 누운 대상에게 틀린 모양이다.** 원뿔은 눈에서 나가므로 발치에 있는
것일수록 밖으로 나간다. 그리고 발치에 쓰러진 사람이 있으면 **누구를 가리키는지
모호할 수가 없다.** 고르는 규칙(`IsBetter`)은 그대로라 둘이 나란히 있어도 더 정면인
쪽이 이긴다.

## 그러다 내가 만든 것 — 내가 나를 일으키는 후보가 됐다

각도를 안 보게 하자 `YouAreNeverYourOwnRescueCandidate` 와
`ADownedPlayerCannotRescueAnyone` 이 깨졌다.

**예전에는 시야각이 우연히 그것을 막고 있었다.** 내 구조 지점은 내 발밑이라 눈에서
보면 거의 수직 아래고, 그래서 35도 원뿔 밖이었다. **규칙을 기하에 기대고 있었던
것이다.**

`OnlyDownedRescue` 에 규칙을 못 박았다 — *나 자신이 아니고, 내가 안 쓰러졌을 때만*.
`DownedRescue.GetAvailability` 도 같은 것을 막지만 **그것은 잡은 뒤에 보는 문이라
후보 목록에는 남는다** — 그러면 화면에 안내가 뜬다.

## 화면이 무엇을 그리는지 화면 없이 잰다

"구조자 화면에 안내가 안 뜬다" 는 신고인데 **그리는 조건이 `OnGUI` 안에만 있어
잴 방법이 없었다.** 기존 검사가 이 화면에 대해 재던 것은 소스에 `wordWrap` 과
`CalcHeight` 가 있는지뿐이다.

`DownedRescueHud.Decide(downed, beingRescued01, hasCandidate, progress01)` 로 뺐다.
`None` · `BeingRescued` · `Prompt` · `Progress` 넷이다.

## 검증

| 무엇을 지키나 |
|---|
| **발치(0.3 · 0.5 · 0.7 · 0.9m)에 쓰러진 사람도 후보다** |
| 가까운 것을 봐 주는 규칙이 **사거리를 늘리지 않는다** (2.6m 는 여전히 아니다) |
| **다른 인터랙터는 원뿔 그대로다** (`NearRadius` 기본 0) |
| 내가 나를 일으키는 후보가 되지 않는다 |
| 쓰러진 사람은 남을 일으킬 후보를 못 받는다 |
| **일으킬 사람이 있으면 `[G]` 안내가 뜬다** |
| 진행분이 있으면 게이지가 뜬다 (이어받기) |
| 쓰러진 쪽 화면은 -448 그대로다 |
| 쓰러진 사람에게는 일으키기 안내가 안 뜬다 |

`RescueVisibilityTests` 3건 · `RescueWiringTests` 5건 신규. 관련 스위트 113개
(1,528건) 중 22건 실패는 **clean develop 에서도 같은 22건**이다 — 새로 깨진 것은 없다.
(기준선에서 하나 더 실패한 `VegetationInteractionTests` 는 접촉으로 흔들림을 재는
검사라 흔들린다. 이 브랜치에서는 통과했다.)

## 남은 것

* **2프로세스 눈 확인** — 신고가 나온 자리다. 호스트·참가자 양쪽에서 구조자 화면에
  `[G]` 가 뜨는지. EditMode 가 대신 못 한다
* **이것이 신고의 전부인지는 확인 못 했다.** 잰 것은 "0.8m 안쪽에서 후보가 떨어진다"
  이고, 실제로 사용자가 그 거리에 있었는지는 2프로세스로 봐야 안다. 다른 원인이
  남아 있으면 이 기록에 덧붙인다
* **운반(`CarryInteractor`)도 같은 모양일 수 있다.** 구조와 같은 사거리·시야각을
  쓰고 같은 사람을 겨냥한다. 재 보지 않았다
