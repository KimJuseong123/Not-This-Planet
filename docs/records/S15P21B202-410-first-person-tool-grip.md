# S15P21B202-410 — 1인칭 도구 장착 위치 및 방망이 휘두르기 보정

## 문제

- 플라즈마 용접기를 들면 실제 모델이 카메라 앞을 넓게 가려 작업 지점을 보기 어려웠다.
- 운석 방망이는 손 표시와 떨어져 보였고, 스윙 후반에 큰 모델이 화면 아래로 내려가 지면을
  뚫는 것처럼 보였다.

두 도구의 물리 루트는 `PlayerRig`가 카메라 조준 방향 0.55m 앞에 둔다. 그 뒤 도구별
스크립트가 보이는 자식 모델에 큰 위치 오프셋과 원본 크기를 다시 적용하고 있었다.
용접기는 `(0.70, -0.90, 0.25)`, 방망이는 `(0.45, -0.55, 0.35)`여서 1인칭 손의 기본
위치 `(±0.18, -0.14, 0.37)`와도 크게 어긋났다.

또한 물리 루트는 `FixedUpdate`에서 위치·회전을 지수 보간하고 Rigidbody 보간도 적용한다.
보이는 모델까지 그 루트의 자식이어서, 플레이어가 이동하거나 시점을 돌리면 도구가 화면을
한 박자 늦게 따라오는 현상이 생겼다.

## 변경

물리 루트·콜라이더·타격 판정·빔 사거리는 유지하고, 로컬 1인칭에서 보이는 모델만 카메라
아래로 분리했다. 화면 모델은 `LateUpdate`에서 카메라와 같은 프레임에 움직이므로 물리
보간의 지연을 받지 않는다. 방망이의 스윙 방향은 같은 렌더 프레임에 별도로 적용한다.
도구 화면 갱신 순서를 카메라와 손 표시 뒤로 고정해, 같은 프레임 안에서도 오래된 카메라
자세를 읽지 않게 했다.

3인칭 전환 또는 장비 해제 시 모델을 원래 물리 도구 계층과 형제 순서로 복원한다. 원격
플레이어에게는 기존 월드 휴대 포즈가 계속 적용된다.

| 도구 | 월드 휴대 위치/크기 | 로컬 1인칭 위치/크기 | 회전 |
| --- | --- | --- | --- |
| 플라즈마 용접기 | `(0.18, -0.14, 0.12)` / `0.55` | `(0.20, -0.17, 0.52)` / `0.275` | 기존 값 유지 |
| 운석 방망이 | `(0.18, -0.12, 0.12)` / `0.64` | `(0.23, -0.20, 0.58)` / `0.64` | 기존 값 유지 |

방망이에도 용접기와 같은 장착 전용 스케일을 추가했다. 장착 직전에 위치·회전·크기를 모두
저장하고, 내려놓을 때 원래 값을 복원한다. 따라서 맵에 놓인 도구의 외형 크기와 물리 크기는
달라지지 않는다.

두 컴포넌트에서 월드 휴대 포즈와 `로컬 1인칭 화면 포즈`를 구분해 위치·회전·크기를
`SerializeField`로 노출했다.
Play 중 장착된 도구의 값을 Inspector에서 수정하면 `OnValidate`가 즉시 화면 모델에 다시
적용한다. 원하는 구도를 보면서 조절할 수 있고, 최종 값은 Play를 종료하기 전에 별도로
기록해 Edit 모드의 프리팹 또는 씬 인스턴스에 입력해야 한다.

`Stage1_Astra`에는 프리팹과 연결되지 않은 도구 컴포넌트 값이 따로 저장돼 있어, 프리팹과
씬의 두 인스턴스 값을 함께 갱신했다. 도구의 월드 배치 좌표와 다른 씬 오브젝트는 변경하지
않았다.

용접기 모델의 위치와 크기가 바뀐 뒤에도 노즐 기준점은 `ResolveNozzleTip`이 실제 렌더러
경계에서 다시 계산한다. 빔·용접·절단 판정이 축소된 모델의 노즐 끝을 계속 사용한다.

## 확인 방법

1. `Stage1_Astra` 씬을 열고 Play 한다.
2. 플라즈마 용접기를 들어 중앙 조준점과 작업 대상이 모델에 가려지지 않는지 확인한다.
3. 용접·절단 빔이 보이는 노즐 끝에서 시작하는지 확인한다.
4. 운석 방망이를 들어 손 가까이에 보이는지 확인하고, 정면과 아래쪽을 보며 휘두른다.
5. 스윙 후반의 방망이가 지면 아래로 파고드는 것처럼 보이지 않는지 확인한다.
6. 걷고 뛰거나 시점을 빠르게 돌려도 도구가 화면보다 한 박자 늦게 따라오지 않는지 확인한다.
7. 3인칭으로 전환했을 때 도구 모델이 월드의 물리 도구 위치로 돌아오는지 확인한다.
8. 두 도구를 내려놓아 월드에서 원래 크기로 복원되는지 확인한다.

## 자동 검증 상태

- 수정 파일의 공백·충돌 검사는 통과했다(`git diff --check`).
- Unity EditMode 검증을 실행했으나 이 PC의 `Unity Licensing Client` 연결이 반복해서
  끊겨 테스트 러너 진입 전에 중단됐다. 카메라 부착·물리 이동과의 분리·3인칭 복원 검증은
  테스트 코드에 추가했다.
- 이후 Unity를 일반 편집기 모드로 열어 자산 재가져오기와 스크립트 컴파일이 완료됐고,
  Editor 로그에서 C# 컴파일 오류가 없음을 확인했다.
- `Metagame.Gameplay.Tests.Editor.csproj` 전체 빌드도 경고·오류 없이 통과했다.
