# S15P21B202-226 — 우주선 몸체에 용접 비드 생성과 성장

용접건을 우주선 몸체에 대면 금속 비드가 자란다. 상한 크기에 이르면 다음 덩어리가
이어져 기둥이 뻗는다. 기획 §16.2 의 "용접한 구간에는 실제 금속 비드와 불탄 자국이
남는다" 를 <b>물리 있는 물체</b>로 만든 것이다.

비드 방식으로 가기로 한 근거는 이렇다. 지금 용접은 파츠 사이의 정해진 원형 접합선
위에서만 되고, 그마저 진행 바도 소리도 불꽃도 없어 <b>되고 있는지 알 수 없다</b>.
플레이테스트에서 "용접 방법을 모름" 으로 나온 것이 이것이다. 비드는 자국·강도·피드백을
하나로 합친다 — 보이는 것이 곧 진행이고, 쌓인 양이 곧 강도다.

이 이슈는 <b>쌓이는 것까지</b> 다. 비드가 다른 몸체에 닿아 하나로 합쳐지는 것은 다음
이슈에서 한다.

## 조인트 사슬로 만들지 않았다

덩어리마다 Rigidbody 를 주고 조인트로 이으면 가늘고 긴 조인트 사슬이 된다. PhysX 에서
그런 사슬은 위에 얹힌 406~745kg 짜리 파츠를 버티지 못하고 떨거나 터진다. S15P21B202-194
에서 실측한 탑 붕괴는 조인트가 <b>하나</b>일 때의 값이었다.

대신 덩어리를 자란 파츠의 <b>자식 콜라이더</b>로 뒀다.

```
Part_1 (Rigidbody 하나)
 ├ Body_0..2                ← 원래 컴파운드 콜라이더 (S15P21B202-166)
 └ WeldBeads
    └ Bead_0_0, Bead_0_1 ...  ← 자란 비드 (콜라이더 + 렌더러, 강체 없음)
```

`Beads_AddNoRigidbodiesAndNoJoints` 가 이 결정을 잠근다 — 강체는 파츠 하나, 조인트는 0개다.

## 무게중심 — 대입하지 않았고, 대입할 필요도 없었다

"하나의 물체가 되었을 때 무게중심을 다시 설정해야 하는가" 가 이 작업의 출발 질문이었다.
답은 <b>아니다</b> 다.

이 프로젝트는 `Rigidbody.centerOfMass` 를 어디에서도 대입하지 않는다(전체 검색으로 확인).
Unity 가 자식 콜라이더에서 자동 계산하고, S15P21B202-166 이 파츠별 컴파운드 콜라이더를
실측해 넣은 것이 그 자동 계산을 쓰기 위해서다. 비드를 콜라이더로 붙이면 무게중심이
저절로 따라온다. 한 번이라도 대입하면 자동 계산이 <b>영구히</b> 꺼지므로 앞으로도
대입하지 않는다.

### 실측하며 알게 된 것 — 질량과 무게중심은 따로 논다

처음에는 "오른쪽에만 쌓으면 무게중심이 2.5cm 옮겨갈 것" 으로 보고 검증을 그 크기로
썼다. <b>실측은 0.6mm 였다.</b>

원인은 자동 무게중심이 우리가 정한 `Rigidbody.mass` 가 아니라 <b>콜라이더 부피</b>로
계산되기 때문이다(밀도가 균일하다고 본다). 그래서

| | 값 |
| --- | --- |
| 파츠 상자 부피 | 3 × 3.7 × 3 = 33.3 m³ |
| 비드 한 덩어리 | 4/3π(0.1)³ = 0.0042 m³ |
| 부피비 | 약 1/4000 |
| 지레팔 | 약 1.6m |
| 예상 이동량 | 0.4mm — 실측 0.6mm 와 맞는다 |

비드 질량을 얼마로 잡든 무게중심은 부피만큼만 움직인다. <b>그리고 그것이 맞다</b> —
3.7m 짜리 파츠의 무게중심이 비드 몇 덩어리로 크게 흔들리면 그쪽이 이상하다.

그래서 검증을 <b>양</b>이 아니라 <b>방향</b>으로 바꿨다. 자동 계산이 꺼지면 이 값이
정확히 0 이 되므로 방향만으로도 잡힌다. 짝으로 `SymmetricBeads_LeaveTheCenterOfMassInPlace`
를 뒀다 — 양쪽에 똑같이 쌓으면 제자리여야, 아무 쪽으로나 흔들리는 것과 구분된다.

## 질량은 파츠를 거쳐 간다

`Rigidbody.mass` 를 밖에서 더할 수 없다. `SpaceshipPart.ApplyRepresentation` 이 상태 전환마다
질량을 <b>다시 쓰기</b> 때문에 밖에서 더해 두면 다음 전환에 조용히 사라진다. 그래서
질량의 주인을 하나로 두고 덧붙는 몫만 `SetExtraMass` 로 넘긴다.

`BeadMass_SurvivesAStateChange` 가 이 함정을 잠근다.

견인 중(`Carried`)에는 더하지 않는다. `CarriedPartMass` 는 크기와 무관하게 "플레이어를
압사시키지 않는 값" 이라 파츠 질량조차 무시하는 자리인데, 여기에 비드 무게를 더하면
비드를 쌓은 파츠만 견인이 달라진다.

## 우주선 몸체에만

지형·운석·소품·운반체에는 생기지 않는다. 안 그러면 비드로 사다리를 만들어 올라가거나
우주선을 지면에 용접해 버린다.

<b>레이어와 컴포넌트를 둘 다 본다.</b> 레이어만 보면 파츠와 같은 레이어에 있는 다른
것에도 붙고, 컴포넌트만 보면 파츠의 자식인 고정못(Interactable 레이어)에도 붙는다.
검증 네 개가 각각 지면·운석·소품·"레이어만 맞는 것" 을 막는다.

이미 쌓인 비드는 <b>씨앗으로 쓰지 않는다</b>. 비드 위에서 새 기둥이 시작되면 사슬
길이 상한이 무의미해진다.

## 상한 셋이 곧 게임 규칙이다

| 상한 | 값 | 뜻 |
| --- | --- | --- |
| 덩어리 최대 반지름 | 0.10m | 그림의 "상한선". 넘으면 다음 덩어리가 시작된다 |
| 사슬당 덩어리 수 | 6개 | <b>최대 다리 길이</b> ≈ 0.75m |
| 파츠당 총 덩어리 | 48개 | 성능 상한 (사슬 8개 × 6개) |

사슬 길이 상한을 사거리(0.80m)보다 <b>짧게</b> 둔 것이 의도다. 길이 상한이 사거리보다
길면 플레이어가 자기 기둥의 끝을 놓쳐 왜 멈췄는지 알 수 없다.

## 사슬을 잇는 판정에서 한 번 틀렸다

처음에는 "노즐이 사슬 <b>끝</b>에서 0.35m 안이면 잇는다" 로 썼다. 검증을 돌려 보니
기둥이 5번째 덩어리까지 자란 순간 끝이 노즐에서 0.37m 로 멀어져 사슬을 놓치고,
<b>같은 자리에 두 번째 기둥이 겹쳐</b> 생겼다. 플레이어는 가만히 서 있는데 기둥이
갑자기 둘로 갈라지는 셈이다.

사슬의 <b>모든 덩어리</b>와 재는 것으로 바꿨다. 기둥 밑동은 언제나 노즐 근처에 있으므로
기둥이 얼마나 길어져도 놓치지 않는다.

## 겉모습 — 에셋이 필요하지 않다

`Prim.Ball` 로 만든 구 하나에 금속색을 줬다. 이 프로젝트의 다른 외형도 모두 코드로
만든 도형이고(`Prim.Box/Ball/Pipe`, `Puff`), `Prim.Dough` 가 색·광택별로 머티리얼을
공유하므로 48개를 만들어도 머티리얼은 하나다.

[Art] 가 실제 비드 메시(울퉁불퉁한 금속, 불탄 자국 텍스처)를 주면 `SpawnBlob` 의
`Prim.Ball` 자리만 바꾼다.

## 절단으로 되돌린다

쌓을 수만 있고 되돌릴 수 없으면 잘못 쏜 한 번이 파츠에 영구히 남는다. 우클릭으로
끝 덩어리가 줄고, 최소보다 작아지면 지워지고 아래 덩어리가 새 끝이 된다.

도구에서 원형 접합선이 <b>먼저</b>다(`AnAssembledSeam_TakesPriorityOverBeads`). 접합선
위에서 비드부터 쌓이면 §16.1 의 원형 용접이 영영 채워지지 않는다.

`WeldBeadTests` <b>25개 전부 통과</b>. EditMode 전체 383개 중 378 통과.

실패 5개는 <b>develop 에 이미 있던 것</b>이다. develop(f153ede)만 체크아웃해 같은 다섯
개를 돌려 다섯 개가 그대로 실패하는 것을 확인했다.

### 실제 파츠에서도 확인했다

이 이슈가 손대는 것이 파츠의 콜라이더 구성이므로, 검증 리그의 상자 하나가 아니라
`PartSpec` 의 실측 상자로 만든 컴파운드 콜라이더 파츠에서도 잠갔다
(`BeadsGrowOnARealPart_AndItsCenterOfMassStaysBelowCenter`). 실측 질량에 비드 무게가
더해지고, S15P21B202-166 이 세운 "무게중심이 파츠 중심보다 아래" 가 위에 비드를 쌓은
뒤에도 유지된다.

## 인게임 확인은 못 했다 — 빌드가 develop 에서 깨져 있다

윈도우 빌드가 `UrpRenderValidation` 에서 멈춘다. 원인 두 개 모두 내가 건드리지 않은
자산이다.

### 1. 지형 자산이 체크아웃에서 깨진다

```
Unknown error occurred while loading
  'Assets/_Project/Terrain/Stage1/TerrainData/TD_Stage1_Arena.asset'.
Invalid serialized file header.
```

`.gitattributes:4` 의 `*.asset text` 가 <b>바이너리</b> TerrainData 를 텍스트로 보고
체크아웃할 때 개행을 변환한다. 실측:

```
git blob : 393,724 바이트
worktree : 393,726 바이트     ← CRLF 변환으로 2바이트가 끼어든다
git check-attr text → text: set
```

이것이 그동안 게임에 지면이 없던 원인이고(`Terrain.terrainData == null`), 이제
<b>빌드 자체를 막는 단계로 올라왔다</b>. 팀 전원의 체크아웃이 같은 상태다.

고치는 것은 한 줄이다.

```
METAGAME/Assets/_Project/Terrain/**/*.asset -text
```

`.gitattributes` 는 [Infra] 소유이고 모든 팀원의 체크아웃에 영향을 주므로 <b>아직
적용하지 않았다</b>. 승인이 필요하다.

### 2. 로비 씬이 공용 URP Volume Profile 을 참조하지 않는다

```
[URP] Assets/Scenes/Lobby.unity가 공용 URP 기본 Volume Profile을 참조하지 않습니다.
```

`Lobby.unity` 안에 VolumeProfile 참조가 하나도 없다(검색으로 확인). URP 전환
(`465493d`)과 로비 매치 진입(`!161`) 사이에 생긴 빈틈이고 [Art]·[Level]·[Network]
몫이다.
