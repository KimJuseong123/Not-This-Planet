# AI 대상 배정과 재미 행동 1차

> 후속: 자연어 대상/행동 연결 및 요청자를 바라보는 반응은 [AI 자연어 대상 선택과 사회적 반응](2026-09-21-ai-social-language.md)에 구현·검증 결과를 기록했다. 아래는 버튼 우선 구현 시점의 기록이다.

## 범위
- 로컬 실험 브랜치 `codex/ai-team-slots-local`, 기준 `e5df800e`.
- 방장 개발용 ESC 메뉴에서 이름으로 한 명, 빈 동료 한 명/두 명, AI 전원을 선택한다.
- 인사(양손 들기 + 따봉 이모티콘), 기존 뮤직챌린지 춤, 하트/따봉, 모여, 따라오기, 대기, 중단, 기존 못 하나 뽑기를 직접 실행한다.
- 새 키, 모델 다운로드, 유료 API, 씬/프리팹 편집 없이 기존 입력/춤/이모티콘/서버 권한을 재사용한다.

## 배정 정책
- 인간 플레이어는 절대로 대상에 넣지 않는다.
- 자동 한 명/두 명은 작업하지 않는 AI를 거리순으로 선택한다. 수가 부족하면 가능한 인원만 배정하고 성공 수/요청 수를 표시한다.
- 이름 선택 또는 전원 지시는 기존 작업을 안전하게 교체한다. 다만 춤/인사/감정표현은 작업 중이거나 물체를 잡은 AI를 방해하지 않는다. 필요하면 먼저 중단한다.
- 비동기 LLM 요청은 전송 시점의 대상 객체와 명령 순번을 기억한다. 응답 전에 새 명령을 받은 AI, 사라진 AI, 사람으로 교체된 자리를 새로 찾아 명령하지 않는다.
- 모여는 명령 당시 플레이어 주변의 서로 다른 도착 지점을 배정한다. 도착하면 대기한다.
- 여러 명 따라오기는 서로 다른 상대 위치를 배정한다. 단일 따라오기는 기존 동작을 유지한다.
- 모일 공간이나 완전한 경로를 찾을 수 없으면 해당 동료는 기존 행동을 유지하고 미배정으로 표시한다.

## 게임에서 확인
1. 같은 프로젝트로 방장 게임을 시작하고 AI 추가팩 준비 완료/AI 활성 상태를 확인한다.
2. ESC 메뉴 아래 AI 지시 영역에서 대상 모드를 고른다. 안쪽 스크롤로 행동과 상태를 확인한다.
3. `AI 전원 → 모여`: 세 동료가 나누어 서는지 확인한다.
4. `빈 동료 2명 → 따라와`: 둘만 따라오는지 확인한다.
5. `빈 동료 1명 → 인사`: 남은 동료만 반응하는지 확인한다.
6. `모든 AI 즉시 중단 → AI 전원 → 춤`: 기존 춤 클립을 재생한다. 중단하면 춤도 멈춘다.
7. `하트/따봉`: 기존 네트워크 이모티콘을 표시한다.

## 텍스트와 직접 실행의 차이
- 직접 실행 버튼은 LLM을 거치지 않는다. 행동 로직과 대상 배정을 먼저 테스트하기 위한 기능이다.
- LLM 전송도 같은 대상 배정 경로를 사용하지만 현재 추가팩의 행동 분류 목록/프롬프트는 변경하지 않았다. 새 춤/인사/모여를 자연어로 인식하는지는 보장하지 않는다.
- 문장 안의 이름/색상/`다들`/`둘` 해석, 다른 사람의 명령, 복합 문장, 음성 연결은 아직 구현하지 않았다. 이번 대상 지정은 메뉴에서 한다.
- 못 전부 해제, 도구 줍기, 운반 등 작업 확장은 별도다.

## 검증
- `METAGAME/Logs/ai-group-v1.xml`: 기존 못/복구/춤 관련 44/44 통과.
- `METAGAME/Logs/ai-group-v2.xml`: 기존 AI 런타임/정책/자리/이동 검사 54개 통과(로컬 LLM 실연동 포함). 새 그룹 검사 1개는 배치 서버가 모델을 생략하여 춤 검사에서 실패했다.
- `METAGAME/Logs/ai-group-v3.xml`: 테스트 전용으로 실제 모델을 붙인 뒤 새 그룹 검사 1/1 통과. 두 명 배정, 작업 보호, 늦은 응답 보호, 춤 재생/중단 상태, 전원 모이기와 도착 간격을 확인했다. 제품의 헤드리스 모델 생략 정책은 변경하지 않았다.
- 최종 관련 검사 결과 합계 99개 통과(44 + 54 + 재검사 1). 전체 프로젝트 테스트 및 새 배포 빌드 검증은 아니다.
- 별도 PC 관찰 화면과 GUI 외형의 수동 검증은 아직 하지 않았다. 춤·이모티콘은 기존 SyncVar 경로를 사용한다.
