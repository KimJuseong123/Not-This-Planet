# Stage2 배수로 물과 수중 이동

## 요청과 기획 대조

2026-09-18 사용자 요청에 따라 기존 동쪽 배수로 장식을 실제 흐르는 수로로 바꾸고, 얕은 물 감속과 깊은 물 부유 이동을 추가했다. `chapter-2-plan.md`의 추가 결정에 반영했다. 기존 크레인·사다리 작업과 오염·제독 규칙은 그대로 유지한다. 입수는 제독이 아니며, 익사나 산소 자원을 새로 만들지 않았다.

## 맵과 화면

- x=33 중심의 동쪽 배수로. 보이는 수로는 약 7m × 60m, 수면 메시/판정 범위는 둑과 자연스럽게 겹치도록 9m × 64m. 수면 y=-0.12, 중앙 Terrain 바닥 약 -2.5m.
- 실제 TerrainData를 파고 TerrainCollider를 그대로 사용한다. 바닥을 가리는 평평한 충돌판은 추가하지 않는다. 양끝은 완만한 진출입 경사, 측면은 얕은 선반과 둑으로 이어진다.
- z=-16 / 10에 충돌과 난간이 있는 건널 다리 2개. 기존 식생은 둑으로 옮기고 수로를 가리던 폐허 벽은 안쪽으로 이동했다.
- URP 전용 수면 셰이더: 두 방향 잔물결, 흐름 방향의 미세 요철, Fresnel 반사, 장면 색 굴절, 깊이에 따른 흡수와 색 변화, 물가 포말과 흐르는 포말 조각.
- 256px HDR 큐브맵으로 실제 씬의 주변 환경을 미리 캡처한다. 수면 자체는 캡처에서 제외하며 플레이 중 반사 카메라를 추가 실행하지 않는다. 캐릭터 주위 최대 4개 잔물결과 잠수 시 색조가 추가된다.
- 로컬 게임 카메라에만 depth/opaque texture를 요청하며 비활성화 시 이전 설정을 복구한다. 프로젝트 전체 렌더 설정을 바꾸지 않는다.

## 이동 규칙

- 실제 토끼 골반 높이는 발 기준 0.30m. 발이 잠기는 정도에 따라 목표 속도가 최대 50%로 감소한다.
- 골반이 수면 아래 0.04m를 지나면 부유 진입, 수면 위 0.14m까지 유지하는 히스테리시스로 경계 떨림을 막는다.
- 깊은 곳은 수평 1.65m/s, 상승/하강 1.15m/s. 기존 WASD와 Space/Ctrl 입력 사용. 입력을 놓으면 감속하며 깊이를 유지한다.
- 수면 가까이에서 상승 목표 속도를 줄인다. 물속 진입 시 과도한 수직 속도를 제한해 바닥까지 관통하듯 떨어지는 것을 방지한다.
- 흐름은 -Z 방향 0.3m/s이며 얕은 곳에서는 35%만 반영한다.
- 물 밖, 물 영역 비활성화, 개인 복구, 탑승 시 중력을 복원한다. 작업대 이동 잠금과 매달리기를 존중하며, 기절 중 수영 입력은 받지 않는다.
- 기존 `PlayerRig`의 부유/래그돌 이동 경로를 확장한다. 별도 CharacterController나 물리 업데이트를 병렬로 추가하지 않는다.

## 멀티플레이

정적인 수로 좌표를 서버와 소유 클라이언트가 같은 방식으로 샘플링한다. 서버는 클라이언트의 ‘수영 중’ 결과를 받지 않고 직접 판정한다. 입력과 캐릭터 자세는 기존 `NetPlayer` 예측·서버 보정·관전자 보간 경로를 사용한다. 수면 효과는 표시 전용이며 실제 판정 수면을 흔들지 않는다. 새 NetworkIdentity, RPC, 패킷 형식은 없다.

## 검증 결과

- Unity 6000.5.4f1 배치모드 컴파일 및 관련 테스트 **35/35 통과** (`Stage2WaterTests`, `PlayerFloatTests`, `Stage2ArtTests`, `Stage2ContaminationTests`, `Stage2Tests`).
- 실제 Stage2 Play Mode에서 깊이 유지·상승·하강·수면 경계·감속·다리 위 건조 판정·물 비활성화·리스폰·기절·클라이언트 예측 권한 경로·끝 경사 출수를 검증했다.
- Terrain 바닥/얕은 선반, URP 카메라의 굴절 입력, 저장된 HDR 반사 RGB 데이터, 임시 카메라 미잔류와 셰이더 지원을 확인했다. 실제 URP 렌더 3장을 직접 검수했다.
- 최초 물 테스트는 EditMode의 EnterPlayMode 실행기에서 `WaitForFixedUpdate` 횟수를 물리 스텝 수로 잘못 간주해 충분한 시간을 기다리지 않았다. 실제 `Time.fixedTime` 경과를 기준으로 수정한 뒤 6/6 통과했고 최종 회귀에서도 재확인했다.
- 별도 Player 빌드나 실제 여러 PC의 네트워크 지연 검사는 이번 변경에서 실행하지 않았다.

## 표현 범위와 한계

실시간 게임용 수면 셰이더와 이동 물리다. 체적 유체 시뮬레이션, 물의 질량 보존·범람, 동적 파츠 부력, 캐릭터 전용 수영 애니메이션은 구현 범위에 포함하지 않았다. 물결은 연속적으로 움직이지만 지형이나 물체에 맞춰 유량이 다시 계산되지는 않는다. 반사 텍스처는 제작 시점의 정적 환경을 반영하므로 움직이는 크레인을 실시간 거울처럼 갱신하지 않는다.

실제 여러 PC 간 지연·재접속과 GPU 성능 수치는 별도 측정이 필요하다. 검수 이미지와 자동 테스트 결과는 `artifacts/stage2-water`에 저장한다.

환경 캡처는 프로젝트에서 검증된 URP `SubmitRenderRequest` 경로로 6면을 렌더링하고 GPU 픽셀을 읽어 저장한다. API 기준: [Unity RenderPipeline.StandardRequest](https://docs.unity3d.com/kr/2022.2/ScriptReference/Rendering.RenderPipeline.StandardRequest.html). 저장 후에도 RGB 데이터가 남는지 테스트한다.
