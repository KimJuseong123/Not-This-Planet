# S15P21B202-628 · 점프·낙하 애니메이션

공중 자세를 **세로 속도 하나로** 정한다. 그래서 난간에서 떨어질 때도 점프와
같은 자세가 그대로 쓰이고, 최고점 조각이 따로 필요 없다.

## 지금까지 공중에는 애니메이션이 없었다

`RabbitLocomotion.Apply` 가 `if (state.Blocked || !state.Grounded) return;` 로
꺼 버렸다. 공중에서는 `Balance` 힘도 26% 로 떨어져 팔다리가 허우적거린다 —
그건 의도된 물리 인형 톤이라 **덮지 않는다**(`AirPoseWeight = 0.65`).

점프 자체는 이미 있다. `PlayerRig` 가 모든 래그돌 몸체에 `v.y += 3.4` 를 한 번
얹고 중력이 나머지를 한다. **물리는 한 줄도 안 건드렸다.**

## 실측값

```
중력 -5 m/s² · JumpSpeed 3.4 m/s
=> 최고점 1.156m · 체공 1.36초 · 상승 0.68초
캐릭터 키 1.147m — 제 키만큼 뛴다
```

체공 1.36초는 보통 게임(0.6~0.8초)의 두 배다. **공중 자세가 오래 보인다** —
그래서 공중 자세가 이 티켓의 무게다.

## 클립의 시간축이 시간이 아니다

`Rabbit_Air` 는 **0프레임 = 최대 하강 · 가운데 = 중립 · 끝 = 최대 상승**이다.
런타임은 세로 속도를 시간으로 되매핑해 `SetTime` 만 한다.

| | |
|---|---|
| 얻는 것 | 상승/하강을 가르는 분기가 없다 · 최고점 조각이 없다 · **낙하가 점프와 같은 길** |
| 대가 | 클립이 순환이면 안 된다 — 순환하면 속도축이 되감겨 최고점에서 튄다 |

걷기/달리기가 `_phase` 로 하는 것과 같은 방식이라 새 블렌딩 코드가 없다.

### 중립을 가운데 둔 이유

처음에는 상승↔하강 둘만 섞었다. 그러면 **속도 0 이 "상승과 하강의 절반"** 이라,
난간에서 걸어 나가는 순간(속도 0) **뛰지도 않았는데 팔이 반쯤 올라간다.**
중립(선 자세에 가까운 느슨한 자세)을 0 에 두고 양쪽으로 갈라지게 했다.
검증이 이것을 잠근다(`SteppingOffALedgeDoesNotLookLikeALaunch`).

## 세로 속도를 어디서 얻나 — 리지드바디를 안 쓴다

`RemoteAvatar` 가 남의 몸을 `doll.Hips.MovePosition(target)` 으로 옮긴다.
그 리지드바디의 속도는 **물리 결과가 아니다** — 원격에서 엉뚱한 수가 나온다.

그래서 **골반이 실제로 움직인 거리**를 매 틱 재서 쓴다
(`PlayerRig.VerticalSpeed`). 내 몸이든 남의 몸이든 같은 방법으로 같은 답이
나오고, **새로 동기화할 것도 권위 문제도 없다.**

순간이동·탑승처럼 몸이 확 옮겨지는 자리에서는 그 한 틱의 값이 가짜이므로
`Teleport` 에서 기준을 버린다.

## 뛴 것과 떨어진 것을 구별한다

`PlayerRig.JumpedUp` — 제 발로 뛰었을 때만 선다. 쓰는 곳 둘:

* **뛰어오름 동작**은 점프에만 붙는다. 난간에서 걸어 나간 것에 웅크렸다 뻗는
  동작을 붙이면 안 된다
* **최고점 뒤꿈치 딱**도 점프에만. 떨어지는 것에는 최고점이 없다

## 시안에서 실제로 걸린 것 셋

눈으로는 "좀 끊기네" 로 끝났을 것을, **한 프레임에 뼈가 몇 도 움직이는지** 재서
잡았다. 픽셀 변화량으로 먼저 쟀다가 실패했다 — 몸이 움직이는 것에 묻혀
이음새가 안 보였다(최대/평균이 1.5배로 나와 "괜찮다" 로 읽혔다).

| 원인 | 고침 | 최대 튐 |
|---|---|---|
| 조각을 잘라 붙임 | 속도로 연속 블렌딩 | |
| **선형보간**으로 방향을 섞음 | 구면보간(slerp) | 67도 → 52도 |
| 팔 스윙을 몸과 같은 창에 묶음 | **팔에 별도 시간표** | 52도 → **22도** |

두 번째가 핵심이다. **거의 반대인 두 방향을 선형보간하면 중간에서 벡터가 0 에
가까워지고, 정규화하면서 각속도가 폭주한다.** 구면보간은 각속도가 일정하다.

세 번째도 같은 종류다. 팔 스윙은 130도가 넘는데 0.16초(4.8프레임)에 밀어넣고
있었다. 실제 점프의 팔은 **웅크리는 중에 이미 움직이기 시작해 이륙 뒤까지
이어진다** — 그 시간표를 그대로 줬다.

최종: 점프 프레임당 평균 4.11도 · 최대 22.15도(팔 스윙의 의도된 스냅) ·
난간 낙하 평균 2.49도 · 최대 13.54도(착지). **발을 떼는 지점에는 튐이 없다.**

## 굽기가 또 "안 움직이는 뼈" 를 잡았다

뒤꿈치 딱 클립의 허리·척추가 중립과 똑같아서 3/18 이 정지였다. 616 의 엎드린
대기와 같은 자리다. **뒤꿈치를 부딪치면 몸이 조금 펴지는 것이 맞으므로**
척추를 조금 폈다 — 가드가 옳았다.

## 승인받은 그 코드에서 데이터를 냈다

시안을 만든 코드와 커밋하는 코드가 다르면 다른 것이 들어간다(593 에서 겪었다).
그래서 시안 스크립트에 `emit` 모드를 달아 **같은 파일에서** 네 json 을 냈다.

## 주석과 검증이 낡아 있었다

```
Tuning.cs:43  JumpSpeed = 3.4f;  // 최고점 v²/2g = 2.06m, 체공 2.4초
```

실제는 **1.156m · 1.36초** 다. `FallImpactTests.JumpApexIsBelowTheStaggerThreshold`
가 같은 2.06 을 글자로 박아 두고 있어 **오래 실패하는 17개 중 하나가 이것이었다.**

**글자로 박는 방식은 맞다**(S15P21B202-584 가 "기대값을 계산하지 말고 글자로
박는다" 를 정했다). 낡은 것은 그 숫자였다. 점프 애니메이션이 이 값들 위에
서므로 여기서 같이 고쳤다.
