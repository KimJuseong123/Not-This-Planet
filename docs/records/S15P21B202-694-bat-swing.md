# S15P21B202-694 · 방망이를 휘두르면 몸도 휘두른다

> "이거 상대플레이어한테도 보여야 하는거 알지?"

**그 말이 이 이슈의 절반이다.** 1인칭이 기본이라 내 화면에는 팔밖에 안 나온다.
몸이 휘두르는 그림이 값을 하는 곳은 **오직 남의 화면**이다.

## 무엇이 없었나

`MeteorBat.SwingAim` 이 0.28초 동안 배트 방향을 돌리고 `DriveArm` 이 그 방향으로
팔을 뻗는다. 코드 주석에도 *"팔도 같은 방향을 따라간다 — 팔을 따로 움직이는 코드를
쓰지 않아도 된다"* 고 적혀 있다.

**골반·허리·어깨·발은 전혀 안 움직였다.** 원샷 9개(toss·dance·redred·bad·
lieDown·standUp·launch·land·heel) 어디에도 스윙이 없다. 밖에서 보면 몸은 가만히
선 채 팔만 배트를 따라 돌아간다.

## 실제 야구와 맞춰 보니 맞는 것이 셋이었다

| 무엇 | 실제 | 우리 |
|---|---|---|
| 컨택까지 시간 | 프로 타자 약 0.15초 | **0.126초 — 맞다** |
| 궤적 | 오른쪽 뒤 위 → 정면 → 왼쪽 앞 | **같다** |
| 가속 비대칭 | 가속했다가 감속 | **있다** |

S15P21B202-261 이 인게임에서 보고 고친 값들이 실제와 맞아떨어졌다. **그래서 배트
궤적은 안 건드렸다.** 이 이슈가 더한 것은 그 궤적을 몸이 받쳐 주는 것뿐이다.

## 클립 둘

`generate_rabbit_batswing.py` — 옆걸음 생성기와 같은 구조다.

* `Rabbit_BatSwing` 9프레임. 골반이 먼저 풀리고 척추가 그 위에 제 몫을 얹는다
  (분리). 컨택에서 앞다리가 펴진다 — 앞무릎 54° → 24° → 10°
* `Rabbit_BatReady` 대기 코일, 고리

**배트 각도는 `SwingAim` 과 같은 식을 파이썬에 옮겨 적었다.** 두 곳이 같은 공식을
쓰므로 어긋날 수 없다.

### 로드는 클릭 뒤가 아니라 대기 자세에 넣는다

판정이 `PerfectAt = 0.60` 이라 **운석이 0.6초 남았을 때 클릭**해야 하고 허용오차가
±0.08초다. 로드를 클릭 뒤에 재생하면 그 창을 통째로 먹는다.

덤이 하나 붙는다. 지금은 "칠 수 있는 상태" 가 왼쪽 타이밍 게이지에만 있는데,
캐릭터가 배트를 감아 들면 **자세 자체가 알린다** — 665 · 669 와 같은 자리다.

## 남의 화면에 보이게 한 길

**새 동기화를 두 개 만들지 않았다.** 이미 있는 두 길에 얹었다.

* **스윙**(한 번짜리) → `PlayerRig.SwingSeq` 를 올리고 `NetPlayer.swingSeq` SyncVar 로
  보낸다. 받은 쪽은 값이 **바뀌었을 때만** 재생한다 — 던지기(519)가 쓰던 규칙 그대로다
* **대기 코일**(지속 상태) → `RabbitLocomotion.State` 에 `BatCoiled` 한 칸.
  **그 구조체가 이미 SyncVar 다**

던지기의 두 함정을 그대로 물려받았다. 검사가 둘 다 잠근다.

* **처음 받은 값으로는 재생하지 않는다.** 늦게 들어온 사람에게는 쌓인 수가 한꺼번에
  오는데, 그것을 새 스윙으로 보면 접속하자마자 모두가 허공에 휘두른다
* `>` 가 아니라 `!=` 로 본다. `uint` 는 한 바퀴 돌면 작아지고, 그때 `>` 는 영영 거짓이다

## 손과 배트가 어긋나지 않게

`SpaceSuit.LateUpdate` 는 물리를 뼈에 복사한 **뒤에** 클립으로 덮어쓴다. 배트는
`HoldToolPose` 가 직접 들고 있으므로, **클립이 손뼈를 덮으면 보이는 손과 배트가
어긋난다.**

그래서 스윙은 `SkipArms` 로 **팔을 건너뛴다**. 대기 코일은 한 걸음 더 나가
**다리도 건너뛴다** — 다리를 쓰면 걸음과 싸운다. 감은 채로 걸어 다닐 수 있다.

**클립에는 팔 커브가 들어 있다.** 굽기가 "안 움직이는 뼈" 를 거부하기 때문이고,
나중에 팔까지 쓰기로 정하면 다시 구울 필요가 없다.

## 클립 길이가 아니라 게임이 정한 길이로 재생한다

구운 클립은 0.27초, 게임의 스윙은 `BatSwingSeconds` 0.28초다. 클립 길이를 그대로
쓰면 **굽는 프레임 수를 바꿀 때마다 타격 순간이 밀린다.** `OneShot.Duration` 을
주고 진행도로 찍는다. 검사가 "둘이 같아지면 실패" 로 이 연결을 잠근다.

## 굽기 가드가 또 잡았다 — 네 번째다

대기 클립에서 **다리 여섯 뼈(L_Thigh … R_Foot)가 안 움직인다** 고 거부했다. 숨만
넣고 다리는 고정값을 썼기 때문이다. 맞는 지적이다 — 가만히 선 타자도 무릎을
까딱이며 체중을 옮기고, 고정하면 마네킹이 된다. 616 · 628 · 670 에 이어 네 번째다.

## 검사 하나를 내가 틀리게 썼다

*"어깨가 골반보다 크게 돈다"* 로 적었는데 0.320 < 0.913 으로 걸렸다. **커브가 로컬
회전**이라 부모인 `Waist` 가 골반 회전을 통째로 갖고 척추는 그 위에 더하는 몫만
갖는다. 월드에서는 어깨 108° · 골반 60° 로 맞다 — **검사가 로컬 값을 월드인 줄
알고 있었다.** 재는 대상이 아니라 검사를 고쳤다.

```
실측  Waist 0.913 · Spine01 0.268 · Spine02 0.320 · Head 0.764
```

## 검증

| 무엇을 지키나 |
|---|
| 두 클립이 구워져 있다 |
| 대기는 고리, 스윙은 한 번 |
| **클립 길이와 게임의 스윙 길이가 다르다** — 같아지면 누르는 코드가 죽는다 |
| 척추가 골반 위에 제 몫을 얹는다 (분리) |
| 머리가 제 커브를 갖는다 (컨택까지 정면) |
| 스윙이 다리를 움직인다 (앞다리 블록) |
| 대기 코일이 다리를 움직인다 (마네킹이 아니다) |
| **휘두를 때마다 네트워크로 갈 수가 오른다** |
| **처음 받은 값으로는 재생하지 않는다** |
| **수가 한 바퀴 돌아도 멈추지 않는다** |
| 빈손이면 코일이 꺼진다 |

`BatSwingPoseTests` 12건 신규. 손·도구·보행·네트워크에 닿는 스위트 89개(1,198건)
중 22건 실패는 **clean develop 에서 같은 필터로 돌려도 같은 22건**이다 — 새로
깨진 것은 없다.

## 남은 것

* **2프로세스 눈 확인** — 이 이슈의 본체다. 남의 화면에서 스윙이 보이는지,
  대기 코일이 걷는 동안에도 유지되는지. EditMode 가 대신 못 하는 자리다
* **헛스윙을 따로 만들지** — 야구 게임은 다 별도 클립이다. 지금은 맞았든 헛쳤든
  같은 동작이고 소리·쿨다운만 다르다
* **팔까지 클립으로 쓸지** — 그러면 배트를 모델 손뼈에 붙여야 한다. 지금은 팔을
  물리에 맡겨 어긋날 자리를 안 만들었다
* **`SwingAim` 상수를 고치면 클립을 다시 구워야 한다** — 두 곳이 같은 공식을 손으로
  나눠 갖고 있다. 검사로 잠그는 것은 별도다
