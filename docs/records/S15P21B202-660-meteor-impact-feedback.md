# S15P21B202-660 · 운석 방망이 타격 피드백

## 후속 요청 · 여러 운석의 타이밍 게이지 동시 표시

- 단일 `rhythmTarget` 대신 보조 반경 안에 있는 모든 낙하 운석을 수집하여, 착탄까지 남은 시간이 짧은 순서대로 게이지를 표시한다. 동일 시각이면 기존 타격 대상 선택 순서를 유지한다.
- 각 게이지는 해당 운석의 현재 높이·속도·지면으로 계산한 남은 시간과 개별 타격 창을 사용한다. 먼저 쳐낸 운석만 목록에서 빠지며, 나머지 게이지는 재시작하지 않는다.
- 게이지는 타격 창에 진입하기 전부터 보여 다음 운석을 미리 준비할 수 있다. 좌클릭으로 실제 타격 가능한 첫 운석에 `지금 클릭!`과 강조선을 표시한다.
- 운석 생성 전 예고는 기존 준비 안내를 유지한다. 반사된 운석·착지한 운석·범위 밖 운석은 제외하며, 방망이를 내려놓거나 메뉴/태블릿/기절/탑승/엔딩 상태에서는 기존 표시 제한을 따른다.
- 호스트 운석과 비활성 원격 그림에 같은 수집 규칙을 사용하고 중복 객체를 제외한다. 매 프레임 새 목록을 생성하지 않고 기존 목록을 재사용한다.
- 기본은 세로 목록이며 화면 높이를 넘으면 추가 열에 나누어 표시한다. 작은 화면의 행에는 작은 글꼴을 사용한다. 새 문구의 글리프를 기존 사전 준비 목록에도 추가했다.
- 타격 입력·대상 우선순위·판정 범위·점수·반사 속도·네트워크 메시지는 이번 후속 변경에서 바꾸지 않았다.
- 후속 최종 검증: Unity 6000.5.4f1 컴파일 및 자동 테스트 185개 통과, 실패 0개. 이전 타격 피드백 검증 176개와 신규 다중 게이지 검증 9개(독립 진행/제거 후 유지, 원격/중복/범위 이탈, 동시 착탄 순서, 6개 해상도·개수 배치 조합)를 실행했다. 결과는 메인 워크스페이스 `.local-validation/660-impact/multiple-gauges-final.xml`과 동일 이름 `.log`에 있다. 최종 변경 스크립트 11개와 검증 프로젝트의 파일이 일치한다.
- 화면 직접 조작은 수행하지 않았다. 실제 HUD 시각 확인 및 두 프로세스 멀티플레이는 이번 검증 범위에 포함되지 않는다.

## 범위와 기준

- `origin/S15P21B202-660-puzzle`의 `7b69e199`에서 동일 이름 로컬 브랜치와 `.local-worktrees/660-puzzle` 워크트리 생성.
- 화면 직접 조작 없이 파일 변경과 Unity 6000.5.4f1 배치 테스트만 수행.
- 씬·프리팹·패키지·프로젝트 설정 변경 및 Inspector 연결 작업 없음.

## 동작

| 판정 | 타격 파티클 | 카메라 회전 진폭 | 반사 속도 |
|---|---|---|---|
| GOOD | 청록색 14개 | 0.65도 | 기존 1배 |
| GREAT | 파란색 22개 | 1.3도 | 기존 1.35배 |
| PERFECT | 금색 32개 | 2.2도 | 기존 1.8배 |
| MISS | 타격 파티클 없음 | 흔들림 없음 | 반사 없음 |

- 카메라는 기존 로컬 HUD의 확정 판정 경로에서 0.24초 동안 감쇠하며 흔들린다. 동료가 쳤다는 이유로 다른 플레이어 카메라를 흔들지 않는다.
- PERFECT 운석의 꼬리는 노란색으로 바뀌고 폭 1.35배, 유지 시간 1.3배가 된다. HUD 결과 색상을 판정별로 구분하고 PERFECT에 `반사 속도 ×1.8`을 표시한다.
- 속도 보상은 기존 기능이다. 추가 피해·범위 공격·타이밍 창 확대 등 새로운 밸런스 변경은 넣지 않았다.
- 파티클은 기존 Puff 풀과 전체 220개 상한을 사용한다. 최대 수명은 0.43초이며, 풀 포화 시 추가 방출을 생략한다. 새 효과는 게임의 전역 난수를 소비하지 않는다.

## 기존 기능과 네트워크 검토

- 운석 → 동료 → 소품 우선순위, 헛스윙 재사용 대기, 동료 넉백 및 부품 보호 경로 유지.
- 반사 후 무해한 소품으로 바뀌는 기존 규칙 유지. 꼬리와 파티클은 충돌·피해 판정에 관여하지 않는다.
- PERFECT 전용 공유 재질을 별도로 사용하여 다른 낙하 운석의 색상을 바꾸지 않는다.
- 원격 운석 스냅샷에 판정 등급을 포함한다. 원격 그림이 일반 운석을 다시 나타내면 색상·폭·유지 시간을 원복한다.
- 도구 스냅샷에 타격 위치를 포함한다. 기존 결과 번호가 바뀐 경우만 파티클을 재생하고, 최초 스냅샷은 지난 타격을 재생하지 않는다. 서버의 실제 타격과 클라이언트 표현을 분리한다.
- 운석 스냅샷의 실제 직렬화 크기 54바이트를 패킷 용량 계산에 사용한다. 다른 객체의 도킹 플래그가 포함된 공용 자세 크기 상수에 의존하지 않으며, 실제 직렬화 길이를 테스트로 비교한다.
- 도구 스냅샷은 도구당 30→42바이트로 늘어난다. 기존 도구 전체 전송 경로에는 분할 전송이 없으므로 다량의 도구를 배치하는 확장 환경에서는 패킷 한도를 별도로 검증해야 한다. 기본 1194바이트 전송 한도와 프로젝트의 64바이트 여유분 기준으로 26개까지가 보수적인 예산이다.
- 기존 비신뢰 스냅샷 전달 구조를 유지하므로 지연/손실 또는 연속 타격 사이 스냅샷 생략 시 모든 중간 파티클 재생을 보장하지 않는다. 물리 판정과 지속 꼬리 상태는 서버 결과를 따른다.
- 네트워크 메시지 구조가 변경되므로 호스트·서버·참가자는 같은 버전을 사용해야 한다.

## 검증

- 격리 경로: `.local-validation/660-impact/project` (메인 워크스페이스 기준). 브랜치의 전체 스크립트·ThirdParty·셰이더와 프로젝트 설정 복사본, 로컬에 설치된 동일 버전 패키지를 사용했다.
- 변경 전: 172개 통과, 실패 0개 (`baseline.xml`, `baseline-retry.log`).
- 최종 변경 후: 176개 통과, 실패 0개 (`accepted.xml`, `accepted.log`). 전체 스크립트 컴파일 및 Mirror 후처리 완료. 변경 파일 10개가 검증 프로젝트와 바이트 단위로 일치함을 확인했다.
- 기존 타격·동료/소품·무해 전환·카메라·네트워크 수신 회귀 172개와 추가 4개를 실행했다. 추가 검증은 꼬리 재질 분리/원격 원복, 지연 생성 꼬리, Play Mode 파티클 중복 억제/수명/풀 재사용/난수 보존, Mirror 직렬화와 패킷 크기 일치다.
- 최초 제한 환경의 라이선스 연결 실패 후 배치 실행 권한을 확보하여 재시도했다. 신규 테스트 타입명 오타를 수정했다.
- 신규 테스트에서는 TrailRenderer 색상의 8비트 저장 오차를 허용하고, EditMode 러너에서 Play Mode로 전환한 후 실제 게임 시간 경과로 수명을 확인한다. 초기에 검출한 테스트 오타·정밀도·대기 방식 오류를 수정했으며,
- 기존 obsolete API 및 Mirror BouncyCastle assembly resolver 경고가 기준 로그에도 존재한다.
- 실제 게임 화면의 시각 품질, 두 프로세스 멀티플레이 지연 상황, 타깃 플레이어 빌드는 검증하지 않았다. 자동 테스트 통과를 실제 타격감 검증이나 모든 오류 부재로 해석하지 않는다.
