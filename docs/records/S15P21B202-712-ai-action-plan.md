# S15P21B202-712 · AI 동료 행동 명령 — 실행 계획과 첫 안정화

AI 동료가 받는 명령 34개(`companion_plan.ACTIONS`)가 **게임 안에서 어떻게 실행되고, 언제 끝났다고 보고, 실패하면 무엇을 하는지**를 한 곳에 적는다. 받아쓰기·판단(LLM/STT)은 이 문서의 범위가 아니다 — 명령이 정해진 **뒤**의 일이다.

실행은 전부 서버에서, **보통 플레이어와 같은 입력(`InputFrame`)으로만** 한다. 물리 결과를 코드로 정해 버리지 않는다(`AiWorkTask` 머리 주석).

## 끝을 적는 방식 (`-703`)

모든 작업은 `AiWorkTask.Outcome`(`진행 중 · 완료 · 실패 · 취소`)과 `Reason` 으로 끝난다. 끝날 때 `Player.log` 에 한 줄이 남는다:

```
[AI] 작업 결과 carry_part → 실패 · 파츠를 놓침 (12.3초)
```

컨트롤러가 멈추면(AI 쓰러짐 · 말한 사람이 쓰러짐 · 새 명령 · 취소 명령) 그 이유가 **취소 이유**로 남는다. 시작하지 못한 이유도 화면까지 올라간다.

## 명령별 표

"대상" 은 명령을 받은 순간 한 번 고른다(`NearestPart` 등). "끝" 은 `Finish(true)` 가 되는 조건, 지속 작업은 취소될 때까지 돈다.

### 이동 · 대기 (`AiFollowController` · `AiWorkTask.goto`)

| 명령 | 대상 | 단계 | 끝 | 실패·복구 |
|---|---|---|---|---|
| `follow` | 말한 사람 | 대형 자리로 따라감 | 지속 | 막히면 `AiMovementRecovery` 가 옆으로 틀기 |
| `wait` | — | 그 자리 | 지속 | — |
| `gather` | 말한 사람 곁 · 또는 목적지(`goto` 로 넘김) | 곁에 도착 | 도착 | 따라갈 상대 없음 → 거절 |
| `goto` | 목적지(`default · speaker · aim · assembly · high`) | 길찾기 → 도착 뒤 지키기 | 지속 | 경로 없음 8초 · 진전 없음 8초 → 실패 |
| `cancel` | — | 모든 작업 멈춤 | 즉시 | — |

| 명령 | 대상 | 단계 | 끝 | 실패·복구 |

## 이번 첫 구현 (파츠 잡기 · 운반 · 놓기)

2026-09-25 코드 조사에서 찾은 약점 중 **잡기·운반을 그 자리에서 끝내 버리는 것**부터 고쳤다.

| 전 | 지금 |
|---|---|
| 가장 가까운 파츠가 용접·고정·다른 AI 견인 중이면 **명령 전체가 실패** | 그 파츠를 건너뛰고 다음으로 가까운 파츠를 고른다(걷기 운반 · 견인 모두) |
| 서는 자리를 명령 받을 때 한 번 정하고, 파츠가 밀려나도 **빈자리로 걸어가 5초 뒤 실패** | 파츠가 0.5m 넘게 움직이면 서는 자리를 다시 고른다 |
| 서는 자리 0.12m 안까지 붙어야 해서 몸통이 못 닿으면 **8초 뒤 "이동 막힘"** | 0.3m, 그리고 이미 손이 닿으면 바로 잡기로 넘어간다 |
| 놓치거나 5초 안에 못 잡으면 **바로 실패** | 서는 자리를 다시 골라 2번까지 다시 |
| 파츠 중심이 목적지 1.5m 안이면 **미끄러지는 중에도 완료** | 손을 놓고 파츠가 멈추기(0.4m/s 아래 0.8초)를 확인한 뒤 완료 |
| 몸이 먼저 목적지에 닿으면 **"몸은 도착했지만 파츠 이동 미완료" 로 실패** | 목적지 너머로 조금 더 끈다 — 2번 |
| 조립대로 옮기다 파츠가 조립대에 **붙으면 실패** | 목적이 조립대였으면 완료 |
| 운반 중 파츠가 용접돼도 모름 | 매 틱 용접 상태도 본다 |
| 견인 탑승 E 를 **한 번만** 누름 | 타지 않은 동안 1.5초마다 다시 |
| 내리기 정렬에 **제한 시간이 없어** 180초 전체 제한까지 떠 있음 | 15초 안에 못 맞추면 다시 접근(재시도 한도 공유) |

## 남은 것 (다음 단계)

- **견인 실패 뒤 파츠가 장 안에 떠 있다.** 인양·순항 중 실패하면 장을 끄지 않는다("사람을 높이서 떨어뜨리지 않는다" 규칙이 파츠에도 적용된다). 대상이 파츠일 때는 낮게 내려 장을 끄고 끝내야 한다
- 저중력장 켜기가 매 틱 같은 입력을 준다 — 켜짐이 한 틱 늦으면 도로 꺼질 수 있다(실측 전)
- 견인 차량 쪽 매 틱 용접 상태 확인
- 운반 · 견인 작업의 플레이 모드 시험(지금은 배선 시험만 있다)
- 여러 AI 가 한 파츠를 함께 끌 때의 역할 나누기

## 검증 한계

이번 변경은 EditMode 컴파일·회귀 시험과 **배선 시험**으로만 확인했다. 파츠를 실제로 끌어 보는 확인은 QA 에서 한다 — 개발 패널(`AiTextTestControls` — 에디터·개발 빌드의 방장 화면)의 **직접 실행** 버튼으로 LLM 없이 같은 명령을 반복하고, 각 AI 줄 끝의 "마지막 완료/실패(이유)" 와 `Player.log` 의 `[AI] 작업 결과` 줄을 본다.
