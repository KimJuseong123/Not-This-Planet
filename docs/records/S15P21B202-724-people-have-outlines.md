# S15P21B202-724 · 사람에게 투시 테두리

> "사람 테두리 없어서 죽은거 모르겠음. 오브젝트는 노란색, 완성된 우주선은 파란색
> 테두리가 있음. 똑같은 형식으로 사람에게 초록색 테두리를 만들어야 함."

## 사람에게 테두리가 없던 것은 우연이 아니다

```csharp
// OccludedInteractionTargets.IsEligible — 예전
if (root == null || !root.gameObject.activeInHierarchy ||
    root.GetComponentInParent<PlayerRig>() != null) return false;
```

S15P21B202-591 이 **손에 든 도구가 테두리를 그리지 않게** 하려고 넣은 줄이다.
그런데 `PlayerRig` 자신도 그 규칙에 걸린다 — 리그는 제 자신을 부모로 갖는다.

세계 안에 쓰러짐을 알리는 표시가 하나도 없었다.

| 무엇 | 색 | 어디 |
|---|---|---|
| 상호작용 물체 | 노랑 | 가려져도 보이는 테두리 (-591) |
| 파츠 덩어리 | 하늘 | 용접으로 묶인 윤곽 (-562) |
| 팀원 쓰러짐 | 빨강 | **HUD 팀 목록에만** |
| 머리 위 이름표 | 팀 색 | 쓰러져도 **그대로** |

누가 쓰러졌는지는 알 수 있었고, **어디인지를** 몰랐다.

## -591 형식을 본떴다. -562 가 아니다

재서 확인한 이유 셋이다.

1. **이미 "가려져도 보인다"** — 마스크는 `ZTest LEqual`, 테두리는 `ZTest Always` 고,
   `here.x > sceneDepth` 일 때만 그린다. 쓰러진 사람은 바위·파츠 뒤에 있기 쉽다
2. **동기화가 필요 없다** — `AddRenderPasses` 가 `camera != LocalPlayer.Cam.Cam` 이면
   돌아간다. 각 기계가 제 화면에 그리는 순수 렌더 효과다. 필요한 사실(`downed`)은
   이미 SyncVar 다. "호스트와 참가자 모두에게, 서로" 가 저절로 만족된다
3. **한 사람이 하나의 윤곽이 된다** — `Group` 이 루트 번호라 한 루트 아래 렌더러는
   같은 번호를 받고, 같은 번호 사이에는 선이 안 생긴다

-562 는 용접 덩어리를 번호로 묶는 별개 시스템이라 사람에게 쓸 이유가 없다.

## 색을 덩어리마다 다르게 — 셰이더도 마스크 포맷도 안 건드렸다

마스크는 `float2(eyeDepth, group)` 를 쓰고 포맷이 `R32G32_SFloat` 다. **빈 채널이
없다.** 그래서 처음에는 포맷을 늘리거나 패스를 색마다 도는 것을 생각했다.

**그럴 필요가 없었다.** 렌더러 피처가 이미 **덩어리 하나에 마스크와 블릿을 한
벌씩** 돌고, 블릿에 `MaterialPropertyBlock` 이 있다. 색을 거기 실으면 끝이다.

```csharp
data.Color = targets[start].Outline;
...
pass.Properties.SetColor(ColorId, pass.Color);
```

## 재서 알아낸 것 — 세 가지가 공짜였다

**물리 인형은 저절로 빠진다.** 사람 하나에 렌더러가 **66개**(삼각형 34,560)인데
전부 물리 프리미티브다. `Doll.HidePrimitiveRenderers` 가 모델이 씌워질 때 그것들의
`enabled` 를 끄고, 수집기가 이미 `!renderer.enabled` 를 거른다.

**1인칭에서 내 몸도 저절로 빠진다.** `Doll.SetVisible(false)` 가 렌더러를 끈다.
그래도 **명시적으로 뺐다** — 기절·밀기·탑승은 3인칭이라 내 등에 테두리가 붙어
화면을 먹는다. 규칙을 우연에 기대지 않는다(-699 에서 같은 것을 배웠다).

**씬 이름 검사에 안 걸리게 했다.** `RefreshMeshes` 가
`root.gameObject.scene.name != "Stage1_Astra"` 로 거르는데, **플레이어는 런타임에
만들어져 어느 씬에 들어갈지 이 파일이 알 수 없다**(검증에서 재니 빈 문자열이었다).
사람은 `PlayerRig.All` 에서 받으므로 씬을 물을 이유가 없다 — 그 검사를 씬에 놓인
것에만 건다.

## 색

| 무엇 | 색 |
|---|---|
| 물체 | `(1, .78, .2)` 노랑 — -591 그대로 |
| 사람 | `(.36, 1, .55)` 초록 |
| 쓰러진 사람 | `(1, .24, .28)` 빨강 |

**빨강은 `GameHud.TeamDownedColor` 와 같은 값이다.** 팀 목록이 이미 그 색으로
쓰러진 사람을 그린다 — 세계에서 다른 빨강을 쓰면 둘이 다른 뜻으로 읽힌다.
검사가 두 값이 같은지 잠근다.

### 내가 쓴 검사 하나가 전역 상태에 기대고 있었다

"세션이 없으면 다 그린다" 를 `GameSession.Instance` 가 `null` 인지 확인하는 것으로
적었다. **혼자 돌 때는 통과하고 다 같이 돌 때는 깨졌다** — 앞 검사가 세션을 남긴다.

규칙을 순수 함수로 뺐다(`IsCrewTarget(rig, localViewer)`). 보는 쪽을 인수로 받으니
전역 상태 없이 잰다. -699 에서 HUD 결정을 뺀 것과 같은 처리다. **그리는 그림이 아니라 정하는 규칙을 잰다** — 실제로
그리는 검사(`OccludedInteractionRenderTests`)는 Play 모드와 화면이 필요해
`-nographics` 에서 `RenderTexture.Create failed` 로 죽는다. 이 브랜치가 아니라
develop 에서도 그렇다.

## 남은 것

* **2프로세스 눈 확인** — 이 이슈의 본체다. 호스트·참가자 양쪽에서 서로의 테두리가
  보이는지, 쓰러지면 빨강으로 바뀌는지. EditMode 가 대신 못 한다
* **비용을 안 쟀다.** 사람 하나가 66개 렌더러이고(물리 프리미티브라 대부분 꺼져
  있지만) 모델이 씌워지면 스킨드 메시가 마스크 패스에 들어간다. 4인에서 프레임이
  어떻게 되는지는 인게임에서 봐야 한다
* **색이 겹쳐 보일 때** — 사람이 파츠 앞에 서 있으면 초록과 노랑이 붙는다. 실제로
  거슬리는지는 눈으로 봐야 한다
