# 우주선 실제 탑승과 발사 실패 시 플레이어 사출 (S15P21B202-201)

## 결론부터

`S15P21B202-200` 의 탑승은 **인원을 세는 것뿐이었다.** 플레이어를 우주선에 붙이지
않았으므로 발사하면 발사대에 서서 우주선이 올라가는 것을 구경했다. 200 의
"하지 않은 것" 에 진입 *연출*은 적었지만 실제 부착은 적지 않았다 — 빠진 것을
빠졌다고 적지 않은 것이 문제였다.

그리고 `LaunchTest` 의 `Succeed`/`Fail` 은 상태만 바꾸고 아무것도 하지 않았다.
실패해도 플레이어에게 아무 일이 없었고 재시도 절차도 없었다.

## 탑승 경로를 일반화했다

탑승 상태가 `PlayerRig.MountedVehicle` 하나였고 타입이 `TransportVehicle` 로
못박혀 있었다. 그래서 우주선에는 탈 수 없었다.

`RidingBody`(Rigidbody)를 새 축으로 두고, 운반 장치 고유의 처리 — 조종 입력,
조종석 시야, 하차 발판 탐색 — 는 `MountedVehicle` 에 그대로 남겼다.
`RidingBody` 가 뜻하는 것은 **"몸이 붙어 있으니 보행 물리를 돌리지 않는다"**
하나뿐이다.

| 상태 | 운반 장치 | 우주선 |
| --- | --- | --- |
| `RidingBody` | ✅ | ✅ |
| `MountedVehicle` | ✅ | ❌ |
| 조종석 시야 (`SetVehicleView`) | ✅ | ❌ |
| 몸 감춤 | ✅ | ✅ |

조인트를 만드는 코드도 `AttachTo(Rigidbody)` 한 곳으로 모았다.
`connectedBody` 를 반드시 채운다 — 비우면 `connectedAnchor` 가 월드 좌표로
해석되어 몸이 원점으로 빨려간다(S15P21B202-132 의 21.34m).

회귀 방어선은 기존 `TransportDismountTests`·`TransportCockpitTests` 다.
리팩터링이므로 그것들이 그대로 통과해야 의미가 있다.

## 실패해도 즉시 내리지 않는다

기획 §22.4 는 **"해당 모듈이 지면에 닿는 순간"** 튀어나온다고 정한다.
접합부가 터진 즉시가 아니다. 모듈이 떨어지는 동안은 타고 있어야 하고,
그 낙하가 실패의 연출이다. `Failure_KeepsThePlayerAboardUntilTheModuleLands`
가 접합부가 터진 순간에 아직 타고 있는지까지 본다.

### `HasLanded` 를 처음에 틀렸다

지면 높이만 봤다. 세 검증이 8초 안에 `Failing` 에 못 갔다.

**최상단 모듈이 잔해 위에 얹혀 멈추면 지면 높이에 영원히 닿지 않는다.**
견인 조종 모듈 반높이 1.22m 아래에 엔진 모듈 2.16m 가 깔리면 밑면이 2.16m 에서
멈춘다. 임계값 1.2m 에 절대 못 미친다. 그러면 사출이 오지 않고 플레이어가
잔해 위에 매달린 채로 남는다.

통과한 하나(`Failure_KeepsThePlayerAboard…`)는 모듈이 옆으로 굴러 떨어져서
운이 좋았을 뿐이다. **테스트 하나가 통과한 것이 규칙이 맞다는 증거가 아니다.**

기획의 "지면에 닿는 순간" 이 뜻하는 것은 낙하가 끝나는 순간이다. 그래서 지면
높이와 정지(`EjectRestSpeed` 0.6m/s 가 `EjectRestSeconds` 0.25초 이어짐) 중
먼저 오는 것을 쓴다. 한 순간만 보면 튀어오른 정점에서 걸리므로 지속 시간이
필요하다.

## 사출에서 하지 않은 것 두 가지

**위치를 옮기지 않는다.** 몸은 이미 모듈 안에 있다. 밖으로 순간이동시키면
지면이나 잔해 속에 박히지 않을 자리를 다시 찾아야 하는데, 그 탐색이
S15P21B202-132 의 흰 화면을 만든 곳이다. 충격으로 밀어내는 편이 안전하다.

**체력을 깎지 않는다.** 기획 §22.4 가 "기절하지 않고 자동으로 일어난다" 로
못박았다. 깎으면 운석 두 방 맞은 상태에서 발사 실패가 사망이 된다.
기절 처리도 새로 만들지 않았다 — `PlayerRig.Balance` 가 이미 넘어진 자세를
스스로 세운다.

## 운석 공세

기획 §22.3 발사 중 정지, §22.4 "일반 운석 공세가 다시 시작된다".

`MeteorSpawner.SetPaused` 를 새로 만들었다. **이미 떨어지는 중인 운석은 그대로
둔다** — 공중에서 멈춰 세우면 발사 순간에 하늘에 운석이 박혀 있게 된다.
예고만 끊는다.

재개할 때 `ResetRun` 을 쓰지 않는다. 시드를 다시 심으면 실패 이전과 같은 순서가
반복되고, 무엇보다 기획 §22.4 가 **"발사 실패는 스테이지 초기화가 아니다"** 라고
못박았다. `Failure_IsNotAStageReset` 이 진행값이 되돌아가지 않는지 본다.

## `Failing` 상태를 둔 이유

실패 후 `Closed` 로 바로 돌아가지 않는다. 실패가 초기화가 아니므로, 무너진 탑을
다시 판정해 조건이 갖춰지면 그때 문이 다시 열린다. `ShipAssembly` 는 이미 매 스텝
다시 판정하니 절단·재배치·재용접 뒤 저절로 열린다.

## 이 이슈가 하지 않는 것

- 탑승 궤도 카메라 (§22.2)
- 성공 시 8~10초 상승과 임시 1장 완료 처리 (§22.5) — 다음 이슈
- 문 열림 애니메이션·진입 연출 (§22.1 후반, [Art])
- 사출 이펙트·사운드 ([Art] / [Sound])
- 접속 인원 동기화 ([Network])
