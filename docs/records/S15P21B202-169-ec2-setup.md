## 목적

2026-08-31 지급받은 EC2 를 실제로 쓸 수 있는 상태로 만든다. 받은 서버는 비어 있어
백엔드를 올릴 수 없고, 자동 배포(-141)와 HTTPS(-164)는 이 단계가 끝나야 얹을 수 있다.

## 서버 사양 (2026-08-31 확인)

| 항목 | 값 |
| --- | --- |
| 도메인 | `j15b202.p.ssafy.io` |
| OS | Ubuntu 24.04.4 LTS |
| **아키텍처** | **x86_64** |
| 메모리 | 15 GiB (사용 537 MiB) |
| 디스크 | 309 GB (사용 1%) |
| 스왑 | 없음 |
| 설치된 것 | 없음 (docker · java · nginx 모두 미설치) |
| UFW | 활성 · **22 번만 허용** |

`uname -m` 이 `x86_64` 인 것이 중요하다. ARM 이었다면 Unity 전용 서버 빌드가 사실상
지원되지 않아 Mirror 헤드리스 게임 서버를 이 서버에서 돌릴 수 없었다.

지급 공지에는 `22 · 8989 · 443` 이 접속 가능하다고 적혀 있었으나, 실제 UFW 에는 22 번만
등록되어 있었다. 공지를 믿지 말고 `sudo ufw status verbose` 로 직접 확인할 것.

## 포트 설계

밖에서 보이는 것을 최소로 한다.

| 용도 | 포트 | 외부 공개 |
| --- | --- | --- |
| SSH | 22 | 공개 (지급 시 이미 열림) |
| HTTPS (nginx) | 443 | 공개 |
| Spring 백엔드 | 8080 | **비공개** — 127.0.0.1 바인딩, nginx 가 전달 |
| MySQL | 3306 | **비공개** — 컨테이너 네트워크 안에서만 |
| Mirror 게임 서버 | UDP (번호 미정) | 공개 예정 — Network 파트와 합의 필요 |

`8080` 을 밖에 열지 않으므로 "기본 포트를 바꿔 쓰라"는 지급 지침도 함께 충족한다.
게임 서버 포트는 기본값 `7777` 대신 다른 번호를 쓰기로 하되 클라이언트와 맞춰야 한다.

## 한 일

1. 서버 접속 및 사양·방화벽·설치 상태 조사
2. 도커 · docker compose 설치 (공식 저장소), `ubuntu` 계정을 `docker` 그룹에 추가
3. `~/metagame/.env` 에 비밀번호·시크릿을 서버에서 생성 (화면에 찍지 않고 파일로 바로, 권한 600)
4. MySQL 컨테이너 기동 — 볼륨으로 데이터 유지, 포트는 열지 않음
5. 백엔드 jar 를 로컬에서 빌드해 `scp` 로 올리고 이미지 빌드·기동 — `127.0.0.1:8080` 에만 바인딩
6. UFW 에 80 · 443 추가
7. nginx 설치, 443 → 백엔드 전달 설정 (WebSocket `Upgrade` 헤더 포함)
8. certbot 으로 Let's Encrypt 인증서 발급, http → https 전환, 자동 갱신 타이머 확인
9. 재부팅 후 컨테이너·nginx·인증서가 모두 자동 기동되는지 확인

로그인(HTTP)만 확인하면 안 된다. nginx 가 `Upgrade` 헤더를 넘기지 않으면

## 결정 · 배운 점

### 도커는 UFW 를 우회한다 — 가장 중요

`docker run -p 8080:8080` 으로 띄우면 **UFW 로 8080 을 막아 두어도 인터넷에서 접속된다.**
도커가 UFW 보다 아래 단계에서 방화벽 규칙을 넣기 때문이다. "UFW 에 안 열었으니 안전하다"가
성립하지 않는다.

막으려면 포트를 루프백에 묶는다.

```
-p 127.0.0.1:8080:8080     # 서버 안에서만 열린다
-p 8080:8080               # 인터넷에 열린다 (UFW 와 무관)
```

공용 클라우드 서버가 털리는 흔한 경로라 별도로 적어 둔다.

### 그 밖

- 로컬 개발용 비밀번호(`docker-compose.yml` 의 `metagame1234`, `.env.example` 의 JWT 시크릿)는
  저장소에 공개되어 있다. 서버에서는 반드시 새로 생성해 `.env` 에만 둔다.
- 인증키(`.pem`)는 저장소에 넣지 않는다. 화면·기록에도 내용을 남기지 않는다.
- UFW 는 켠 채로 유지하고 포트만 추가한다. 22 번을 막으면 본인도 들어갈 수 없고 복구가 불가능하다.

### 도메인이 생겨 HTTPS 가 가능해졌다

인증서는 IP 가 아니라 도메인에만 발급된다. 도메인을 받은 덕분에 같은 날 HTTPS 까지 붙였고,
그 결과 클라이언트도 `https`·`wss` 로 전환할 수 있게 됐다.

### YAML 은 들여쓰기로 소속이 정해진다

`docker-compose.yml` 에 `cat >>` 로 서비스를 덧붙였더니 파일 끝의 `volumes:` 아래로 들어가
도커가 `backend` 를 볼륨 이름으로 읽었다. 블록을 추가할 때는 덧붙이기보다 **파일 전체를 다시 쓰는 편**이
안전하다.

### 로컬 개발용 값을 서버에 쓰지 않는다

저장소의 `docker-compose.yml`·`.env.example` 에 있는 비밀번호와 JWT 시크릿은 팀 전원이 볼 수 있다.
서버에서는 `openssl rand` 로 새로 만들어 `.env` 에만 두었고, 값이 화면·기록에 남지 않도록
파일로 바로 넣었다.

## 남은 것 / 후속 이슈

- 배포가 아직 수동이다 — jar 를 로컬에서 빌드해 `scp` 로 올린다. 자동화는 S15P21B202-141
- 애플리케이션 설정(`allowedOrigins` 제한 · `ddl-auto` 를 validate 로)은 S15P21B202-56
- 게임 서버용 UDP 포트는 아직 열지 않았다. 번호를 Network 파트와 확정한 뒤 연다 (S15P21B202-162)
- 서버의 `docker-compose.yml` 이 저장소에 없다. 배포 자동화 때 저장소로 옮길지 정해야 한다
- 스왑이 없다. 게임 서버까지 올린 뒤 메모리가 빠듯하면 검토한다
