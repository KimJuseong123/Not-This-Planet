# S15P21B202-442 — 살아있는 플레이어도 잡아서 밀고 당기기

> 2026-09-11 · 김주성(물리·퍼즐·캐릭터·상호작용·QA) · 브랜치 `S15P21B202-442-character`
>
> 기획 §20.2 플레이어 충돌 · §20.4 기절한 동료 운반 · §13 파츠 수동 밀기

---

## 1. 무엇이 문제였나

> "살아있는 플레이어끼리 잡기가 안 된다. 잡아서 당기거나 밀 수 있어야 한다."

**협력 요소가 아니다.** 근거는 둘이다.

1. **일관성** — 세계의 다른 물건은 전부 잡아서 밀고 당길 수 있는데 사람만 안 된다.
   게다가 **기절한 사람은 된다**(§20.4). 같은 몸이 의식이 있을 때만 안 잡히는 것은
   규칙으로 설명되지 않는다.
2. **장난 요소** — 서로 붙들고 끌고 당기는 것 자체가 놀이다.

**결함이 아니라 만든 적이 없는 것이다.** 그리고 막는 것이 하나가 아니었다.

---

## 2. 실측 — 관문을 따로 쟀다

읽어서 단정하지 않았다. 경로마다 따로 재는 프로브를 임시로 만들었다(조사용이라
커밋하지 않았다).

```
관문1  살아있는 플레이어의 잡을 지점: CarryTarget=없음 활성=False
관문1b 기절 직후 잡을 지점        : 활성=True
관문2  WorldMask                 : Player=False PlayerDowned=False RemotePlayer=True
관문2b 동료 골반 위에서 잡기 탐색  : Grabbable=없음 · 마스크에 걸린 콜라이더 0개
관문3  바로 앞 동료의 상호작용 후보: 살아있을 때=None / 기절했을 때=Grabbable
관문4  RemotePlayer 충돌         : Player=False Ground=False RemotePlayer=False
```

**관문3 이 가장 값진 한 줄이다.** 같은 자리, 같은 조준, 같은 거리에서 `GoDown()` 만
불렀더니 후보가 `None → Grabbable` 로 바뀐다. 거리·각도·조준은 **이미 전부 맞아
있었고**, 갈라놓는 것은 `Downed` 조건 하나였다.

## 3. 막고 있던 것 — 그리고 셋째가 제일 비쌌다

| | 어디 | 무엇 |
| --- | --- | --- |
| 1 | `RefreshCarryTarget` | `SetActive(Downed)` — 살아있는 사람에게는 잡을 지점이 **아예 없다**(객체 자체가 null) |
| 2 | `FindDownedTeammate` | `!other.Downed` 로 거른다. 다른 플레이어를 후보로 보는 **유일한 함수**다 |
| 3 | `DriveMovementVelocity` | **잡혀도 끌려오지 않는다** — 이동 코드가 매 스텝 속도를 덮어써서 조인트 결과를 지운다 |

**1·2 만 열면 "잡히기는 하는데 안 움직인다" 가 된다.** 그리고 그 상태에서도 잡기
검증은 전부 초록불이다 — 실제로 그랬다.

### 3-1. 잡을 지점을 항상 켠다

태어날 때 만들고 계속 켜 둔다. 이름만 상태를 따라간다(`"기절한 동료"` / `"동료"`).

**`Create` 에서 만드는 것이 중요하다.** 예전에는 `GoDown`·`Revive`·`SetRemoteDowned`
안에서만 만들어졌다. 참가자 기계에서는 앞의 둘이 돌지 않으므로(물리가 서버 것이다),
`SetRemoteDowned` 가 기절한 동료에 한해 대신 만들어 주고 있었다(S15P21B202-390).
살아있는 동료에게는 **그 경로조차 없었다.**

### 3-2. 후보 탐색이 살아있는 사람도 본다

`FindDownedTeammate` → **`FindTeammateGrabPoint`**. 이름을 바꾼 이유는 동작이
바뀌어서다 — 기절한 사람만 걸렀는데 이제 아니다. 이름이 거짓이 되는 것을 두지 않는다.

**물리 질의를 열어서 푼 것이 아니다.** 조준 탐색 마스크는 그대로 `Player` 를 뺀다 —
열면 고정못(파츠의 자식이다)이 파츠의 잡기 지점으로 딸려 들어온다(S15P21B202-249).
후보는 `PlayerRig.All` 을 훑어서 찾는다. `TheAimingMaskStillExcludesPlayers` 가 그
결정을 잠근다.

### 3-3. 잡혀 있는 동안에는 조인트가 이동을 결정한다 — 여기가 핵심이다

```csharp
if (Hanging || GrabbedByOthers) { /* 힘으로 */ }
else                            { DriveMovementVelocity(targetVel); }
```

`DriveMovementVelocity` 는 인형의 **모든 몸**에 `linearVelocity = ...` 를 직접 써
넣는다. 입력이 없으면 목표 속도가 0 이므로 **제자리에 못을 박는 것**과 같고, 조인트가
끌어온 속도가 매 스텝 지워진다.

**기절한 동료가 끌려오던 이유는 래그돌이라 이 코드가 돌지 않아서였다.** 살아있는
몸에는 그대로 적용된다.

> **매달릴 때 이미 같은 문제를 풀어 두었다.** 바로 위 분기의 주석이 "매달린 동안에는
> 손 조인트가 이동을 결정해야 하므로" 라고 적고 있다. 같은 길을 쓴 것이지 새로
> 발명한 것이 아니다.

#### 3-3-1. 가만히 있는 것과 버티는 것은 다르다

처음에는 조건만 넓혔는데 **0.2771m** 밖에 안 끌려왔다. 목표 속도 0 을 향해 힘을 주는
것은 "가만히 있는 것" 이 아니라 **"버티는 것"** 이기 때문이다.

그래서 입력이 실제로 있을 때만 힘을 넣는다. 가만히 서 있으면 감속은 지면 마찰이
맡는다.

| | 2초 동안 끌려간 거리 |
| --- | ---: |
| 고치기 전 | 0.0785 m |
| 조건만 넓힘 | 0.2771 m |
| **가만히 있을 때 힘을 빼고** | **1.2691 m** |
| (대조) 잡지 않고 걸어감 | 0.0097 m |

### 3-4. 동료를 끌면 느려진다 — 기절 여부와 무관하게

`CarryingDownedTeammate` 를 둘로 갈랐다.

| | 뜻 |
| --- | --- |
| `CarryingTeammate` | 사람을 잡고 끌고 있다. **감속은 이쪽을 본다** |
| `CarryingDownedTeammate` | 그 사람이 기절해 있다(§20.4 전용) |

예전에는 하나였고 판정이 `hand.Held.PhysicsGrip` 이었다 — 살아있는 사람도 잡히게
되면서 그 이름이 거짓이 된다. 감속을 양쪽에 다 거는 이유는 무게가 같고, 이것이 없으면
잡은 쪽이 일방적으로 이겨 잡힌 쪽이 빠져나갈 방법이 없기 때문이다.

### 3-5. 순간이동·탑승에서 잡은 손을 놓게 한다 — 내가 만든 결함이다

`Teleport` 는 **자기 손만** 놓는다. 나를 잡고 있는 손은 놓지 않는다.

잡을 지점이 기절 중에만 켜져 있던 동안에는 이 경로가 기절 해제와 겹쳐 가려져 있었다.
항상 켜면 드러난다 — 남은 `FixedJoint` 가 순간이동한 몸을 **맵 저쪽에서 도로
끌어당긴다.** `R`(끼임 복구, §21)과 부활이 모두 이 경로다.

`ClearForRide` 도 같다. 탑승하는 사람을 붙들고 있으면 잡은 쪽이 탈것에 끌려다닌다.

둘 다 `ReleaseCarriersOf` 를 부른다. 그 함수는 원래 "일어나면 놓게 한다" 용이었고
이번에 그 호출이 없어져 죽은 코드가 될 뻔했는데, **지울 것이 아니라 옮길 자리가
있었다.**

## 4. 멀티 — 처음 판단이 틀렸다

지라 초안에 "멀티가 이 작업의 진짜 크기다" 라고 적었다. **틀렸다.**

```csharp
[Command] void CmdSendInput(InputFrame frame)   // GrabLeft·GrabRight 가 실려 간다
...
if (!adoptedBody) body.SetInput(frame);          // 서버의 PlayerRig 가 실행한다
```

**잡기는 서버에서 일어난다.** 참가자가 누른 버튼은 입력 프레임으로 서버에 가고 서버의
`PlayerRig` 가 손을 뻗는다. 잡기 입력이 지워지는 경우는 **탑승 중 하나뿐**이다. 그리고
서버에서는 모든 플레이어가 진짜 `PlayerRig` 다 — `Player` 레이어에 콜라이더가 살아
있다. 관문 4(`RemotePlayer` 그림)는 **참가자 기계의 로컬 사본에만** 해당한다.

| | 필요한가 |
| --- | --- |
| 힘·조인트를 서버가 계산 | **이미 그렇다** |
| 잡기 상태 SyncVar 신설 | **필요 없다.** `PartPush` 가 SyncVar 를 쓴 이유는 그쪽이 로컬 물리 예측을 하기 때문이고, 잡기는 예측 없이 서버 단독이다 |
| 참가자 화면의 후보 표시 | **필요하다** — §3-1 이 그것이다 |

> **내가 왜 틀렸나.** `-394`/`-400`/`-408` 이 연속으로 멀티에서 깨졌던 기억으로
> "이것도 그렇겠다" 고 **유추했다.** 그 셋은 전부 로컬 물리 예측이 있는 기능이라
> 서버와 갈라졌던 것이고, 잡기는 구조가 다르다. **지라 본문을 쓰기 전에 `NetPlayer`
> 를 열었어야 했다.**

## 5. 잠겨 있던 검증 3개를 뒤집었다

이 이슈에서 새로 깨진 검증은 **정확히 셋이고, 셋 다 "멀쩡한 사람은 못 잡는다" 를
잠그던 것**이다.

| 검증 | 무엇이었나 | 어떻게 바꿨나 |
| --- | --- | --- |
| `AStandingPlayer_HasNoCarryPoint` | "멀쩡한 사람을 끌고 다닐 수는 없다" | → `AStandingPlayer_AlsoHasAGrabPoint` |
| `GettingUp_TurnsItOff` | 일어나면 지점이 꺼진다 | → `GettingUp_KeepsThePointButRenamesIt` |
| `BeingRescuedWhileCarried_MakesTheCarrierLetGo` | 구조되면 잡은 손이 풀린다 | → `…_KeepsTheGripButChangesWhatItIs` |

**그 문장들은 기획에 근거가 없었다.** §20.4 의 제목이 "기절한 동료 운반" 인 것에서
유추한 판단이 검증으로 굳은 것이다. 그때의 판단으로는 맞았다 — 문제는 **기획 확인을
거치지 않고 잠겼다**는 것이다.

> 이 유형을 QA 기록에 **유형 I** 로 새로 적었다: "검증이 결함을 못 잡은 게 아니라
> 기능을 막고 있었다." 지금까지 기록한 8개 유형은 전부 "검증이 통과하는데 게임이
> 틀렸다" 였고 이것은 정반대다.
>
> **대책**: 기획에 없는 제약을 검증 단언에 적을 때는 근거 절 번호를 함께 적는다.
> 번호를 못 적으면 그것은 판단이고, 판단은 잠그기 전에 [Plan] 에 묻는다.

### 6-1. 내 측정이 두 번 틀렸다

**둘 다 제품이 아니라 측정의 문제였고, 둘 다 잘못된 결론을 하마터면 적을 뻔했다.**

**첫째 — `GrabLeft` 를 안 켰다.** 프로브가 이동 입력만 넣고 잡기 버튼을 켜지 않았다.
`PlayerRig.DriveArm` 은 `reaching` 이 거짓이면 그 스텝에 바로 손을 놓는다. 그래서
2초 뒤 둘이 **5.96m** 떨어져 있었고, 나는 "조인트가 안 붙든다" 로 읽을 뻔했다.

**둘째 — 거리의 크기를 쟀다.** `ResistingMakesYouHarderToDrag` 가 처음에 실패했다.

```
가만히=0.816m  버팀=2.528m
```

버티는 쪽이 **더 많이** 움직였다. 버티는 사람은 반대쪽으로 걸어가므로 크기만 보면
많이 움직인 것이 된다. 재야 하는 것은 "끌려간 만큼" 이고 그것은 **부호가 있는 양**이다.
끌린 방향으로 투영해 다시 쟀다.

> **교훈**: 두 상태를 비교할 때 **스칼라로 뭉개면 방향이 사라진다.** 무엇이 늘고
> 무엇이 주는지가 판정의 전부인데, 크기는 둘 다 늘 수 있다.

## 7. 남은 것

- **기획에 절이 없다.** [Plan] 이 §20 에 "살아있는 플레이어 잡기" 를 넣어야 한다.
  §20.4 의 제목이 "기절한 동료 운반" 이라 지금은 이 기능이 문서에 없는 상태로 있다.
- **인게임 확인이 아직이다.** `GrabbedGroundControl = 0.55` 는 실측으로 끌림·버팀이
  둘 다 성립하는 값을 고른 것이고, **손맛은 플레이로만 안다.** 1 에 가까울수록 잡힌
  쪽이 버티고 0 에 가까울수록 끌려온다.
- **2인 이상 실제 멀티 확인이 아직이다.** 서버가 잡기를 실행한다는 것은 코드로
  확인했지만 돌려 보지는 않았다.
- **파츠를 밀고 있는 사람을 잡으면 어떻게 되는가.** `PartPush` 의 `Hauling` 중에 몸이
  끌려가면 밀기 방향 계산(`HaulDirection`)과 싸운다. 이번에 건드리지 않았다 —
  겹치는 상태의 우선순위는 따로 정해야 한다.
- **뿌리치기 수단이 `R`(끼임 복구) 뿐이다.** 장난 요소가 목적이라면 그것으로 충분한지
  플레이로 봐야 한다. 지금은 버티기로 끌림을 늦출 수 있을 뿐 떼어낼 수는 없다.
