# S15P21B202-245 방망이로 소품을 쳐낼 수 있게 한다

## 무엇을

방망이로 굴러다니는 소품을 밀칠 수 있게 했다. 우주선 파츠·용접부·견인 조종 모듈·도구는
**그대로 안 맞는다.**

## 기획에 없는 기능이다

§18.3 이 정한 것은 **플레이어 타격**이고, "굴러다니는 소품을 밀친다" 는 언급이 없다.
넣기로 정한 것이므로 **무엇을 빼는지가 규칙의 전부**다. 이 문서의 대부분이 배제 목록이다.

## 레이어 하나로 가를 수 없다

`GameLayers.Prop` 을 그대로 쓰면 될 것처럼 보였다. 실제로 무엇이 들어 있는지 세어 보니
때려서는 **안 되는** 것들이 섞여 있었다.

| Prop 레이어에 있는 것 | 때려도 되나 | 근거 |
| --- | --- | --- |
| `TransportVehicle` (견인 조종 모듈) + 발판 + 좌석 | **안 된다** | §14.5 가 "마지막 우주선 파츠이기도 하다". **사람이 타고 있을 수도 있다** |
| 플라즈마 용접기 · 방망이 자신 | **안 된다** | §18.3 "장비를 떨어뜨리게 … 하지는 않는다" |
| 해제된 고정못 | 된다 | 뽑아 던져 둔 못이 굴러가는 것은 금지된 것이 아니다 — 이 이슈에서 정했다 |
| 자연물 · 화물 상자 | 된다 | 이것이 소품이다 |

가장 위험한 것이 견인 조종 모듈이다. 레이어로만 판정하면 **사람이 타고 있는 모듈이
날아간다.**

그래서 컴포넌트로 걸러낸다.

```csharp
bool CanPush(Rigidbody body)
{
    if (body == null || body.isKinematic) return false;
    if (body.GetComponentInParent<ToolBase>() != null) return false;
    if (body.GetComponentInParent<Parts.SpaceshipPart>() != null) return false;
    if (body.GetComponentInParent<Parts.TransportVehicle>() != null) return false;
    return true;
}
```

`GetComponentInParent` 인 것이 중요하다. **비드는 파츠의 자식 콜라이더**이므로
(S15P21B202-226) 부모에서 함께 걸린다 — 안 걸리면 용접부를 때리는 것이 되고, §18.3 이
그것을 금지한다.

"레이어와 컴포넌트를 둘 다 본다" 는 `WeldBead` 가 같은 문제를 푼 선례다.

## 속도가 아니라 충격량이다

```csharp
prop.AddForce(direction * PhysicsScale.BatPropImpulse, ForceMode.Impulse);
```

소품은 질량이 제각각인데(`LevelBuilder` 가 개별로 받는다) **속도를 대입하면** 무거운
상자와 가벼운 조각이 똑같이 날아간다. 충격량은 질량이 나누므로 무거운 것이 덜 움직인다 —
방망이로 **밀친다** 는 감각이 그것이다.

`BatPropImpulse = 80` N·s 는 60kg 운석이 `BatDeflectSpeed`(14m/s)로 날아가는 것과 비슷한
크기로 잡았다. 20kg 상자면 초속 4m 쯤이다.

운석은 여전히 **속도를 대입**한다. 쳐낸 운석이 어디로 가는지가 §18.2 의 판정이므로
질량에 따라 달라지면 안 된다.

## 우선순위 — 운석 → 동료 → 소품

운석이 방망이의 목적이고(§18.1), 동료 타격은 기획에 있는 기능이며(§18.3), 소품은
곁가지다. 소품이 앞에 오면 **발밑 상자 때문에 운석을 놓친다.**

## 이름을 고쳤다

`BatPlayerReach` → **`BatStrikeReach`**. 사거리는 **도구의 성질**이지 맞는 쪽의 성질이
아니다 — 소품이 대상에 들어오면서 이름이 사실과 어긋났다. 동료와 소품이 다른 거리에서
맞으면 플레이어가 두 값을 배워야 한다.

운석은 이 값을 쓰지 않는다. 운석은 `BatAssistRadius`(2.5m)로 **낙하 지점**까지의 거리를
잰다 — 공중에 있는 것을 팔 길이로 재면 맞을 수 없다.

## 검증에서 걸린 것

**`AddForce(Impulse)` 는 속도를 즉시 바꾸지 않는다.** 다음 물리 걸음에 반영된다. 처음
검증 3개가 속도 0 으로 실패했고, `Physics.simulationMode = SimulationMode.Script` +
`Physics.Simulate(0.01f)` 로 직접 돌려서 풀었다(`ClampPullTests` 등 7개 스위트의 기존
방식이다). 운석 검증에는 이 문제가 없었다 — 운석은 속도를 대입하기 때문이다.

**도구가 밀리지 않는 것을 확인하는 검증이 0.028m/s 로 실패했다.** 중력이었다
(2.8 × 0.01). 프로젝트 중력이 −2.8m/s² 이라는 것을 잊고 소품 쪽에만 `useGravity = false`
를 두었다. 떨어지는 것과 밀리는 것을 섞지 않게 도구 쪽도 껐다.

**무게 비교를 두 장면으로 나눌 필요가 없었다.** 처음에 `TearDown()`/`SetUp()` 을 손으로
불러 두 번 재려 했는데, 가벼운 것을 +X 에 무거운 것을 −X 에 두고 방망이 둘로 한 번씩
휘두르면 **같은 물리 걸음**을 받아 비교가 더 공정하다.
