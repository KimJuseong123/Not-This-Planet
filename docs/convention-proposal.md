## 결정 요약

| 항목 | 결정 |
| --- | --- |
| 원칙 | **Jira 우선.** 모든 작업(비코드 포함)은 Jira 이슈 → 브랜치 → MR → develop 머지 |
| 브랜치 | **master – develop – 작업 브랜치** 3단. 작업 브랜치는 1~3일(≤13pt) 안에 머지. 문서·설정도 예외 없음 |
| 브랜치 생성 | **Jira 이슈 화면 "브랜치 만들기"** = 진행 중으로 가는 유일한 길. 이름 `KEY-번호-영문설명`. 이슈 키 없는 이름은 **GitLab이 생성 거부** |
| Jira 구조 | Epic → Task 2단계만. 타입은 Task 통일. 제목 `[파트] 제목`, **레이블 = 파트**(Task는 수행 파트, Epic은 검증 파트) |
| 필수 필드 | 담당자(실작업자) · 상위 Epic · 기한(비면 스프린트 종료일 자동) · 스프린트·스토리 포인트(진행 중 진입 시). 보고자는 Epic 담당자로 자동 |
| 스토리 포인트 | **1pt = 1시간**, 값 1/2/3/5/8/13, 이슈 ≤13, 개인 주 30~40(상한 60) |
| 상태 | **해야 할 일 → 진행 중 → 완료** 3개. 진행 중 = 브랜치 생성, 완료 = MR 머지. 손으로 끌면 되돌려짐 |
| MR | 템플릿 자동 적용 · 제목 `[파트] type: 요약 (KEY-번호)` · Draft 금지 · squash |
| 승인 | **팀장(Maintainer)만 develop에 머지** = 승인. 체크리스트 5항목(범위·완료 조건·씬/프리팹·구조·기록). SLA 24h, 대리 = Epic 담당 파트원 |
| 자동 검사 | 0단계: Jira 자동화·보호 브랜치·훅 / 1단계(러너): MR 린트·리포 위생 / 2단계: Unity 컴파일·AI 리뷰(비차단) |
| LFS | `.gitattributes`로 모델·텍스처·오디오·영상 LFS 적용 중. 클론 전 `git lfs install` |

## 작업 흐름 한 장

```
① Jira 이슈 생성 ([파트] 제목 · Epic · 담당자 · 기한)          → [해야 할 일]  ⚙ 레이블·기한·설명 자동
② 이슈 화면 "브랜치 만들기" → 소스 develop → 이름 확인            → [진행 중]    ⚙ 자동 (끌어서 못 감)
③ git fetch → checkout → 작업(코드·에셋·씬·문서/기록) → 커밋 → push
④ MR 생성 (템플릿 자동) → ⚙ 자동 검사 → 👤 팀장 승인·머지(squash)  → [완료]      ⚙ 자동 (끌어서 못 감)
```

비코드 작업(회의·리서치·외부 툴)은 `docs/records/<KEY>-<slug>.md` 기록 1장이 산출물.

## Git

```
master   ─────●───────────────●──────   항상 릴리즈 가능 · 마일스톤마다 태그(v0.1.0)
              ↑               ↑
develop  ──●──●──●──●──●──●───●──────   통합 브랜치 · 항상 에디터에서 실행 가능
           ↑     ↑     ↑
S15P21B202-12-player-jump               Jira 이슈 1개 = 브랜치 1개 · 1~3일
```

| 무엇 | 형식 | 예 |
| --- | --- | --- |
| 브랜치 | `<JIRA키>-<번호>-<영문-설명>` (hotfix만 `hotfix/` 접두어) | `S15P21B202-12-player-jump` |
| 커밋 | `<type>(<scope>): <summary> (<JIRA키>-<번호>)` — scope 선택 | `feat(player): 이단 점프 구현 (S15P21B202-12)` |
| MR 제목 | `[파트] <type>: 요약 (<JIRA키>-<번호>)` | `[Network] feat: 로비 매치메이킹 (S15P21B202-31)` |

**규칙 강제 3겹(2026-08-27~):** 로컬 `pre-push` 훅 → CI `mr-lint`(브랜치명·제목·Jira 키 검사, MR 빨간불) → Jira 자동화 되돌림. 서버 와일드카드 보호(`*` 금지 + `S15P21B202-*` 허용)는 CI 도입 후 해제 — 머지 시 소스 브랜치 자동 삭제를 얻기 위해.
보호 브랜치는 `master`·`develop`·`hotfix/*`만. 작업 브랜치는 머지와 함께 자동 삭제된다.

## Jira

- Epic의 `[파트]`는 **"완료 판정을 누가 내리는가"**. Epic 아래 Task는 모든 파트가 참여. Task의 `[파트]`·레이블은 수행 파트.
- Epic 상태는 담당자가 수동 완료. Task 상태는 전부 자동(브랜치 생성/MR 머지).

### 파트 태그 9종 (= 레이블)

| 태그 | 영역 | 범위 |
| --- | --- | --- |
| `[Plan]` | 기획 | 게임 기획, 레벨 디자인, 밸런싱 |
| `[Art]` | 3D 아트 | 모델링, 텍스처, 애니메이션, VFX |
| `[UI]` | UI/UX | UI 디자인, uGUI 구현, HUD, 메뉴 |
| `[Sound]` | 사운드 | BGM, 효과음, 믹싱 |

담당 팀원 매핑은 `docs/parts.md`(살아있는 문서).
