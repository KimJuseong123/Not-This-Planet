> 규칙 전체 요약은 [conventions.md](./conventions.md) · 관련 문서: [Git 컨벤션](./git-convention.md) · [파트 구분](./parts.md) · [Jira-GitLab 자동화](./jira-gitlab-automation.md) · [결정 근거](./workflow-plan.md)
> 기준 버전: workflow-plan v1.0 (2026-08-26)

## 0. 원칙: Jira 우선

**모든 작업은 Jira 이슈로 먼저 등록한다.** 코드, 에셋, 문서, 회의, 리서치 — 리포에 코드가 들어가지 않는 작업도 예외 없이.
브랜치는 Jira 이슈 화면에서 만든다. 이슈 키 없는 이름은 **로컬 훅이 push 를 막고**, 우회해도 CI 양식 검사가 MR 을 빨간불로 만들며, Jira 에도 연결되지 않는다(서버가 이름으로 거부하던 규칙은 2026-08-27 에 해제 — 머지 시 브랜치 자동 삭제를 얻기 위해. 강제 장치 전체는 [conventions §3](./conventions.md)).

작성은 사람이 직접 해도 되고, 개인 Atlassian 계정 권한을 AI에 주어 대신 작성시켜도 된다(개인 선택).
AI에게는 이 문서를 컨텍스트로 준다. 토큰은 개인 계정 것만 사용한다.

## 1. 이슈 계층

```
Epic  ── 큰 작업 카테고리. [파트] = 최종 검증 책임 파트
 └─ Task ── 실제 작업 단위. 1명이 1~3일(스토리 포인트 ≤ 13) 안에 끝낼 크기
```

- **Epic → Task 2단계만.** Subtask를 만들지 않는다. Task가 커지면 Task를 쪼갠다.
- 이슈 타입은 Task / Story / Bug를 쓸 수 있지만, 구분 기준이 정해질 때까지 **전부 `Task`로 통일**한다.

## 2. 제목과 레이블

```
[파트] 제목           ← 모든 이슈(Epic, Task). 파트 태그는 parts.md의 13종
```

- **레이블 = 제목의 `[파트]`와 글자까지 동일한 값** (`Network`, `UI`, … 대소문자 구분). 자동화가 제목에서 읽어 채우므로 직접 고르지 않는다.
- **Task의 파트는 그 작업을 수행하는 파트**, Epic의 파트는 검증 책임 파트다. Task에 Epic의 파트를 달지 않는다 —
  레이블의 쓸모는 "Epic 무관하게 내 파트 일 모아 보기"(`labels = UI`)이고, Epic의 파트는 상위 항목 관계로 이미 따라온다.
- 제목이 형식에 맞지 않으면 자동화가 `needs-fix` 레이블과 코멘트를 남기고, 그 상태로는 진행 중으로 갈 수 없다.

## 3. Epic 규칙

| 필드 | 값 |
| --- | --- |
| 제목 | `[파트] 제목` — 파트 = 최종 확인·검증 책임 |
| 담당자 | 해당 파트의 팀원 (하위 Task 결과물의 통합 확인 책임) |
| 보고자 | 생성자 그대로 (규칙 없음, 2026-08-27 결정) |
| 설명 | "이 Epic이 끝났다고 볼 조건" 한 줄 |

- Epic에는 **모든 파트가 Task로 참여**할 수 있다. Epic의 파트는 "누가 일하는가"가 아니라 "완료 판정을 누가 내리는가"다.
- Epic의 상태는 자동화하지 않는다. 하위 Task가 모두 완료되고 담당 파트가 검증하면 **Epic 담당자가 수동으로 완료** 처리한다.

## 4. Task 필드 규칙

| 필드 | 규칙 | 누가 채우나 |
| --- | --- | --- |
| **제목** | `[파트] 제목` | 작성자 |
| **담당자** | 실제 작업자 1명. **필수** | 작성자 |
| **보고자** | 생성자 그대로 — 규칙 없음(2026-08-27 결정). 하위 Task의 책임자는 **상위 Epic 담당자** | — |
| **레이블** | 제목의 `[파트]` — 자동 설정 | 자동 |
| **기한** | **필수.** 비어 있으면 스프린트 종료일로 자동 채움. 더 빠른 기한만 직접 입력 | 작성자 / 자동 |
| **스프린트** | 백로그 이슈는 비어도 됨. **진행 중으로 가려면 필수** | 스프린트 계획 |
| **우선순위** | 기본 Medium. Highest = 이번 스프린트의 다른 작업을 막음 / High = 이번 스프린트 필수 / Medium = 기본 / Low = 여유 시 / Lowest = 아이디어 | 작성자 |
| **상위 항목(Epic)** | **필수.** Epic 담당자가 하위 Task 전체(진행 확인·검증·리뷰 대리)를 책임진다. 소속 없는 잡무는 `[Infra] 개발 환경 및 Unity 초기화`(S15P21B202-9). 비어 있으면 `needs-fix`(R2 보강) | 작성자 |
| **스토리 포인트** | §5 척도. **진행 중으로 가려면 필수** | 작성자 |
| **설명** | 비어 있으면 템플릿(목적 · 완료 조건 · 산출물 · 참고)이 자동 삽입됨. 특히 **완료 조건**은 팀장 승인의 기준이므로 반드시 채운다 | 작성자 |

- 설명 템플릿 원본: [`docs/templates/jira-issue-description.md`](./templates/jira-issue-description.md)
- 필수 표시된 필드(담당자·Epic·기한)는 Jira 폼에서 비우면 생성이 막힌다. 스프린트·스토리 포인트는 진행 중 진입 시 자동화가 검사한다.

## 5. 스토리 포인트 척도

| 규칙 | 값 |
| --- | --- |
| 단위 | **1 pt = 집중 작업 1시간** |
| 허용 값 | 1 · 2 · 3 · 5 · 8 · 13 |
| 이슈 상한 | 13 — 넘으면 이슈를 쪼갠다 |
| 개인 주간 합계 | **목표 30~40, 상한 60** (항상 두 자리). 보드 백로그의 담당자 아바타에 스프린트 합계가 보인다 |
| 초과 시 | 스프린트 계획에서 다음 스프린트로 넘기거나 재배분 |

## 6. 작업 흐름 (단일)

```
① Jira 이슈 생성 → 상태 [해야 할 일]                                (필수 필드 채움, 자동 보정)
② 이슈 화면 → 개발 패널 → "브랜치 만들기" → 소스 develop → 이름 확인    → 자동: [진행 중]
③ git fetch → checkout → 작업 → 커밋 → push
④ MR 생성 (템플릿 자동 적용, 제목·본문에 이슈 키 필수, Draft 금지) → 팀장 승인·머지 → 자동: [완료]
```

- 비코드 작업도 같다. 브랜치에는 최소한 **작업 기록 1장**(`docs/records/<KEY>-<slug>.md`, 템플릿 [`docs/templates/work-record.md`](./templates/work-record.md))이 들어간다.
- 브랜치명은 Jira가 제안한 `KEY-번호-…`를 쓰되, 한글 제목 때문에 설명부가 비면 영문으로 채운다. ([Git 컨벤션 §3](./git-convention.md))

## 7. 상태 흐름과 진입 규칙

```
해야 할 일 ──(브랜치 생성)──▶ 진행 중 ──(MR 머지)──▶ 완료
```

| 상태 | 들어오는 유일한 길 | 손으로 카드를 끌면 |
| --- | --- | --- |
| 해야 할 일 | 이슈 생성 | (되돌아가는 것은 허용) |
| **진행 중** | 이슈 화면 **"브랜치 만들기"** (또는 이슈 키가 든 브랜치 push) | 연결된 브랜치가 없거나 스프린트·포인트가 비어 있으면 자동으로 **해야 할 일로 되돌려지고** 안내 코멘트가 달린다 |
| **완료** | 해당 브랜치의 MR이 develop에 **머지** | **무조건 진행 중으로 되돌려진다** (모든 이슈가 MR을 가지므로 수동 완료는 없다) |

- 워크플로우 편집 권한이 확보되면 위 두 전환은 드래그 자체가 불가능해진다(자동화 계정만 허용). 그 전까지는 되돌림 규칙이 막는다.
- MR이 머지 없이 닫히면 상태는 진행 중 그대로, 코멘트만 남는다.

## 8. 스프린트 운영

- 주기 **1주**. 스프린트 계획에서 각자 이번 주 Task를 배치하고 스토리 포인트 합계(§5)를 확인한다.
- 회고에서 미완료 Task는 다음 스프린트로 이월하거나 쪼갠다. MR 대기 시간·주간 머지 수를 함께 본다([계획 §3.5](./workflow-plan.md)).

```
Epic:  [Network] 멀티플레이어 로비 구축     담당: 네트워크 파트원 · 레이블 Network
 ├─ Task: [Network] 세션 생성/참가 로직     담당: A · 레이블 Network · 8pt
 ├─ Task: [UI] 로비 화면 및 방 목록 UI      담당: B · 레이블 UI · 5pt
 ├─ Task: [Plan] 로비 UX 흐름 기획서        담당: C · 레이블 Plan · 3pt  → 브랜치에 docs/planning/lobby-ux.md
 └─ Task: [Sound] 로비 BGM 레퍼런스 조사    담당: D · 레이블 Sound · 2pt → 브랜치에 docs/records/S15P21B202-27-lobby-bgm.md
```
