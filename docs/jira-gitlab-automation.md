## 목표

```
이슈 생성 ──▶ [해야 할 일]   ⚙ 레이블·기한·설명 자동 보정, 제목 형식 검사
브랜치 생성 ─▶ [진행 중]     ⚙ 손으로 끌면 되돌림 (브랜치·스프린트·포인트 없을 때)
MR 머지 ────▶ [완료]         ⚙ 손으로 끌면 무조건 되돌림
```

전제: Jira–GitLab 연동 앱(GitLab for Jira Cloud)이 설치되어 이슈 화면에 "브랜치 만들기"가 보임 — **2026-08-25 확인됨.**

## 1. Jira 사전 설정

1. **레이블:** 미리 만들 필요 없음 — R2가 제목의 `[파트]`를 읽어 자동으로 붙이고, `needs-fix`도 규칙이 생성한다. 값은 파트 태그와 글자까지 동일(대소문자 구분).
2. **필수 필드:** Task 유형에서 **담당자 · 상위 항목 · 기한**을 필수로.
   - 팀 관리형: 프로젝트 설정 → 이슈 유형 → Task → 각 필드의 "필수" 체크 (프로젝트 관리자)
   - 회사 관리형: 필드 구성에서 Required (Jira 관리자에게 요청)
3. **설명 템플릿 본문**을 [`docs/templates/jira-issue-description.md`](./templates/jira-issue-description.md)에서 복사해 둔다 (R1에 붙임).

  | 무엇으로 쓰나 | 넣어야 하는 서식 | 위키 마크업을 넣으면 |
  | --- | --- | --- |
  | Automation(R1) 이슈 편집 | **위키 마크업** — `h2.` · 별표 불릿 · 중괄호 금지 | 정상 |
  | MCP·REST(사람·에이전트가 갱신) | **Markdown** — `##` · `-` · 백틱 | 변환기가 Markdown 이 아니라고 보고 **글자 그대로 저장** |

  이 서식 규칙은 **설명뿐 아니라 자동화의 코멘트 액션에도 그대로 적용된다.** 위키 마크업에서 굵게는 별표 **1개**
  (`*텍스트*`)다. 마크다운식 `**텍스트**` 를 넣으면 파서가 엉켜 **기울임으로 렌더링된다**(2026-08-31 실측:
  R5 되돌림 코멘트가 화면에 기울임으로 표시됨. API 로 읽으면 별표 4개로 내려온다).
  주의 — **Mattermost 웹 요청 액션의 본문은 Markdown 이므로 `**텍스트**` 가 맞다.** 위키 마크업은 Jira 안에
  글을 쓰는 액션(이슈 편집·코멘트)에만 해당한다.

  MCP 서버는 Markdown → 위키 마크업 → ADF 순으로 변환한다. 그래서 MCP 로 `h2.` 를 넣으면 제목이 아니라 `h2.` 라는 글자가 남는다(이슈 23건에서 그렇게 보였던 원인). 반대로 템플릿을 Markdown 으로 "고치면" 위 ①로 깨진다. **부수 실측**: MCP 로 쓸 때 코드 표기 안에 별표 하나만 넣으면 굵게 표기 경계가 어긋나고 뒤따르는 목록이 중첩으로 잘못 해석된다 — 별표는 글로 쓴다.

  내부 API 는 API 토큰이 403 이라 브라우저 로그인 세션이 필요한데, 그 세션을 스크립트로 얻는 것이 막힌다:
  Playwright(`launch_persistent_context`, channel="chrome")로 창을 띄워도 프로필이 새로 생겨 로그인 상태가 없고,
  Atlassian 로그인은 이메일 → 계속 → 비밀번호/구글 SSO → 2단계 인증의 다단계 흐름이라 사람이 그 창에서 직접
  로그인을 끝내야 한다(2026-08-31 실측: 로그인 단계에서 넘어가지 않음). 사람 손이 필요한 것은 어차피 같으므로
  **규칙 편집에는 쓰지 않는다** — 쓸 만한 곳은 사람이 로그인해 둔 창을 이어받아 규칙 JSON 을 **읽어오는** 경우뿐이다.
  그때 동기 API 대기는 `time.sleep` 대신 `page.wait_for_timeout`.
## 부록 B · 자동화 편집기 조작법 (UI에서 규칙을 만들거나 고칠 때)

```
규칙 만들기
 └ ① 트리거 선택 (검색창에 이름 입력) → 옵션 설정 → [다음]
 └ ② [구성 요소 추가] 반복:  조건 | 작업 | IF/ELSE 블록 | 분기
      각 구성 요소 설정 후 [다음]
 └ ③ 오른쪽 위 [규칙 켜기] → 규칙 이름 입력 → [규칙 켜기]
```

- **규칙 세부 정보**(왼쪽 상단 규칙 이름 클릭): 범위 = 이 프로젝트 · 실행 주체(Actor) = `Automation for Jira` · **"다른 규칙 작업이 이 규칙을 트리거하도록 허용" = 해제(기본값)**. R5·R9에서 특히 중요.
- **스마트 값**은 텍스트 입력란에 `{{...}}`를 그대로 친다. 사용자 필드(보고자 등)는 드롭다운에서 **"스마트 값"** 을 고른 뒤 입력하거나, 편집 작업 하단 **"추가 필드"(JSON)** 를 쓴다.
- **필드 조건**(작업 항목 필드 조건): 필드 / 조건(같음·같지 않음·비어 있음·비어 있지 않음·포함·포함하지 않음) / 값.
- **고급 비교 조건**: 첫 값 `{{스마트 값}}` / 조건(같음·같지 않음·정규식과 일치·정규식과 일치하지 않음…) / 두 번째 값.
- **JQL 조건**("작업 항목이 JQL과 일치"): JQL 입력 후 **검증** 버튼으로 문법 확인.
- 저장 후 규칙 목록에서 **감사 로그**로 실행 결과를 본다.
