# AI 동료 명령 목록

작성: 2026-09-16. 기준 브랜치 `S15P21B202-531-ai-companion-prototype`.

현재 구현된 명령과 앞으로 추가할 명령을 한곳에 모았습니다.
한국어 표현 예시는 그대로 서버 프롬프트(`companion_v4.py`)의 설명·예시로 쓸 수 있습니다.

**설계 경계**: LLM은 행동 하나만 고릅니다. 대상 선택, 이동, 물리, 장착, 타격은 게임 로직이 결정합니다.

## 1. 구현 완료 (실행 행동 12개)

### 이동 · 대기

| action | 표현 예시 | 게임 동작 |
|---|---|---|
| `follow` | 나 따라와 / 이리 와 / 일로 와봐 / 내 뒤로 붙어 / 같이 가자 | 화자를 따라 이동 |
| `wait` | 여기서 기다려 / 가만히 있어 / 거기 서 있어 / 잠시 대기해 | 현재 위치에서 정지 |
| `cancel` | 멈춰 / 그만해 / 하지 마 / 취소해 / 됐어 / 스톱 | 진행 중 작업 중단. 든 도구는 유지 |

### 고정못

| action | 표현 예시 | 게임 동작 |
|---|---|---|
| `pull_pin` | 못 뽑아줘 / 이 나사 빼줘 / 고정핀 하나 제거해 | 화자 12m 안 가까운 못 1개 제거 |
| `move_to_pin` | 못 쪽으로 가봐 / 고정못 앞에서 기다려 | 못 앞으로 이동만. 뽑지 않음 |
| `pull_nearby_pins` | 못 전부 뽑아줘 / 주변 나사 다 빼 / 싹 다 제거해 | 명령 시점 후보를 순서대로 처리 |

### 도구

| action | 표현 예시 | 게임 동작 |
|---|---|---|
| `pickup_tool` | 도구 하나 집어 / 장비 주워 / 연장 가져와 | 종류 무관, 빈 도구 1개 |
| `pickup_bat` | 몽둥이 주워줘 / 방망이 가져와 / 배트 챙겨 | 몽둥이 집기 (타격은 안 함) |
| `pickup_welder` | 용접건 주워줘 / 플라즈마 총 집어 / 용접기 들어 | 용접건 집기 (용접은 미지원) |
| `drop_tool` | 내려놔 / 그거 놔 / 손에 든 거 버려 | 짧은 Q 입력으로 내려놓기 |

### 전투 · 방어

| action | 표현 예시 | 게임 동작 |
|---|---|---|
| `hit_target` | 공 때려줘 / 저거 한 대 쳐 / 타격해 | 연습용 공 1회 타격 |
| `defend_meteors` | 운석 막아줘 / 쳐내줘 / 방어해 | 몽둥이 확보 후 지속 방어 |

### 제어 결과 (실행 아님)

| action | 의미 | 화면 |
|---|---|---|
| `none` | 미지원 작업, 잡담, 질문 | "실행할 요청 없음" |
| `clarify` | 대상·행동이 불분명 | "확인 필요" + 물음표 이모티콘 |

둘 다 `CompanionPolicy.TryParse`가 `false`를 반환해 **게임 동작이 일어나지 않습니다.**

## 2. 추가 제안 — 사회 · 재미 요소

팀에서 춤 애니메이션을 작업 중이므로 함께 붙일 수 있습니다.

**이 범주가 쉬운 이유**: 대상 선택도, 이동도, 물리도 없습니다. 제자리에서 애니메이션이나
이모티콘만 재생하면 되므로 기존 도구 명령보다 구현이 훨씬 단순합니다.

### 이미 있는 이모티콘 6종

`01-question` `02-exclamation` `03-thumbsup` `04-heart` `05-crying` `06-angry`

`EmoteState`는 `Count = 6`, 표시 3.5초, 쿨다운 0.8초입니다. 새 이모티콘을 늘리려면 `Count`도 함께 올립니다.

### 제안 명령

| action | 표현 예시 | 게임 동작 | 필요한 것 |
|---|---|---|---|
| `dance` | 춤춰 / 춤 좀 춰봐 / 신나게 춤춰 / 댄스 | 제자리 춤 애니메이션 재생 | **춤 애니메이션** (팀원 작업 중) |
| `greet` | 인사해 / 안녕이라고 해 / 손 흔들어 / 하이 | 손 흔들기 + `02-exclamation` | 손 흔들기 애니메이션 (없으면 이모티콘만) |
| `celebrate` | 칭찬 받는 상황 — 잘했어 / 굿 / 고마워 / 최고야 | `03-thumbsup` 또는 `04-heart` | 기존 이모티콘으로 충분 |
| `sulk` | 혼나는 상황 — 야 뭐해 / 바보야 / 못한다 / (욕설) | `05-crying` 또는 `06-angry`, 잠깐 시무룩 | 기존 이모티콘으로 충분 |
| `cheer` | 파이팅 / 힘내 / 응원해줘 | `02-exclamation` + 짧은 동작 | 기존 이모티콘으로 충분 |

### 욕설 처리에 대한 설계 판단

`sulk`은 **플레이어가 동료에게 험한 말을 했을 때 동료가 반응하는 것**입니다.
AI가 욕설을 만들어 내거나 따라 하는 것이 아닙니다. 이 구분이 중요합니다.

- 멀티플레이에서 AI가 욕설을 출력하면 괴롭힘 수단이 됩니다. **출력은 이모티콘/애니메이션으로 한정합니다.**
- LLM은 행동 이름 하나만 반환하므로 구조적으로 자유 문장을 만들지 않습니다. 이 성질을 유지합니다.
- 분류는 "이 발화가 동료를 나무라는 톤인가"까지만 합니다. 어떤 단어였는지는 게임에 전달하지 않습니다.

`celebrate`와 `sulk`은 **명령이 아니라 반응**이라는 점에서 나머지와 성격이 다릅니다.
"춤춰"는 시키는 말이고 "잘했어"는 시키는 말이 아닙니다. 프롬프트에 이 차이를 적어야
`잘했어`가 엉뚱한 행동으로 가지 않습니다.

## 3. 미구현 게임플레이 (백로그)

인수인계 문서에 미구현으로 기록된 것들입니다. 현재는 모두 `none`으로 분류됩니다.

| 후보 action | 표현 예시 | 막혀 있는 이유 |
|---|---|---|
| `weld` | 용접해줘 / 붙여줘 | 용접 실행 로직 미연결. 현재 프롬프트가 명시적으로 `none` 처리 |
| `carry_part` | 파츠 옮겨줘 / 같이 밀자 | 운반 동작 미구현 |
| `throw_tool` | 도구 던져줘 / 이리 던져 | 던지기 미구현 |
| `bring_to_me` | 가져와 (집은 뒤 화자에게 복귀) | 현재 `pickup_*`은 집기까지만. 복귀는 별도 `follow` 필요 |

`weld`를 추가할 때는 **기존 프롬프트의 "'용접해줘'는 none" 규칙을 함께 지워야 합니다.**
안 지우면 새 행동과 기존 규칙이 충돌합니다.

### ⚠️ `IsToolOrder` 함정

```csharp
public static bool IsToolOrder(CompanionOrder order)
    => order >= CompanionOrder.PickUpTool && order <= CompanionOrder.DefendMeteors;
```

**enum 범위로 판정합니다.** 사회 명령을 끝에 추가하면 자동으로 제외되므로 안전합니다.
그러나 **새 도구 명령을 끝에 추가하면 도구로 인식되지 않습니다.** 범위를 함께 넓혀야 합니다.

## 5. 음성 인식 관점에서 주의할 점

2026-09-16 측정 결과([진단 기록](../records/2026-09-16-ai-stt-llm-diagnosis.md))에서 나온 제약입니다.

- **짧은 명령일수록 인식이 나쁩니다.** 2~4글자 명령은 키워드 보존율 0.10, 7글자 이상은 0.35였습니다.
  `춤춰`, `하이` 같은 2글자 명령은 특히 취약합니다. **`춤 좀 춰봐`처럼 조금 긴 표현을 함께 등록**하세요.
- 새 명령끼리 발음이 겹치지 않게 합니다. 예를 들어 `치어`(cheer)와 `쳐`(hit_target)는 위험합니다.
- 긍정·부정이 갈리는 쌍은 프롬프트에 명시합니다. `춤춰` / `춤추지 마`처럼요.
- 표현을 많이 나열해도 사람마다 말이 달라 다 덮지 못합니다.
  후보 매칭으로 보완하려 했으나 **효과 0으로 측정돼 폐기**했습니다. 프롬프트의 발음 보정이 더 효과적이었습니다.

## 6. 구현 순서 제안

1. **`dance`** — 팀원 애니메이션이 준비되면 바로. 재미 요소 중 체감이 가장 큽니다
2. **`greet`, `celebrate`, `sulk`** — 기존 이모티콘만으로 되므로 애니메이션 없이 오늘도 가능
3. **`cheer`** — 위 셋과 묶어서
4. **`bring_to_me`** — 기존 `pickup_*` + `follow` 조합이라 신규 물리 없음
5. `weld`, `carry_part`, `throw_tool` — 게임 로직 자체가 필요. 별도 작업

1~3번은 **대상 선택도 물리도 없어** 오늘 만든 12개보다 훨씬 단순합니다.
