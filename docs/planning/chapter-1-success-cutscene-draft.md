# 1장 로켓 완성·성공 컷씬 초안

작성: 2026-09-10. 기준: [1장 상세 기획](./chapter-1-detailed-design.md). **복구는 구현, 아래 성공 흐름은 후속 구현을 위한 초안**이다.

## 1. 목표

조립대에서 네 핵심 부품을 올바르게 쌓고 모든 필수 접합부의 용접을 완료하면 성공 연출로 전환한다. 접속 중인 모든 플레이어가 자신들이 만든 로켓에 들어가고, 로켓이 행성을 떠나는 모습을 함께 본다. 컷씬 마지막에 1장 성공을 확정한다.

이번 요청에서는 용접 성공 뒤의 발사를 확정적인 보상 연출로 제안한다. 기존 §22의 미완성 탑승·실제 하중 시험·발사 실패 분기는 이 새 흐름을 구현할 때 대체하며, 현재 코드는 아직 교체하지 않는다.

## 2. 완성 판정

서버가 다음을 모두 확인한 경우 한 번만 `Playing → Boarding`으로 전환한다.

1. 필수 네 파츠가 각각 한 개씩 있고, 기존 `PartSpec.All` 순서로 연결되어 있다.
2. 최하단 엔진이 `ShipAssembly.LaunchPad`의 유효 범위 안에 있고 탑승 가능한 기울기다.
3. 네 부품이 실제로 하나의 조립체로 연결되어 있다. 가까이 놓인 것만으로는 인정하지 않는다.
4. 위·아래를 잇는 필수 세 접합부가 모두 살아 있으며 `PartAssemblyLink.IsFullyWelded`를 만족한다. 불필요하게 추가한 비드까지 전부 용접할 필요는 없다.
5. 초기 테스트값으로 위 조건이 **0.5초 연속** 유지된다. 마지막 용접 프레임의 절단·파손·이탈이 있으면 누적 시간을 취소한다.
6. 씬 초기화 또는 다른 종료 처리가 진행 중이지 않다. 같은 판에서는 재진입할 수 없다.

현재 `ShipAssembly.IsBoardable`은 용접 완료를 확인하지 않는다. 그 값을 성공 조건으로 그대로 사용해서는 안 된다. `ShipAssembly`의 순서·조립대 검사를 재사용하고, 실제 접합 그래프의 필수 연결을 추가 검증한다. 진행률 숫자나 정렬 점수는 HUD에 추가하지 않는다.

## 3. 약 18초의 연출 구성

| 구간 | 화면·소리 | 플레이어와 로켓 처리 |
| --- | --- | --- |
| 0~2초: 완성 인지 | 마지막 용접 소리, 로켓의 결합선·엔진 불빛 점등. 카메라가 조립대 전경으로 이동 | 서버가 완성 시각과 참가자 목록 확정. 장비 내려놓기, 손·견인·탑승 연결 정리, 게임 조작 잠금 |
| 2~7초: 전원 탑승 | 하단 해치가 열리고 각 캐릭터가 차례로 들어감. 유리창 안에 최대 4명 실루엣 표시 | 기절·끼임·맵 원거리 때문에 성공이 지연되지 않도록 전원 회복 후 연출용 대기점과 좌석 배정 |
| 7~10초: 점화 | 해치 닫힘, 엔진 저음과 진동, 배기 연기·먼지. 짧은 3초 점화 리듬 | 로켓·탑승자는 게임 물리에서 연출 제어로 전환. 완성된 로켓의 실제 외형 유지 |
| 10~17초: 상승 | 지면 가까운 측면 숏에서 시작해 카메라가 위로 추적. 마지막에는 행성과 로켓을 넓게 보여줌 | 부품 간 상대 위치를 보존한 채 하나의 연출 루트를 이동. 비행 중 접합 파손 없음 |
| 17~18초: 탈출 | 하늘로 사라지는 로켓, 음악 마무리, 페이드 | 서버가 한 번만 `Success` 확정. 성공 화면 표시 |

탑승 초안은 자동 연출을 기본으로 한다. 완성 후 다시 전원이 직접 걸어와 E를 누르도록 기다리는 단계는 두지 않는다. 실제 진입 애니메이션이 없으면 짧은 페이드 뒤 좌석으로 옮기는 임시 연출을 먼저 사용한다.

캐릭터 이동 애니메이션을 적용할 때도 길찾기를 성공 조건으로 삼지 않는다. 5초 탑승 구간이 끝나면 아직 도착하지 않은 플레이어는 화면 전환 중 자기 좌석으로 옮긴다.

## 4. 상태·복구·위협의 관계

`Playing → Boarding → Ignition → Ascending → Success`

- `Playing`: 현재 맵 이탈 복구를 적용한다. 핵심 파츠 유실은 씬 초기화가 우선이다.
- `Boarding` 진입: 서버가 완료 상태를 확정하고 플레이어를 회복시킨다. 이후 운석·모래폭풍 피해, 절단, 밀기, R 개인 복구, 맵 이탈에 의한 초기화를 잠근다.
- `Ignition / Ascending`: 컷씬 루트가 로켓과 탑승자를 제어한다. 외곽을 지나가는 정상 발사가 유실로 처리되면 안 된다.
- `Success`: 서버만 `GameSession.Clear()`를 호출한다. 로컬 영상 재생 종료 이벤트가 서버 기록을 직접 확정하지 않는다.
- 일시적인 애니메이션 누락은 전체 초기화 사유가 아니다. 서버 시각 기준으로 좌석 배치와 최종 상태를 보장하고 대체 카메라를 사용한다.

현재 복구 코드의 `RecoverySuspended`는 기존 `LaunchTest.Ascending / Success`와 `GameSession.Cleared`를 읽는다. 새 컷씬을 구현할 때는 `Boarding`부터 복구를 잠그는 명시적 상태 연결이 추가로 필요하다.

## 5. 멀티플레이와 예외

- 서버가 `runId`, 단계, 단계 시작 시각, 로켓 식별자, 참가자별 좌석을 확정한다. 클라이언트는 서버 시각에 맞춰 카메라·음향·애니메이션을 재생한다.
- 후속 접속자는 이미 지난 탑승 연출을 다시 시작하지 않는다. 현재 단계의 관전 화면부터 보여주고, 완료 당시 참가자 목록에 소급 추가하지 않는다.
- 중도 이탈자는 대기 대상에서 제거한다. 나머지 참가자의 컷씬은 계속 진행한다. 전원 연결 해제와 호스트 종료는 기존 세션 종료 처리를 따른다.
- 초안에서는 건너뛰기 버튼을 제공하지 않는다. 추가한다면 서버가 접속 참가자 전원의 동의를 받은 뒤 전원에게 같은 최종 상태를 적용한다.
- 시간 기록은 마지막 용접 완성을 확정한 시점까지의 플레이 시간으로 제안한다. 현재 `GameSession.Clear()`는 호출 시점의 시간을 쓰므로, 컷씬 18초를 기록에 더하지 않도록 완료 시각을 전달하는 변경이 필요하다.
- 성공 화면은 팀 기록과 ‘로비로’ 버튼을 우선 제공한다. 2장이 준비되면 페이드 뒤 서버가 다음 씬 전환을 수행한다.

## 6. 후속 구현 연결 지점

| 기존 코드 | 사용할 책임·추가 작업 |
| --- | --- |
| `ShipAssembly`, `PartGraph`, `PartAssemblyLink` | 조립대·파츠 순서·연결·필수 용접 완료 검증 |
| `ShipHatch` | 기존 수동 탑승 인원 관리와 자동 컷씬 탑승을 중복 실행하지 않도록 통합 |
| `LaunchTest` | 기존 물리 시험과 새 확정 발사를 동시에 실행하지 않도록 실행 모드 분리 |
| `PlayerRig`, `TractorBeamController` | 장비·손·운반체 연결 해제, 좌석 배치, 몸체 표시 |
| `MapRecovery` | `Boarding` 이후 종료 상태를 받아 복구 중단 |
| `WorldSync`, `ProgressSync` | 서버 단계·시각·로켓 상태 동기화 및 성공 한 번 확정 |
| `GameSession`, HUD | 조작 잠금, 플레이 완료 시각 기록, 성공 화면 |

필요한 연출 에셋: 해치 진입점·최대 4개 대기점과 좌석점, 해치 열림/닫힘, 캐릭터 탑승/착석, 로켓 점화/상승 카메라 경로, 엔진 불꽃/연기/지면 먼지, 완성/해치/점화/발사 사운드. 이번 변경에는 새 컷씬 씬·Timeline·애니메이션 에셋을 만들지 않는다.

## 7. 구현된 복구 기능의 검증 절차

화면 직접 조작 없이 코드 컴파일을 검증했으며, Unity 플레이 검증은 아래 순서로 별도 수행한다.

| 시나리오 | 기대 결과 |
| --- | --- |
| 솔로에서 수평 네 방향 경계 + 3m 바깥으로 이동 | 해당 플레이어만 리스폰. 파츠·용접·운반체 위치 보존 |
| 플레이어를 기준면 - 5m 아래로 이동 | 체력 회복, 속도·손 연결 제거 후 리스폰 |
| 도구를 들거나 운반체에 탄 채 R, 기절 중 R | 개인 복구. 도구는 원래 자리에서 드롭, 다른 플레이어의 운반체는 그대로 유지 |
| Esc 메뉴가 열린 상태에서 추락 | 입력 잠금과 무관하게 개인 복구 |
| 태블릿 또는 메뉴 중 R | 개인 리스폰 요청 없음 |
| 용접 건·방망이를 각각 수평 밖/바닥 아래로 이동하고 두 번 반복 | 각각 최초 위치·회전 복원, 속도 0, 오브젝트 개수 동일, 다시 집기 가능 |
| 아직 고정된/해제된/용접된 핵심 파츠를 하나씩 이탈시킴 | 전체 씬 초기화 1회. 시작 파츠·고정못·용접·도구·운석·진행 시간 복원 |
| 호스트+참가자 또는 전용 서버+2명에서 참가자 R | 요청자의 리스폰만 적용되고 모든 관전자에게 반영 |
| 멀티에서 핵심 파츠 2개 동시 이탈, 초기화 후 한 번 더 이탈 | 연결 유지, 매번 씬 초기화 1회, 전원 플레이어 재생성·이동·도구 및 월드 동기화 재개 |
| 정상 발사 상승 중 경계 통과 | 개인 복구나 씬 초기화 없음 |

자동 테스트 `MapRecoveryTests`: 이동한 월드 경계, 수평 4방향, 바닥 임계값, 높이 상한 없음, NaN/Infinity, 도구 반복 복원, 핵심 파츠 초기화 우선순위 및 중복 요청 방지.

검증 상태: Core·Gameplay·Network·UI·Bootstrap 및 Editor 테스트 소스를 Unity 참조와 C# 9 설정으로 컴파일해 오류 0개. Unity EditMode 테스트 실행은 프로젝트 잠금으로 중단되어 **미실행**이다. Mirror Weaver, 실제 물리·RPC·씬 재로드와 2인 플레이 동작은 아직 확인하지 않았다.
