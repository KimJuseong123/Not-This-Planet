# AI 동료 계획

[문서 안내](README.md) → **AI 동료**

> **아직 만들지 않은 것의 계획입니다.** 지금 구조가 강제하는 것(§2)은 사실이고, 나머지는 제안입니다.

4인 협동 게임인데 사람이 모이지 않습니다. 빈자리를 **말로 지시하는 NPC 동료**가 채웁니다.

## 1. 무엇을 만드나

- 방에 NPC 동료를 넣습니다. 다른 플레이어처럼 **세계 안의 몸**을 갖고 물건을 나르고 용접합니다
- 플레이어가 **채팅 또는 음성**으로 지시하면 그대로 움직입니다 — *"왼쪽 파트 가져와"* · *"여기 붙여"* · *"그만"*
- 대화 상대가 아니라 **손이 하나 더 있는 것**입니다. 잡담은 범위 밖입니다

## 2. 지금 구조가 강제하는 것

이 세 줄이 설계를 거의 다 정합니다.

| 사실 | 어디 | 따라 나오는 것 |
| --- | --- | --- |
| **물리는 서버에서만 돈다.** 클라이언트의 같은 오브젝트는 키네마틱으로 두고 받은 자세를 따라간다 | `WorldSync.cs` (`-145`) | NPC 의 **몸은 호스트에서** 굴러야 한다. 클라이언트가 NPC 를 직접 움직이면 결과가 갈린다 |
| 플레이어는 입력을 `[Command]` 로 보내고 **서버의 `PlayerRig` 가 그 입력으로 힘을 가한다** | `NetPlayer.cs` | *"클라이언트가 의도를 보내고 호스트가 실행한다"* 는 **이미 있는 모양**이다. NPC 명령은 그 모양을 그대로 쓴다 |
| 씬에 배치된 오브젝트는 `NetworkIdentity` 를 못 단다(sceneId 문제). 대신 중계 오브젝트가 자세를 실어 나른다 | `WorldSync.cs` | NPC 는 **씬 오브젝트가 아니라 서버가 띄우는 프리팹**이어야 한다. 그러면 이 제약을 안 만난다 |

**그래서 구상하신 방향이 구조와 맞습니다.** 각자 로컬에서 말을 해석하고 **결과만** 호스트로 보내면, 그것은 키보드 입력이 `[Command]` 로 가는 것과 같은 길입니다. 호스트가 권위를 갖는 것도 그대로입니다.

## 3. 층을 셋으로 나눕니다

| 층 | 하는 일 | 어디서 도나 | 없으면 |
| --- | --- | --- | --- |
| **말 → 글** | 음성 인식(STT) | 말한 사람의 PC | 채팅으로 친다 |
| **글 → 의도** | `"왼쪽 파트 가져와"` → `fetch(part=3)` | 말한 사람의 PC | 규칙 파서가 대신한다 |
| **의도 → 행동** | 길 찾고 집고 용접한다 | **호스트** | 아무것도 안 움직인다 |

**셋째 층이 핵심이고, 거기에 LLM 은 없습니다.** NPC 가 실제로 움직이는 것은 호스트의 상태 기계이고, 그것은 기존 `PlayerRig`·`ToolBase`·`PartClamp` 를 그대로 씁니다 — **두 번째 물리 경로를 만들지 않습니다.**

이렇게 나누면 좋은 점이 큽니다. **모델이 없어도 게임이 됩니다.** 1·2층이 빠져도 3층은 돌고, 채팅에 `가져와 3` 이라고 치면 NPC 가 움직입니다.

## 4. 모델이 할 일은 대화가 아니라 **분류**입니다

여기가 이 계획에서 가장 중요한 판단입니다.

*"왼쪽에 있는 거 가져와"* 를 `fetch(part=3)` 으로 바꾸는 것은 **정해진 목록 중 하나를 고르고 칸을 채우는 일**입니다. 자유로운 대화가 아닙니다. 그러면 필요한 모델이 완전히 달라집니다.

| | 대화용 | 의도 분류용 |
| --- | --- | --- |
| 크기(4bit) | 4~8 GB | **0.4~1 GB** |
| 출력 | 자유 문장 | 정해진 칸만 (문법 제약 디코딩) |
| 틀렸을 때 | 이상한 말을 한다 | **목록 밖이면 그냥 거절된다** |

**출력을 문법으로 묶습니다.** 모델이 무엇을 뱉든 의도 목록 밖이면 호스트가 받지 않습니다. 이것은 편의가 아니라 **필수**입니다 — `[Command]` 는 클라이언트가 보내는 것이고, 클라이언트는 고쳐질 수 있습니다. 호스트는 지금도 모든 `[Command]` 를 검증해야 하고, NPC 명령도 예외가 아닙니다.

## 5. 의도 목록 (초안)

| 의도 | 칸 | 뜻 |
| --- | --- | --- |
| `fetch` | `part` | 그 파트를 집어 우주선 쪽으로 가져온다 |
| `goto` | `target`(플레이어·파트·지점) | 그리로 간다 |
| `follow` | `player` | 따라다닌다 |
| `weld` | `joint` | 그 접합부를 용접한다 |
| `hold` / `release` | — | 지금 든 것을 유지·놓는다 |
| `revive` | `player` | 기절한 사람을 일으킨다 |
| `stop` | — | 지금 하던 것을 그만둔다 |

**`stop` 은 반드시 있어야 하고, 반드시 즉시 들어야 합니다.** 사람이 통제를 되찾는 길이 없으면 NPC 는 도우미가 아니라 사고입니다.

**칸의 값은 사람이 부르는 이름이 아니라 번호입니다.** *"왼쪽 거"* 를 번호로 바꾸는 것은 말한 사람의 클라이언트가 합니다 — 그 화면에서 무엇이 왼쪽인지는 그 클라이언트만 압니다.

## 6. 여러 사람이 동시에 시키면

| 규칙 | 이유 |
| --- | --- |
| 한 NPC 는 **한 번에 하나**를 한다 | 두 지시를 섞으면 둘 다 안 된다 |
| 나중 지시가 앞 지시를 **대신한다**(덮어쓰기) | 줄을 세우면 사람이 한참 뒤에 반응을 본다 |
| `stop` 은 누구든 즉시 | 위 |
| 호스트가 최종 판정한다 | 권위가 하나여야 한다 |

**누가 시킬 수 있나**는 정해야 합니다(§10). 전부 허용이 단순하지만, 서로 덮어쓰면 짜증이 납니다.

## 7. 모델을 어디서 돌리나 — 대안 비교

| 어디 | 장점 | 문제 |
| --- | --- | --- |
| **각 플레이어 PC(구상안)** | 서버 부하 0 · 음성 원문이 기기 밖으로 안 나간다 · 오프라인에서도 된다 | 배포 크기 · 하드웨어 편차 · 설치 실패 |
| 호스트 1대만 | 설치가 1대 · 결과가 일관된다 | 호스트는 **플레이어의 PC** 다. 물리·릴레이에 추론까지 얹으면 그 사람 프레임이 떨어진다 |
| 배포 서버(EC2) | 설치 1곳 | 4 vCPU · GPU 없음 · 메모리 15 G 를 백엔드·MySQL 둘씩과 나눠 쓴다. **"플레이 중 네트워킹 안 쓴다"** 결정과도 어긋난다 |
| 외부 API | 가장 쉽다 | 비용 · 키 관리 · 오프라인 불가. 팀 계정·토큰 규칙과도 맞지 않는다 |

**각 플레이어 PC 가 맞습니다.** 표에서 유일하게 성립합니다. 남는 문제는 **어떻게 전달하고, 편차를 어떻게 견디나** 입니다.

## 8. 전달 — 여기가 진짜 위험입니다

지금 빌드는 폴더 **444 MB** · zip **156 MB** 입니다(2026-09-15 새벽 개발 빌드 실측 — 릴리스 빌드도 같은 규모입니다). 모델을 같이 넣으면 배포물의 성격이 바뀝니다.

| 방법 | 됨? | 판단 |
| --- | --- | --- |
| 빌드에 넣는다 | ✅ 되지만 | 업데이트마다 모델까지 다시 받는다. **택하지 않습니다** |
| 런처가 **선택 내려받기** | ✅ | 런처는 이미 `files/<sha256>.gz` 를 매니페스트대로 받습니다 — **큰 파일을 하나 더 다는 것은 새 구조가 아닙니다.** 서버 디스크도 246 G 비어 있습니다 |
| 사용자가 별도 런타임 설치 | ✅ | 우리는 편하고 **플레이어가 고생합니다.** 데모에서 "먼저 이걸 까세요" 는 그 자리에서 끝입니다 |

→ **런처 선택 내려받기**로 갑니다. "AI 동료를 쓰겠다" 를 고른 사람만 받습니다.

**모르는 것은 대역폭입니다.** 우리 EC2 한 대가 nginx 로 내보냅니다. 지금 `/var/www` 는 603 MB 이고 동시 내려받기를 재 본 적이 없습니다 — **1 GB 짜리를 여러 명이 동시에 받을 때** 어떻게 되는지는 **재 봐야 압니다**(§9 M2).

## 9. 단계

각 단계가 **혼자서도 쓸모 있어야** 합니다. 뒤가 안 되면 앞에서 멈춥니다.

| 단계 | 무엇 | 끝났다고 말할 수 있는 조건 |
| --- | --- | --- |
| **M0** | 의도 계약을 정한다 — 목록·칸·검증 | 문서와 코드의 목록이 같고, 목록 밖 값이 거절되는 것을 시험이 지킨다 |
| **M1** | 호스트의 NPC 몸과 상태 기계 | 채팅에 `fetch 3` 을 치면 NPC 가 파트를 가져온다. **모델 0 MB** |
| **M2** | 로컬 소형 모델로 글 → 의도 | *"왼쪽 거 가져와"* 가 `fetch(3)` 이 된다. 실패하면 규칙 파서로 되돌아간다. 내려받기 대역폭 실측 |
| **M3** | 음성(STT) | 말로 해도 M2 와 같은 결과. 지연 목표 아래(§10) |
| **M4** | 자동 플레이어 | 같은 의도 계층을 대본이 몰아 판을 완주하고 이벤트를 낸다 |

**M4 가 데이터 파이프라인과 만나는 자리입니다.** 의도 계층이 호스트에 있으므로, 그 위를 사람이 아니라 대본이 몰면 그대로 자동 플레이가 됩니다. 사람이 없어도 판이 돌고 [플레이 데이터 파이프라인](data-pipeline.md) 의 이벤트가 쌓입니다.

**다만 그것은 사람의 데이터가 아닙니다.** 봇은 시스템(밸런스·물리·크래시)에 대해 말하지, 사람이 무엇을 헷갈려 하는지는 말하지 않습니다. `source` 로 갈라 둡니다.

## 10. 정해야 할 것

| 항목 | 선택지 |
| --- | --- |
| NPC 인원 | 빈자리를 다 채울지, 최대 1명으로 둘지 |
| 지시 권한 | 모두 / 호스트만 / NPC 마다 담당자 |
| 방 인원 셈 | NPC 가 4인 정원에 들어가나 (`Room`·`RoomPlayer` 는 지금 메모리에만 있습니다) |
| 음성 원문 처리 | **기본은 기기 밖으로 내보내지 않음.** 데이터 파이프라인에도 담지 않는다 |
| 지연 목표 | 말이 끝나고 NPC 가 움직이기 시작할 때까지 — **1.5초 이내**를 제안합니다 |
| 최소 사양 | 모델을 못 돌리는 PC 에서의 기본 동작(= 규칙 파서) |

## 11. 안 하기로 하는 것

- **잡담·역할극** — 범위를 넓히면 모델이 커지고, 커지면 §8 이 무너집니다
- **NPC 가 스스로 판단해서 움직이는 것** — 지시 없이 움직이면 사람이 통제를 잃고, 무엇이 버그인지 가릴 수 없습니다. M4 의 자동 플레이어는 **대본**이지 자율이 아닙니다
- **모델을 게임 로직 판정에 쓰는 것** — 용접이 됐는지 같은 판정은 지금처럼 규칙이 합니다
