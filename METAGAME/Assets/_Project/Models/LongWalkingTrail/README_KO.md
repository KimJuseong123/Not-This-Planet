# Stage1 Astra · Long Walking Trail 모델 패키지

2026-09-16 · Blender **5.2.2 LTS / Blender MCP**로 제작.

이 대화에서 만든 L01~L11 컨셉을 바탕으로 **11종의 실제 3D 모델**을 제작했다. 흰 프레임·라벤더 패널·청록 유도등을 유지하면서 이음새, 미끄럼방지 인레이, 측면 점검구, 육각 체결구, 하부 보강재, 센서 통풍구와 케이블 접점, 난간 고정부를 추가했다.

## 포함 파일

- 외관 FBX **11개**: 각 오브젝트 폴더의 `SM_Astra_*.fbx`.
- 충돌 전용 FBX **11개**: 각 폴더의 `Colliders/UCX_SM_Astra_*.fbx`. 외관 FBX와 같은 원점·축이다.
- `.fbm` 텍스처 폴더 **11개**, 1024×1024 PNG **66장**: BaseColor / Metallic / Roughness / Normal / Emission / MetallicSmoothness.
- Unity URP Lit 재질 **11개**와 `.meta`: FBX의 재질 이름을 해당 `.mat`으로 연결했다.
- 실제 모델 렌더 **11개**, 실제 정투상 5방향 렌더 **55개**, 6뷰 시트 **11개**, 전체 미리보기 1개.
- [Blender 편집 원본](Source~/Astra_LongWalkingTrail.blend): 11개 독립 씬, 개별 구성품과 수정 가능한 베벨, 병합된 출력 메시 및 촬영 설정. 텍스처를 내부에도 패킹했다.
- [재현용 제작 스크립트](Source~/build_astra_longwalking.py).
- ZIP 파일은 생성하지 않았고 최종 패키지에서 **0개**임을 확인했다.

`Source~`, `Previews~`는 Unity가 자동 임포트하지 않는 보관용 폴더다. 모델 사용에는 각 오브젝트의 FBX·FBM·MAT·META를 사용한다. 소스 `.blend`의 중복 자동 변환을 피하도록 구성했다.

## 크기·원점·배치

단위는 **미터**. Blender는 X=폭, Y=길이, Z=높이이고 FBX는 `-Z forward / Y up` 옵션으로 내보냈다. 축 변환 행렬 기준 Blender 정면 -Y는 내보낸 +Z 쪽이다. 컨셉 문서의 추상 -Z 정면 정의와 다르므로 실제 모델의 낮은 계단·센서 점검구·방향 표식을 기준으로 맞춘다.

- L01~L05: 기존 폭 **4.4m**, 두께 약 **0.6m**, 길이 각각 **13.810682 / 13.824023 / 15.951557 / 11.277806 / 8.51025m**. 중심 원점이다. 작은 볼트 등의 장식으로 외형 경계는 수 mm 커질 수 있다.
- L06: **3.8 × 0.36 × 2.7832742m**, 중심 원점.
- 위 데크는 경사를 메시 안에 넣지 않았다. 씬의 기존 회전값으로 설치한다. 기존 Cube의 스케일 수치를 다시 적용하면 이중 확대되므로 **새 모델 스케일 1,1,1**을 기준으로 배치한다.
- L07: 폭 3.355m, 높이 약 0.81m, 길이 약 2.04m. 바닥 중앙 원점, Blender -Y 쪽이 낮은 첫 단.
- L08: 약 0.8m 지름의 낮은 원통 센서. 바닥 중앙 원점. 정면 점검구·우측 루버·후면 소켓으로 구분한다.
- L09: 약 **4.4 × 0.2 × 2.4m**, 중심 원점. 접점 높이와 각도를 후속 배치 때 맞춘다.
- L10: 약 **2 × 1 × 0.18m**, 바닥 중앙 원점. 보행면을 향한 쪽에 청록 조명이 있다.
- L11: 중심선 반지름 **14m**, 외곽 지름 **32.4m**, 데크 전체 폭 **4.4m**, 270° 구간에서 **7m 상승**, 평균 경사 약 **6.06°**. 길이 약 **65.97m**. 원점은 원 중심의 지면 높이이며 낮은 입구 바닥 상면은 약 0.60m, 높은 출구는 약 7.60m다. 프레임 포함 최대 높이는 약 7.622m다.
- L11은 기존 직선 길 5개를 곡선으로 재해석한 **대체 노선**이다. 현재 씬의 언덕 형상과 정확히 맞춰 배치한 상태는 아니다. 지지대는 평평한 기준 바닥에 닿으므로 실제 지형에 맞춰 길이·위치를 조정한다.

정확한 최종 외형 경계와 삼각형 수는 `asset-catalog.json`에 기록했다. 원래 폭은 전체 외곽 폭이며, 흰 프레임 사이의 라벤더 바닥 폭은 그보다 작다.

## Unity 사용

1. 각 폴더의 `SM_Astra_*.fbx`를 사용한다. `.fbm` 폴더와 `.mat`, `.meta`를 함께 유지한다. UV0는 재질 종류별 4×4 아틀라스이며 임포터에 라이트맵 UV 생성 설정을 넣었다.
2. FBX의 재질 remap이 `.mat`을 참조한다. BaseColor·Emission은 sRGB, Normal·Metallic·Roughness·MetallicSmoothness는 선형 데이터다. URP에는 **MetallicSmoothness의 R=금속도, A=매끄러움**을 연결했다. Roughness 원본은 타 DCC용으로 함께 제공한다.
3. 기존 보행로를 교체할 때 위치·회전을 먼저 맞추고 스케일은 1로 시작한다. L07·L08처럼 통합 모델로 만든 요소는 기존 반복 장식과 중복 배치하지 않도록 확인한다.
4. `Colliders`의 FBX는 **MeshCollider에 지정할 단순 메시**다. `UCX_`는 파일 구분 이름이며 Unity에서 충돌체를 자동 생성하는 기능이 아니다. 외관과 같은 원점으로 두고 MeshRenderer는 사용하지 않는다.
5. 나선형 길은 **정적 non-convex MeshCollider**로 사용한다. Convex로 만들면 열린 중앙과 곡선 내부를 막을 수 있다. 지지대·볼트·센서 루버 등의 세부 형상은 충돌 메시에서 생략했다. 난간 충돌체는 열린 중간부도 막는 단순 박스다.
6. 씬 적용 후 파츠 운반 폭, 문턱, 지형 관통, 플레이어 이동을 확인한다. 이번 작업은 모델 패키지 제작이며 씬 배치·게임플레이 코드는 변경하지 않았다.

## Blender 원본 편집

`Source~/Astra_LongWalkingTrail.blend`를 열고 `Astra_LWT_*` 씬을 선택한다. 각 씬에는 렌더용 병합 메시 `SM_Astra_*`, 숨겨진 개별 구성품, 충돌 메시, 카메라·조명이 있다. 개별 구성품을 편집할 때 병합 메시를 숨기고 해당 구성품을 표시한다. 겹쳐 표시하면 두 메시가 포개진다. 원본 구성품도 재질 아틀라스 UV를 갖고 있다.

## 검증 결과와 범위

- 11개 외관 FBX를 Blender에서 재가져오기: **크기·삼각형 수 유지, UV 유지, 연결 텍스처 누락 0**.
- 11개 충돌 FBX 재가져오기: **삼각형 수 유지**.
- 외관 및 충돌 메시: 퇴화 면 0, 비매니폴드 엣지 0. 서로 접하거나 겹치는 독립 부품을 포함하는 조립형 외관이며 하나의 결합된 솔리드라는 뜻은 아니다.
- 나선형 충돌 표면: 폭 방향 3줄 × 경로 방향 143점 = **429점** 레이 검사 통과. 높이 최대 오차 약 **0.000004m**.
- 실제 모델의 전체 렌더 및 6방향 시트를 확인했다. 겹친 이음판 표면, 계단 측면 중복 면을 수정했다.
- Unity용 파일 참조와 임포트 설정을 준비했다. **Unity Editor 내 재질 렌더·Play Mode·실제 캐릭터 운반 테스트는 수행하지 않았다.**
- 원래 Blender 씬을 보존하고 작업 후 해당 씬으로 복귀했다. 최종 산출물 폴더에 ZIP 없음.
