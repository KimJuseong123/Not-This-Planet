## 수동 파츠 운반 설정 (2026-09-10)

컨셉 Playable의 네 파츠에 `Part Ground Hover`를 추가하고 기존 `Part Push`에서
`Allow Pull`을 활성화했다. 모든 필수 고정못 해제 후 지면 가까이에서 약 0.25m 부유한다.
견인 중, 용접 완료, 다른 소켓과 결합 중, 저중력장 안에서는 자체 부유를 멈춘다.
절벽 밖에서 같은 고도를 유지하지는 않으며, 지면이 멀면 낙하한다.

- 밀기: 몸체 가까이에서 파츠 방향으로 걷기. 별도 버튼은 필요 없다.
- 당기기: 파츠 몸체를 조준하고 좌/우클릭으로 잡은 채 뒤로 이동하기.
- 속도: Play를 끈 뒤 Hierarchy `Stage1 > Gameplay > Puzzle` 아래 `Part_1`~`Part_4` 선택.
  Inspector `Part Push > Speed Multiplier`를 수정하고 씬을 저장한다.
  1은 기본 속도(1/2/3/4인: 0.4/0.8/1.2/1.5m/s), 2는 두 배, 0.5는 절반이다.
  여러 파츠를 함께 선택하면 일괄 수정 가능하다. Play 중 수정은 종료하면 되돌아간다.
- 높이: 같은 파츠의 `Part Ground Hover > Hover Height` (m). 기본 0.25.

속도는 수동 운반 목표 속도 배율이며, 운석 충격이나 견인 속도의 상한이 아니다.
기존 Main은 Allow Pull을 기본 비활성화로 보존하고 Ground Hover도 추가하지 않았다.
물리 처리는 기존 서버 권한 판정을 존중한다. 실제 다중 클라이언트 플레이는 미검증이다.

검증: `../concept-playtest/manual-unit.xml` (PartPush 23개 통과),
`../concept-playtest/manual-transport.txt` (실제 씬 입력 경로; 결과/실행 시각 확인).
09:07:15 실제 씬 재검사 통과: 엔진의 첫 3개 못은 테스트 준비로 해제하고 마지막 못은
실제 잡기/뒤로 이동 입력으로 해제했다. 부유 간격 0.250m, 1인 기본 배율에서
3초 밀기 약 1.18m / 3초 당기기 약 0.98m 이동을 확인했다.
견인 상태로 전환하면 자체 부유와 수동 밀기가 모두 중지된다.
접촉 중 보행 속도도 목표 속도에 맞추므로 플레이어 충돌로 배율을 우회하지 않는다.
이 검사는 엔진 대표 파츠 기준이며, 첫 3개 못의 입력 및 멀티플레이 전체 완주를 포함하지 않는다.

## 2026-09-10: 플레이 연결·비주얼 수정 (아래 초기 기록보다 우선)

### 바로 플레이하기

Unity에서 `Tools → NOT THIS PLANET → 컨셉 맵 → 플레이용 씬 열기`를 선택한 뒤 Play.
대상은 `Assets/Scenes/Stage1_Concept_Playable.unity`다.
남서쪽 기지에서 기존 플레이어로 시작한다. Tab 태블릿, 장비 줍기와 사용,
좌클릭 용접 / 우클릭 절단, 견인체 가까이에서 E 탑승 등 기존 조작을 사용한다.
`Stage1_Concept`는 자유 카메라 아트 검토용이므로 플레이용과 혼동하지 않는다.

Main에서 실제 4개 파츠·8개 소켓·16개 고정못·장비·조립·해치·발사·운석을
별도 씬으로 복사하고 새 위치에 연결했다. 원본 Main/Lobby와 공유 프리팹은 변경하지 않았다.
도보용 경사로, 새 시작점, 넓어진 비행 범위와 고도, 맵에 맞춘 운석 영역을 제공한다.

### 확정 기획과 아직 다른 부분

- Main의 PartTractorActivator는 엔진 Part_1을 견인체로 바꾸면서 조립 소켓을 끈다.
  컨셉 복사본에서만 이 컴포넌트를 제거하고 별도 견인체를 두어 4단 조립을 유지했다.
  따라서 견인체와 최상단 조립 파츠가 같은 계열 모델로 각각 존재한다.
  **견인체 자체가 마지막 파츠로 도킹하는 기능은 아직 미구현**이다.
- 색상 암호, 태블릿 순서와 신호 연동, 필수 플레이어 던지기, 인원별 퍼즐은 미구현이다.
  단말기와 신호는 시각 모형이다. 끊어진 다리에는 테스트용 보행 연결로를 추가했다.

### 비주얼 수정

- 우주선 캡슐을 거주동으로 중복 사용하던 부분을 없애고 별도 조립식 시작기지를 만들었다.
- 격납고 지붕 위 반복 바위를 금속 패널로 교체하고, 외곽 바위·식생 크기를 조정했다.
- 지면은 기존 `SandTexture.png`의 입자 질감을 전용 URP 셰이더로 광물색 처리한다.
  원본 텍스처는 수정하지 않으며, 행성용 MoonTexture를 지면에 쓰지 않는다.
- 푸른 환경광, 완화한 그림자, 청록 시설과 따뜻한 기지 조명을 사용한다.
- 납작한 원형 발판에 붙었던 기본 CapsuleCollider를 MeshCollider로 교체했다.
  캡슐형 충돌체가 플레이어를 위로 밀어내던 원인을 수정한 것이다.
- 컨셉아트와 같은 완성 아트는 아니다. 시설·지형 형태와 세부 장식은 프로토타입이다.

- 생성 메뉴: `Assets/_Project/Scripts/Editor/Stage1ConceptMapBuilder.cs`
- 독립 카메라: `Assets/_Project/Scripts/Runtime/Gameplay/World/Stage1ConceptExplorer.cs`
- 선택적 배치 실행 검사: `Assets/_Project/Scripts/Editor/Stage1ConceptSmokeCheck.cs`

Hierarchy는 Landscape / Assembly / Camp / Tractor / Hill / Hangar / Ecology /
Atmosphere / Viewer로 구분되어 있다. 씬의 오브젝트를 직접 움직여 수정할 수 있다.

공유 환경·토끼·우주선 프리팹과 텍스처는 참조만 한다.
암석 색상 조정용 재질은 복제했으며 공유 원본을 저장하지 않는다.
배치된 우주선·소품은 아트 전시용으로 고정했다.
Main/Lobby, Build Profiles, 중력, 네트워크 구성, 기존 에셋 원본은 변경 대상이 아니다.
컨셉 씬은 의도적으로 정식 빌드 목록에 추가하지 않았다.

컨셉용 파이프라인은 기존 PC URP 설정을 복제해 조감 시점의 그림자 거리를 늘렸다.
Play 동안만 임시 적용하며 카메라 컴포넌트를 끄거나 Play를 종료하면 이전 설정으로 복구한다.
에디터에서 Play 전 Scene 뷰는 원래 프로젝트 파이프라인을 사용하므로 먼 그림자가 다를 수 있다.

`컨셉 씬 생성·재구성`은 생성 결과로 씬을 다시 만드는 명령이다.
수동 편집 이후에는 주의해서 사용해야 한다. 실행 전 프로젝트 밖
`../concept-backups/날짜-시각/`에 기존 씬을 복사한다.
이 백업은 씬 배치 백업이며, 재생성되는 재질·메시까지 포함한 전체 프로젝트 백업은 아니다.

## 비용과 도구

- Tripo3D, 이미지/영상 생성 서비스, 유료 API 호출 없음.
- 추가 결제, 구독 변경, 크레딧 충전 없음.
- Blender나 새로운 Unity 패키지 설치 없음.
- 설치된 Unity Editor와 기존 로컬 에셋만 사용.
- Unity Essentials는 가이드 스킬로 사용했으며, 이번 세션에 호출 가능한 Unity MCP 연결은 없어 로컬 Unity 배치 실행을 사용했다.

## 검증과 한계

별도 로그와 실제 Unity 렌더는 저장소 밖이 아닌 저장소 최상위의
`concept-previews/`에 저장된다. 실행 로그는 checkout 상위 `astra/concept-*.log`에 있다.
프리뷰 이미지는 생성형 컨셉아트가 아니라 Unity 카메라 렌더다.

컴파일, 씬 재열기, Missing Script·재질 검사, 시점별 실제 렌더를 확인한다.
Play Mode 자동 검사는 120프레임 실행 및 카메라 비활성화/재활성화에 따른
임시 파이프라인 복원을 확인하는 범위다. 실제 키 입력 조작·멀티플레이·게임 퍼즐 테스트와 다르다.

정식 플레이 맵에 편입하기 전에는 도보 경사/충돌/간격, 모듈 반출 폭,
견인 모듈의 천장 통과 여부, 플레이 인원별 퍼즐 규칙을 별도로 검증해야 한다.
최적화·플레이어 빌드·멀티플레이 검증은 이번 아트 작업의 완료 주장에 포함하지 않는다.
