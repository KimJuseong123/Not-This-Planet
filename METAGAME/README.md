# 둥실둥실 우주 대탈출 (SpaceFlop)

휴먼 폴 플랫 식 **물리 인형 장애물 코스** — 소행성 표면 버전.
Unity 6000.5.4f1 / Built-in Render Pipeline.
세계와 물리는 전부 런타임 코드가 세우고, 겉모습만 블렌더 모델 2종을 그 위에 씌운다.

지구 버전([../FloppyFall](../FloppyFall))에서 세 가지를 바꿨다.

| | FloppyFall (지구) | SpaceFlop (소행성) |
|---|---|---|
| 캐릭터 | 키 1.95m, 7등신 인형 | **귀 끝까지 1.33m, 약 2.1등신 우주 토끼** (헬멧 지름 0.636m) |
| 중력 | −18 m/s² (현실보다 무겁게) | **−2.8 m/s²** (지구의 29%). 점프 2.06m · 체공 2.4초 |
| 잡기 | 반경 0.26m, 닿아야 잡힌다 | **반경 0.50m + 자석 손 1.10m**. 잡은 물건은 **무게를 무시**하고 끌려온다 |
| 룩 | 전부 프리미티브 | **블렌더 모델 2종**(우주 토끼·캡슐 우주선)을 물리 위에 씌운다 |

```
Unity.exe -batchmode -quit -projectPath . -executeMethod Metagame.EditorTools.SpaceBuild.BuildWindows
Build/Windows/SpaceFlop.exe                                     # 그냥 플레이
Build/Windows/SpaceFlop.exe -batchmode -nographics -space-selftest -logFile out.log   # 종료코드 0 = 통과
Build/Windows/SpaceFlop.exe -space-screenshot -space-shotdir Screenshots -screen-width 1280 -screen-height 720
```

에디터 메뉴는 `Tools/둥실둥실 우주 대탈출/` 아래에 있다.
씬(`Assets/_Project/Scenes/Surface.unity`)에는 `SpaceBootstrap` 컴포넌트 하나뿐이다.

## 체력 · 피해

체력은 100으로 시작하며 화면 왼쪽 위의 별도 체력 바에서 확인할 수 있다.
낙하할 때는 현재 낙하 높이와 착지 속도를 함께 검사하므로 일반 점프 착지는 안전하고,
높은 곳에서 빠르게 떨어져 착지하면 피해를 받는다. 체력이 0이 되면 현재 체크포인트로 되돌아가며 체력이 회복된다.

운반할 수 있는 오브젝트에는 `Grabbable`을 붙이면 도구로 취급된다. 좌클릭과 우클릭은 고정물에서는 기존처럼 각각의 손으로 작동하고,
동적 Rigidbody가 있는 도구에서는 양손이 함께 잡는다. `Q`를 짧게 누르면 내려놓고, 꾹 누르면 최대 2초 동안 충전한 뒤 놓는 순간 충전량에 비례해 시선 방향으로 던진다.

운석이나 위험 오브젝트에는 `DamageSource` 컴포넌트를 붙이면 된다. 인스펙터에서 피해량,
최소 충돌 속도, 연속 충돌 피해 간격을 설정할 수 있고, 물리 충돌과 트리거 모두 지원한다.
코드에서 직접 피해를 줄 때는 플레이어의 `PlayerRig.ApplyDamage(amount, source)`를 사용한다.

## 캐릭터 — 2등신 우주 토끼

귀 끝까지 1.33m, 헬멧 지름 0.636m → **약 2.1등신**.
통통한 달걀 몸에 다리가 짧고 머리가 절반을 차지한다.

**물리 뼈대의 치수는 상상해서 정한 것이 아니라 모델에서 직접 뽑았다.**

| | 값 (m) | |
|---|---|---|
| 부츠 | 0 ~ 0.14 | |
| 골반 | **0.30** | `Tuning.RideHeight` — 지구 버전(0.50)보다 훨씬 낮다 |
| 가슴 | 0.49 | |
| 어깨 | 0.606 | 모델의 0.204 보다 조금 바깥(0.255)에 둔다 — 안 그러면 팔이 몸에 파묻힌다 |
| 헬멧 | 0.51 ~ 1.15, 지름 0.636 | 콜라이더는 여기까지 |
| 귀 | 1.02 ~ 1.33 | 콜라이더 없음 (실루엣만) |

부위 15개(골반·가슴·헬멧 + 팔 6 + 다리 6), 몸무게 34.9kg. 애니메이션 클립은 하나도 없다.

> **왜 뼈대를 모델에 맞췄나.** 반대로 (모델을 기존 뼈대에 맞춰) 늘이면 짧은 다리가 42% 길어져
> 캐릭터가 다른 것이 된다. 이 모델은 부품별 rigid 가 아니라 **부드럽게 스킨된 단일 메시**(정점 10,649개)라
> 본을 억지로 늘이면 살이 그대로 늘어난다.

서 있는 방법은 지구 버전과 같다 — 골반을 떠받치는 스프링, **세계에 매인 회전 조인트**로 세우기,
조인트 목표 자세로 만드는 걷기. (`AddTorque` 로는 인형을 못 세운다. 조인트 드라이브는 솔버 *안*에서
풀리고 AddTorque 는 *밖*에서 더해지는 힘이라 언제나 진다.)

## 시점 — 1인칭

카메라는 캐릭터의 머리 높이에 고정된 **1인칭 시점**이다. 화면 중앙이 보는 방향으로 팔을 뻗고,
WASD는 시선의 수평 방향을 기준으로 움직인다.

카메라가 **각도를 두 벌** 들고 있다.

- `yaw/pitch` — 실제로 보는 각도
- `aimYaw/aimPitch` — **조작의 기준**이 되는 각도 (WASD 방향, 팔이 뻗는 방향)

평소엔 둘이 같다. **Alt 를 누르고 있는 동안만** 보는 각도만 움직이고 조작 기준은 얼어붙는다.
그래서 이동 방향을 유지한 채 주변을 둘러볼 수 있다.
손을 떼면 보는 각도가 조작 기준으로 부드럽게 되돌아온다(`ReturnSpeed 7.5`).
되돌아오는 중에 마우스를 움직이면 사람이 우선이다 — 복귀가 즉시 취소된다.

자유 시점 동안에는 위아래 각도 제한도 넓어진다(−42~74° → −78~84°).

## 블렌더 모델 씌우기

`Assets/_Project/Models/` 의 FBX 두 개가 이 프로토타입의 겉모습이다.

| 파일 | 쓰이는 곳 |
|---|---|
| `Characters/SF_Rabbit_Base.fbx` | 플레이어 (본 41개 · 스킨 메시 1개 · 21k 삼각형) |
| `Spaceships/SF_Spaceship_Capsule.fbx` | 출발 착륙선과 골의 구조 캡슐 (메시 91조각) |

원본 `.blend` 는 `BlenderSource/` 에 있다. 토끼는 `.blend` 만 있어서 FBX 로 내보내야 했다 —
`Tools/Blender/` 의 스크립트와 같은 설정(`axis_forward=-Z`, `axis_up=Y`, `primary_bone_axis=Y`)으로 뽑았다.
`Characters/SF_Rabbit_Base.fbm/` 의 컬러·노멀 맵이 같이 들어간다.

이전 캐릭터 `SF_Astronaut_Base.fbx` 는 `Models/Characters/` 에 그대로 남아 있지만 빌드에는 들어가지 않는다
(`SpaceSuit.ResourceKey` 와 `ArtLink` 한 줄만 바꾸면 되돌릴 수 있다).

### 물리는 건드리지 않는다

`SpaceSuit.cs` 는 랙돌 위에 메시를 **덮어씌우기만** 한다.
강체·콜라이더·조인트는 그대로 두고, 프리미티브 Renderer 를 끈 다음
모델의 본 25개를 대응하는 강체의 월드 트랜스폼으로 매 LateUpdate 마다 덮어쓴다.
트위스트 본(`*Twist01/02`)은 표에 없다 — 부모를 따라가면 저절로 제자리에 온다.

셀프테스트가 이걸 지킨다 — **콜라이더는 여전히 15개**, 프리미티브는 **0개가 보이고**,
본이 강체에서 벌어진 거리 **< 0.02m**, 실루엣 높이 **1.33m**,
그리고 **보이는 손과 실제 잡는 손의 거리 < 0.18m**.
`SpaceBootstrap.useModel` 을 끄면 프리미티브 룩으로 돌아간다 (물리는 완전히 같다).

### 여기서 네 번 데였다

- **좌우는 이름이 아니라 좌표로 판단한다.** FBX 축 변환이 X 를 뒤집기 때문에 모델마다
  `L_` 이 어느 쪽인지 달라진다. 이 토끼는 `L_` 이 유니티 −X 라 우리 인형의 왼쪽과 맞지만,
  앞의 우주비행사는 정반대였다. 우주선도 같은 이유로 큰 창이 문서의 `+Z` 가 아니라 **−Z** 를 본다.
  **문서가 아니라 임포트 결과를 믿는다** — `Tools/모델 구조 찍어보기` 로 실제 좌표를 찍어 보면 된다.
- **바인드 자세 보정.** 토끼는 팔을 옆으로 뻗은 **T 자세**로 바인드돼 있는데 랙돌의 팔은 아래로 내려와 있다.
  그대로 따라가게 하면 손이 몸 옆 30cm 에 떠 있는다 — **잡는 지점과 보이는 손이 어긋난다.**
  팔 6개만 "아래로 펴는" 보정을 넣고, 팔 길이는 모델 자신의 마디 길이로 이어 붙였다
  (본의 로컬 +Y 가 뼈 방향이다 — 블렌더 규약이라 모든 본에 통한다).
- **`Renderer.bounds` 로 키를 재면 안 된다.** 스킨 메시의 바운드에는 유니티가 여유분을 붙여
  0.979m 모델이 1.084m 로 나온다(11% 크게). 메시 자신의 바인드 바운드를 월드로 옮겨 재야 한다.
  그때도 **메시 로컬 축이 블렌더 그대로**일 수 있어(이 모델은 로컬 y 가 '깊이'다) 축을 골라 읽으면 안 되고
  8모서리를 전부 옮겨서 봐야 한다.
- **강체의 Renderer 만 끄면 모자란다.** 팔 띠·무릎테 같은 장식은 강체가 아니라 그 자식이라
  그대로 남아, 모델 위에 주황 고리가 둥둥 떠 있게 된다. 인형 아래 **모든** Renderer 를 꺼야 한다.

### 텍스처가 blend 안에 pack 되어 있을 때

Tripo 로 만든 모델이라 4096² 맵이 `.blend` 안에 packed 되어 있었다.
그 상태로 내보내면 텍스처가 **한 장도 따라오지 않는다**(원본 경로가 이미 사라진 임시 폴더다).
`image.save()` 로 `.fbm` 폴더에 풀어 쓴 뒤 `unpack(method='REMOVE')` 로 떼고 내보내야 한다
(`image.packed_file = None` 은 읽기 전용이라 안 된다).
쓰지 않는 metallic/roughness 맵은 재질에서 떼어 낸다 — 안 그러면 4096 텍스처를 두 장 더 끌고 온다.

### 씬에 에셋을 꽂을 자리가 없다

이 프로젝트는 씬에 부트스트랩 하나만 두고 나머지를 코드가 세우는 구조라 인스펙터로 FBX 를 꽂을 데가 없다.
그렇다고 FBX 를 `Resources/` 로 옮기면 블렌더 쪽 경로가 깨진다.
그래서 `ArtLink.cs` 가 **원본은 `Models/` 에 그대로 두고 그것을 가리키는 얇은 프리팹만 `Prefabs/Resources/` 에** 만들고,
안 쓰는 프리팹은 지운다. 빌드할 때 자동으로 돌고,
손으로 돌리려면 `Tools/둥실둥실 우주 대탈출/모델 → Resources 프리팹 갱신`.

## 저중력 — 코스 설계가 전부 여기 매여 있다

```
중력      2.8 m/s²                    (지구의 29%)
점프 높이  v²/2g  = 3.4² / 5.6 = 2.06m
체공      2v/g   = 2.43초
달려 뛴 사거리  4.6 × 2.43 = 11.17m
```

이 세 숫자가 코스의 모든 간격을 정한다. 셀프테스트가 부등식을 지킨다.

| 구간 | 수치 | 지켜야 하는 것 |
|---|---|---|
| 크레이터 도약 | 5.0m / 4.0m | **< 사거리 11.17m** — 뛰어 넘을 수 있어야 한다 |
| 절벽 단차 | 3.10m | **> 점프 2.06m + 0.6** — 점프만으로는 못 넘는다 |
| 핸드레일 아랫면 | 4.30m | **서서 닿는 3.02m 보다 높고**, 뛰면 닿는 5.08m 보다 낮다 |
| 케이블 균열 | 20m | **> 사거리** — 케이블을 잡아야 한다 |
| 화물판 구간 | 14m | **> 사거리** — 발판을 타야 한다 |

공중 제어(`AirControl 0.42`)가 지구 게임보다 후한 것은 **등짐의 자세제어 분사기(RCS)** 라는 설정이다.
공중에서 방향을 틀면 등에서 김이 나온다.

먼지는 진공답게 **퍼지지 않는다** — 튀어 오른 레골리스가 공기 저항 없이 그대로 포물선을 그린다.
`Puff.cs` 가 강체 없이 직접 적분한다.

## 잡기 — 이 프로토타입이 관대한 부분

세 겹으로 쉽게 만들었다.

1. **넉넉한 반경** — 장갑 반지름(0.075m)의 여섯 배가 넘는 `GrabRadius 0.50m` 안이면 붙는다.
2. **자석 손** — 뻗은 손끝 주위 `GrabAssistRange 1.10m` 안에 잡을 것이 있으면 손 목표가 그쪽으로 옮겨간다.
   조준이 45° 빗나가도 잡힌다. HUD 조준점이 초록으로 벌어지며 이름을 띄운다.
3. **질량 무시 나르기** — 잡은 물체는 `ForceMode.Acceleration` 으로 끌어온다.
   **55kg 궤짝이 5kg 상자와 같은 속도로 온다.** 무게의 85%는 대신 들어주고,
   반작용은 16%만 몸에 실어 무거운 걸 잡아도 딸려가 자빠지지 않는다.

> **각도 판정은 어깨 기준으로 해야 한다.** 뻗은 손끝 기준으로 재면 손끝 바로 옆에 있는 물건이
> 90° 로 계산돼 전부 걸러진다 — 자석이 안 먹는 이유는 대개 이것이다.

`GripBreakForce` 는 몸무게의 40배라 사실상 놓치지 않는다.

| 3 | 계류 케이블 (58~78) | 20m 균열 위의 케이블 두 줄. 진공이라 오래 흔들린다 |
| 4 | 화물 널빤지 (x 85) | 26kg 널빤지가 밟는 쪽으로 기운다 |
| 5 | 자기부상 화물판 (92~106) | 9초 주기로 오가는 판을 탄다 |
| 6 | 에어록 (x 120.5) | **배터리 셀을 들고 와 소켓에 꽂으면** 해치가 내려간다 |
| — | 골 (x 136.5) | 회전 안테나를 피해 구조 캡슐의 옆문 앞으로 |

에어록이 이 게임의 "물건 나르기" 를 퍼즐로 쓰는 곳이다 —
14kg 셀을 7m 들고 와서 소켓 근처(1.0m)에 놓기만 하면 빨려 들어간다. 조준을 요구하지 않는다.

y < −30 으로 떨어지면 마지막 표지로 되돌아온다.
구덩이 저 아래에는 콜라이더 없는 **균열 바닥**이 깔려 있다 — 진공에는 안개가 없어서,
이게 없으면 모든 구덩이가 그냥 검은 화면으로 보인다.

## 하늘

진공이라 지구 하늘과 정반대로 맞췄다.

- **안개 없음** — 먼 것도 또렷하다
- **하늘빛 없음** — 그림자가 새까맣다. 발밑 레골리스의 반사광만 조금 넣는다
- 해는 세고 하얗다 (intensity 1.75, shadowStrength 0.94)

별 2400개는 **메시 하나**로 찍는다 (GameObject 로 만들면 드로우콜이 2400개다).
정점 색을 쓰는 `SpaceFlop/Flat` 셰이더로 그리고, 별밭·행성·해는 카메라를 따라다니되 회전하지 않는다
(스카이박스와 같은 원리 — 그래서 150m 코스를 걸어도 별자리가 흐르지 않는다).

행성의 구름 띠는 **같은 중심의 납작한 타원체**다. 표면 위로 삐져나온 테두리만 보이므로
언제나 "띠" 로 읽힌다. 덩어리를 표면에 붙이면 각도에 따라 공이 매달린 것처럼 보인다.
